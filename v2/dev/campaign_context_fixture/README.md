# Campaign context owner acceptance fixture

Development tooling for BP-07.03/B1.02d. Production Planning clients are exercised from an independently installed Planning-only interpreter against installed Registry, Runtime, Data and Knowledge CLI hosts. Source setup uses public Data APIs, Registry uses public commands, and synthetic Knowledge acceptance uses the separate Knowledge-owned fixture process. Research actual-owner acceptance is explicitly reused from its unchanged client checkpoint.

Fresh scopes and output directories preserve all prior evidence. The harness never migrates, deletes state, imports peer implementations into Planning, executes a scientific tool or calls a model. PostgreSQL/Qdrant fixtures must already exist and be explicitly enabled. Environment variables carry secrets; retained files contain only configuration references and synthetic records. Hosts are closed on failure; bytes, stores and evidence remain for diagnosis. Success requires assertions for original reads, unavailable inputs, source processing denial, historical graph stability, future retraction and owner restart.

Context packet/token fitting, runtime graph activation, real-source/scientific validation and provider authority are outside this gate. Replacement proof here means new processes using retained owner data, not a newly rewritten implementation.
