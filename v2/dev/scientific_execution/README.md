# Scientific execution demo composition

UI-01.05 adds an optional source-backed Knowledge association before admission.
build_context_schema.py derives the additive demo.campaign-knowledge-context schema
from pinned public Knowledge definitions; existing artifact version fields stay1.
knowledge_records.py publishes authored illustrative text/plain, rights, source and
conversion trace through Data, then six concepts/five hypotheses through Knowledge.
The source is an explicit engineering description, not an LLM extraction or measured
science. knowledge_configuration.py composes public scoped owner configs. No private
state reads/writes. A new campaign retains exact revision and method/entity links as
planning_context; tools still consume parameter artifacts. Existing campaigns cannot
be relabeled with later context. Failed publications/campaign evidence remain retained.

Entry helpers: prepare_scientific_knowledge.py prepares before starting owners and
publishes only with --publish; run_scientific_demo.py --knowledge-records selects
that exact scope/context; verify_knowledge_review.py qualifies served traversal.
Single supervisor ownership requires draining the previous viewer before process
replacement. Preserve original manifests/assets for rollback and restore LAN access.

UI-01.04 adds an exact reviewed context input and finish output. context.schema.json
is an internal demonstration artifact publication, not a new Runtime API. The full
review-design.json and explicit method/candidate/tool bindings are admitted and
retained; source SHA is also pinned in executable context. Studio consumes a local
public schema copy and validates exact scope, method identity and root activations.
Preparation compiles before startup. Run history is never rewritten to attach a
plan after execution. Review context is authored by Codex, not runtime Planning.

Owner: dev acceptance composition / UI-01.03. This module creates a separate
bounded scientific campaign using the public Runtime/Artifact/Registry protocols.
It does not implement those services or grant scientific authority. Tool kernels,
schemas, workers and images have independent tool owners.

Two declared fixture candidates each have a Hansen solvency screen and Arrhenius
viscosity adjustment. Four independent invokes converge on retained output ports.
The candidate parameters are illustrative, not generated molecular structures or
measured science. Authored graph is Codex-curated, not runtime LLM generated. No
automatic fitness policy, synthesis route or biological inference is fabricated.

Preparation uses independently built images/descriptors/schema bytes, isolated
Registry lock validation and isolated Runtime compiler probe. Existing installations,
campaigns and migrations remain unchanged. A dedicated project scope and manifest
bound new worker claims. Rehearsal records commands, actual completions and output
artifacts, drains workers/owners, then builds a separate read-only UI scenario.
The original qualified demo remains a fallback. Credentials stay in environment
from the existing local vault and are never written into evidence.
