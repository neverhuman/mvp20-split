# Campaign curation integration fixture

UI-01.08 P4.4 acceptance tooling. This package owns disposable test preparation
and evidence, not application behavior or execution authority. It exercises
independently installed owners through their public boundaries. Only an adapter
running inside Planning's interpreter may use Planning internals to supply a
deterministic synthetic provider; no paid model key is read in P4.4.

`restore.py` verifies the previously accepted BP-09 cold backup against the
committed trusted digest and explicit owner release/schema pins. It creates a
new physical root, Deployment identity, PostgreSQL/Qdrant containers and volumes,
and free owner ports through the existing restore operator tool. It never starts
owner traffic or targets the serving demo. Existing targets are rejected; failed
targets and evidence are retained for diagnosis. No source volume is modified.

The restore result proves infrastructure preparation only. P4.4a additionally
requires actual Planning curation/compiler, Runtime successor acceptance and
Deployment managed-worker binding; P4.4b owns receipt/replacement/failure cases;
P4.4c owns browser and independent-install evidence reconciliation. Synthetic
provider output proves software behavior, not scientific or model quality.

Run from `v2/dev` with its managed interpreter:
`python -m campaign_curation_fixture.restore --backup <verified-backup> --target
<new-physical-root> --output <new-evidence-directory>`. The backing stores remain
available for subsequent bounded qualification; teardown may stop only the exact
new resources recorded in `restore.json`, preserving volumes and journals.

`forward.py` advances only the restored Planning schema to independently installed
0.127, preserving predecessor migration bytes and the initial Deployment receipt.
`preparation.py` composes immutable owner/Studio configuration, private physical
TLS and one numeric seed-tool profile. Hash-pinned source inputs are copied byte
for byte under relative paths required by native workers. `session.py` starts one
installed supervisor, uses public owner HTTP and drains its owned processes.

curation/compiler/successor acceptance is still pending. No live-provider claim.
