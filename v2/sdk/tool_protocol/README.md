# Tool Protocol SDK

- Status: BP-03.03/B1 typed clients and bounded pure-tool stage adapter implemented; expanded lifecycle/failure and installed peer acceptance pending.
- Package: `amphora-tool-protocol` 0.1.0; explicit public client boundary.
- Architecture: [tool services](../../docs/Architecture/Capabilities/Tool_Services.md).

This library owns bounded authenticated HTTP and worker-facing claim, renew, complete, artifact publication and artifact reads. Import only `amphora_tool_protocol`. It has no server, database, graph scheduler, work-admission API, scientific algorithm, provider integration or shared business repository. Each tool owns its payload schemas and behavior. Its only internal package dependencies are public contracts; manifests/locks declare the independent install closure.

`WorkerIdentity` binds actor/scope to canonical command bytes. RuntimeClient and ArtifactClient call only public owner interfaces. Callers supply stable command IDs: an ID must not be changed to hide an ambiguous outcome. After transport loss/503/pending, CommandExchange queries the original receipt before resubmitting identical bytes. Identity and canonical request digest must match. Inspection failure prevents blind retry; bounded exhaustion yields CommandUnresolved carrying identity and request hash. Rejected receipts are terminal. Read-only receipt inspection is permitted after a local authority guard fails; resubmission is not.

Streaming PUT has no command receipt and is never automatically retried. A returned provisional UploadContentReceipt is distinct from finalization. A failed/ambiguous stream cannot be followed by an assumed-success finalization. The owning runtime controls new execution attempts; the artifact owner controls cleanup. Finalized references must match scope, upload and all declared content metadata. Downloads verify immutable metadata, byte length and digest. Client validation does not grant scientific or execution authority.

HttpTransport disables redirects and environment proxies, uses explicit bearer credentials, accepts HTTPS or loopback HTTP and bounds response bytes and socket timeout. It does not log tokens, payloads or peer diagnostics. Local plaintext HTTP is for single-host development. Deployment must supply authenticated endpoints and grants; the SDK does not discover credentials or attest the deployed image. Caller-supplied guard callbacks gate writes. ToolAttemptContext owns conservative monotonic expiry and stage-bound renewal; each successful renewal is followed by a scoped current-attempt snapshot because runtime expiry can be capped by activation deadline. Unknown authority, changed attempt/fence, expired observations or failed renewal stop further writes. The initial single-host profile requires clocks within the configured skew allowance (default one second). Long-running kernels and remote deployment need their own reviewed renewal/cancellation/clock profile. The runtime remains authoritative under races.

Tests under `tests/transport/` distinguish scripted receipt-loss oracles from actual loopback HTTP transport. Run `uv run --project v2/dev --locked python v2/dev/run_tests.py --module worker-sdk --coverage`. Installed runtime/artifact/tool integration is a separate B3/V1 gate and is not claimed by scripted peers. Replacement must preserve exact canonical requests, receipt-first recovery, actor/scope isolation, bounded I/O and no automatic stream replay. Durable receipts remain with owners; SDK scratch is disposable.

`PureToolWorker` executes one pinned pure synthetic tool with one required input/output and no checkpoint. It reads verified input bytes, delegates only payload computation to the tool, publishes output through typed artifact APIs and submits same-attempt completion. ToolInputRejected preserves tool-owned safe reason codes. Stream ambiguity becomes retryable pure-attempt failure only if authority is reconfirmed; completion ambiguity never triggers a contradictory report. WorkerConfig contains endpoint/token environment references and no inline credentials. Tests under `tests/lifecycle/` are scripted policy probes, not live owner evidence.

B1 coverage checkpoint: 22 focused SDK cases, 72% combined line/branch over 363 statements/94 branches. Attempt-context policy is fully exercised in this denominator; typed-client negative projections, adapter errors and configured launch paths remain explicit B2/B3 work. Scripted/loopback evidence does not replace actual owner integration.
