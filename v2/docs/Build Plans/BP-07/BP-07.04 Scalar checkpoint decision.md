## Problem and source evidence

The [physical design](BP-07.04%20Physical%20design.md) specifies scalar input adjustments at unmaterialized Invoke targets. Existing executable tools accept Artifact references, not scalar input values. Implementing that text literally would either fail before dispatch or require a wider tool contract change.

- [InvocationIntent.prepared](../../../services/campaign_runtime/src/amphora_campaign_runtime/coordinator/bindings.py) rejects every non-Artifact input with `tool_artifact_input_required`. Prepared worker specifications preserve Artifact-only bindings.
- [NodeObservation](../../../services/campaign_runtime/src/amphora_campaign_runtime/supervision_scope/observations.py) permits only waiting/ready Invoke targets in the existing footprint profile. B1 validates and records proposals; it does not establish executable scalar acceptance.
- [ArtifactMaterializeV4](../../../contracts/campaigns/src/amphora_contracts_campaigns/executable/bindings.py) already defines named fields with explicit inline/reference modes. [BindingInput](../../../services/campaign_runtime/src/amphora_campaign_runtime/artifact_bindings/model.py) resolves those fields from committed graph values.
- [BindingExecution.step](../../../services/campaign_runtime/src/amphora_campaign_runtime/artifact_bindings/storage.py) freezes the conversion inputs and marks the node issued before external I/O. [BindingCoordinator.context](../../../services/campaign_runtime/src/amphora_campaign_runtime/artifact_bindings/coordinator.py) reconstructs and verifies that source cut on recovery. Both must use the same immutable effective-input resolution.
- [Binding module contract](../../../services/campaign_runtime/src/amphora_campaign_runtime/artifact_bindings/README.md) preserves schema pins, authenticated Data publication, reservation proof, stable identities and replay. No tool or scientific transformation belongs in this conversion primitive.

## Recommended correction

Add an explicitly versioned checkpoint target profile supporting named scalar fields on `artifact_materialize` nodes. Retain Invoke targets for review/continuation and existing non-scalar dispositions. Do not silently widen old footprint/frame parsers or reinterpret old requests.

Example: a graph resolves `temperature = 25` into a parameter materialization node. An admitted policy permits a numeric range; Runtime may accept a proposal for `30` before the conversion opens. The ordinary conversion publishes a new schema-validated parameter Artifact, and the downstream Invoke receives its reference. No existing Artifact bytes or stored plan are edited. This example demonstrates software behavior, not scientific validity.

1. Admission pins exact authored target paths, named inline scalar fields, scalar type/unit and finite numeric bounds or finite allowed values, relevant observations, fallback, deadlines and ceilings. Reject Artifact/reference/collection edits, schema changes and undeclared fields. Already published parameter Artifacts cannot be adjusted through this mechanism; future authored graphs must expose explicit scalar materialization fields.
2. Resolve concrete loop/scatter occurrences and pause only the selected target before any binding intent, reservation or publication exists. Check retained plan, active ancestors, readiness, original scalar digest and absence of issued conversion state under the run lock. Unrelated branches continue.
3. Commit one winner and immutable effective-field records with audit/outbox. The adjustment is bound to plan, concrete occurrence, original field value and admitted policy. Reuse the same resolver at conversion opening, source-cut revalidation and replacement recovery; never patch the stored node definition or its original value sources.
4. Preserve ordinary conversion schema validation, Data publication/rights/retention and immutable worker inputs. Runtime acceptance authorizes an effective scalar value; it does not claim publication or tool execution succeeded. Expose conversion failures separately.
5. Version any affected private frame/fingerprint and public request/proposal profile explicitly after a bounded contract audit. Old profiles, command bytes, receipts, schemas and migrations remain readable and unchanged. Do not infer field semantics from an old Invoke adjustment record.

## Alternatives

| Choice | Consequence |
|---|---|

| Review-only checkpoints for this delivery | Defers the required scalar execution effect; must explicitly change scope and acceptance rather than claim B2 complete. |
