## Pinning and authority

The existing decision_scope digest is not permission by itself. A closed Planning-owned `planning-campaign-decision.v1` declaration gives it reviewed meaning. The original request pins SHA-256 of the declaration's canonical bytes. The declaration is a separate original required `constraint` Artifact, with an explicit declaration_artifact_id; preparation must contain its exact available bytes. This makes bounds visible in model context and prevents an output from minting a broader scope. Human authors configure it between campaigns; an authorized automated caller may create it for the original engagement.

Avoid a hash cycle: the declaration contains its Artifact identifier, original engagement, objective/policy Artifact references and Runtime cut, but never its own Artifact reference/digest or the request digest. Build declaration bytes first, then its Artifact reference and request. The independent root policy Artifact remains unchanged. Canonical UTF-8 JSON can travel as text/plain under an existing reviewed text profile; Planning's closed parser owns internal configuration meaning, as with BudgetPolicy. This is not a new public output schema or cryptographic signature claim.

Bound the declaration to64KiB, reject unknown fields/profiles, duplicate keys, nonfinite numbers and malformed scalar values. Scope, original engagement, objective/policy references, optional Runtime cut and allowed actions must match or narrow the original request. Require the named original constraint entry to be required, exactly hash/size bound and actually included in preparation. A historical packet alone grants no fresh source-processing authority.

## Future campaign bounds

An optional future boundary declares the intended campaign identifier/revision, exact context-pin set, maximum authored nodes/scopes/depth, iteration bound and tool timeout, and allowed side-effect classes. Its context pins include the original policy and objective identities/hashes; additional reviewed pins must be explicit. The generated definition cannot remove, replace or invent those pins. Bounds may narrow the documented Runtime ceilings but cannot widen them.

An explicit eligibility_context selects the requested scientific/applicability context. Local policy requires each selected descriptor to list it and allows only reviewed side-effect classes. This is a metadata prerequisite, not scientific eligibility or operational admission. Fresh Registry policy/capacity and actual Runtime type/control-flow compilation remain B2.02; model rationale cannot substitute for them.

## Bounded adjustment proposals

An optional finite permit list names each exact authored scope path/node/input, expected previous-value digest and either an explicit scalar enumeration or finite numeric kind/unit/range. Duplicate permit identities reject. Values cannot change type or units implicitly, and booleans are not numbers. Adjustment proposals must match the original supervision cut and a permit; output cannot create new targets, ranges or permissions.

Runtime has no adjustment-write API in this baseline. Passing local bounds leaves `runtime_adjustment_acceptance_required` explicit. Current-node existence, current prior-value equality and application still require the later Runtime engagement boundary. Never invent a successful adjustment receipt or use an unrelated command to apply it.

## Combined policy result

Combine the declaration with reconstructed CompositionReview and the existing reviewed BudgetPolicy. Rebind BudgetPolicy and calculate its original-attempt reservation demand; this is not a new reservation, spend or refund. Preserve exact preparation, capture, proposal, declaration and budget identities. Required objective/policy/declaration observations join the policy-selected evidence/tool/input read-set. The model cannot supply dependency hashes.

Expose a bounded next step: compile a future draft, retain an evidence request, abstain, or retain an adjustment pending its Runtime API. Missing/weak/contradictory scientific points remain findings and do not alone prohibit a valid exploratory future draft. Explicit action prerequisites remain binding. This pure result grants no durable submission success, scientific acceptance or execution authority; B2.02/B2.03 own those further boundaries.

## Exit evidence

Verify an exact declaration is present and visible before interpreting output; reject changed digest/engagement/roots/cut/role/requiredness/body and forged declaration objects. Verify future identifiers/context pins/size/iteration/timeout/side effects and applicability metadata, finite adjustment targets/prior pins/enumerations/ranges/units, unchanged budget ceilings and immutable request/capture history. Preserve uncertain science and explicit Runtime gaps. Tests stay module-owned with independent installation proof; schemas and numeric command/receipt bytes remain unchanged.
