## Exact owned origins

A private runtime-supervision-request-frame.v1 groups the existing public SupervisionRequest, preparing Runtime actor and original concrete node observations. Retain canonical state/output bytes using strict base64 so later reads can reconstruct the original DecisionFootprint and rebind its public projection without consulting mutable current nodes. The public request remains256KiB; individual observations1MiB, aggregate8MiB and at most256 observations remain unchanged. Cap the complete private frame at16MiB. Hashes are integrity/binding checks, not signatures or authorization.

A frame factory must reconstruct and validate the original public request against its byte-owned footprint; directly constructing a dataclass or receiving valid JSON does not authorize storage or use. Private parsing rejects duplicate/nonfinite/noncanonical JSON, wrong profiles, invalid base64 and changed scope/request/view hashes. Exact canonical bytes survive history readback. New private profiles retain old readers rather than rewriting stored evidence.

A series has1..16 ordered frames in one scoped decision/checkpoint/footprint with the same Runtime preparer and Planning actor. Initial lineage has ordinal1 and null root/parent; each successor names the exact original full supervisor-request hash, immediate preceding request hash and ordinal. Planning engagement IDs are distinct across members. Original and successor policy/objective/prompt/model/output profile remain fixed. Allowed actions and numeric call ceilings cannot widen from the previous member; accounting unit remains fixed and deadline cannot extend. These limits do not reserve actual provider budget, which remains Planning-owned.

Required source/context entries cannot silently disappear or become optional. The prior per-request declaration Artifact may be replaced because it binds that prior engagement/cut; identify only the required constraint whose digest equals the prior Planning decision_scope. This exception does not grant broader declaration permissions: B2 checks each new declaration against the original admitted Runtime policy. Source rights and scientific applicability still require their public owners. Active receipt pins are never changed by a correction notice.

The conflict footprint and selected runtime observation identities stay fixed across this series; newer actual values/cuts may motivate a bounded repair, but it is an explicit successor request with original lineage/ceilings. Older or foreign cuts reject. An unbounded change of targets/read selections creates a separate reviewed decision, not an implicit repair. Shared-read/disjoint scopes retain B1.01 semantics.

## Persistence and authority

Runtime's configured principal and owner handlers enforce prepare/read/dispatch rights and original actor/scope. The preparing Runtime actor may differ from the configured Planning delivery actor; never infer that delegation from a model-provided actor string. Persist both identities and require the original configured binding. Producer SQL reconstructs node membership/path/kind/status/state/output from the retained plan and current scoped run under the existing run lock. Targets must have active ancestors and no materialized activation row, not merely a waiting/ready public view.

Use forward migration after runtime0017, never edit prior migrations. Exact scoped foreign keys link request records to run/plan and their original decision. Immutable frames, outgoing command bytes and append-only events receive SELECT/INSERT only. Mutable lease/control rows receive narrow column grants; no peer role obtains access. Database time bounds holder/fence expiry. Stale holders cannot append final history or mutate successor control. One record per original identity; exact retries return original timestamps/hashes and changed retries conflict.

Preparing a request and its outbox intent is atomic; no network spans SQL. Pending outbox state or a lease is not permission for a paid call or graph change. Dispatch must still pass the owning current-policy/rights checks. Store original family/identity/profile/bytes before each effect; ambiguous delivery keeps the same identity. Response recording and command recording are distinct from a Runtime decision winner. A generic private CommandStore accepted status, where reused, means command storage completed; the public supervisor receipt says recorded and never implies accepted execution. New-family receipt routes must not widen old Runtime receipt parsers.

Historical reads and receipt reconciliation preserve committed evidence even if fresh processing is now denied. New source use still requires Data authorization. Late responses remain attributable diagnostics; B2 alone arbitrates winner/effect atomically with current target/precondition checks. Unknown provider usage stays in Planning's conservative ledger, not converted into a Runtime refund or second budget.

## Verification gates

Unit a: byte reconstruction, immutable origin/actor, exact ordered lineage, finite count/size, no widening or required-context loss, different decision/footprint/actor/cut negatives. Tests live under Runtime tests/supervision_journal; public wire contracts remain unchanged.

Units b/c: serial opt-in retained PostgreSQL fixtures, actual original graph/run records, strict SQL grants/FKs, exact replay/conflict/read-scope, rollback, competing root/member inserts, expiry/fence loss and bounded event behavior. Do not accept caller-generated node hashes as stored Runtime state. No fixture reset or older Runtime migrator after the new head.

Unit d: separately installed current Runtime against the retained journal, competing connections/process barriers, exact timestamps/frames/command bytes after process replacement and lease expiry. Named failure outcomes, cleanup and uncertainty are evidence requirements. No provider/HTTP/accepted graph effect claim from journal tests. Module README must specify rebuild/cutover rules and generated schema/migration evidence before closeout.
