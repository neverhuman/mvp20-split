# BP-07.05 evaluation and inspection physical design

- Design status: activation baseline; implementation owned by [canonical tracker](BP-07.05%20Live%20evaluation%20and%20closeout.md).
- Owners: Planning evaluation protocol/history; Runtime checkpoint decisions; Studio scoped presentation. Existing production attempts remain owned by Planning's attempt ledger.

## Ordered B1 units

B1 has four equally weighted units; each is25% of B1,6.25% of child,1.25% of parent. B2,B3,V1 remain unchanged. These units clarify existing scope; design writing earns no implementation credit.

1. B1.01: private versioned evaluation manifest/corpus and independent scorer. Frozen model/adapter/prompt/corpus/data/budget/repetition/category criteria, deterministic integrity checks, independent labels and transparent category metrics. Pure tests first.
2. B1.02: bounded repeated evaluation runner with durable original manifest/corpus, every issuance/result/error/abstention and restart-safe attempt history. Bind the existing production provider/accounting path rather than introduce an unaccounted model caller. Fixture-only adapter first; real transport needs owner selection and approved egress. Exactly-once external calls are not promised; uncertain issued attempts remain retained and count against ceilings. No cherry-picked reruns overwrite failures.
3. B1.03: bounded scoped owner inspection reads for original requests, attempts/completion dispositions, context inclusion/omission, response rejection and committed decision. Reuse public exact DTOs and add a versioned discovery projection only where absent. Runtime read permission cannot grant Planning or source-processing permission. No cross-owner SQL; no prompt/raw capture bytes in default UI.
4. B1.04: Studio transport, page model and inspector with one owner per region. Researcher's question: what did this checkpoint consider, propose and actually change, and what should improve next campaign? Primary action is inspect linked evidence, never approve a running campaign. Use current tokens/table/selection patterns. Pending, empty, partial, stale, denied and failed states stay distinct. Provider error, scientific abstention, rejected proposal and committed fallback cannot collapse into success. Actual browser check at intended/narrow viewports; preserve selection on refresh.

## Evaluation boundary

Planning evaluation owns immutable experiment configuration and evaluation outcomes, not scientific truth or execution acceptance. The manifest pins exact model, adapter revision, prompt revision/content digest, corpus content digest, allowed data references, repetition count and conservative resource ceiling before issuance. A fixture/live mode is explicit and cannot be inferred from scores. Category rules define minimum semantic score, allowed abstention rate and hard authority cases before results exist. Held-out corpus labels remain outside model inputs; a generated response never supplies its own expected answer.

Independent labels describe expected structured semantic facts from reviewed cases, not prose fluency or JSON-schema validity alone. B1.01 uses explicit value assertions over the validated output document with exact identity/path and strict JSON equality. This is a deterministic rubric, not a claim of general biological entailment. Domain-specific rubrics/corpora can extend through explicit reviewed versions; no dynamic code imports or model-authored evaluators. A missing expected fact fails; malformed/provider-error/unknown results remain separate failures. Allowed scientific abstention is explicit in the case and separately limited by category, never silently removed from the denominator. Hard authority violations fail the suite regardless of average semantic score. Partial/missing repetitions cannot pass.

Boundary DTOs validate persisted configuration; focused frozen domain objects own canonical hashes, set/cardinality checks, denominator accounting and scoring. Existing public contracts remain unchanged until a cross-owner consumer requires a new version. Every score retains original suite/case/repetition identity and precise rubric result; category metrics report all planned attempts, present/missing, error and abstention counts.

## Acceptance and remaining external choices

B1 fixtures prove software semantics only. B2 freezes owner-approved real provider/model, allowed egress/data, budget, held-out corpus and thresholds before any real call. Retain every attempt, including unknown calls and unsuccessful reruns. B3 tests actual provider and browser behavior against original hard/semantic criteria; failed live thresholds keep the gate open. V1 rebuilds the harness/UI boundaries, preserves configuration/result bytes and audits child/parent scope. Do not invent scientific validity from successful software or a campaign completing.
