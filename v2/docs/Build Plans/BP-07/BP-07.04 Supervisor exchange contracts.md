## Bounded ordering

B1.02 has three equal subunits: a public scope/request DTOs plus Runtime-owned binding/projection; b proposal/decision/receipt records and exact command profiles; c independent installation and full predecessor schema/byte compatibility. All0%. B1.02 retains one quarter of B1's weight. Each subunit requires scoped contract/domain tests; c verifies the combined published boundary. Journals/outbox remain B1.03, actual HTTP/process integration B1.04.

## Request ownership and identities

Create contracts/supervision, an independent wire package depending on existing public Core, Graph Runtime and Planning contracts. Runtime implementation may depend on this public package; Graph Runtime must not import Planning. Existing510 schema files remain unchanged; publish only new supervisor roots. No provider SDK, persistence or domain behavior lives in the contract package.

SupervisionRef binds scoped run and logical decision slot. SupervisionSnapshot projects the original GraphReadCut, exact sorted targets, selected node views plus state/output hashes, and separate conflict-footprint/relevant-read-set hashes. It serializes the existing Runtime supervision_scope domain without acquiring authority. Raw node state/output stays owned; transported hashes must be rederived against stored owner state before acceptance.

SupervisionRequest groups that reference/snapshot, admitted checkpoint identity and policy Artifact, original Planning EngagementRequest and exact request digest, absolute deadline in Unix milliseconds and lineage. Request identity is Planning's scoped engagement identity, distinct from decision slot and provider attempt. Planning decision_scope remains its reviewed declaration digest, not a Runtime footprint hash. Original context policy, actor/scope and cut must bind; Runtime's admitted policy is checked from owner storage later, never inferred from a request alone.

The first lineage member has ordinal1 and no parent/root digest, avoiding a self-hash prerequisite. A successor has ordinal2..16 plus exact original-root and preceding-request digests. Owner storage must bind lineage and aggregate budgets; pure DTO/domain checks cannot authorize another call. Deadline/limits cannot be widened through repair. Preserve original request bytes using the established UTF-8 sorted-key Planning request protocol, separately from supervisor command encoding.

Runtime's focused projection/binding objects produce schemas and check cross-record identities. They do not invoke Planning's private ContextPolicy or imply it has passed. Planning's receiving owner must revalidate its own context/request and persist original accounting before dispatch. Runtime must independently validate its admitted checkpoint/policy and current frontier before opening a slot.

## Response and command follow-up

B1.02b must distinguish request acceptance/pending dispatch, immutable physical attempt observation and Runtime decision outcome. Reuse public TaskProviderObservation and retain capture Artifact provenance where available; unknown output/usage is not zero or an accepted action. Runtime validates original request/attempt/profile and exact captured/typed proposal before conditional decision acceptance. No model output may submit an accepted state flag.

Persist Runtime decisions separately from delivery receipts. At least pending, accepted, rejected, stale, expired, failed and cancelled dispositions remain distinct; late results become diagnostics. Only owner routes/domain transitions produce decision readbacks, never a model parser. Wire records grant no authority by themselves. Runtime outcomes cannot claim an effect where no owner interface exists.

Closed command families use the existing bounded canonical command library with explicit numericv2 where scalar proposals require it; no widened legacy parser or float normalization of old bytes. Exact full command identity, request hash, actor/scope and operation/readback binding are verified independently. B1.02b refines concrete variants before publishing them; this request subunit does not fabricate completion semantics.

## B1.02b concrete response and receipt profile

Add SupervisionResponse with exact Runtime decision reference, original full supervisor-request SHA256, existing TaskProviderObservation and optional capture ArtifactRef. Bind observation.attempt to the original Planning engagement/request hash and allowed attempt ordinal; do not confuse its ordinal with supervisor-request lineage. Captured bytes are at most65536 and must match both observation hash/length and the optional Artifact metadata. Proposed/abstained observations require a complete nonempty capture and typed proposal; an empty unknown/unavailable capture remains explicit, with unknown usage retained. A missing raw source body is not a successful validation.

Runtime's pure response binder reinterprets the reviewed campaign JSON profile from fetched bytes, rejects duplicate keys/nonfinite/unsupported profiles and verifies exact canonical TypedProposal payload/hash/action/rationale, original declaration digest and scoped references. It does not import private Planning code. This binds reported content to bytes; tool/adjustment eligibility, actual policy, current grants, budgets and atomic effects still belong to B2. A source Artifact reference alone is not a processing grant; callers must acquire bytes through Data's current public processing boundary outside acceptance SQL.

Keep four new root families separate: response submission, scoped cancellation request, command receipt and Runtime decision readback. Command receipt pending/rejected/recorded outcomes bind complete CommandIdentity/request SHA/operation and exact committed object kind/id/revision/content hash. A recorded response can be a late diagnostic and is not an accepted decision. Do not widen old Runtime/DraftCommandReceipt committed-kind enums.

Decision readback preserves pending requested/dispatched/proposed posture or a terminal accepted/rejected/stale/expired/failed/cancelled outcome. Accepted effects distinguish immutable effective input changes, retained future/evidence/abstention proposals and a declared continue-without-change fallback. Readback is owner-produced evidence, not a model input schema; public shape alone grants no acceptance. Concrete effects are not implemented until B2 transactions and their failure tests pass.

Closed command families: planning.supervision.request, runtime.supervision.respond and runtime.supervision.cancel. Use CanonicalCommand.for_family with explicit amphora-command-v2, existing256KiB/depth64/safe-number limits and full payload scope matching. Request delivery also binds command actor to the original Planning request actor; handler credentials must independently enforce that principal. Response/cancellation actor authorization belongs to the Runtime owner. No endpoint or private provider URL is selected by command data. Retain exact numeric-profile bytes and old command receipts unchanged.

B1.02b tests must cover original request versus physical attempt swaps, wrong scopes/profile/capture, fabricated proposal content, malformed/duplicate JSON, unknown and partial diagnostics, schema-only accepted-state injection, exact numeric command bytes/hash and complete receipt readback binding. Preserve all520 currently published schema files before adding new roots. B1.02c installs the completed public/Runtime boundary independently and verifies predecessor compatibility.
