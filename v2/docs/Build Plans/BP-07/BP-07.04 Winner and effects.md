## Pure effective-field boundary

An exact concrete occurrence, scalar-bearing checkpoint seed and pinned reviewed policy authorize the shape of a proposed effect, not its execution. Validate named fields, exact prior scalar digests, strict types/units and finite bounds. Store a canonical immutable selection with an explicit private profile. Resolve the selection against original values without changing stored graph definitions or unrelated fields. Reject legacy value-less seeds, other occurrences and changed original values. Retaining an original value outside adjustment bounds remains allowed.

## Contract audit and exchange

Existing CampaignAdjustmentDraft uses static authored addresses and float NumberConstant. Existing SupervisionDecision requires a request digest, even though deterministic fallback may precede a Planning request. Neither is silently reinterpreted for materialization fields. Add explicit versioned proposal/effect and checkpoint-decision records using exact decimal-string ScalarValue and concrete occurrences. Preserve all predecessor schema, parser and receipt bytes. Runtime reconstructs provenance through the existing captured-output boundary before applying its own policy checks. Planning cannot choose accepted state or effective authority.

## Atomic winner and conversion

Under the existing run lock, recheck actual membership, ready/unissued target, selected observations, original scalar values, pinned policy, deadline and request lineage. One immutable winner competes with fallback and run cancellation; rejected/late responses remain diagnostics. Commit winner/effective fields/audit/outbox atomically. No provider or Data calls in this transaction. Fallback uses the pinned continue-unchanged or block-target action and requires an explicit reason. It must work before request creation without fabricating a request hash.

Conversion intent opening and source-cut revalidation use the same effective-field resolver. Accepted selection means selected parameters only; Data publication and tool success remain separate outcomes. Preserve original plan, original Artifact identities and issued inputs. SQL tests prove rollback, no duplicate winner, stale/issued rejection, unchanged fallback, cancellation precedence and an adjusted scalar reaching conversion. Process contention and installed multi-owner downstream acceptance remain the later named gates.

## Atomic storage implementation boundary

B2.02c will separate i the winner transaction and ii coordinator target release, equal units. Both remain0%. Use a forward migration after runtime0023; immutable winner/effective-selection records reference the original slot and, for model outcomes, actual stored request/response evidence. Reuse Runtime audit_events/outbox in the same transaction, advancing the run revision under its existing lock. Original winner readback wins on retries before evaluating a later run status or deadline.

A cancelled/terminal run cannot accept a new model effect. Deterministic deadline/eligibility fallback is derived from the stored slot and database clock, not caller-selected policy. Provider/repair exhaustion evidence is supplied by the later bounded loop through retained owner records. A failed proposal remains diagnostic and does not steal the slot from an attributable repair/fallback. Current selected observations are checked for model acceptance; unchanged fallback validates actual target membership/issuance without treating an old observation of another progressing branch as a permanent block.

An explicit refreshed request can reconstruct a scalar seed from its retained footprint and original scalar fields. Its decision identity, policy, concrete target and original slot deadline/ceilings stay fixed. The winner retains any refreshed seed needed to replay its selection; it never overwrites the first slot. Conversion integration consumes only a committed winner. A schema-valid proposal or a pure ScalarSelection never releases the coordinator.

Coordinator staging: c.ii releases review/unchanged winners and blocks a target for its pinned block fallback. An adjusted-field winner remains held until d connects the shared effective-field resolver at both conversion boundaries. This prevents a committed scalar selection from accidentally issuing the original values between implementation gates; d owns removal of that temporary hold and proves selected values reach conversion. No effect is reported as executed at c.
