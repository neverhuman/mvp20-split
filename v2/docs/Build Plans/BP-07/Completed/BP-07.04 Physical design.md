## Ownership and compatibility

Runtime owns engagement requests, outbox delivery, decision slots, run/target preconditions and atomic decision effects. Planning owns immutable task/context, provider attempts, conservative accounting and typed proposals. Separate journals exchange public versioned records over bounded HTTP; no shared SQL, private imports, direct provider calls from Runtime or model-created authority. Existing numeric command profiles and all historical schema/migration bytes remain unchanged.

Planning's existing EngagementRequest is a context-bound logical request, not a Runtime decision grant. Its decision_scope digest currently binds an original reviewed declaration. Keep that identity distinct from the Runtime conflict footprint and relevant frontier fingerprint. Existing GraphReadCut global revisions are provenance; unrelated branch progress must not become a blanket stale condition.

Graph Runtime contracts cannot import Planning contracts because Planning already depends on Graph Runtime. When cross-owner supervisor transport is introduced, use a focused public contracts/supervision package depending on the existing public packages; never introduce a cycle. The initial pure Runtime scope module needs no new published DTO, database or endpoint. Additive supervisor profiles do not widen old parsers.

## B1.01 - Runtime scope and relevant observations

Create Runtime supervision_scope with module-owned tests. A frozen node observation binds the existing plan-derived ActivationAddress, concrete ActivationPath including loop/scatter occurrence, typed node kind/status/reason and bounded canonical committed state/output bytes. Owner snapshot construction must validate identities; a supplied hash is not proof of stored state. No storage, auth, HTTP or acceptance resides here.

A decision footprint binds tenant/project/run/plan,1..64 exact unmaterialized Invoke targets and at most256 selected node observations. Every target must appear in the read set, be waiting/ready and have no issued/materialized activation in the eventual owner transaction. Target/read duplicates and mismatches reject. Capturing a public node view alone cannot prove absence of a queued worker row: B2 integration must check it under the run lock. Canonical identity is order-independent; concrete occurrences prevent two loop/scatter members collapsing into one decision target.

Overlap is read/write interference within the same scoped run: either target set intersects the other's targets or relevant reads. Two scopes sharing only immutable reads do not overlap. Run-wide cancellation competes through the existing run lock and terminal status. Containers are not implicit wildcard targets; expansion/ancestor terminal conditions are checked by integration, not inferred from a node ID string.

Relevant comparison rechecks original selected node observations, including missing observations, state/output changes and target availability. Original cut remains retained. A higher unrelated global revision alone does not invalidate; wrong run/plan/scope or older cuts reject. This pure comparison grants no execution authority, source-processing lease or scientific acceptance. Pinned Knowledge/Research receipt corrections remain future-only; no latest-head refresh enters this read set.

Exit: scoped positive/negative/occurrence/conflict/staleness tests with measured coverage, current Runtime wheel installed independently without private peers, predecessor compatibility and boundary checks. No schema/migration credit from the pure boundary.

## B2 - Checkpoints, winners and effects

Pin reviewed supervision policy with admission, including exact authored target paths, allowed finite scalar input bounds, observation selection, fallback, deadlines and aggregate engagement/call ceilings. It is graph-specific configuration, not a hard-coded scientific pathway. Existing campaigns without this explicit policy keep their original behavior. Human policy edits take effect only for later campaigns. Resolve authored targets to concrete occurrences before opening a slot; no mutation of stored graph definitions or issued invocations.

For the approved v2 profile, scalar targets are named inline fields on artifact_materialize nodes; Invoke targets support review/continuation. Coordinator must open the configured checkpoint before creating a target conversion intent or materializing a target invocation, under its existing run lock, and pause only target work while unrelated branches progress. Target readiness/current input value and absence of any materialized activation are authoritative Runtime checks. External callers cannot bolt a new policy onto an active campaign. The pure B1 footprint is necessary but not sufficient for these checks.

Model response, declared deterministic fallback and cancellation compete for the same pending slot/preconditions. Commit the winner, permitted runtime effect, audit and outbox together; no HTTP inside acceptance. Scalar changes use separate immutable effective-input records bound to original plan/occurrence/prior-value digest; conversion opening and source-cut revalidation read the same effective values before publishing a new parameter Artifact. Downstream workers retain Artifact-only inputs. No accepted change can rewrite an issued input, topology, tool binding, signed constraint, budget or scientific status. Runtime revalidates types/schema and policy independently; Planning's earlier review is not authority.

Successor topology proposals remain retained/compiled future drafts; admission waits for the original campaign's terminal reconciliation and existing single-active-run guard. Abstention/evidence requests retain unresolved points and an explicit disposition; they do not produce measurements or automatically satisfy a research question. No action with a missing owner interface is reported as accepted execution.

Late responses attach immutable diagnostic provenance without reopening terminal slots. Rejection, timeout, cancellation, exhausted repair/budget and unavailable provider have reasoned bounded outcomes. Repair creates an attributable request/attempt with original ceilings, never an unbounded loop or human approval wait. Relevant runtime changes invalidate the proposal; unrelated branch progress and future-only receipt corrections do not. Shared execution and model budgets remain separately owned, conservatively accounted and conditionally checked.

## Required acceptance tiers

Pure tests cover footprints, concrete occurrences, policy and terminal transitions. Serial actual PostgreSQL tests cover overlapping targets, shared-read independence, relevant changes versus unrelated completion, fallback/model/cancel contention, authority withdrawal, exact replay, no double acceptance and atomic effect rollback. Process barriers cover committed request before send, paid call before response and response before acceptance commit; unknown usage remains charged/reserved by its existing policy.

Actual installed Runtime and Planning processes must demonstrate a delayed/failing model lane alongside an independently completing graph branch, duplicate delivery/late response, restart/lease recovery, declared scalar effect at a checkpoint and future successor handling without active topology changes. Deterministic provider is explicitly a software fixture; live efficacy remains BP-07.05. Rebuild acceptance preserves histories and old schemas/migrations, public owner boundaries, scoped tests and service replacement. Runtime UI read projections must expose reasoned outcomes; full Studio quality views remain SQ-01.
