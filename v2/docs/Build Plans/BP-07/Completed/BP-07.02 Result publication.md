## Implemented value boundary

result_publication owns diagnostic feedback and attributed candidate-answer payloads, complete source plus interpretation ancestry, and stable effect slots. A slot is actor/trace/kind/local key; publisher configuration and payload fingerprint are immutable bindings within that slot. Same-slot changes conflict. Existing trace publication bytes, commands, schemas and journal remain unchanged. Content preparation by itself is neither durable provenance nor Data publication.

## b.ii owner-state composition

The durable input selects an exact owned trace, its finalized interpretation publication and the result kind/local key. It must not accept arbitrary caller-supplied payload bytes or an acceptance verdict. Load task/observation/prior facts through Planning's own journals, enforce original actor ownership, and reconstruct the finalized interpretation receipt. Existence of a hash-shaped reference alone is insufficient.

Perform new source processing through SourceReviewer and interpretation processing through ArtifactReview outside SQL, with a shared bounded deadline. Answer preparation reads exact selected Research questions through the public reader. Unknown/gapped questions withhold only dependent answers. Store the first exact selected-question metadata and review witness used for preparation; later retries cannot reinterpret the same result slot with different peer state.

New result tables separate immutable selection/preparation/event history from mutable DB-clock lease/fence/position controls. Forward planning_0010 is applied and immutable; applied0001..0009 remain unchanged. Register the exact effect selection before any externally visible upload, then persist the complete payload/manifest before begin. Scoped foreign keys bind the owned trace and interpretation publication. Service history grants remain SELECT/INSERT only; control updates are column-scoped. Each store operation is a short transaction; no peer/provider call occurs under SQL.

Historical replay verifies payload digest/content profile, canonical identity, task/trace/observation pins, exact interpretation receipt and complete persisted ancestry. It does not re-read source bytes or rerun scientific validation. Historical review metadata records the prior observation of source facts; it is never continuing processing permission. New Data begin/finalize calls still enforce current ancestry rights. Persisted scientific posture remains proposal_only/diagnostic_only.

## Upload and recovery

Reuse the public ArtifactClient/transport and compatible pure PublicationAttempt command/receipt checks. Result-specific persisted event formats must remain distinct from trace-publication records. An original stable begin/finalize command reconciles unknown replies. Only the invocation that commits a streaming-intent CAS may send its one PUT; a recovered streaming intent is uncertain and requires a bounded successor upload. An uncertain finalization must keep its original command, not abandon/reupload. Lease/fence/position checks reject late writes even when an external operation completes after lease loss. No exactly-once network claim.

Use the existing eight-upload and64-event ceilings unless a concrete result-size requirement forces a separately recorded bounded change. Payload limits stay256KiB; input references stay128. No silent payload/input truncation or unbounded automatic retry. Keep rejected, abandoned and prior useful results visible.

## Diagnostic producer and dependent handoff

The concrete repair producer must load owned attempt/trace facts, derive a bounded diagnostic decision through configured reviewed validation, publish the matching interpretation and feedback, and return RepairInputs tied to that exact parent. Caller text cannot supply a trusted diagnostic or scientific verdict. Once a diagnostic snapshot is bound to a parent result slot, later findings cannot overwrite it; further model output gets a new trace, and later scientific corrections remain future-campaign inputs. Owner-handoff diagnostics are integrated under b.iii after its durable outcome journal exists.

A successful local publication says only that an Artifact exists with exact provenance. Question registration, need registration, Knowledge acceptance and answer sufficiency are separate owner operations. Never block independent useful proposals because one owner outcome is unavailable or scientifically weak.
