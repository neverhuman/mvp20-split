## Existing boundary

ReferenceProposal and ProviderObservation/v1 contain a selected Artifact reference only. Their published bytes and stored journal format remain unchanged. ExtractionDraft/v1 is a separate reviewed typed output schema, not a new interpretation of reference-only payloads. SchemaRef.version remains1 because the extraction output schema itself is version1; the new observation format has its own versioned root.

## Additive profile

Publish TypedProposal/v1 containing exact output SchemaRef, derived action/rationale, bounded canonical payload JSON and its digest, plus ProviderObservation/v2 with that proposal type. The existing v1 class remains separate. A closed owner-reviewed profile catalog accepts only exact known schema identities; it cannot import handlers or execute code selected by model text. For extraction, parse strict ExtractionDraft, check allowed action, selected Artifact/scope references and abstention shape, then derive the envelope from those bytes. Later grounding/identity/domain policy validates the task-specific meaning; proposed means an attributed candidate, not accepted science.

Persisted observation decoding inspects the explicit version with strict duplicate/nonfinite handling and per-version byte limits. Legacy v1 keeps64KiB encoded and unchanged model bytes. V2 permits256KiB encoded to hold an escaped canonical JSON payload while preserving the64KiB raw capture and64KiB canonical payload bounds. This is storage overhead, not a larger model-output/context allowance. Failed extraction outcomes also retain the explicit v2 format; unsupported profiles still reject before calling a provider. Legacy failed records remain readable.
