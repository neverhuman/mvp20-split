## Confirmed mismatch

Planning's private `planning-campaign-decision.v1` requires `declaration_artifact_id` inside its canonical body ([private profile](../../../services/agent_planning/src/amphora_agent_planning/campaign_decisions/wire.py)). `DecisionDeclaration.bind` locates that ID in the original required constraint entries and verifies digest, size and exact consumed body ([binding](../../../services/agent_planning/src/amphora_agent_planning/campaign_decisions/declaration.py)).

Data's public `FinalizeArtifact` accepts upload ID and content metadata, with no client-selected Artifact ID ([public payload](../../../contracts/artifacts/src/amphora_contracts_artifacts/models.py)). Its finalizer verifies already uploaded content and only then generates `uuid.uuid4().hex` for a new catalog identity ([finalizer](../../../services/data_artifacts/src/amphora_data_artifacts/publication/finalize.py)). Consequently a newly authored declaration cannot know its own eventual catalog ID when fixing the uploaded body. Republishing with the returned ID allocates a different ID. Predicting an ID or writing Data's tables would violate the owner boundary.

Existing synthetic declaration fixtures have predetermined IDs. Their policy/journal evidence remains valid within that synthetic scope, but does not establish normal Data publication. The earlier actual Runtime/Registry test did not publish a decision declaration through Data. This is an integration prerequisite correction, not a scientific limitation.

## Recommended correction

Add a private `planning-campaign-decision.v2` profile that omits the self Artifact ID. Preserve every other authority constraint, including engagement, objective/policy pins, runtime cut, action bounds, applicability and allowed future graph or adjustments. Keep the original request's `decision_scope` equal to the canonical declaration digest.

For v2, locate exactly one original required `constraint` entry matching the canonical declaration digest, size and media type. Reject absent or ambiguous matches; never choose the first of several matching references. Verify that exact full ArtifactRef was actually consumed and its original body equals the declaration bytes. Return that full ArtifactRef's observation key, preserving original read-set attribution. The caller can publish the fixed declaration bytes, obtain Data's actual ArtifactRef, and then construct the original request and packet before the provider attempt.

Continue accepting v1 using its existing ID-based rule. Preserve its canonical bytes, hashes, stored selections, commands and receipts. Never upgrade stored records in place. Do not alter Data's allocation behavior, introduce a new public API or repin an active campaign. New integration fixtures use v2; explicit v1 compatibility fixtures remain.
