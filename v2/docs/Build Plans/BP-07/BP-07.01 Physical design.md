# BP-07.01 Model and Provider Boundary Design

- Last reviewed: `2026-10-04 01:49:10` (America/Chicago).
- Design status: bounded deterministic implementation profile; not a live provider selection.
- Canonical progress: [child tracker](BP-07.01%20Model%20and%20engagement%20contracts.md).

## Ownership and sequencing

contracts/planning publishes strict versioned DTOs. services/agent_planning/context owns validated immutable request snapshots and fingerprints. providers owns deterministic adversarial call behavior and bounded response parsing. persistence owns its own PostgreSQL request/attempt/output journal. No service imports peer implementations or writes Runtime tables. Runtime retains engagement/decision acceptance; a request or proposal never constitutes a campaign transition.

B1 has four equal milestones: .01 model/context/request/attempt contracts and pure identity domain; .02 deterministic provider port and bounded response/proposal envelope; .03 private request/attempt/output persistence with forward migration; .04 actual persistence/replay readback and independent boundary compatibility. B2 has three equal milestones: .01 reserve call/token/accounting limits before dispatch; .02 ambiguous/interrupt accounting and retries; .03 policy-preserving bounded outcome/abstention. B3 has three equal milestones: .01 malformed/oversized/invented action, .02 late/duplicate/concurrent attempt barriers, .03 separate-process restart/unknown-outcome recovery. V1 has two equal milestones: .01 independent installation/verification, .02 scoped audit/archive. Work remains in prerequisite order.

## Initial request snapshot

A logical request has scoped engagement identity, actor, purpose and optional exact public Runtime read cut. Supervision requires a Runtime cut; offline decomposition/campaign proposal does not invent a running campaign. Runtime staleness policy is not implemented by comparing the whole cut here. A manifest pins objective, prompt, policy, provider/model/revision and reviewed configuration/tokenizer/output-schema identities. Included entries have explicit role and mandatory status; omissions have exact reference/reason and cannot overlap selected entries. IDs alone cannot hide differing Artifact identity. Scope and exact content/configuration affect fingerprints.

No endpoint, secret, arbitrary provider parameters or model-authored permission appears in these DTOs. Configuration and policy Artifact bytes must be loaded and authorized by later owner workflow; a reference is not existence/current-rights proof. B1.01 validates immutable snapshot shape/relationships only, with no persistence, provider dispatch, egress permission or scientific-authority claim.

Allowed output actions are bounded proposal categories: abstain, request evidence, propose knowledge change, propose campaign. Action permission is distinct from actual domain validation. A response envelope binds the exact request fingerprint and physical attempt; retained output and observed usage are distinct. Later extraction/proposal children introduce their task payload contracts through the existing owning public schemas. No generic model output executes tools or code.

## Budget and uncertainty

Positive bounded input/output token limits, maximum physical attempts, total tokens and integer accounting units are explicit. A context window and tokenizer/configuration are pinned; no estimated char count is called an exact token count. Before a call, reserve conservative maxima. Known observed usage is retained separately; absent/ambiguous usage does not refund a call or turn interrupted dispatch into a free retry. Detailed durable budget/fence policy belongs to B2 after B1 stores exist. No shared Runtime budget is mutated by Agent Planning.

## Verification

Pure tests independently reject scope/identity conflicts, mandatory omissions, duplicates, missing supervision cut, request tampering, invalid budgets, nonfinite/duplicate-key/oversized JSON and caller mutation. Schema tests preserve strict types/extra-field rejection. Actual PostgreSQL/process tests prove own-state replay, concurrency and interruption separately. Deterministic adapters cannot substitute for BP-07.05 live model semantic evaluation. Public DTO evolution is additive/versioned; existing schema bytes must remain unchanged.

## B1.02 deterministic profile

ReferenceProposal/v1 is deliberately reference-only: abstain or propose an exact selected context Artifact. It establishes no scientific payload shape/existence or domain acceptance. Later task children add reviewed extraction/campaign payload profiles rather than treating generic model JSON as executable commands. ProviderObservation separately records bounded64KiB/256-chunk capture identity, completeness, status and observed usage. Interrupted/ambiguous calls remain unknown; partial usage is never silently zero. Deterministic barriers prove binding/local non-starvation, not actual network deadlines or Runtime scheduling. Durable reservation/accounting remains B2.

## B1.03 journal boundary

planning_0001 introduces immutable requests, attempt intents and observations in the Planning-owned schema. Separate service/migrator roles, scoped actor/read-write grants, request-key advisory transactions and exact capture verification preserve replay and first-observation-wins. Pending intent is not an accepted output. No locks span provider calls. begin_attempt is a private journal primitive, not dispatch permission; B2 must add conservative reservations and fenced orchestration before any public call surface. B1.04 separately proves installed/process readback; fresh-engine tests alone do not fulfill it.
