# BP-07.04 Capture publication and response exchange

- Design status: bounded implementation design; pure origin/response verified; journal next.
- Owner: Planning, B2.03b.iii; [loop design](BP-07.04%20Autonomous%20loop.md).
- Reviewed: 2026-10-05 23:31:16 (America/Chicago).
- Implementation credit remains in the canonical child tracker, not this design.

The original intake, retained CampaignPreparation and immutable physical-attempt observation determine capture identity. The publication journal must reconstruct those records inside Planning storage rather than accepting a caller-provided origin. The stable slot is scoped to original wrapper, physical attempt and primary/late observation kind; configured publisher, original preparation and full observation are immutable bindings within that slot. Empty failed/unknown captures need no Artifact; nonempty bytes retain their exact binary content, even when malformed, incomplete or non-UTF-8.

Use the existing Data opaque-octet profile with explicit deployment admission. Derivation includes every available Artifact actually consumed by the retained packet, excluding unavailable and omitted bodies. Original wrapper, preparation and observation hashes bind the transformation. Data's128-direct-parent ceiling remains explicit; over-capacity ancestry returns capture_derivation_input_limit and cannot be truncated. Publication failure preserves local capture and leads to bounded technical handling, not invented successful evidence. Future fan-in publication, if needed, requires separate bounded design.

A new forward-only Planning migration should add immutable capture-publication identities, append-only upload events, lease control, immutable original response commands and append-only response observations. Foreign keys bind original intake/preparation/observation. Existing raw capture bytes are already durable and should not be duplicated unnecessarily. Identity and event hashes must be reconstructed on reads, along with ordinal/position correspondence. Service grants permit INSERT/SELECT on evidence and narrowly scoped UPDATE only for lease/fence/position control.

Use a database-clock lease and position compare-and-set for effect authorization; final transaction writes recheck lease validity. No owner SQL transaction spans Data or Runtime I/O. Reuse the bounded PublicationAttempt upload transitions and shared driver without fabricating an extraction trace. Existing trace/result canonical bytes and attempt command identities remain unchanged. A committed streaming intent whose acknowledgement was lost remains uncertain and uses the existing bounded replacement rule. Finalization receipt recovery always precedes repeating an effect.

Build the existing numeric-v2 runtime.supervision.respond command only from a finalized exact capture reference or empty failed capture. Persist that original command before transport. RuntimeClient receipt, submit and readback remain distinct calls with lease checks around writes; a missing response is not proof the write failed. Receipt and exact public readback must be retained before declaring recording complete. Replays preserve prior terminal receipts and never republish or reinterpret captures. Runtime alone selects a winner; response recording is not graph acceptance.

Publication and late diagnostic exchange may outlive the original call deadline. They require current publication/processing authorization and a valid local lease, but must not erase expired/cancelled-call history. Active campaign pins do not change. No live provider/model/egress/spend is authorized by this work.

Exit evidence: exact raw/prefix/empty capture behavior; immutable origin/configuration; real-SQL registration rollback and concurrent writers; lease expiry and stale position rollback; upload uncertainty and bounded replacement; exact finalized descriptor/derivation; response-before-send and receipt/readback replay after lost replies; rights denial with retained diagnostics; no second model call. Scripted peers prove their boundary only; B3 and V1 retain process-death and installed multi-owner gates.
