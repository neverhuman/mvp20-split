# Campaign proposal policy design

- Design status: B2.01 scoped refinement; no implementation credit.
- Baseline: Planning0.52/public0.9, campaign output and durable observation compatibility verified; planning0012,510 schemas.
- Canonical owner: [BP-07.03](BP-07.03%20Campaign%20proposals%20and%20context.md).

## Ordered policy units

B2.01 has four equal units: a prepared-output binding and relevant observation values; b exact evidence-purpose relationships; c selected tool and authored composition relationships; d reviewed decision declaration and combined policy. All start0%. B2.02 owns actual compiler/eligibility/budget clients and handoff preparation; B2.03 owns immutable submission and reconciliation. This refines the existing three equal B2 milestones without changing delivery weights.

## Prepared output and observations

Reconstruct CampaignPreparation from its original request, manifest and exact packet, and reconstruct the observation through verified_observation. Require a successful campaign output under that same request. A byte-owned PreparedCampaignProposal retains preparation, attempt, raw-capture and canonical-output identities. Missing, invalid or foreign preparation is not repaired by a caller-supplied digest. It is still a proposal, never an admitted graph or scientifically accepted answer.

Build the observation index only from included candidate summaries and the matched packet consumed observations. Preserve lane, kind, exact identity and original observed hash; omitted slices contribute no read dependencies. Duplicate identical observations can coalesce within an identity; conflicting observations in the same lane reject. Distinct Registry inventory and exact-lock lanes may legitimately observe different lifecycle states and remain distinct. Policy selects relevant original dependencies through this index; model text cannot inject or replace the read-set. Do not automatically declare all discovered tools or unrelated graph branches stale.

Provide a pure comparison of a chosen read-set against explicitly supplied later observations. Report changed/missing relevant identities, ignore unrelated added identities and never repin an active campaign. This is a comparison of observations, not evidence that a fresh owner read or processing grant occurred. B2.02/B2.03 supply actual refresh and handoff authority.

## Evidence purposes

Resolve each question, need and assessment intent against the consumed Research selection and retained records/gaps. Check exact revisions, question/need relationships, selected complete assessment requests and expected hashes. Expected evidence describes an intended output, not an accepted answer. Producer addresses must resolve to authored nodes when provided. Missing/unknown/weak/contradictory evidence remains explicit; it must not become a blanket exploration veto. Reject invented or unrelated identities without requiring every uncertainty to be solved.

## Tools and composition

Walk bounded authored scopes with stable scope paths. Match invoked tools to exact discovered locks and the reviewed Runtime universe, retaining exclusions and reasons. Tool metadata similarity never grants eligibility. Actual representation/port compilation remains Runtime-owned; local relationship checks cannot substitute for its compiler. Explicit applicability and eligibility observations are required at the handoff gate. Never import scientific tool implementation or infer domain compatibility from names.

## Decision declaration

The original decision_scope is an opaque digest. Introduce a closed, versioned Planning-owned declaration whose canonical hash must equal that original digest; the reviewed caller supplies it before interpretation, not the model. Bind objective/policy pins, allowed proposal class and any original Runtime cut. Adjustment declarations identify exact authored target/input, expected prior-value digest and allowed finite scalar bounds or enumerated values. A declaration is not a Runtime command, eligibility grant or proof of owner acceptance. Unknown declaration profiles or missing declarations prevent dependent eligibility, while retaining the proposal and diagnostic evidence.

Future topology remains a future-campaign proposal. Existing Runtime has no adjustment-write API; keep that acceptance gap explicit for BP-07.04 rather than inventing successful execution. Budgets retain their existing reviewed accounting boundary. Human choices remain between campaigns; this policy introduces no routine approval ceremony.

## Exit evidence

Module-owned pure tests cover exact prepared-output binding, request/capture reconstruction, omitted versus consumed inputs, lane collisions, relevant-only changes, foreign or invented evidence and tool links, bounded decision declarations, and preserved uncertain science. Independent wheel proof must accompany each bounded implementation checkpoint. Semantic policy grants no durable success before B2.03, and no scientific or live-model claim follows from deterministic fixtures.
