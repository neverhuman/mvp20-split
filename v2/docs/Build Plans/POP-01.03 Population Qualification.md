## Q1: fresh end-to-end population campaign

Freeze the manifest of installed releases, schema/model/policy pins, datasets,
seeds, independent oracle and planned outcomes before running. Use inexpensive,
deterministic numerical objectives with known trade-offs/constraint cases and at
least two named evaluator branches. No paid model call in the evaluation loop.

From the actual UI, use the existing Knowledge/inventory/LLM proposal flow to prepare
a bounded campaign, validate it, press Run and observe population generations.
Retained model requests can support deterministic replay, but a claimed live LLM
path requires an actual call under a separately declared token/cost ceiling.
Ordinary graph execution continues without human approval between generations.

Required small integrated case:128 candidate slots/generation, generation0 plus
four successor generations, configurable16-item batches and at most4 active tool
invocations. Include real sibling overlap, selection receipts and offspring ancestry.
Demonstrate existing-profile128/256 limits correctly and new-profile operation;
population slot count, unique evaluations and attempts are reported separately.

Verify against an independently calculated small oracle and exact semantic replay:
complete frozen membership, correct global selection, consistent RNG progression,
no missing attempt dispositions and identical final evidence under shuffled finishes.
Use a separate valid representation fixture through UI-02 to prove formula/structure
identity. Do not claim numeric evolution optimizes that fixture's molecular shape.

## Q2: interruption and adverse outcomes

Q1 also includes a19-stage synthetic process graph with at least three distinct
width changes: independently prepare A/B, combine into a new intermediate, apply a
process transform, combine with independently prepared C, then branch into downstream
analyses/routes. Include multi-output and conditional stages, unequal branch times
and one explicit bounded loop. Preserve named stages; do not fake depth by copying
the same no-op node19 times. Each synthetic transform has a known input/output oracle.

Q2 must prove a missing required precursor prevents only its dependent transform;
independent branches continue. Reject cross-candidate/generation joins, invalid units,
implicit Cartesian products and expansion beyond admitted bounds. Restart after an
intermediate commit and verify its reuse and exact multi-input lineage. Actual
chemical reaction, heating equipment or laboratory automation is outside this fixture.
Q3 repeats the process shape across a bounded subset of the large cohort to prove
nested occurrence identity and a stable readable graph without implying all1000
candidates underwent a physical19-step drug-synthesis process.

| Case | Required observation |
|---|---|
| Worker dies during evaluation; lease expires | Only outstanding work retries; old attempt is fenced; counts and consumed resources remain honest |
| Runtime dies after accepted result, before aggregation | Resume from authoritative retained evidence without reevaluating accepted work unnecessarily |
| Crash around selection/next-generation commit | One accepted successor and one survivor decision; no RNG drift or lost parentage |
| Duplicate/late/out-of-order result | No duplicate score, candidate or transition; source attempt and rejection reason remain traceable |
| Slow/failed required method | Terminal timeout/exhaustion follows pinned policy; no fast-candidate selection bias or favorable missing zero |
| Too few eligible/no feasible candidates | Explicit stopped disposition, evidence and useful future-campaign focus |
| Budget exhausted mid-generation or duplicate-only population | Defined stop/progress accounting; no infinite variation/resampling |
| New Knowledge/evaluator revision arrives | Current pins stay fixed; later campaign records changed comparison/reuse context |
| Browser reload/reconnect/permission loss | Same retained generation/selection or explicit stale/denied state; no leaked or fabricated result |
| Two concurrent advance/selection requests | Expected-revision/identity checks yield a single accepted transition |

Record failed trials as evidence. Never stop unrelated shared Docker services without
the applicable permission; use owned worker/Runtime process boundaries. Every drill
must prove cleanup and isolation before the next trial. Runtime stop and scientific
infeasibility remain different diagnoses. Pull LR-01 forward if its unresolved fault
recurs; a later successful run does not prove that fault repaired.

## Q3: genuine large population and bounded UI

Execute the new profile with1000 candidate slots per generation, generation0 plus
two successors, two cheap evaluator methods, batch size32 and in-flight cap8.
Account for a selection union of up to2000 members. This is an actual campaign,
not a table populated from fabricated successful records. Freeze a finite attempt,
artifact, graph-expansion, time and storage budget that covers the computed workload
before admission; never disable limits to make the fixture pass.

Compare with a lower-concurrency run on a bounded representative cohort and the
independent global-selection oracle. Prove that dispatch batches do not partition
selection. On a declared1000-member trial collect observed queue pressure, max active
attempts, elapsed time, peak process memory, artifact sizes, projection lag, query
latency and UI timings. No production capacity claim beyond this host/profile.

Assert that the main graph remains the same method graph regardless of cohort size;
the user can locate a failed member, explain a survivor, inspect a chosen molecule
when its representation exists, and return without losing generation/context.
Whole-history browser download, silent truncation, per-batch top-k substitution or
unbounded checkpoint growth fails this gate. A scale failure becomes a named repair,
not a covert downgrade to a tiny-population completion claim.
