## Next Validation Boundary

A save creates a revision, not a validation or run. definition.validate names draft_id, revision and content_sha256; the server loads that exact retained revision and its configured reviewed tool/schema universe. It compiles without I/O using the existing compiler, then commits an immutable validation record and original command receipt. A structural finding is a successfully recorded validation result, not a lost command or an accepted campaign. Missing/foreign revision or mismatched digest rejects the command.

Validation records pin universe_sha256 and the exact compiled plan hash or bounded findings. Saving later edits cannot mutate them. Validation may inspect an older retained revision, but activation must require the explicitly selected current draft head plus matching validation/content/universe; no implicit rebase. The immutable validation store may retain the compiled plan and required public descriptor/schema material needed for replacement; no request-supplied arbitrary schema URL is fetched.

The configured reviewed universe is separate from the live Registry lifecycle. Registry-driven UI forms use public descriptors and exact pins; validation cannot silently admit an unknown release because its JSON shape resembles a reviewed one. Current eligibility, permission, budget and the one-active-campaign guard are activation checks. A structural validation record explicitly leaves scientific applicability/acceptance unestablished. Broader scientific validation requires its owning services.

For dynamic draft admission, extend the existing Runtime admission path with a scoped verified plan resolver and draft validation guard; do not add a second scheduler or run database. Resolve external observations before the short transaction; recheck owner-local draft/validation/eligibility cut under the existing admission guard. Return an original pending/rejected/accepted command receipt and preserve old configured-plan admission behavior. Publication/activation of a draft must have an explicit idempotent command and versioned contract, not implicit side effects of GET or save.
