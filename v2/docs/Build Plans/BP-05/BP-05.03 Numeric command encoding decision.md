## Observed mismatch

Campaign wire-v4 exposes `NumberConstant.value` as a bounded float, including ordinary decimal scientific parameters. Commands0.1.0 deliberately rejects float tokens before validation and rejects all float values after DTO default/type normalization. Consequently a public-schema-valid `SaveDraft` containing a numeric constant cannot pass `parse_authoring_command`:

| Authored numeric constant | Public SaveDraft JSON validation | Original command parser |
|---|---|---|
| `1` | accepted, normalized to float | `unsupported_value` |
| `1.25` | accepted | `non_integer_number` |

Verified against the installed editable public packages on `2026-09-30 11:57:59`; no database or live run mutation. The same canonical parser is used by graph admission, so fixing only Studio's input validator cannot resolve the owner boundary. Number ports sourced from tool artifacts are distinct and are not evidence that literal commands work. This is a pre-existing cross-contract gap exposed by authoring work, not a reason to rewrite historical receipt hashes.

Relevant contracts: [Commands README](../../../contracts/commands/README.md), [canonical parser](../../../contracts/commands/src/amphora_contracts_commands/canonical.py), [value types](../../../contracts/campaigns/src/amphora_contracts_campaigns/executable/values.py), [authoring commands](../../../contracts/graph_runtime/src/amphora_contracts_graph_runtime/authoring.py).

## Approved correction

Add an explicitly versioned numeric command envelope/profile, opt-in only at the affected authoring and draft-admission boundaries. Preserve the existing profile, parser entry point, golden byte/digest fixtures and historical receipt replay unchanged. Do not silently permit floats under the published v1 encoding contract.

The new envelope carries an explicit encoding marker included in retained canonical bytes and the request digest. Command identity/actor/scope remain authoritative; reusing an existing command ID with another encoding or payload remains an identity conflict. Retries retain the original profile and bytes. Receipt schemas need not change merely to add a profile: they already bind the owner-computed digest and original identity.

Numeric rules must be explicit and fixture-backed before activation: finite binary64 values only, bounded by the consuming DTO; reject NaN/infinity/overflow; preserve safe-integer/depth/size/Unicode/duplicate-key checks; materialize DTO defaults before canonical encoding; define stable server-owned decimal rendering and signed-zero behavior in golden fixtures. Studio consumes the profile and receipt binding without independently claiming an equivalent browser canonical hash. No decimal-to-string reinterpretation of existing scientific values or change to artifact/schema hashing.

Implementation gates within the active B1 correction:

1. Add the public profile contract and immutable canonical fixtures, including legacy byte-for-byte replay, integer versus normalized number, decimal/exponent values, signed zero, bounds and malformed input rejection.
2. Opt in Runtime save/draft-admission parsing; prove persisted duplicate/conflicting identity and post-restart receipt replay with both profiles. Existing callers stay on v1 unless explicitly using the new envelope.
3. Update Studio submission selection and public examples; test decimal draft save/validate/admission through actual owner APIs. Preserve original bytes after acknowledgement loss.
4. Regenerate/version affected public packages, run module coverage and independent installs, update README/architecture/drift evidence. No B1 delivery credit until the remaining forms/comparison/emergency scope also passes.

No new service or reopened closed plan is proposed. If owner direction adds work outside this bounded repair, update the active plan's scope and completion basis explicitly first.

## Alternative

Keep v1 commands unchanged and make all numeric literal controls explicitly unavailable, including integral values typed as `number`, until a named successor implements the numeric profile. This preserves the current limitation but restricts the research editor; it is not equivalent to supporting the existing graph contract. Existing integer constants and artifact/tool-produced numeric values remain separate supported mechanisms. Recommendation: implement the versioned correction now.

[AGENTS](../../../AGENTS.md) requires: "Material scope/sequence changes need owner direction; routine blocking repairs do not need unnecessary permission requests." The implementation choice here expands a foundational persisted command-encoding contract explicitly documented to reject floats. Treating that as a versioned compatibility decision, rather than silently loosening a parser during UI work, warrants owner direction. This is a scoped interpretation of that rule; no external deployment or broader permission is requested.
