## Concrete problem and source evidence

The scientific review currently carries a locally authored evaluation design and
exact tool/Knowledge bindings. That is useful context, but does not prove an LLM or
Planning generated the executed draft, or identify the Research criteria it used.

Runtime's public DraftRevision contains scope, head, parent revision and definition;
it has no originating Planning attempt or compiler receipt link
(`contracts/graph_runtime/.../authoring.py`). Planning's CompilerHistory reconstructs
the original preparation, request/attempt, proposal, reservation and settlement.
CompilerJournal reads accepted Runtime save/validation effects against that original
history (`services/agent_planning/.../campaign_dispatch`). These are owner-internal
interfaces, not Gateway/Studio contracts.

Planning's current HTTP surface exposes supervision request/receipt/completion and
topology proposals. Runtime supervision responses and the existing FollowupClient
can verify selected response captures; they do not attest that an arbitrary saved
draft was produced by that response through Planning's compiler. Research's exact
question/need reads already exist and can be reused once the association is known.

Consequently, displaying an unrelated retained proposal beside the current graph
would fabricate provenance. Reading Planning's tables from Studio, Runtime or the
Gateway would violate service isolation.

## Recommended bounded contract

Add an authenticated, read-only Planning route, proposed spelling:

`GET /v1/campaign-origins/{draft_id}?revision={revision}&content_sha256={sha256}`

Scope comes from the authenticated principal; the exact requested draft identity is
mandatory. There is no latest-head fallback, broad history scan, mutation, provider
call, compilation or campaign launch in this route. A separate read_campaign_origin
grant authorizes project-scoped provenance inspection without granting record_attempts
or impersonating the original Planning actor.

Publish an additive versioned Pydantic/JSON Schema projection. Reuse existing public
references and receipt types wherever possible. Proposed contents:

- Exact scope/draft revision/content digest, origin digest and original producer
  actor attribution; authority is historical_compiler_provenance.
- Original Planning engagement/attempt/request and interpreted proposal digests;
  bounded recorded action/rationale, model/prompt/policy reference identities and
  recorded usage/accounting when available. No generated reasoning or confidence.
- Exact Runtime save command identity/hash and accepted receipt/readback identity;
  validation evidence, if exposed, must be a separately pinned observation and must
  never masquerade as current eligibility or scientific acceptance.
- Exact Research selection: question and need revisions, selected criterion IDs and
  available assessment pins. Include selected Knowledge/tool reference identities
  needed to explain the association, with explicit unavailable or omitted context.
- Existing capture/derivation ArtifactRefs only where Planning actually retained
  them. Missing publication is explicit; no fabricated ArtifactRef or raw private
  preparation packet. Data authorization remains necessary to read content.

The complete response is bounded at256KiB. A record that cannot fit must fail with
a named bounded-read limitation; it must not silently truncate its identity chain.
Field/cardinality limits reuse the owning contracts rather than introducing an
unbounded general context dump. Raw prompts, credentials, database details and
arbitrary provider payloads are excluded from this summary route.

Missing origin returns404 and means no recorded association, not human authorship.
Denied remains403. Changed/conflicting draft pins or corrupt owner reconstruction
fail closed with a sanitized reason. No response grants execution or source rights.

## Owned lookup and consistency

Planning needs a private indexed projection keyed by authenticated scope and exact
Runtime draft identity. It points to the original compiler selection and accepted
save effect, whose existing owned readers revalidate the chain. It is a rebuildable
lookup, not a second owner of Runtime drafts or a new proposal journal.

Record the lookup with Planning's accepted save observation in the same local
transaction. Runtime's save remains independently committed through its existing
command/receipt protocol. A lost acknowledgement is reconciled first; it cannot
produce another origin or launch. Duplicate identical observation is idempotent;
conflicting association fails. Failed/pending compiler work has no accepted origin.

Existing history requires an explicit bounded backfill from Planning's retained
effects; the reader must not scan all compiler history on each request. Backfill
does not rewrite old receipts, drafts or proposal captures. Any private migration
must preserve the existing compiler history and isolation/replacement guarantees.

Keep origin outside the authored graph. Embedding a future provider response in
the definition that the provider must produce creates a circular dependency and
would alter the supposedly exact proposed graph. Provenance is a derived projection.

## Studio and integration scope

Gateway adds only the exact read route with its scoped Planning grant. Studio loads
the original draft from the verified launch association, then reads that exact
Planning origin and independently reads selected Research records. It verifies
scope, draft digest, criterion membership and original save/proposal bindings before
showing them as provenance. The current design view remains clearly locally authored
when no origin exists; an unavailable read never silently changes authorship.

The review should answer: which Research objective/criteria informed this draft,
which recorded Planning proposal produced it, what tools/evidence were selected,
and what remains unsupported? Details are progressive, not a raw JSON dashboard.
The API is independent of scientific tool execution, population scale or LLM chat.

N2.2 qualification may use a clearly labelled configured deterministic provider to
prove actual Planning storage/compiler/Research boundaries. That does not earn
N2.4 live-provider reasoning or N3/I1 conversational curation credit. Later actual
model work retains its separate configured budget and evidence requirements.

## Alternatives considered

| Alternative | Assessment |
|---|---|
| Existing supervision response reads alone | Useful for a selected checkpoint response, but no compiler-origin association for an arbitrary draft |
| User-supplied URL/context annotation | Can select a record; cannot attest the Planning-to-Runtime compiler relationship |
| Publish an origin Artifact through Data only | Viable producer mechanism, but still needs a durable exact-draft discovery association and a new public projection; defer duplicate publication until a consumer needs it |
| Embed provenance in the proposed definition | Creates a future-reference cycle or changes the definition after proposal; conflicts with exact origin verification |
| Read another service's private state | Rejected by isolation requirements |
