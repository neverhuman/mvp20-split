## Concrete Missing Boundary

The [source-derived baseline](../../../services/campaign_runtime/tests/fixtures/v1_solver/README.md) requires a generated population, parallel per-candidate scoring, ordered collection, parent selection from retained results and the next generated population. CLI/engine/ranking normalized source hashes were rechecked at this proposal timestamp; all three match. No v1 code was executed or changed.

The current [graph values](../../../contracts/campaigns/src/amphora_contracts_campaigns/executable/values.py) distinguish Artifact references from graph collections. [Invocation binding](../../../services/campaign_runtime/src/amphora_campaign_runtime/coordinator/bindings.py) explicitly rejects non-Artifact tool inputs. [Predicate projection](../../../contracts/campaigns/src/amphora_contracts_campaigns/executable/predicates.py) extracts scalars for conditions; it does not expose arbitrary typed collections as graph outputs. The [SDK worker](../../../sdk/tool_protocol/src/amphora_tool_protocol/worker.py) accepts one Artifact input and produces one Artifact output in its initial reviewed pure profile.

Consequently, a population produced inside an Artifact cannot yet become graph-controlled scatter membership; a gathered collection cannot yet become the input Artifact for a population-selection/retention tool. The previous generic scatter and wait tests remain valid. They do not establish this producer/consumer conversion, and their closed plans must stay closed.

## Approved Scope

Add two explicit, domain-neutral graph binding primitives with narrow module ownership:

1. **Artifact to typed graph value/collection.** Read only a pinned, scoped Artifact through its public owner, verify metadata/bytes/schema, and apply an explicitly declared bounded path and output type. For inline population records, publish schema-pinned member Artifacts before exposing ordered references. Distinguish inline records from already-pinned reference manifests; JSON fields that resemble references confer no authority. Freeze expansion membership at the committed output.
2. **Typed graph values/collection to Artifact.** Use a declared finite mapping and output schema to publish an immutable input for an ordinary tool. Specify reference-manifest versus verified inline-value materialization explicitly. Preserve declared order, missing/failure slots and input provenance; never silently filter or rank candidates. A scientific aggregation/selection operation remains a capability tool.

Graph configuration determines composition, iteration and candidate concurrency. Runtime owns binding validation and acceptance; Artifact owns publication/storage/protection; tools own scientific or synthetic computations. No arbitrary expressions, Python snippets, dynamic import, molecule-specific representation, score policy or hidden population scheduler enters the runner.

Bound member count, recursion/path depth, fetched/published bytes and per-pass work. Read/publish/reserve outside Runtime SQL transactions. Recheck run authority, exact source cut and cancellation/deadline at commit. Persist a distinct resumable binding/publication operation; stable retries must recover original identities without duplicate logical acceptance. Protect produced and referenced Artifacts across interruption and reconcile losing preparations. Reuse existing public Artifact protocols; do not invent worker attempts or charge scientific invocation budget for a graph binding operation. Explicitly meter its own bounded resources.

## Decision and Alternatives

**Decision:** user approved this general binding prerequisite before BP-04.04. It closes a reusable engine boundary needed by polymers, biology and other domains.

A single batch tool could hide the complete population loop internally, but then candidate-level parallelism, feedback and stage inspection would be tool-private. That would require explicitly revising the graph-native parity acceptance criteria. Fixed pre-authored populations can demonstrate existing scatter behavior but cannot satisfy the current generated-population/feedback gate. Neither alternative is silently substituted for the approved plan.

The applicable [AGENTS rule](../../../AGENTS.md) states: “Material scope/sequence changes need owner direction; routine blocking repairs do not need unnecessary permission requests.” This proposal adds a new cross-owner data conversion/publication boundary and four deliveries before the next approved child; it is treated as a material addition, not as a routine local fix. Explicit user approval now authorizes implementation and the 24-delivery rebaseline; no additional approval is needed for this scoped work.
