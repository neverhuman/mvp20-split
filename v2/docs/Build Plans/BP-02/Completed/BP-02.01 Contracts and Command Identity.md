## C1 Implementation-Ready Contract

Create standalone `contracts/commands` depending only on the public core contract package and Pydantic. `CommandIdentity` carries version, command family, command ID, scope and actor ID. A family-specific WireModel owns payload shape; there is no arbitrary dict acceptance API. `CanonicalCommand.parse(raw, payload_model)` validates top-level identity and payload through JSON-aware strict validation so immutable tuple fields accept JSON arrays. It freezes only canonical bytes plus immutable identity, avoiding nested mutable payload state.

Input limit: 256 KiB; container depth limit 64; safe integers in +/- (2^53-1); UTF-8 without BOM. Reject duplicate keys at every level, floating syntax including 1.0, NaN/Infinity, malformed/unpaired Unicode, non-object root and unknown envelope fields. Canonical envelope contains identity and materialized payload defaults; no transport credentials or caller digest field. Encode ASCII escapes with sorted keys and compact separators, no trailing newline; hash SHA-256. The parser must validate before and after schema normalization so a model cannot introduce an unsupported float/default. Canonical bytes remain immutable after return.

Fixed test vectors independently store canonical bytes and SHA-256, covering Unicode and escaped spelling, key order, whitespace, omitted/default/null behavior and safe integer boundaries. Failure table tests every rejection, exact byte/depth bounds and payload-shape mismatch; field change must change digest while semantic-equivalent formatting must not. Tests stay under `contracts/commands/tests/`. Independent JSON Schema checks cover identity transport; runtime authorization is explicitly outside this package.

C2/C3 operation schemas require additional family field tables before coding; C1 cannot be used as a catch-all untyped command DTO. Existing core/tool/campaign v1 schema bytes remain unchanged. C4 owns publication of new contracts; C5 owns package closeout and consumers. No live DB/fencing claim from these tests.

## C2/C3 Field and Ownership Decisions

The common command envelope remains `{identity, payload}`. Family-specific public parsers bind `identity.command_family` to a fixed registered payload model before returning canonical bytes; clients cannot select a different family by adding a discriminator. Runtime operations are `runtime.admit_fixture`, `runtime.claim`, `runtime.renew`, `runtime.complete`, `runtime.cancel`, `runtime.revoke_worker`. Artifact operations are `artifacts.begin_upload`, `artifacts.finalize`, `artifacts.reserve`, `artifacts.confirm`, `artifacts.reconcile`. Byte upload/read and scoped queries are transport operations, not arbitrary JSON blobs.

Runtime DTOs group immutable prepared invocation specs (no pre-issued attempt), finite budget, attempt reference and optional checkpoint precondition. Completion reuses the existing tools.Completion shape, adding run binding and expected checkpoint revision. The worker ID and scope are asserted request values; authenticated handler policy checks them. Renew carries exact attempt/fence and bounded lease seconds. Receipt references bind identity, request digest and operation ID. Pending, accepted and rejected receipt variants remain distinct; accepted receipts identify a committed reference/revision, not a claim of scientific success. Actual claim execution responses also carry the issued tools.Invocation and explicit UTC lease expiry. Family/result consistency and calendar validity remain semantic handler checks, not false JSON Schema guarantees.

Artifact descriptors group content digest, byte count, media and schema identity. Provisional IDs never carry paths. Reserve binds a scoped artifact reference to runtime owner, intent ID, semantic completion digest and output binding. Reservation lifecycle variants RESERVED/CONFIRMED/RELEASED cannot contradict their proof payload: CONFIRMED includes a committed outcome, RELEASED includes an aborted outcome. Receipts authenticate only at the service transport boundary; these schemas do not let a caller manufacture authority. Reconcile takes a reservation ID; clients do not supply a guessed terminal outcome. Confirm references the runtime intent and accepted completion receipt for owner verification. No expiration timestamp authorizes release.

Owned tests use per-family fixture JSON, independent JSON Schema validation and canonical parsing with unknown-key/type/version/family negatives. Schema constraints enforce structural shape; handlers must enforce cross-scope identity, artifact metadata consistency, current fence, command/result relation and authenticated issuer. These outstanding semantics map to the persistence/artifact/lifecycle children rather than hide in DTO validators.
