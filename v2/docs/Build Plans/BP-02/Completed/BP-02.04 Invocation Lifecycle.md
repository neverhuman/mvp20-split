| Command / policy | Guard and locked state | Mutation / invariant |
|---|---|---|
| AdmitFixtureRun | Configured synthetic fixture allowlist, exact pins, authenticated scope; admission guard then run | One running installation slot, immutable input/budget and queued activation set |
| ClaimInvocation | Running run, active worker, matching exact tool, queued activation and available unit | New immutable attempt ID, increased activation fence, bounded lease and one reserved unit |
| RenewAttempt | Same current attempt/fence/worker; DB clock strictly before expiry and invocation deadline | Extend bounded lease with same attempt/fence; replay returns original renewal receipt |
| Expire | DB clock at or beyond lease expiry under owner locks | Terminalize issued attempt once; settle reserved to spent; only eligible pure work becomes queued |
| CancelRun | Authorized scope and explicit revision precondition under run lock | Stop new claims; abort prepared intents and settle/cancel by effect policy; preserve accepted history |
| RevokeWorker | Authorized scope; serialize with run and worker policy | Durable revocation revision prevents renew/commit; a remembered client grant cannot override it |

Lock order refinement: admission guard if needed -> run -> worker-policy rows in stable ID order -> activation -> attempt -> intent -> command. Revocation and all authority-changing paths use the same order. Compare leases with database clock after locks are obtained; transaction-start or worker time cannot accept a lease that expired while waiting. Read/claim projections cannot bypass current authority checks.

Fixture admission is a distinct narrow API; the existing general graph validation route still returns non-executable until BP-04. A claim with no eligible work has a stable no-work receipt for that command ID; a later poll uses a fresh command ID. Renewal replay never extends twice. Infrastructure retry exhaustion leaves command retryable/pending rather than fabricating a business rejection.

Budget conservation oracle: initial limit = available + reserved + spent; each issued attempt reserves once and terminalizes once; spent never decreases. Unclaimed cancellation spends zero. Pure expired work can be reissued only within attempt and run limits. Unknown external effects retain explicit uncertainty; non-pure tools are not enabled by this initial fixture API.
