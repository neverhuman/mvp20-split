## Detailed Implementation Contract

Planning review: `2026-09-25 13:35:12`. The [storage/access design](../../../Architecture/System/Artifact_Storage_Design.md) is the authority for byte handling. The proposed route names below become public only after A2/A6 implementation and schema publication.

| Boundary | Owner action and preconditions | Durable result / failure |
|---|---|---|
| POST /v1/uploads | Authenticated principal, scoped BeginUpload command, configured content/schema pair and capacity | Provisional upload plus stable command receipt; no artifact reference |
| PUT /v1/uploads/{id}/content | Same upload owner/scope; bounded full-body restart, no arbitrary path/offset | New generated attempt/generation; streamed state only after full verification and generation CAS |
| POST /v1/artifacts/finalize | FinalizeArtifact command binds upload and original descriptor | Immutable catalog plus receipt/audit in one transaction after verified bytes |
| POST /v1/reservations | Runtime-only ReserveArtifact command and exact scoped artifact/intent binding | Stable protective reservation or identity conflict |
| POST /v1/reservations/confirm | Authenticated runtime outcome lookup outside transaction | Exact committed proof confirms; pending/mismatch never releases |
| POST /v1/reservations/reconcile | Exact reservation identity; owner reads authoritative terminal intent | Committed confirms, aborted releases, unknown protects |
| GET /v1/artifacts/{id} and /content | Current scoped read grant, catalog membership and integrity checks | Metadata/bytes; guessed digest/key gives no access |

Streaming itself has no generic canonical JSON command envelope: retry creates a new attempt generation on the same provisional upload. Concurrent requests may have distinct attempts; only latest admitted generation can become selected. Finalized uploads reject new content writes. Failed/abandoned attempts consume their measured storage until cleanup and cannot bypass capacity limits. Replay of BeginUpload/Finalize returns its original receipt, not a new upload or artifact. Transport response mapping must distinguish retryable infrastructure failure from terminal business rejection.

A2 forward migration adds upload principal, generation, attempt status/key/expected descriptor and capacity ledger with exact scoped foreign keys. Scope capacity is locked before upload; stable ID ordering for multiple rows. Short transactions admit/select/settle attempts; no byte stream or runtime lookup under DB locks. Count outstanding allocated bytes and actual retained bytes without double-counting successful transfer. A process killed before settlement leaves a reconcilable reservation; timeout alone never deletes finalized bytes.

A2 fixtures: UP-01 partial body, UP-02 declared size overrun, UP-03 old writer finishes last, UP-04 duplicate BeginUpload, UP-05 capacity races, UP-06 cross-owner upload. A3: PUB-01 wrong hash/schema, PUB-02 kill after fsync, PUB-03 kill after catalog commit, PUB-04 finalized overwrite attempt. A4/A5: RET-01 commit proof, RET-02 abort proof, RET-03 unknown/outage, RET-04 two intent bindings, RET-05 late reserve after abort. Each case asserts catalog/reference state and surviving byte protection, not merely HTTP status.

The scripted runtime outcome server used before .05 implements an explicit public proof fixture; its credentials and outcomes are not production authority. .06 must repeat RET cases against the actual runtime. A6 cannot claim integrated runtime race safety from the fixture.
