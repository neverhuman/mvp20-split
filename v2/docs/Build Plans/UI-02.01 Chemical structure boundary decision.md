- Reviewed: 2026-10-13 10:43:09 America/Chicago; baseline f141257e.

- Gate: P1.3 opt-in Research profile next; downstream P2-P4 wait for P1.4.

## Recommended first boundary

Implement one independently packaged `chemical_structure` capability that accepts
a supplied, fully specified, finite molecular graph encoded as SMILES and derives
normalized structure, molecular formula and a two-dimensional depiction. A finite
oligomer with explicit end groups is supported as a molecule. Inputs and UI must
say supplied; this first tool does not generate, optimize or recommend compounds.
It makes structural interpretation inspectable without waiting for ML-01.

Unspecified polymer repeat units, BigSMILES, distributions, mixtures, disconnected
salts/components, reaction strings and biological sequences are explicit unsupported
representations in the first profile. They must never be silently capped, completed,
converted to a guessed full formula or drawn as a real finite chain. Their adapters
remain named later profiles; this decision does not turn the engine into a fixed
small-molecule pipeline. UI-02's formula semantics for those types remain requirements.
The first actual demo should use a separate supplied finite oligomer example, with
no asserted property connection to existing Hansen/viscosity parameter fixtures.

### Owned artifacts and exact associations

New DTO package: `contracts/chemical_structure`, public roots
`chemical-structure.request.v1` and `chemical-structure.result.v1` (final schema
publication naming follows the repository generator's version convention).
The package contains transport validation only; the tool owns chemical behavior.

| Record | Required contents and meaning |
|---|---|
| Request | wire version, scope, exact proposed CandidateRevisionRef, semantic profile, origin=supplied, representation_kind=finite_molecule, supplied SMILES. No claimed formula, score or render bytes are trusted inputs. |
| Result | same scope/candidate/profile, source request byte SHA-256, origin=supplied, authority=structural_derivation, exact toolkit/version/method pins, canonical isomeric SMILES, normalized atom/bond representation, formula with explicit charge/isotope policy, bounded PNG depiction plus its content hash, declared structural warnings. |
| CandidateRevision | Existing Research DTO remains unchanged: exact candidate reference and representation ArtifactRef. A new configured chemical profile checks the result's scope/candidate/profile match and supported schema. No inferred scientific validity or synthetic canonicalization receipt. |
| Accepted producer | Existing Runtime accepted-invocation/completion projection binds the actual input and output artifacts/tool release. Result-internal source hashes are attribution claims until these public owner records and exact Data bytes agree. |

Use separately typed objects for parsed structure, derivation profile and display
bundle. Convert them into DTOs explicitly. Do not construct one wide behavior-bearing
Pydantic response at the adapter call site. Candidate revision stays owner identity;
canonical molecular bytes are a versioned structural identity, not universal polymer
equivalence or authorization for evaluation reuse.

Proposed bounds: input SMILES at most4096 characters; a single connected molecule
with at most128 heavy atoms; no wildcard/query atoms or unspecified attachments.
Input/output JSON at most262144 bytes, preserving the existing Research artifact
limit. PNG at most131072 decoded bytes, fixed maximum1024x768; fail explicitly when
limits cannot be met. Preserve isotopes, formal charge and supplied stereochemistry;
do not resolve unspecified stereocenters, tautomers or protonation silently. A
partial/ambiguous feature outside this exact profile yields a safe unsupported or
invalid result, not success with dropped information. These bounds are engineering
limits, not statements about possible chemistry.

Use RDKit through the scientific tool only, with exact dependency/environment locks
chosen and verified in P1. It supports molecule parsing/canonical SMILES and drawing
([official guide](https://rdkit.org/docs/GettingStartedInPython.html)); molecular
formula generation is exposed by [CalcMolFormula](https://rdkit.org/docs/source/rdkit.Chem.rdMolDescriptors.html).
Pin isotope/charge/normalization behavior in the semantic profile and golden cases;
these library APIs do not prove synthesizability, property accuracy or biological
safety. No browser RDKit runtime, remote chemistry API or paid model call is needed.

### Service ownership and compatibility

- Tool: focused parser/derivation/depiction objects, public CLI/schema/descriptor and existing Tool SDK adapter. No Research SQL, graph scheduling or model ownership.
- Runtime/Registry: unchanged protocols; register one reviewed capability version and execute it as an ordinary graph node. No hard-coded chemical path in Runtime.
- Data: unchanged immutable artifact/rights reads; one bounded result bundle, no arbitrary web/image fetching.
- Research: explicit opt-in chemical registration profile. Keep old candidate-space schema bytes, literal synthetic authority, schema dispatch and default allowed profiles unchanged. Validate the exact CandidateRevisionRef inside the result against the registration record. Registration declares identity; it does not promote chemical or biological efficacy.
- Studio: verify current artifact rights, exact bytes/schema, candidate/revision and accepted producer before rendering. Show formula and image from the same bundle. Render PNG as an inert image with an accessible textual structure/formula alternative; no raw SVG/HTML injection. Wrong candidate/revision, malformed image, denial or unsupported profile clears the affected detail.

Existing public candidate routes and DTOs can be reused; no universal campaign
catalog or new Runtime query is proposed. No new Research table is expected because
the existing immutable identity/registration ledger can retain the new representation
ArtifactRef. Verify this assumption against actual transactions in P1; if a material
new API/storage boundary is discovered, record it before implementation.

## Ordered implementation within UI-02/P1

Four equal P1 deliveries; P1.1/P1.2 complete100%, P1.3/P1.4=0%:

1. P1.1 publish additive schemas/examples/semantic profile and compatibility checks; all existing schema fingerprints unchanged. Define invalid/unsupported/error vocabulary without an execution or scientific authority claim.
2. P1.2 implement the isolated tool with exact source attribution, independent formula/atom-count goldens, normalized structure and bounded depiction. Verify explicit hydrogen/isotope/charge/stereo handling, unsupported inputs, deterministic replacement and safe failures.
3. P1.3 add opt-in Research profile resolution and exact candidate/result matching. Cover current rights on every write/retry, foreign scope, revision conflict, immutable history, malformed/unconfigured profiles and preserved synthetic registration behavior. No private tool implementation imports.
4. P1.4 execute an actual registered graph capability with independent tool/owner installation, retain input/result, register/read the exact candidate, and reject deliberately mismatched attribution. Record replacement boundaries and scoped audit before P2.

P2 remains recommendation evidence, not a license to invent a winner. The new
structure-only candidate starts unranked with missing selection policy/property/
synthesis evidence explicit. Inventory existing fitness/selection projections there
before choosing a producer. Do not attach the synthetic digest objective or fixture
ID tie-breaker as chemical fitness. Any real recommendation needs an actual retained
policy, candidates, evidence and conditions. P3 displays supported/unsupported states;
P4 proves actual browser/local-LAN and wrong-identity/denial recovery.

## Acceptance and owner choice

Approve the additive chemical artifact/tool and Research registration profile above
as UI-02/P1's first supported representation. This explicitly extends the former
synthetic-only admission boundary while retaining its original contract/semantics.
Approval permits implementation and bounded local scientific-structure fixtures;
it does not authorize paid providers, inherited model integration, chemistry claims,
lab work, unrestricted source egress or changed current campaign history.

Alternative: require unspecified repeat-unit/mixture semantics in the first profile.
That expands P1's scientific representation and formula interpretation work; document
that choice before publishing a profile. No implementation completion is claimed.
