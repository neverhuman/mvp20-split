## Reproduced boundary gap

The current `CampaignEvidenceIntent` in
`contracts/planning/src/amphora_contracts_planning/campaign_output.py` names a
question, needs, assessments, optional producer, expected evidence and uncertainty.
It has no criterion selection. `CampaignUnresolvedPoint` also has no criterion ID.
`CheckpointDraft` inherits these types unchanged. Research evidence needs may name
many criteria; the quality browser fixture has 32 criteria in one need.

Consequently, matching an AI proposal to that need establishes need-level relevance,
not that it targets the one conflicting criterion the human selected. Studio must
not infer that stronger relationship from labels, generated prose or shared scope.
Current Knowledge graph proposals likewise identify question/need assertion lineage;
their DTO does not establish AI authorship or criterion-specific improvement intent.

Existing public read infrastructure can expose retained model proposals: Runtime's
checkpoint decision includes the retained capture ArtifactRef and request/response
digests, and Data separately authorizes content access. The absence of a read API
is therefore **not** the blocker. The missing piece is an explicit validated target
binding between a focus point and the proposal. Parsing an old capture cannot create it.

## Recommended additive profile

Add a distinct Planning output profile, provisionally
`planning.checkpoint-followup-draft/v1`, rather than changing the published bytes or
meaning of `planning.checkpoint-draft/v1` or `planning.campaign-draft/v1`.

The new profile carries the existing future-campaign/evidence-request draft plus:

| Field | Contract |
|---|---|
| `targets` | At most 32 unique exact criterion targets; each has question revision, need revision, criterion ID, and optional exact assessment selection |
| `improvement` per target | Nonempty text, maximum 2048 characters; proposed change, not a scientific verdict |
| `expected_learning` per target | Nonempty text, maximum 2048 characters; qualitative expectation, never an invented numerical gain |
| `unresolved` | Exact targeted or untargeted criterion references with explanatory posture; missing coverage remains explicit |
| `focus_artifact` | Optional exact authorized ArtifactRef for a retained human focus input; absence supports autonomous AI proposals |

Planning must bind each target to the exact question/need/assessment records included
in its authorized preparation. The criterion must belong to the selected need and
question; assessment selections must agree. Unknown, omitted, duplicate or foreign
references reject before publication. A human focus document is an untrusted input,
never permission or evidence. Model output cannot mark a selected point resolved.

The new input preparation selects this profile explicitly and includes the bounded
criterion references. Existing preparations continue using their original pinned
profiles. Reuse Data retention and existing public Runtime decision/content reads;
do not introduce another scheduler or a separate proposal database merely for the UI.
Planning and Runtime validate the new profile through focused domain objects and
public schemas. Runtime retains proposals; active campaigns are not edited or repinned.

Studio displays each verified target with its original point, intended improvement,
expected learning and unresolved remainder. It distinguishes a retained proposal
from a validated/admitted subsequent campaign. Old proposals remain readable as
need-level proposals with criterion targeting unavailable; no historical backfill.

## Alternative

Keep existing schemas and display AI proposals only as related to the broader need.
Retain the exact human focus draft separately. This avoids the profile addition but
requires an explicit narrowing of B3/V1: no claim that the proposal or subsequent
campaign targets selected individual weaknesses. Recommendation: the additive profile.
