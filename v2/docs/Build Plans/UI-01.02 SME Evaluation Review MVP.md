## Correction and MVP boundary

The owner rejected the numerical execution graph as a demonstration of the product.
The missing acceptance criterion is whether an SME can challenge the evaluation
itself: a wrong method, unsupported assumption, missing criterion, or misleading
aggregation. G1/N2.C remain completed infrastructure; they do not satisfy this gate.

Deliver a domain-neutral evaluation-design document and inspector, with a small
Codex-authored polymer/formulation proposal grounded in named read-only v1 sources.
Expose objective -> criteria -> selected methods -> evidence/selection -> next
generation, proposed independent branches, method applicability, required inputs,
assumptions, alternatives and unresolved decisions. Every design choice is a
proposal, not an executed fact. The example is not produced by the runtime Planning
service, not an admitted executable graph, and not connected to the numerical run.
The user can import another bounded document; scientific choices must not be
hardcoded into the renderer. No fake candidate scores or completed scientific nodes.

For tomorrow, SME feedback is a revision-pinned local review export/import. It does
not mutate a running campaign or automatically drive the LLM. Runtime publication,
registered scientific adapters, persisted provider provenance and automatic review
consumption remain explicit follow-on scope; do not count them as delivered here.
The existing numerical history remains available as a separate execution view.
