# Synthetic evaluator reconstruction boundary

- Status: specified for BP-09.04/B1; implementation remains B2.
- Reviewed: 2026-10-07 08:37:00 (America/Chicago).
- Owner: standalone synthetic evaluator; Runtime retains execution acceptance.
- Inputs reviewed: synthetic_objectives README, public package manifest, owned
  kernel/CLI tests and fixtures, public EvaluationRequest/EvaluationObservation contracts.
- Original private kernel/adapter implementation is not a reconstruction input.

Reconstruct the evaluator in a separate package directory with a new immutable release
and independently built Linux image. Preserve the original package/image/configuration
for old pinned campaigns. Do not copy the original private kernel, import the search
owner or change peer implementations to accommodate the replacement. Public schemas,
SDK mechanisms, descriptor/policy artifacts and acceptance fixtures may be reused.

The two named Artifact inputs are parameters and policy. Parameters validate as the
public EvaluationRequest; policy must be the actual declared Artifact identity and the
exact fixed synthetic-quadratic-v1 policy bytes/schema/size. Requests must bind the
new evaluator tool/version/image, proposed candidate, ev- candidate-derived identity,
1..32 finite dimensionless genes within [-1000000,1000000], unique supported objectives,
and no undeclared context. Preserve objective order and subset semantics.

The independent arithmetic oracle is cost=sum(x*x), distance=sum((x-1)*(x-1)). For
[1,-2], cost=5 and distance=9. No hard constraints: violation exactly zero; quality
synthetic. EvaluationObservation preserves request scope/identity, canonical request
digest and the actual policy reference. No scientific promotion, real measurement,
molecular model, synthesis or laboratory behavior is introduced.

Pure/domain objects own input applicability, policy binding and arithmetic. Boundary
Pydantic records validate/serialize requests and observations. The adapter owns one
image binding, bounded input and named safe errors. No SQL, network or execution
authority in the kernel. Worker calls use the existing public multi-input SDK, Runtime
claim/fencing and Data provisional publication contracts.

Public CLI parity: describe with explicit image digest, schema by input/output/policy,
policy canonical bytes, offline compute with policy file, and configured worker entry.
Successful compute emits exact canonical bytes without trailing newline. Malformed
input exits2, no stdout/payload leak, and the existing closed safe error. Rebinding a
worker to another image rejects. Payload size caps remain explicit in the descriptor.

Acceptance layers:

1. Original arithmetic/schema/order/policy/image/applicability rejection fixtures against
   the rebuilt implementation; include boundary and malformed values independently.
2. Fresh wheel/environment with only declared public dependencies, no original evaluator
   or search implementation. Rebuilt image runs nonroot/offline golden and worker probes.
3. Separately restored Runtime/Data/Registry peers register/select the new immutable
   release, then execute a new synthetic campaign between campaigns. Original graph,
   evaluator observations, receipts and artifact hashes remain byte-exact.
4. Wrong version/image/policy and stale worker results remain ineligible. No numeric
   result is silently relabeled under the new identity. Existing source installation
   remains intact; measured replacement evidence includes clean worker/API drain.

Module tests remain beside the rebuilt tool with kernel/CLI/worker scopes and registry
registration in dev/test_scopes.json. The source-adjacent README must capture this
actual boundary, rejection behavior, state ownership and replacement verification.
No credit for merely rebuilding an unchanged wheel or reusing the private kernel.
