## Assessment identity and authority

An assessment selects an exact ResearchQuestion revision, its candidate answer artifacts, a predeclared policy revision and exact EvidenceNeed revisions. Each criterion maps to one answer artifact. The answer artifact pins the Knowledge result and therefore its exact assertion revisions; the Research wire must not import Knowledge DTOs, because Knowledge contracts already depend on Research contracts. The Research implementation may consume public Knowledge DTOs through an explicit package dependency.

The immutable policy binds every criterion to at least one evidence need, acceptable evidence categories and trusted receipt issuers. Each need already pins method and required context. No implicit latest revision, empty requirement set, description-to-policy guessing, confidence threshold or category ranking may grant eligibility. Opinion, simulation, observation and independent replication are distinct labels. Independence/control validation is a producer responsibility that must be attested, not inferred from several receipts or different identifiers.

The initial profile has **synthetic authority only**. A supported answer, evidence sufficiency for this exact configured decision and scientific establishment are distinct outputs. Even a fully satisfied synthetic assessment never establishes a scientific claim and must not satisfy a scientific-purpose Runtime wait. Actual laboratory observation eligibility belongs to BP-06.04.

## Focused objects and algorithm

`AssessmentPolicy` owns an exact question, purpose, version and bounded need requirements. It validates complete criterion coverage and one definition per need, with a deterministic content fingerprint. `CandidateAnswer` identifies one criterion's immutable answer artifact and the logical disposition obtained from Knowledge. `EvidenceObservation` is a private adapter projection of an authenticated owner receipt, including exact need, answer subject, method, context, category, issuer, purpose and support/contradiction. Neither is a public caller attestation endpoint.

For each requirement, inspect only receipts naming its exact need revision. Match scope, the full answer ArtifactRef, exact method and context, configured category and issuer, and authority. Record matched supporting and contradicting receipt references separately; mismatches remain explicit rejected observations. Supporting and contradicting evidence together is a conflict, never a majority vote. Unknown evidence cannot satisfy a need. Duplicate receipt identity, including identity reuse with changed bytes, is an error rather than extra evidence. Limits:32 answers,128 needs,256 observations.

An explicit gap identifies the remaining need and why it remains unmet: missing answer, logical contradiction/unknown, no matching evidence, evidence contradiction or conflict. `answered` means every criterion has an answer artifact; it says nothing about sufficiency. Overall disposition is unknown for conflict, contradicted for an unopposed negative answer/evidence, unknown for other gaps and supported only when every requirement is satisfied. Return all need decisions and rejected-receipt reasons so a planner can choose the next bounded experiment without parsing prose. Deterministic ordering follows the pinned policy, not incoming evidence order.

## Durable and public boundary

Implemented additive Research request/profile/result DTOs with a compatibility check against all predecessor schema bytes. Request identities bind authenticated actor/scope, question revision, policy digest, answer and receipt references. Public input contains references, never trusted verdict/category fields. Configuration installs reviewed profiles; campaigns cannot manufacture issuer trust. Public Data reads verify exact immutable bytes and current authorization; public Knowledge results/owner receipts must establish their issuer and subject before private projections are built. A caller-uploaded JSON blob that resembles a receipt is insufficient. Unknown network outcomes stay retryable, not missing-evidence verdicts.

Research persists the selected request, canonical policy, resolved immutable input observations and terminal assessment in its own schema. Applied research_0001/0002 remain unchanged; use forward migrations with append-only history and least-privilege grants. No peer I/O inside SQL transactions. Freeze exact inputs once observed, reconcile same request identity after uncertain commits, and reject changed requests rather than silently reevaluate them. Terminal assessment plus Research receipt commit atomically before HTTP success. A correction creates a new assessment/receipt identity with explicit supersession; old campaign history stays pinned.

An assessment artifact, if required for Runtime ArtifactConstant output, uses the existing derived-publication SDK protocol and retains stable command identities across ambiguous external effects. Reuse public protocol, not Knowledge's private publication implementation. Research owns its own journal and recovery. Public routes require explicit assessment actions, exact actor/scope and bounded JSON. Existing identity-only grants do not gain assessment or publication authority.

## B1.08 bounded storage design

Use forward research_0003 with two append-only tables: assessment_intents pins the authenticated actor, canonical request and full configured profile; assessment_decisions pins the resolved input references and complete assessment. Both share the scoped assessment identity; decisions require an existing intent. Only SELECT/INSERT are granted to research_service. No update, delete or peer SQL is needed. A scoped transaction advisory lock serializes same-identity operations; different actor/request/profile bytes conflict. Read checks the original actor. Service credentials remain trusted infrastructure, not tenant-specific database authorization.

The private AssessmentStore registers intent before resolution and records a validated ResolvedAssessment after resolution. It does no network I/O. A pending intent survives resolution failure; retries reconcile the original identity. First committed decision wins; identical canonical replay succeeds and differing decisions conflict. Every required/request input must be present, scope must match, artifact IDs must be unique, and at most128 inputs may be retained. Input order is normalized; request/profile array order remains significant. Store limits are2MiB for the combined intent and8MiB for the decision; exceeding either fails closed without truncation. These are private record encodings, not changes to command profiles.

This freezes successfully resolved inputs and the decision together, not partially completed network attempts. Interrupted precommit resolution may retry immutable references under current authorization. Committed decisions are read/replayed without reevaluation; later publication rechecks current Data rights. B1.09 owns the publication journal and atomic artifact/receipt terminal; B1.10 owns public authorization/routes. B1.08 verification covers actual PostgreSQL migration/repeat upgrade, service-role denials, actor/scope isolation, conflicting/concurrent replay, insertion rollback, bounds and replacement reads.

## B1.09 publication implementation boundary

Research owns one immutable publication per scoped assessment identity. The original actor selects a stored completed decision; caller payloads cannot replace its bytes, inputs or receipt authority. An AssessmentArtifact fixes canonical EvidenceAssessment bytes, their self-contained validation schema, retained input references and a transformation digest binding the entire configured profile. SyntheticReceiptPolicy has the fixed purpose research.synthetic_sufficiency; supported and sufficient accepts, contradicted rejects, unresolved/gapped decisions abstain. Never derive receipt authority from caller-requested purpose.

Before Data effects, retain publisher/issuer, payload/schema/declaration identity and stable begin/finalize command IDs in an owner journal. Forward research_0004 will grant history SELECT/INSERT only, with separately mutable DB-clock lease/fence state. Every transition verifies current fence/position; no database lock spans peer I/O. Use the public SDK for receipt-first begin/finalize. Persist streaming before PUT; uncertain streams require a bounded new upload attempt, retaining old history. Finalizing cannot be replaced: reconcile its original command. Final derivation and receipt commit in one immutable owner event. Replay reads stored decisions and terminal output without reevaluation; publication checks current Data access and downstream use remains independently authorized. B1.10 supplies public authentication/routes; B3 supplies Runtime consumption.
