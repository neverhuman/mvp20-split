## Ordered B1.07 work

1. Intake durability: actor/scope/request/full-profile intent before peer resolution; atomic observation batch and reconciliation terminal after peer I/O. Exact retries preserve original committed outcomes. A conflict in any observation rolls back all new observation writes and the terminal. Acquire observation locks in stable identity order after the intake lock; no network operation occurs inside the transaction.
2. Scientific decisions and impacts: persist exact purpose/policy/context and consumed observation/model/route evidence for eligibility and synthesis decisions. Index owned dependencies and explicitly registered immutable consumer Artifacts. Corrections expose affected identities for future-campaign reevaluation without rewriting old decisions, fitness or active pins. No global consumer discovery or arbitrary caller verdict ingestion.
3. Artifact publication: publish bounded immutable scientific result documents through Data's public Artifact/derivation contracts with stable commands and recoverable effects. This boundary publishes evidence documents, not new Runtime DomainReceipt authority. The existing fixed research.synthetic_sufficiency receipt must not be repurposed. BP-06.06 owns subsequent feedback/receipt integration; B2 owns measurement normalization and correction-policy integration.

These are three equally weighted implementation slices within the existing B1.07 milestone, not new parent gates. Intake durability is complete100%; decisions/impacts and publication remain0%. No slice alone closes B1.07. B1.08 remains the public authenticated API/isolated workflow gate.

## Intake identity and replay

A reference-only LabIntakeRequest pins an intake identity, full-profile digest/reference and exact report Artifact. The configured profile comes from reviewed service configuration. The intent persists that full configuration with the authenticated actor and scope. A changed request, actor or profile cannot reuse an existing intake identity. Source-result identity remains in exact ObservationRevision references; source repeats cannot mutate those records.

Read/terminal replay uses persisted intent and terminal bytes, not whatever configuration or source happens to be current. The stored outcome distinguishes pending, resolved and explicit operational failure; failure is not negative scientific evidence. Transient source outages leave the same intent retryable. Public source disclosure and grants remain an adapter responsibility in B1.08; no private store method authenticates a network caller.

Resolved intake persists the reconciliation plus complete consumed Artifact set with the observation revisions in one owner transaction. The original report source is attached by the authenticated resolver, never supplied as a self-hash inside its own payload. Required raw/protocol/applicability sources remain exact. Batch byte limits are checked before opening the transaction; no truncation or peer read under locks. A separately rebuilt owner must recover identical historical outcomes and original attribution.

## Explicit limits

The current profiles are synthetic. Software storage/authentication does not establish scientific validity, assay quality or universal synthesis feasibility. Weak or missing optional evidence remains inspectable and usable for exploration under declared policy. Only a named action's explicit prerequisites govern that action. Corrections apply to future campaigns only; rights/security remain a separate authority.
