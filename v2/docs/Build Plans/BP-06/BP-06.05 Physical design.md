## Scope and module boundaries

The initial implementation proves deterministic synthetic encoding, reuse, rights isolation and index publication/retrieval. It does not select a useful scientific encoder, train a model, equate vector similarity with truth, or add live campaign corrections. Real embedding tools remain graph capabilities; the reviewed local fixture encoder demonstrates the catalog/consistency boundary without claiming a deployed provider or graph worker.

| Focused module | Owns | Excludes |
|---|---|---|
| Data representations | Complete profiles, exact encoded input/vector identities, scoped single-flight work, immutable vector cache and attributable source bindings | Source rights policy, scientific eligibility, Knowledge truth, Runtime scheduling |
| Data retrieval | Corpus manifests, index generations, expected-head publication, adapter protocol, scoped retrieval records and current-use filtering | Canonical source/vector storage, unreviewed profile pairing, scientific ranking quality |
| Data existing source_rights | Current read/process authorization and final owner fences through source/derived lineage | Scientific correction selection or representation compatibility |
| Public contracts/representations | Versioned reference-only requests, profiles, bindings, generation/retrieval projections and examples | Domain behavior, database or backend clients |

New source modules and tests remain under the Data owner, with separate READMEs and selectors. Public representation contracts form a focused package depending only on public core/artifact/evidence contracts; existing schema bytes remain unchanged. No sibling implementation imports or peer SQL. Do not extend a catch-all API file with business logic: focused representation/retrieval adapters register bounded routes.

## Complete profiles and initial deterministic encoder

A profile is composed from focused value objects: encoder identity/revision/implementation digest, input recipe, output space and declared applicability/limitations. The recipe pins modality, task, query/document/shared role, tokenizer, preprocessing, chunking, truncation, pooling, input template and instructions. Every result-affecting choice participates in a canonical versioned digest; mutable deployment labels do not define compatibility. Registry scope is separate from semantic profile identity.

The first fixture is strict UTF-8 byte-histogram encoding:16 bins, each byte contributes to bin byte modulo16; no text normalization, tokenization, chunking, truncation or hidden instruction. Input is1..65536 bytes, valid UTF-8; source span ordering/bounds/hash are independently checked. Counts are encoded as finite IEEE754 binary32 in explicit little-endian order. The fixture supports declared none or L2 normalization; a changed normalization has a different profile identity. L2 arithmetic and rounding are pinned to the fixture implementation/version and evaluated against known fixtures; it is not a cross-provider reproducibility guarantee. Empty input and nonfinite/overflowed output fail explicitly. Original input bytes/hash and exact source span remain attributable.

The general value objects bound dimensions1..4096 and validate numeric representation/metric/normalization choices. Unsupported encoder configurations remain unavailable rather than silently falling back to the fixture. The initial comparison policy permits an explicitly symmetric shared-role profile compared with itself only. Equal dimensions, model aliases or similar profile names grant nothing; asymmetric/cross-space pairing requires a later separately versioned evaluated declaration.

Vector payload identity uses canonical binary32 bytes plus the complete profile/input/context identities. Artifact payloads carry the profile and exact vector encoding, not ambiguous native float serialization. Public requests reference source/profile records; they cannot supply trusted vectors or backend scores. Query requests also pin their exact input and generation. Similarity scores are bounded finite outputs of a declared metric, not confidence percentages.

## Computation reuse versus provenance and permission

Use two separate identities. Encoding work/cache identity includes scope, complete profile, exact encoded bytes hash and any declared context digest. A binding additionally identifies the source revision/span, preprocessing lineage and source-specific vector Artifact. Identical bytes under different profiles or contexts cannot share work; identical authorized bytes under distinct sources may reuse the computed vector inside the same scope without merging provenance.

The reusable internal vector cache is private and cannot be fetched as an unassociated public Artifact. Each distinct source binding publishes its own derived Artifact using the existing declared-input/finalization protocol. Its lineage contains that binding's actual source, so existing ArtifactReads rights traversal protects direct reads as well as retrieval. Concurrent identical binding requests converge on one published Artifact; independent workflows can reuse that same binding/Artifact. Equal-content bindings with different sources share encoding computation, while retaining separate Artifact identities and rights. Do not combine unrelated sources into one all-ancestors rights chain or infer permission from a content hash.

The initial retention profile remains retain_audit_payload. Revocation stops new consumption before physical index cleanup; retained private bytes and audit metadata are not new-use authority. Mandatory payload-erasure licenses remain unsupported and must not be admitted. No global cache-hit/existence or cross-tenant deduplication API is exposed.

## Encoding persistence and publication

The B1.02 wire boundary will separate the complete profile document from its scoped registry reference. Component DTOs mirror encoder identity, input recipe, pipeline and vector space; a Data mapper validates them into the existing behavior-owning objects before computing a digest. A profile reference includes scope, profile id/version and digest. A source-binding request contains an idempotency identifier, the scoped profile reference and an exact source byte span. The initial fixture has no context input and only supports the declared identity preprocessing pipeline; unsupported configurations remain unavailable. Public callers cannot submit a vector or claim a cache hit.

The retained vector Artifact document contains the complete profile reference, input/context digests, declared vector encoding, dimension and canonical payload bytes encoded as hexadecimal. Its digest is computed from the canonical document; a raw vector digest alone is not a complete representation identity. A binding projection links source span and profile to that Artifact. Pending/published status retains the original request and actor; a published status requires its binding, while a pending status cannot expose a result. Domain mappers verify scope, digest, source span and result consistency rather than treating DTO validation as authorization. Generation/retrieval DTOs follow their owned transitions under B2; schema publication remains additive and preserves existing bytes.

Register immutable reviewed profiles. A reference-only encoding request pins actor, source/span, profile and complete input identity before compute. Validate source content and process rights using existing owner readers/fences. Acquire a bounded DB-clock lease/fence for one scoped work key; compute with no SQL transaction or rights lock held. Completion verifies lease/profile/input/output identities and atomically publishes the immutable cache result. An expired worker cannot replace a newer result. A lost reply replays the accepted outcome; changed inputs under an id conflict.

Source-binding publication has its own pinned request and stable existing upload/finalize commands. Reuse the Data owner's declared transformation and rights fences; never expose a binding before its exact derived Artifact and attribution are verified. No new numeric command profile is needed: vectors are Artifact content and commands carry existing descriptors/references. Record input/cache/publication outcomes separately so a failed binding does not poison reusable authorized computation. Current source rights are checked again when binding becomes visible. Short owner transactions only; no network/filesystem work under a SQL lock.

Forward artifact_0008-or-later migrations introduce only Data-owned representation/index tables. Exact migration decomposition is finalized before the storage milestone; immutable history has SELECT/INSERT grants, narrow mutable leases/heads have explicit columns. Serving never migrates. Older Data owners cannot be rollback targets after new state becomes active unless explicitly compatible.

### B1.03 bounded storage layout

`artifact_0008` adds immutable encoding profiles keyed by scope/id/version, immutable work intents keyed by scoped complete work digest, immutable computed results and one mutable lease row per work intent. Scoped foreign keys connect only Data-owned records. Work rows retain the profile reference and exact input/context hashes, not source rights or raw source bytes. Result rows retain canonical vector documents and the winning actor/token/fence. The private cache is not a catalog Artifact or public route. Source-binding intents and current source rights remain B1.04 prerequisites for exposing reusable results.

The profile registry rejects a different canonical profile under the same id/version and verifies digest-qualified reads. Separate profile-management/read and encoding grants apply inside the owner; optional HTTP grants remain B1.05. A claim persists its complete intent before returning a random token, increasing fence and database-clock expiry. Concurrent claimants receive an explicit busy outcome until expiry; a committed result returns a cache-hit domain object. Equal input bytes under a different scope/profile/context have different work keys.

Completion validates its exact work/profile/input/context/vector identity and current actor/token/fence with unexpired DB time, then inserts an immutable result. Only the winning claim may replay its completion after expiry; a different or stale claimant cannot take credit for that result. Reading a committed result through a new authorized cache claim remains separate. Renewal cannot resurrect an expired lease. Release only expires the matching active lease and never removes intent/result history. All SQL sections use short ordered owner locks; encoding occurs after claim commit with no open SQL transaction. Tests must show independent-connection single flight, expiry/reclaim, stale completion/renewal/release rejection, lost-reply replay, profile conflicts, scope separation, immutable grants, migration idempotency and reconstruction from a fresh store instance. Actual process interruption remains B3.

### B1.04 source binding delivery sequence

Keep the existing B1.04 weight and divide its implementation into four equal bounded tasks: a) binding identity, vector publication document and receipt/content invariants; b) exact source preflight and durable request/binding state; c) recoverable derived-publication orchestration; d) actual Data rights/convergence/reconstruction tests. This is decomposition of existing scope, not additional parent credit. B1.05 owns hosted APIs; B1.06 owns installed HTTP integration; B3 owns process-death/race barriers.

Binding identity includes authenticated publisher actor as well as scope, exact profile and source span. Requests from the same actor with different encoding ids can converge on one binding/Artifact; a different actor can read/reference an existing permitted binding but does not impersonate its original publisher's commands. Separate actors initiating fresh bindings retain separate attributable publication histories. This preserves existing actor-scoped command semantics without introducing a hidden service principal. Computation reuse remains actor-independent within scope.

Before registering a new pending request, validate the complete request, known immutable source revision, raw Artifact reference, nonempty bounded byte span/hash, strict UTF-8, reviewed profile and current read/process rights. Retain the original request/actor and verified input identity before computation. Permanent malformed inputs fail before creating pending work. Transient failure after intent registration remains explicitly retryable; it does not create an unbounded synchronous polling loop or require human intervention. Existing published request replay is historical metadata; a new request or payload read needs current authorization.

Use stable binding-derived begin/finalize command ids with the original actor and exact declaration. The declared transformation digest pins the binding's source/profile recipe; inputs contain only that binding's actual source Artifact, never every source sharing the cache. Verify vector content, upload/declaration and finalized derivation identities before binding visibility. Rights lock precedes binding publication lock; never hold either across encoding, filesystem writes or an existing publication transaction. A persisted staged workflow, its own publication lease and existing upload generations fence duplicated publication attempts. Partial uploads are retained for the existing maintenance policy rather than deleting evidence. Later tasks must prove current-rights fences at admission and final binding visibility, and independent revocation of equal-byte source bindings.

An explicit existing Artifact command rejection is terminal for that command id, unlike a lost or pending response. Binding publication therefore needs a monotonically numbered publication attempt after a verified rejection. Attempt1 preserves the B1.04a command bytes; later attempts add a bounded deterministic suffix. Only a known terminal rejection can authorize a new attempt; absent/pending acknowledgements retain the original attempt and query/replay its exact commands. This avoids permanently poisoning a reusable binding because capacity or rights denied one publication attempt, while preventing duplicate publication after an uncertain success. Per-call work remains bounded; no automatic infinite retry loop is introduced.

For B1.04b, artifact_0009 introduces immutable binding jobs and actor-scoped encoding request aliases, an immutable typed publication-event journal, immutable final bindings and one narrowly mutable publication cursor/lease per job. Job identity pins profile, exact source and work digest before compute; the work cache may be populated later, so final binding checks require its actual result rather than inventing a forward cache foreign key. Request registration retains the observed admission rights epoch; new operations use fresh rights checks, not that historical epoch as a lasting permission. The journal pins commands/receipts before/after their effects, and a stage transition requires the current lease token/fence and exact expected predecessor. A fresh process resumes the retained prefix; no source payload is stored in the journal. Final visibility requires verified Data derivation/catalog identity and current rights inside the rights-before-binding commit lock order. Serving does not migrate; older Data migrators are incompatible with the new head.

## Index generations and publication

A corpus manifest pins an explicit ordered set of eligible source bindings and one compatible profile. Its content digest is the source watermark: it denotes exactly those revisions, not an invented global latest-source counter. Initial fixture corpus bound is256 bindings; reject overflow rather than truncate. A generation owns scope/id, manifest/profile, expected published head, state, backend namespace, verified vector/point manifest and build evidence.

Transitions are prepared -> building -> verified -> published, with explicit failed/abandoned outcomes. Build a fresh backend namespace; insert deterministic point IDs, wait for completion and verify exact point/vector/profile/manifest identities. Do not use a backend alias as the authoritative head. A final PostgreSQL transaction fences current rights/eligibility and expected head before publishing. Competing publishers cannot silently overwrite each other. A completed but unpublished backend collection is an orphan projection and can be rebuilt/cleaned explicitly; it is not visible corpus state. Readers pin a published generation; never fall through to another profile or partially built collection.

Scientific source corrections produce new bindings/generations for later campaign selection. They do not repin active campaigns or rewrite old retrieval records. Representation invalidation caused by an operationally invalid encoding prevents new use of that invalid derivative and retains history; it is distinct from advisory scientific quality. Rights revocation applies at every new read, including a pinned historical generation. Rebuilds reconcile intervening binding/rights changes against their explicit manifest before publication; original generations remain inspectable only as permitted.

## Backend and retrieval boundary

The initial adapter acceptance target is an isolated local Qdrant fixture, not a production cluster deployment. Before its milestone, pin the actual server image digest/API version and bounded loopback authentication/configuration. No JARVIS access is needed. Keep a narrow adapter protocol with create/upsert/read/query/delete-generation operations, strict response validation, deadlines/body limits and exact scope/generation namespace binding. A deterministic local oracle verifies the fixture; it is not a fallback that conceals an unavailable backend.

Official documentation reviewed for design: [collection metrics](https://qdrant.tech/documentation/concepts/collections/) describes automatic normalization for cosine collections; [point operations](https://qdrant.tech/documentation/manage-data/points/) distinguishes acknowledgement from searchable completion and documents wait=true/idempotent loading; [search](https://qdrant.tech/documentation/search/search/) documents exact search. Therefore the first fixture uses declared Dot space, explicit normalization in the encoder, completed writes and exact queries; it does not claim arbitrary ANN recall or silent backend normalization compatibility.

The broker obtains a bounded eligible binding set from authoritative PostgreSQL and current source rights before querying, uses that allow-set as a backend filter, and rechecks all selected bindings under the final owner rights fence before committing/exposing a response. The backend is not an authorization oracle. Rights changes during a query force a retry/denial, not a partial leaked response. No unauthorized snippets, vector/source IDs, scores or counts are exposed. Known caller-requested missing/denied inputs and an unavailable backend remain operational outcomes, not scientific negatives.

Retrieval records retain original actor/query/profile/generation, declared metric/filter/ranking policy, selected binding/source/vector revisions and finite scores. Stable tie order is by binding identity; fixture tests use a declared score tolerance and independent nearest-neighbor oracle. Historical records do not authorize fresh source content. Explicit review-state filters preserve source classifications without treating indexing as Knowledge promotion. No cross-space score fusion or implicit query/document pairing.

## B1.04c orchestration refinement

The synchronous owner workflow takes a bounded number of recovery steps per call and returns the retained pending/published status. It checks exact original-request replay before any source reread; only an exact already-published request may replay without source availability. Pending/new requests use fresh source preflight and rights, register intent before computation, claim or reuse the complete private cache, and independently claim publication. Busy compute/publication claims remain pending, never a false success or an unbounded sleep.

The executor reads a retained prefix, prepares the exact command, performs the owner Artifact operation outside journal transactions, then observes its actual retained outcome. A lost response leaves the original command available for inspection/replay. A retained rejection is recorded before returning its explicit operational error; the next authorized invocation may advance one numbered attempt. Normal completion requires all selected bytes and the final source-only derivation, followed by the final current-rights visibility fence. Writer closure precedes Uploads.finish; uncertain failures remain conservatively charged and cannot publish.

An unstarted, failed or abandoned upload must not strand a binding forever. Selected valid bytes are recovered first. A live outstanding stream is reported pending. An exhausted/abandoned upload needs an owner-proven disposition before a new publication attempt; merely not having observed streamed bytes is insufficient. Refine the narrow upload recovery projection and journal transition under c, preserving public commands and first-attempt bytes. Cleanup remains its existing explicit owner operation; representation execution must not acquire general deletion authority or delete source/finalized Artifacts.

Verification for c uses the actual Data source/cache/upload/finalizer/journal stack: normal completion, cache/publication contention, bounded pending, failures between effects and journal acknowledgement, writer failure settlement, repeated exact request and alias, and recovery from unavailable upload selection. Process-death barriers and broader adversarial race matrices remain B3; c does not borrow those claims from in-process reconstruction.


C recovery implementation detail: StreamRecovery owns actual upload inspection. It settles at most one expired stream per recovery step after obtaining the OS writer guard and fsyncing the existing no-new-writer marker. It does not unlink or refund bytes, and retains full unknown allocation. The narrow journal unavailable-upload path prepares the real final command only for owner-proven abandonment or exhausted attempts with no selected/live/unsettled stream; actual terminal rejection is still required for numbered retry. This preserves existing cleanup authority and avoids requiring a human reset after worker death.


## B1.05 HTTP and hosting boundary

Representations is an explicit boolean host option, disabled by default and independently usable with already-registered sources. Enabling it installs the reviewed vector content rule and probes its required owner tables, never migrates or registers a hidden profile/actor. Dedicated actions are representation_manage, representation_read and representation_encode; encoding also requires existing read/source_history/upload/finalize grants. Unknown/ill-typed configuration still fails closed.

A focused /v1/representations router exposes GET /available-profiles (currently the runtime-pinned synthetic fixture descriptor only), POST /profiles (explicit immutable registration), GET /profiles/{profile_id}/{version}?sha256=... (exact digest-qualified read), POST /encodings (bounded advancement,202 pending/200 published), GET /encodings/{encoding_id} (actor-specific original metadata), and GET /bindings/{binding_id} (scope-specific binding with current read rights). All use existing representation DTOs; no wire-v1 mutation. Arbitrary registered descriptors do not install encoder code or imply scientific validity. Runtime/profile revisions must be explicitly compatible; registration conflicts are not overwritten.

Authentication/action checks precede POST body consumption. JSON is bounded to65536 bytes and5s, with duplicate/nonfinite/nesting checks. Success responses are no-store; expected shape errors return422, immutable conflicts409, unavailable identities404, missing grants/current rights403, and owner storage failures503 without source bytes or credentials. Profile lookup requires the full caller-known digest. Binding reads authorize the derived Artifact ancestry inside the rights transaction before returning metadata; original encoding-status replay remains historical metadata and does not confer fresh content rights. POST is the operation that advances pending work; status GET has no effects.

B1.05 verification uses TestClient with actual Data/PG state, enabled/disabled host configuration, route grants before malformed bodies, exact scope/digest isolation, pending/completed status, profile conflicts, current binding rights and offline history. B1.06 separately starts the independently installed actual HTTP process and proves public-only reconstruction/replacement. No in-process HTTP result is claimed as that later gate.


## B1.06 installed HTTP proof

The fixture launches the isolated Data package as its actual CLI server with explicit credentials/configuration, acquisition and representations enabled, no private Research/Knowledge/Runtime implementation installed, and no migration on startup. All preparation and assertions use public HTTP: raw Artifact upload/stream/finalize, source rights, acquisition prepare (retaining the source revision), available-profile discovery/registration, encoding, status, binding and vector content. The known ABBA span yields the independently specified16-bin binary32 fixture with exactly2 in bins1 and2; this is a protocol oracle, not a semantic similarity claim.

Terminate the first server cleanly and replace it with a fresh process using the retained owner database/storage and isolated package. Exact request/status/binding/vector references must survive; another request alias must resolve to the original binding. Revoke the source policy through the public route: new binding/content use and a new alias must be denied, while the exact historical encoding status/POST remains unchanged. A separately configured scope cannot read the binding. Record actual scope/profile/source/binding/Artifact identities, process checkpoint and statuses without credentials.

This gate proves actual installed HTTP reconstruction and authority. It does not replace B3 abrupt process-death/race barriers, Qdrant acceptance or V1 final module replacement/audit. The bounded local server remains a synthetic fixture and is not a deployment onto the target research host.


## B2.01 bounded decomposition and authority

Keep the existing B2.01 weight and split it into four equal tasks: a) pure ordered manifest/generation/build-attempt identities and transition policy; b) additive public generation DTOs/mappings; c) private generation intents/events/build leases and forward schema; d) owned projection verification and expected-head/current-rights publication with actual PostgreSQL tests. B2.02 supplies the actual Qdrant adapter proof. B2.04's generation migration means integrated profile/index-generation migration and API proof; prerequisite private SQL schema lands with c. No scope/denominator changes.

The manifest contains1..256 distinct binding identities in explicit order and one exact shared-role profile. Its digest is the watermark, pinning full binding/source/vector revisions. Full canonical manifest encoding has a separate4MiB ceiling; do not reuse the64KiB per-profile/command helper for256 complete bindings. Generation identity additionally pins corpus id, generation id, authenticated owner actor, expected prior published head and trusted backend-profile reference. A prior head must belong to the same scope/corpus and cannot name the new generation itself. Public requests cannot provide trusted vectors or backend success certificates.

Each build claim receives a distinct token/fence-derived backend namespace. A stale worker can only mutate its orphan namespace, never the winning/published namespace. Deterministic point IDs are derived from complete binding identity and checked for uniqueness. The owned verifier compares an exact bounded backend point/profile/vector manifest against source-bound Artifact bytes; any omitted/extra/mismatched point fails. A test-only adapter port may establish lifecycle policy, but only B2.02 may claim actual Qdrant behavior; no production fallback backend is introduced. Final PG publication requires the winning claim, retained exact verification, current source rights and expected-head CAS. Failed/abandoned/published histories remain immutable.
