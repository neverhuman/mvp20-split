## Finding and reproducible evidence

Knowledge0.8.0 can persist a derivation result after fresh public provenance checks. To hand that result to Research/Runtime it must become a Data artifact. Ordinary publication accepts content descriptors and bytes; it does not take transformation inputs. Existing Data ancestry follows registered source raw artifacts and retained conversion traces. It deliberately does not infer lineage from equal content hashes.

[Actual PostgreSQL probe](../../Audits/Evidence/BP-06-Knowledge/Derived_Publication_Gap.json) publishes a retained converted output and a separate equal-byte ordinary artifact. After revoking the source, the retained output is denied and the unassociated copy remains readable. This is expected legacy identity behavior, not evidence that existing registered conversion lineage is broken. It means ordinary finalize is insufficient for the new derivation path. The probe is owned by `services/data_artifacts/tests/source_rights/test_enforcement.py::test_unassociated_publication_does_not_infer_source_lineage_from_equal_bytes`.

Relevant boundaries: [source rights](../../../services/data_artifacts/src/amphora_data_artifacts/source_rights/README.md), [publication](../../../services/data_artifacts/src/amphora_data_artifacts/publication/README.md), [maintenance](../../../services/data_artifacts/src/amphora_data_artifacts/maintenance/README.md). Finalized content is currently retained; cleanup only retires provisional uploads. Runtime protective reservations still apply when a wait accepts an artifact. Neither retention nor a matching hash supplies missing derivation ancestry.

## Recommended decision

Add a separate versioned **derived publication** path owned by Data. Register exact transformation inputs with the upload, then commit the output's catalog identity and immutable derivation edges in the same finalization transaction. Ordinary unassociated uploads keep their current semantics. Knowledge and later scientific tools consume the same public interface; no owner may write Data tables directly.

This changes a public owner protocol and adds a prerequisite to the B1 implementation order. It is distinct from merely wiring the already accepted upload API. [AGENTS](../../../AGENTS.md) requires owner direction for material scope/sequence changes. Approval authorizes this bounded extension, not live data licensing decisions or a general-purpose workflow engine inside Data.

## Proposed physical boundary

1. Add bounded public DTOs for a derivation declaration, begin-derived-upload command and immutable derivation receipt. A declaration names exact scoped input ArtifactRefs and a pinned transformation descriptor. Data checks shape, input identity, access and lineage; it does not evaluate scientific rules or certify that the producer's claims are scientifically correct. No caller-supplied rights override is accepted.
2. A new command family/route registers a derived upload. Preserve every existing family, canonical encoding profile, receipt and schema byte. The declaration is immutable and bound to authenticated actor, command identity and upload in the begin transaction. Capture current input processing permission. Conflicting retries fail; exact retries reconcile the original receipt.
3. Once an upload is declared derived, every finalization entry point consults its immutable declaration. The ordinary finalization route cannot strip that declaration. Capture rights before byte/schema verification outside SQL; recheck rights and selection/generation before committing catalog, derivation edges, terminal receipt and audit atomically. No interval exposes a finalized derived artifact without its ancestry.
4. Extend Data-owned ancestry traversal to include these exact edges. All input ancestry must permit current use; no averaging, strongest-source selection or rights inference from a digest. Bound direct inputs (proposed128), visited artifacts (proposed4096) and distinct rights bindings (existing256); overflow fails closed. Preserve scoped graph traversal and cycle handling. Input metadata can remain inspectable under existing audit permissions; payload consumption rechecks current rights and expiry.
5. Use a forward migration after artifact_0006, provisionally artifact_0007. Keep existing migrations immutable. New upload declarations and finalized lineage are append-only. Explicitly enforce owner lock order: source-rights scope before capacity/upload/attempt/terminal-command locks. No filesystem or peer HTTP I/O occurs under these locks. Review all affected finalization paths for inverse ordering.
6. Expose immutable derivation metadata over a scoped read endpoint. Add a public SDK operation for the new begin command; reuse bounded stream/finalize transport and receipt reconciliation. Stable identities survive ambiguous begin/finalize responses. An uncertain PUT is not automatically streamed again or treated as finalized; recovery records a bounded new upload attempt when needed rather than hiding uncertainty under a new command ID.
7. Knowledge publication binds canonical ReasoningResult bytes, its exact schema and original input artifacts to the derived upload. Its owner receipt is published only after verified Data finalization. Runtime retains execution acceptance and its existing reservation handshake. Research independently assesses sufficiency and current-use eligibility. No service gains another owner's write authority.

## Rejected shortcuts and return point

Do not publish a readable unassociated derivation and attach ancestry later. Do not teach Data to parse Knowledge-specific result bodies to guess inputs. Do not treat copied rights flags, equal hashes or a Knowledge database record as Data's authoritative lineage. Reusing the document/lab conversion-retention route is also insufficient: it validates its reviewed converter/output profile and does not describe arbitrary multi-input transformations.

After D1-D4, resume BP-06.03/B1 at Knowledge derivation publication and durable domain receipts, then Research assessment and the Runtime wait integration. B2/B3/V1 retain their current exits. Independent Knowledge replacement, scientific validity, mandatory erasure, real source licenses, live model evaluation and target-host deployment are not accepted by this prerequisite.
