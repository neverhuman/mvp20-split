## Authenticated workflow

Use a focused interpretation API module rather than expanding the scientific input/decision workflow into a common backend. Public requests retain the existing normalization/use shapes. Add an explicit pending/interpreted status with original actor/request and a typed projection; pending source or storage failure cannot become an unresolved scientific result. Status reads and completed submit replay use stored immutable history without Data I/O or current-profile lookup.

For new work, select an exact reviewed scoped profile and persist its complete intent before external work. Pending retry uses that stored profile even if removed from current configuration. Prepare exact owned observations/experiment and their complete explicit source dependencies using the interpretation store. A fresh bounded AssessmentDataReader for each attempt authenticates current content/rights for every required Artifact. No transaction spans those calls; no cached authorization crosses attempts. Only then complete the policy computation and atomically persist result/indexes. Missing source, peer outage and denied access remain explicit operational outcomes. Source authentication is not scientific validation.

Source/raw-report producer checks remain the existing authenticated lab/scientific intake boundary. Interpretation may only consume stored owner revisions and must not accept a caller-supplied observation, material context, value or verdict. Private fixture declarations do not become a public laboratory write authority.

## Hosting and grants

Compose optional reviewed normalization/use profiles with the existing optional science host while preserving old configuration compatibility. Keep bounded profile counts, environment-referenced credentials, loopback validation, startup table checks without migrations, bounded strict JSON and no-store responses. Add focused normalization/use submit and interpretation read grants; reuse explicit scientific record/impact read grants for exact correction/material impact views only where their scope matches. New interpretation impact reads need an explicit scoped grant. Possession of a read grant does not allow source consumption or writing a correction.

Exact correction reads take a stored successor reference and return its immediate predecessor plus changed fields. Material and interpretation impact requests use their new DTOs; old scientific impact schemas remain unchanged. Neither operation selects current heads, discovers global consumers, changes fitness or repins active campaigns. No new Artifact publication or DomainReceipt authority is added.

## Actual transition proof

Use independent Data and Research HTTP owners with owner-local fixture bootstrap. Demonstrate original observation intake, normalization and exploratory use with quality focus, immutable interpretation reads, corrected observation intake, exact before/after view and impacts, then a separate interpretation explicitly selecting the corrected revision. An interpretation accepted before correction still consumes its original pin. Failed controls/low accuracy may remain usable under an exploratory profile; an explicit strict action policy can exclude only that action's use.

Verify scope/action denials, malformed/excess bodies, current source denial/outage without invented scientific verdicts, zero-current-profile historical replay, and pending retry under its original configuration. Replace the Research process/package with Data offline for historical replay, then restore the peer for pending work. State precisely which tests are scripted, owner-local, installed or actual independent HTTP. B3/V1 retain process-barrier crash/failure audits and physical/scientific claims remain unproven.
