## Exact scope and ownership

Research owns specimen and property projections. An exact ExperimentRevisionRef supplies the immutable protocol, specimen inventory and declared expectations. No view follows the newest experiment, material, sample or observation revision. A property query additionally pins an explicit ordered set of up to128 exact observation revisions; it describes that selected evidence set, never all observations in the project. Callers obtain these references from accepted lab intake/campaign provenance. Project-wide discovery is not inferred from this bounded inspection capability.

Specimen pages enumerate the experiment's retained samples in their declared order (maximum256). Each row preserves the complete SampleIdentity and compact material metadata: exact state/candidate/supersedes references, preparation count and feature count. Missing material state remains null. Full preparation/features stay available through the existing exact material read. Different sample or prepared-state identities never merge because their nominal candidate matches.

Property pages retain original observation identity/supersedes, source, reported binding, quality and value semantics. They also expose the selected experiment protocol and, where its declared experiment/expectation IDs identify an exact expectation, that expectation. This is a declared context link, not laboratory reconciliation, eligibility or scientific acceptance. Different-experiment, unbound and unknown-expectation claims remain explicit rows; none is silently dropped. Failed controls and unknown/contradictory values stay useful evidence. Do not invent timestamps or sort equal-time data into a synthetic chronology; selected observation order and original series point order are authoritative for this view.

## Measurement boundaries

Numeric/categorical/censored/missing scalar values retain their original public DTOs without conversion, averaging, imputation or decimal spelling changes. Series rows carry exact x/y units and total point count rather than a lossy scalar preview. A separate exact ObservationSeriesRequest pages the original series by point offset, at most256 points per response, retaining original quantities, censoring, uncertainty, duplicate x values and missing ordinates. A scalar observation is a conflict for that route, not a fabricated one-point series.

Existing normalization/use interpretation and impact/correction APIs remain separately selectable exact provenance. These views do not rerun interpretation, accept caller-supplied normalized values or invent a universal model-evidence score. Material feature evidence and interpretation artifacts remain inspected through their existing owner records.

## Query identity, bounds and availability

Specimen/property pages have1..16 rows; series1..256 points. Typed continuation binds the complete query (including experiment, ordered exact observations and page size), view version and offset. Revisions and current read_scientific_record grants are checked on every request. Offset is not authority. Complete responses must fit1MiB; oversized output fails explicitly. Existing256KiB request transport applies. No shared state, new migration or peer source-byte read is required.

Every selected observation must exist before any property page is returned. The owner validates existence using bounded metadata reads of its immutable revision journal, then loads only the selected page's records. Missing selected input returns unavailable, not a scientific missing measurement or a partial success whose meaning could later change. Exact revision records are append-only; new corrections do not affect already selected pages. Record/schema/domain corruption is an owner failure. No unbounded table scan or mutable latest-head watermark defines pagination.

Capabilities identify the exact experiment, three reviewed view versions (specimens, properties, observation_series), serialization schema pins and fixed limits. Descriptors carry no executable browser routes. Studio composes these owner capabilities separately from Runtime and Knowledge catalogs.
