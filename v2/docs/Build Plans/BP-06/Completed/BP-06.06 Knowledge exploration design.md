## Exact history semantics

The retained snapshot contains entity/assertion revisions, aliases and retractions. Reuse the owner's EntityHistory/AssertionHistory semantics; do not flatten them into latest labels. Search supports explicit current versus retained history. Current entity search means latest revision of each unmerged entity; retained search includes older and merged records with status. Active assertions are latest and not retracted. Retained assertion mode includes all revisions and their status.

Neighborhood focus is an exact EntityRevisionRef present in the requested snapshot. Traverse selected assertions as undirected adjacency for navigation only; retain actual subject/predicate/object direction and polarity in output. Radius0..2 defines the induced assertion neighborhood. Never rewrite an assertion endpoint to a newer context revision or alias target. A current assertion can legitimately reference an older entity context; return that exact endpoint and annotate its status. Alias targets remain explicit metadata, not automatic traversal or scientific equivalence. A focus with no selected assertions is an empty neighborhood observation, not scientific absence.

## Query and continuation identity

All queries pin an exact DomainRevisionRef and a literal versioned view. Search uses bounded case-sensitive literal substring over label/id, optional entity type, explicit history and page size1..50; no normalization, regular expression or arbitrary query language. Neighborhood uses exact focus, radius, history and independent entity1..64/assertion1..128 page limits. Canonical query fingerprint includes every result-affecting field and the view policy/version, excluding continuation position.

Typed continuation pins the exact query fingerprint and separate deterministic offsets into sorted entity/assertion rows. It is readable input, not an authorization token; the owner validates scope/grant, exact revision/hash, query fingerprint and offset bounds on every request. A continuation cannot retarget a query or grant graph access. Stable sorting is identifier then numeric revision. Neighborhood pagination advances each row lane independently and reports exact total counts for the selected authorized graph/query. Endpoints/alias targets not present in that response are explicit unresolved links; no fabricated nodes. Browser models must not mistake one page for a complete graph or accumulate without bounds.

## Summaries, detail and byte limits

Entity summaries contain exact ref, type/label, latest/current status and optional exact alias target; context Artifact is fetched in detail. Assertion summaries contain exact ref/endpoints/predicate, polarity/posture and latest/retracted status; full statement, applicability, grounding and question links remain selected detail. No scientific promotion or quality filtering occurs.

Exact object detail requests bind snapshot plus a discriminated entity/assertion ref. Return the retained public record and status metadata only after proving membership in that exact snapshot. Do not fetch source bytes as a side effect. Data independently authorizes and verifies the later source-span read.

Catalog/read results bind the exact snapshot, immutable view versions and published result schema identities. The catalog states reviewed limits, not arbitrary routes or caller-selected policy. Complete response serialization must fit1MiB; never silently truncate scientific detail to make it fit. Request transport keeps the owner's256KiB/5s bound. Summary/cardinality caps do not replace byte limits.

## Implementation and verification

Additive Knowledge contracts preserve all existing schema bytes. Public contract0.8.0 and Knowledge0.16.0 are proposed release targets; Research's exact Knowledge-contract dependency requires a dependency-only patch release and lock reconciliation, not a scientific behavior change. No persistence migration is required for pure projections or read-only routes.

Private Knowledge exploration module owns snapshot membership indexes, status policy, query fingerprints/continuations, bounded search/neighborhood/detail projections and DTO mappers. Validate snapshot identity/content hash and cross-record membership before deriving rows; malformed stored state is operational failure. Pure tests independently specify history/alias/retraction behavior, exact old endpoint contexts, stable pagination, radius, empty results, forged cursors, changed query/revision, bounds and detached response objects. Existing full snapshot/proposal/rebuild APIs remain intact.

B1.02b attaches focused read routes through existing authenticated Knowledge transport and exact ledger reads, verifies actual PostgreSQL scope/grants and immutable revision replay, then repeats against independent installation. No cache, new authoritative graph store, implicit head-following or cross-owner SQL is introduced.
