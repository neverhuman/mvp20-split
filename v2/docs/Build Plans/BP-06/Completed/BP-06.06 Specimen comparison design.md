# Prepared specimen comparison

Design status: bounded B2.04 implementation design, 2026-10-04. Owner: Studio scientific comparison and the cross-owner acceptance harness. Parent: [feedback integration](BP-06.06%20Feedback%20integration%20and%20closeout.md).

B2.04 comprises four equal substeps: a exact-context comparison model; b visible bounded comparison and prepared-state inspector; c actual two-specimen progression; d owner evidence/reuse acceptance proof. All start0%; design earns no implementation credit. Existing B2 weight is unchanged.

Compare actual Research specimen/property projections, retaining original selection order, values, units, censoring, missingness, uncertainty and quality. The old standalone Studio Measurement/PropertySeries shape requires a timestamp that these public records do not supply. Do not manufacture timestamps or flatten series to adapt it; use a focused projection over the actual published records.

Join a property row to a specimen only by exact SampleRevisionRef within the same pinned ExperimentRevisionRef. Material-state and candidate identity must agree across explicit records. A specimen outside the loaded window is unresolved, never inferred from a matching candidate label. Keep windows bounded and omission counts visible. Full preparation belongs to the existing exact Research material-state read; no new owner projection or migration is needed.

The view can compare exact sample, prepared state, method, applicability, readout and unit identities. It cannot establish physical equivalence, perform unit conversion, promote weak measurements or authorize cache reuse. Distinguish identical pinned evidence, known context differences and incomplete context. Quality flags stay visible; optional weaknesses do not become a global gate.

Research owns purpose-specific evidence eligibility, including exact candidate/state/sample/method/context. Data owns representation reuse by input/profile identity. A same nominal polymer cannot authorize reuse of a different prepared specimen's scientific result. The actual proof must exercise those owner boundaries with two explicit states and incompatible context, rather than treat a UI grouping key as a cache decision. Domain-specific equivalence or scientific validity is outside this synthetic demonstration.

Visible comparison uses one bounded table, two explicit selected observations, text-labeled differences and the existing linked inspector. Keyboard/narrow/long-label and actual-owner acceptance are distinct evidence tiers. B3 adds adverse races, scope/pagination and independent rebuild; B2.04 must first provide working ordinary comparison and owner rejection of mismatched context.
