## B3.02 durable interruption matrix

Use test-owned fault hosts around the production Research entrypoint, not production test switches or fake peers. Kill an actual process after intent commit, during the result transaction before commit, and after result commit before its reply. Cover authenticated lab intake and observation interpretation. After replacement, exact request replay must preserve the original actor/profile/input pin, observe pending versus committed truthfully, and create no duplicate observation revision or partial result/dependency membership.

The precommit kill must roll back every affected owner write; the postcommit lost reply must replay durable history with Data offline. Pending work requires fresh Data access when resumed. Named barriers and test identities must be recorded without credentials. These tests establish process-death/transaction behavior on the fixture PostgreSQL host, not host power-loss durability. Scientific Artifact publication already has its own lease/fence model and does not gain Runtime authority here.

### Defensive test oracles

- Inject an owner error before scientific result commit: return503, retain the accepted pending intent, then permit exact retry. Inject it after commit: the reply may fail, but history and replay must expose the already committed result unchanged.
- Stream an incomplete HTTP body through the configured ASGI route beyond its five-second deadline: return408/no-store and create no intent or result. This proves body handling independently of source-resolution failure.
- Let another publication worker commit between the initial read and lease acquisition: the acquiring workflow must reread and return that terminal, with no new peer effect.
- Inject a stalled publication-store adapter to exhaust the twelve-transition per-call budget: retain the last durable stage and command identity, release the lease, and permit a later healthy retry. This is a defensive adapter probe, not a claim that the normal finite state machine naturally loops twelve times.
- Fail lease release after a terminal commit: known lost-lease cleanup may be ignored; other cleanup failures surface, while committed publication bytes survive and replay without repeating the remote effect. Do not turn either path into a scientific negative.
