# BP-06.04 scientific API boundary

- Design status: B1.08 implementation boundary; reviewed `2026-10-03 02:35:00` (America/Chicago).
- Owner: Research. [Canonical child](BP-06.04%20Laboratory%20returns%20and%20candidate%20eligibility.md) owns credit; B1.01..07 are complete. Existing identity, assessment and sufficiency-publication APIs remain compatible.

## Ordered B1.08 slices

Four equal bounded slices split this milestone's existing weight: a public profiles/requests/input documents/status contracts and private configuration binding; b authenticated synthetic input resolution and pinned intent orchestration; c separately granted optional hosting/routes, exact historical reads, publication and explicit consumer registration; d independently installed actual-owner HTTP/replacement proof. Slices a/b/c/d are complete100%; no parent gate or denominator is added. Tests stay under each owning module, with a new scientific_api area for orchestration/transport. B2 normalization/correction policy integration and B3/V1 failure/replacement gates remain separate.

## Trusted configuration and reference-only submission

Lab intake uses the existing LabReturnProfile/LabProfileRef/LabIntakeRequest. Decision profiles pair a reviewed EligibilityProfile or SynthesisProfile with a named adapter and allowed publisher set. Full configuration is hashed into a scoped kind/id/version reference. A decision request names one stable decision identity and bounded immutable report Artifacts; it cannot supply policies, actors, claimed verdicts or observation values directly. Publisher/adapter proofs and current input rights are verified through Data before private policy evaluation.

Synthetic eligibility reports carry attributed claims with exact context/method/kind, optional observation reference and explicit disposition/flags. A source reference may name a distinct original evidence Artifact; absent source means the actual authenticated report Artifact, avoiding a self-referential hash. Synthetic synthesis reports carry route options and original route/step/search/check sources. Their publisher assertions remain synthetic evidence, not scientifically validated truth. All referenced external sources/context must be in declared lineage and pass authorized content reads. Exact observation/source and subject links remain enforced by the existing stores. Numeric interpretation and normalization are B2; no universal assay or synthesis policy is invented here.

Persist the actor/request/full-profile intent before resolving peers. Exact retries preserve identity. Completed results and historical reads use committed configuration/results, with no current-policy rerun. Pending accepted work retains its original pinned profile; current source authorization still governs new peer reads. Outages leave pending work retryable and never become scientific rejection. Existing old assessment behavior is not silently changed.

## Hosted surface and isolation

Optional science configuration composes lab, eligibility and synthesis profiles with loopback Data/read credentials and a publication principal. Secret values remain environment references. Read-only history hosting may have no active profiles. Default hosting remains unchanged, and startup checks required owner tables without migrating. Profiles cannot be added by incoming requests. Immutable candidate/sample/state/experiment fixtures are bootstrapped by owner setup for this bounded release; arbitrary public declaration writes are not added by a result submission endpoint.

Separate grants cover lab submit/read, eligibility submit, synthesis submit, scientific decision/record reads, scientific publication submit/read, impact reads and explicit consumer registration. Every operation verifies authenticated scope and original actor where the stored job/decision owns attribution. Read/publication selections identify exact immutable owner records and cannot supply replacement payloads or Runtime receipts. Scientific publication returns Artifact/DerivationReceipt only. Read-only publication lookup must not create intent, acquire a lease or call peers.

Consumer registration must verify the actual consumer Artifact's authenticated producer/derivation under reviewed publisher configuration and that its lineage includes the exact published decision Artifact. An ArtifactRef alone does not prove consumption. Register only explicit known consumers; bounded impact pages do not discover arbitrary external consumers or invalidate active campaigns. Current rights/security remain separate from future-only scientific corrections.

Reuse strict bounded JSON decoding, duplicate/nonfinite rejection, no-store responses and safe error mapping. Decompose scientific operations and routes into focused modules; do not expand the existing transport/api.py into a second monolith. Application composition remains a small hook. Peer I/O never occurs inside an owner SQL transaction.

## Acceptance and limits

Source/contract tests cover scope, actor, schema, producer/adapter, immutable identity and body bounds. Actual separately installed Research and Data prove reference-only submissions, useful partial/weak outcomes, publication, denied grants, replacement and historical replay with Data unavailable. Existing API/receipt schemas and command history remain unchanged. New source capabilities, physical labs, scientifically validated model outputs, live human intervention and a quality UI are not implied; SQ-01 remains the quality/iteration UI successor.

B1.08b must retain every authenticated consumed Artifact, including the producer report and raw/protocol provenance, even when a claim points at a separate original evidence source. Extend private decision preparation with an optional complete consumed-source set; default empty must preserve all existing decision bytes/digests. Public decision output already has the bounded sources field, so no DTO widening is needed. Pending source errors follow explicit API operational semantics and never become scientific ineligibility.
