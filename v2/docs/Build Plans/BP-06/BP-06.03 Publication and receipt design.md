## Owned objects and protocol

`ReasoningPublication` binds an immutable stored reasoning result, original scoped Knowledge actor, exact canonical result bytes/output schema, configured Data publisher identity and complete consumed-input declaration. Caller requests select a stored result; they cannot provide result bytes, provenance, owner observations or receipt outcomes. Historical reasoning decisions remain immutable. Publication always performs a fresh exact-snapshot provenance review, including for results computed before Knowledge0.9.0; older stored validation observations are not assumed to contain expanded trace/context inputs.

`PublicationAttempt` owns stable Data begin/finalize command IDs and provisional stream state. `PublicationLease` owns DB-clock expiry and a monotonic fence. `LogicalReceiptPolicy` maps a finalized derivation to a bounded Knowledge receipt. A focused owner store serializes transitions; neither the graph's DTO nor the SDK owns durable behavior. Keep the implementation under a focused Knowledge publication module with its own README/tests, rather than widening the reasoning evaluator or transport route handlers.

Public publication request/status DTOs are implemented without modifying the existing ReasoningStatus/ReferenceValidation schemas. Expose a scoped publication submission/read boundary. Receipts use the existing public DomainReceipt contract; choose no new cross-owner database or shared state. Public dependency direction must remain acyclic: Knowledge contracts may consume generic receipt contracts, but Research contracts must not import Knowledge contracts because Knowledge already consumes Research references. Research's new assessment wire should pin an immutable result artifact; its service verifies the public Knowledge result contents.

## Ordered state and recovery

1. Authenticate scoped publication authority and original result binding. Load the terminal evaluated result and restore its exact stored profile/snapshot. Review current public Data/Research provenance outside SQL, retaining all consumed artifact references. A pending/failed reasoning result cannot become a successful publication. Reasoning input expansion is bounded to128; no source is silently omitted to fit.
2. Persist immutable publication intent, payload identity and initial attempt before peer writes. knowledge_0004 now owns immutable selection and mutable lease tables; use the next forward migration for payload/attempt state. Existing migrations/decisions remain unchanged. Bind subsequent work to a DB-clock lease/fence; no SQL locks span Data HTTP.
3. Begin-derived upload uses stable command identity. Fresh/restarted execution can use SDK receipt-first resume. Persist the accepted upload receipt before streaming. A missing original receipt permits only identical-byte/identity resubmission; unavailable or conflicting inspection never permits a replacement command to hide uncertainty.
4. Persist stream-started before PUT. A verified stream receipt permits finalization. A crash or uncertain PUT never implies success: preserve that attempt's ambiguous history and choose a bounded explicit replacement upload, at most8 attempts. The replacement has its own stable IDs; the original unfinalized upload remains Data-owned cleanup work. Stale lease holders cannot advance Knowledge state or finalize abandoned attempts.
5. Once finalization may have started, reconcile its original command until a bound outcome is known. Do not abandon an uncertain finalize under a fresh identity. Verify exact output content/scope, derived metadata/declaration and original Data command binding. Persist finalized artifact plus owner receipt atomically in Knowledge under the current fence. A Data commit before Knowledge interruption is recovered from its original receipt.
6. Terminal publication replay is immutable metadata. New payload use still checks Data rights; no cross-owner transaction or perpetual rights lease is claimed. Runtime alone owns wait acceptance and artifact reservation/confirmation. Knowledge never impersonates Runtime's retention actor.

Transport/SQL uncertainty remains visible pending; deterministic provenance denial, exhausted stream-attempt policy or incompatible bindings produce explicit failure without minting scientific acceptance. Recovery preserves prior external-effect uncertainty and never issues a contradictory success/failure assertion merely because a response was lost.

## Logical receipt authority

Knowledge's initial issuer/purpose is explicitly synthetic logical entailment. A caller's arbitrary requested purpose cannot turn it into scientific eligibility. Bind the receipt to the request's exact subject, result/profile/context and finalized artifact. Supported, contradicted, unknown, conflicting and incomplete results remain distinct; incomplete/unknown cannot be accepted as supported. Research independently assesses purpose-specific sufficiency. Supersession is a new immutable revision/record with explicit replacement identity, never an update of accepted history. Reconcile the existing Runtime receipt-ID/revision invariants before adding the supersession path in B2.
