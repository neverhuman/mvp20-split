## Separate projection authority

New observation interpretation records have two closed kinds: normalization and observation-use. Do not expand the existing eligibility/synthesis decision identity, reuse a fixed sufficiency receipt or mutate old result bytes. Public profiles declare scoped reviewed configuration with complete original catalog/use policy. Requests reference immutable owner observations and, for use assessment, an exact experiment; normalization also names bounded target units. They cannot submit replacement values or verdicts. Full accepted request/profile/actor is pinned before peer work; stable job identity rejects changed inputs/configuration.

A normalization projection retains its exact original observation, complete profile/target and the normalized-or-unresolved value/applied-rule outcome. A use projection retains exact experiment context and source-ordered original observations with raw/effective matches, optional normalization, blockers/gaps/focus, usable references and missing expectation coverage. Scope, kind, stable projection id, original actor and full canonical content determine the immutable result digest. Synthetic/action-use authority stays explicit. Persistence precedes success; no new DomainReceipt, Runtime retention or scientific truth authority is created.

Public Pydantic models are DTOs. Explicit mappers reconstruct private catalog/requirements/policy objects and serialize their computed output; incoming result-shaped records are not authority. Complete normalization/catalog references must agree with the reconstruction. Preserve every existing public schema and command profile; export new roots rather than silently widening existing wire-version unions.

## Owner persistence and input provenance

A pending operational error is not an unresolved scientific value: the former has no completed projection, while the latter is a computed result under a pinned conversion policy.

B2.04 authenticates current Data reads before completing new work. Completed historical reads use committed configuration/results offline without conferring new source rights. Inputs/results retain existing resource discipline (bounded records, at most128 distinct authenticated source Artifacts, no truncation). No current-head lookup or automatic favorable-result selection is introduced.

## Corrections and material dependency impacts

Read-only correction views select an exact committed successor, load its immediate predecessor and project the pure ObservationCorrection or MaterialStateCorrection. Both original and corrected records remain visible, with changed fields and future_campaigns_only. This is a projection over already committed revisions, not a new correction write authority. Authenticated lab intake remains the observation correction entry; owner-reviewed material fixture/declaration authority remains private in this bounded release.

Observation and Artifact impact queries already exist. Add an explicit material-state dependency index for eligibility records that pin a material state, including a forward backfill of existing committed eligibility records. New decisions maintain it atomically. Introduce a new exact-state impact request/route; preserve existing impact request schemas. Scope/revision/digest are exact, and the index exposes only known owned dependencies and separately registered consumer links. Interpretation results similarly retain their own exact dependencies; no global consumer discovery, live invalidation, graph repinning or fitness rewriting follows.
