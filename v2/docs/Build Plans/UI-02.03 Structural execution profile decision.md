## Observed boundary

Registry0.2.0 now accepts actual registration, activation, deployment, heartbeat and
selection under UI-02.02. Independent handoff d then stops before graph admission.
An isolated compile using installed Runtime0.66.1 and the exact retained graph
raises `unsupported_compiler_tool_profile`. The installed chemical worker's SDK
separately raises `unsupported_worker_profile` before claiming work.

The initial P1 inventory missed both restrictions. Runtime's ResolvedTool explicitly
requires synthetic_only; PureToolWorker does too. This is not a database failure.
The CLI intentionally reports a generic startup error, which initially obscured it.

Related paths were inspected together: Runtime draft Registry observation fixes
context to synthetic-tests, and ValidationUniverse record/restore/digest assumes
the original compiler materials. Changing only the constructor would leave draft
admission and retained reconstruction inconsistent. Planning's separate evolutionary
topology policy also restricts tools to synthetic_only; that is outside this bounded
supplied-structure graph and stays a named POP/ML integration limitation.

## Proposed bounded correction

Runtime owns an explicit reviewed execution-profile object attached to exact host
materials: scope, full release LockEntry, public request/result schema pins,
semantic-profile pin and supplied-finite-molecules context. Only the reviewed
chemistry.chemical-structure0.1.0 capability may use this profile. Require pure
effects, denied egress, no checkpoints and supported required ports. No generic
evidence_proposal allowlist and no chemistry/RDKit dependency in Runtime.

Keep unconfigured/default synthetic compilation and its exact plan bytes unchanged.
Version retained authoring-universe records and identity only for opted-in materials;
bind the new policy pins into their identity, preserve old record restoration and
receipt replay byte-for-byte, and reject tampering or scope/profile mismatch.
Current configured grants must be checked at new admission independently of
historical reconstruction; removing a grant cannot rewrite a prior validation or
cancel/repin an active campaign. Registry observations for new structural admission
use the profile's exact context and current capacity/eligibility checks.

SDK owns a separate explicit opt-in worker execution profile using the same public
pins, exact configured release and scope. Its default synthetic-only behavior stays
unchanged. The chemical CLI selects/configures only its own reviewed profile;
other tools cannot gain eligibility through a boolean bypass. Lease renewal,
attempt/fence checks, artifact integrity, safe failures and receipt recovery remain
identical. No private imports between Runtime, Registry, Research, SDK and tool;
shared public pin records are data, not a shared business-policy implementation.

No new HTTP command/DTO/table is proposed. A versioned internal retained universe
and additive host/worker configuration are required. Scientific interpretation
remains tool-owned; this grants structural derivation, never generation, ranking,
property validity, synthesis or biological efficacy. No paid model calls.
