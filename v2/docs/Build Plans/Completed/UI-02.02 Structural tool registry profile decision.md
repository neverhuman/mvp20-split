## Observed mismatch and correction to the earlier inventory

UI-02.01 authorized chemical_structure artifacts/tool and opt-in Research registration.
It assumed the existing Registry could activate that reviewed capability without
changing its policy. Actual independent Registry/Runtime/Data/Research/tool installation
uncovered the missing prerequisite: catalog/releases.py permits activation only when
all three conditions hold: synthetic_only authority, pure effects, synthetic-tests
applicability. The new tool truthfully declares evidence_proposal and
supplied-finite-molecules. Actual registration succeeds; activation is denied.
The initial harness then incorrectly dereferenced the absent accepted release;
that harness error is repaired to retain the actual denial and stop clearly.

Changing the descriptor to synthetic_only would misdescribe chemical structural
derivation. Skipping Registry would evade the intended common capability lifecycle.
Neither is an acceptable completion of P1.4. The separate SyntheticScientificPolicy
in descriptors/assessments.py also rejects non-synthetic selection, so merely
removing the activation condition would leave a second inconsistent boundary.

## Recommended bounded change

Add one explicitly configured versioned Registry policy object for structural
mapping. Configuration grants an exact scope, immutable release LockEntry
(including descriptor/image/schema pins), supported semantic-profile pin and exact
applicability context. No wildcard capability grants and no arbitrary
promotion of all evidence_proposal tools. Activation and eligibility resolution
consume the same policy object and the same reviewed release pins.

The first permitted capability is chemistry.chemical-structure0.1.0 with the approved
finite-smiles profile: supplied connected finite molecules/fully specified oligomers,
structural_derivation result authority, pure effects, denied egress, bounded resources,
known input/output schema pins. It may produce formulas/2D depictions. It may not
assert generation, ranking, physical-property accuracy, synthesis feasibility or
biological efficacy. Eligibility means eligible for this bounded structural task,
not scientifically validated chemistry. Keep this limitation in reason codes and
UI/LLM inventory descriptions.

Default Registry operation remains synthetic-only. Unconfigured chemical releases,
wrong scope/context/profile/descriptor/schema/image, side effects or egress remain
denied. Other evidence_proposal capabilities require their own reviewed profiles.
Existing pure synthetic activation and its policy digest remain byte-compatible.
The opt-in structural profile has its own policy fingerprint including grants/pins;
exact old command receipts replay without recomputation. No current campaign repins,
receipt rewrite, migration or expanded provider budget.

Existing public ReleaseDescriptor/EligibilityDecision enums and command routes
already represent this boundary; prefer a host-configured policy over a new public
command. If actual implementation proves a new wire contract/table is necessary,
record the concrete change rather than silently expanding this decision.
