## Module and Object Boundaries

| Private module | Behavior owned | Boundary to preserve during replacement |
|---|---|---|
| `storage/` | Generated byte keys, exclusive creation, bounded streaming, digest/size verification and immutable read handles | Never accepts a caller path; returns verified byte metadata, not a usable artifact reference |
| `publication/` | Upload identity, attempt fencing, allowed descriptors and finalization state | Only its committed catalog/receipt makes bytes addressable as an artifact |
| `retention/` | Reservation binding and authenticated immutable runtime outcome reconciliation | Unknown outcome retains protection; terminal release needs exact abort proof |
| `access.py` | Configured local principals, scopes and action grants | Actor/scope come from credential policy and must match the command; body fields are not authentication |
| `persistence/` | Owner-only SQL transactions/migrations | No network or streaming callback within a database transaction |
| `api.py` | Bounded HTTP decoding, credential lookup and DTO mapping | Domain objects own lifecycle; no route-specific policy duplication |

Use immutable `ExpectedContent`, `StoredBytes` and `UploadAttempt` values; a publication aggregate owns state decisions and a configured `ContentPolicy` owns allowed media/schema pairs. Pydantic DTOs validate transport only. There is no generic shared service repository or shared filesystem gateway.

## Developer Access and Bounds

The first profile uses explicitly configured opaque bearer credentials mapped to principal, tenant/project and permitted actions. Bind uploads to their creating principal; reading an artifact requires an explicit same-scope read grant. Runtime retention credentials are distinct from worker upload credentials. Compare secret values without logging them; reject missing/unknown credentials before registering commands or returning existence information. These are local fixture credentials, not enterprise identity or multi-tenant security evidence. Bind the developer server to loopback. Remote deployment requires authenticated transport and target-host policy under BP-09.

Default fixture limits are configuration: 16 MiB per upload, 64 KiB internal read/write chunks, 256 MiB reserved storage per scope and two active streams per scope. Admission reserves declared bytes transactionally before streaming; retries must not bypass quota by creating unlimited attempts. Count provisional attempts and finalized retained bytes; quota exhaustion rejects new work without deleting accepted content. Bound upload duration and HTTP body size independently. Values can change between campaigns; they are not scientific applicability limits.

Initially admit only configured synthetic media/schema pairs: opaque octet bytes, strict UTF-8 text, and bounded JSON through the registered schema validator. Unknown schema or media identity rejects. Declaring JSON does not establish scientific meaning. Size/digest match is required even for opaque bytes. Finalization, scientific acceptance and knowledge promotion remain separate receipts.

## Filesystem Boundary

The process receives one administrator-configured absolute storage root at startup; commands never supply a root, relative path, filename or URL. Validate the root and every existing ancestor against symlinks/reparse points and refuse linked entries within it. Only the artifact service account may mutate this tree. Checks do not defend against a hostile administrator concurrently replacing directory handles; that is outside the single-host service account boundary. Keep the root local to the artifact process; object storage and shared-volume semantics need explicit adapters and acceptance.

Generate unpredictable flat keys for every upload attempt. Create a fresh file exclusively; never reuse or truncate an existing attempt key. A stopped or fenced writer can affect only its own unreferenced file. Flush and sync completed bytes before recording successful streaming. Published files never reopen for writing. Content readers use catalog keys and repeat containment/link checks; missing or corrupted content is an integrity failure, not permission to silently regenerate accepted content.

Process-crash durability is the first gate. Directory sync/rename and power-loss behavior vary by filesystem; target-host evidence is separate. Tests must report the actual storage filesystem/profile, including when this checkout is on a NAS. An API retry cannot convert a filesystem move into a database transaction.

## Upload Attempts and Fencing

`BeginUpload` commits upload ID, actor, immutable expected descriptor and reserved capacity with its command receipt. It returns a provisional upload receipt only. Streaming restarts from byte zero; byte-offset resumption is outside this slice. An interrupted request can be retried with a new generated attempt, subject to quota and concurrency bounds.

Add a forward artifact migration for private `upload_attempts`, a monotonically increasing upload generation and scoped capacity accounting. The attempt records exact upload/actor/generation, generated key, bytes received, status and expiry. Generation and quota allocation occur under scope-capacity then upload locks. Release locks/transaction before reading request bytes. Older attempts retain their own file but cannot become the selected complete attempt after a newer generation is admitted.

After bounded streaming, digest/size verification and sync, a short transaction selects the completed attempt only if upload status and generation still match. It accounts bytes and settles capacity exactly once. Disconnection, overrun, digest failure, timeout or stale generation leaves no usable reference. Never infer successful streaming from file existence. Cleanup of failed attempts requires terminal status and sufficient grace; a stale process cannot publish after cleanup because generation checks reject it. Duplicate request/replay behavior is explicit in the public upload route contract before A2 completion.

## Finalization Transaction

Register the immutable finalize command first. Load the selected completed attempt and expected descriptor, then verify immutable bytes outside the transaction. Under the upload lock, recheck the selected generation/descriptor and provisional state. Atomically insert catalog identity, finalize upload, settle quota, append audit/outbox intent and terminal command receipt. An already finalized matching upload returns its catalog identity; changed metadata rejects. This requires no overwrite or rename of accepted bytes: catalog binding publishes the immutable generated attempt key.

A crash after durable bytes but before the catalog transaction leaves an unreferenced attempt, never a usable reference. A crash after catalog commit returns the original receipt on replay. Finalized catalog bytes are retained without automatic garbage collection in BP-02. Capacity exhaustion remains visible and does not trigger destructive cleanup.

## Runtime Outcome and Retention

Network outcome lookup occurs outside artifact transactions through a configured authenticated runtime client. Match owner, scope, intent ID, semantic completion digest and output binding. A committed outcome additionally identifies the accepted result/receipt and reference; an aborted outcome is irrevocable. Revalidate the immutable binding in the reservation transaction. Unknown, malformed, mismatched or unreachable outcome cannot release protection.

A4/A5 can test their public client boundary against a separately running scripted outcome fixture until BP-02.05 provides the actual runtime endpoint. Label that evidence as client protocol behavior. BP-02.06 must repeat commit/abort/late-reserve races with actual runtime and artifact processes; fixture responses do not prove runtime immutability or integrated race safety. This removes a sequencing ambiguity without waiving the integration gate.

## Required Failure Evidence

| Case | Required outcome | Owning task/test folder |
|---|---|---|
| Traversal, linked root/entry, guessed key, wrong credential/scope | Reject before content disclosure or mutation | A2/A6, `storage/`, `access.py` |
| Partial/disconnected/oversize upload | Provisional only; bounded capacity, no artifact reference | A2, `publication/` |
| Two writers; older completes after newer | Only current generation can be selected; separate files | A2, `publication/` with real connections/processes |
| Mismatched digest/size/media/schema | Reject finalization; retain diagnostic identity safely | A3, `publication/` |
| Kill after sync before selection/catalog | No usable reference; retry/reconciliation safe | A3, `publication/` process tests |
| Kill after catalog before reply | Same immutable receipt on replay | A3/A6, `publication/` |
| Committed/aborted/unknown runtime outcome | Confirm/release/retain respectively, exact binding required | A4/A5, `retention/` |
| Shared artifact, one aborted intent | Other reservation remains protected | A4, `retention/` |
| Runtime outage or malformed proof | Retain; bounded retry and observable pending state | A5, `retention/` |
| Missing/corrupt catalog bytes | Explicit integrity failure, no silent replacement | A6, `storage/` and public read tests |

Storage tests use synthetic bytes and temporary service-owned roots. PostgreSQL tests retain module ownership. Cross-process fixtures have explicit owners and teardown; deployment/scientific E2E remains separate. The implementation README must name actual guarantees, supported filesystem and unimplemented adapters.
