# Bounded topology successors

- Design status: bounded policy/publication, actual compiler/adoption/carry, fair comparison and process recovery verified; fresh replacement accepted and BP-08.04 closed.
- Last reviewed: 2026-10-06 19:03:23 (America/Chicago).
- Parent: [Search](Search.md).

Planning owns bounded proposals; Runtime alone compiles and admits successor campaigns. A configured synthetic topology policy pins original plan/definition and named edit choices. A request selects exactly one choice, original predecessor cut, next revision and carried mappings. The first policy supports compatible evaluator-release replacement or insertion of a reviewed pure unary transform at one explicit invocation input. It cannot emit arbitrary source, change unrelated nodes/context or mutate an active run.

Public parent plan/definition digest profiles and Registry release locks bind original metadata. Pure validation is not owner authentication. A new selected release must be active; an inactive historical original can still be replaced in a future campaign. Complete ports/schema/representation/unit/checkpoint and timeout/resource checks precede a proposed definition. Transform insertion preserves the old input source through the new node, reroutes one control predecessor and leaves other consumers unchanged. Converging control joins reject in the initial profile. Nested scope paths are bounded by existing compiler limits.

Planning retains proposed/rejected dispositions and original inputs. Durable publication must resolve exact authenticated parent/release observations and preserve replay separately from current eligibility. Runtime compilation remains authoritative over full control/value topology; structural compatibility alone does not prove tool scientific equivalence or successful execution. Successor admission reuses existing terminal/settled predecessor, carried-value hash/schema and immutable lineage rules. No Planning access to Runtime tables or compiler implementation is permitted.

Topology ancestry is separate from candidate ancestry. Replacing an evaluator does not make old scores comparable; fair comparisons require identical evaluator/evidence/policy, predeclared seeds, evaluator-attempt allowances, metrics and stopping rules. Record every failure and seed instead of selecting favorable outcomes. Numeric engineering benchmarks do not establish scientific gains, and existing live-model evaluation does not validate a new topology-specific prompt.

The implemented Planning0.98 boundary retains immutable proposals through
planning0020. Runtime0.65 combines existing draft and successor guards through
the additive draft_successor0.1 command; validation, current eligibility and
terminal predecessor checks retain their separate authority. Both publication
and lineage commit with the new run, and original receipt replay survives
current configuration changes. Actual process death before/after commit proves
rollback or original replay without partial publication.

Public-owner acceptance carries an exact parameter Artifact from a completed
parent into a newly compiled evaluator-release successor. Data retains the
original proposal/validation/admission/lineage/execution handoff and independent
numeric benchmark; it does not make the two evaluator revisions scientifically
comparable. The test controller is not a production scheduler. Configured model
integration remains BP-09; no topology-specific live-model claim is made.
