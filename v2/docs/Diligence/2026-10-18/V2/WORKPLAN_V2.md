# Amphora | Investor challenge and delivery plan - version 2

**18 October 2026 | Critical technical investor review | Draft for review**

Amphora has a credible engineering proposition: make bounded research workflows executable, keep model proposals separate from execution authority, and retain the inputs, decisions and outputs needed to inspect what happened. The repository offers concrete mechanisms and historical demonstrations to examine. The investment question is whether those mechanisms can support a useful real workflow, an independently valuable scientific outcome and a defensible business. Those are separate evidence obligations.

Version 2 is more demanding than version 1. It documents two reproduced verifier/status defects, fixes feasible tooling weaknesses, removes task-count readiness percentages and leads with five decision tracks. It does not manufacture better predictive performance, current production qualification, a buyer, exclusive rights or a commercial moat.

| Question | What is available now | What remains unestablished |

**Decision:** the work supports deeper technical diligence and a bounded next proof, rather than a conclusion that scientific or commercial risk has been retired. None of the five investment decision tracks is closed. A script pass is a statement about the named mechanical check, not a financing recommendation.

The 93 original task IDs remain traceable in the backlog. They are a work inventory, not a denominator for investment readiness. Uniform five-to-thirty-minute task estimates and the six-hour aspiration have been removed as uncalibrated scheduling inputs. Future work remains unestimated until a named person accepts a bounded scope and budget. This revision authorizes and delivers the review, feasible local fixes and a public draft PR; it does not execute the remaining backlog.

## 2. The consequential findings

Fourteen findings are recorded with severity, source revision/path/hash, investor impact, concrete fix, verification and disposition. The review distinguishes confirmed code defects, presentation weaknesses, missing evidence and unresolved ownership/commercial questions. Missing evidence is unverified; it is not declared false.

**Confirmed defect RF-01:** version 1 accepted a fake historical checker after its mutable mapping and manifest hashes were recomputed. The unchanged V1 verifier then returned `verified` with fabricated gate names. This demonstrated self-consistency, not a binding to the original checker. Version 2 anchors the approved policy/configuration to reviewed code, checks the exact payload allowlist before execution and verifies the original gate set, profile, limitations and result semantics. The coordinated-substitution regression must reject before running the substituted checker.

**Confirmed defect RF-02:** version 1 accepted future owner-approval task DD-010 as verified when only the root README was supplied as evidence. File existence was insufficient. Version 2 binds evidence to its bytes, supported task IDs, actual result/exit fields and current verifier code for mechanical checks. Preparer records cannot establish the protected role-approval tasks. These checks still rely on an accurately produced receipt; they do not identify a person cryptographically or prove that a fraudulent receipt producer is honest.

**Investment evidence gaps:** historical owner demonstrations and the isolated scientific benchmark do not establish integrated scientific product behavior. The internal PLGA result does not establish predictive lift or transfer. The packet supplies no verified buyer/value or exclusive-asset evidence. Version 2 makes those uncertainties first-class decision tracks with unfavorable-result branches rather than burying them behind a large task register.

**Review provenance:** the local preparer inspected the actual V1 PDF, ledger and code and executed the defect probes. An additional reviewer contributed reconciliation-based questions after Library artifact access was denied. That contribution is not represented as an independent full-artifact or code audit. This is not independent scientific validation, a legal opinion or a patentability review.

## 3. Five decision tracks with real stopping rules

### DG-1 - Diligence inspectability

The adviser must be able to trace every principal statement to an exact source, scope and qualifier, and run the advertised reviewer path from a clean export. Require complete twelve-cell scientific results, all ten contrasts, every requested check and every final PDF page. Scope labels distinguish fresh integrity/arithmetic, historical process execution and omitted current integration. A failed required gate blocks that claimed release profile; a smaller profile must say precisely what it verifies.

Current state is partial: useful source and corrected tooling exist, but the investor brief/systems note and final role-reviewed release are not completed by this plan. If the evidence cannot be exported within rights/disclosure limits, publish a smaller supported route or remain draft. Do not weaken the original assertions to obtain a pass.

### DG-2 - Product end-to-end integration

Choose one real scientific workflow and freeze its versions, inputs, data rights, public tool contracts and expected retained outputs. Qualify admission, tool execution, protective retention, accepted producer chain, output reconciliation and recovery through the actual installed owners. Require every named assertion, with zero unmapped input/output identities. Compare outputs to the separately frozen procedure; execution success alone does not establish scientific quality.

Current state is unverified for PLGA integration. The numerical examples remain valuable bounded software evidence. If integration fails, preserve the failed boundary and keep systems and scientific claims separate. POP-01 -> RG-01 -> ML-01 prerequisites remain owned by their existing plans; this review does not silently activate them.

### DG-3 - Workflow value against the current alternative

First identify the buyer, actual user, bounded workflow and observed current alternative. Predeclare matched task definitions, primary effort/time measure, correctness threshold, onboarding/integration cost, sample/replication plan and decision margin. Those design values are currently undecided, not invented to make the packet appear complete. They must be chosen before outcomes are examined.

Retain all matched observations, failures and uncertainty. A faster different task is not a saving. If the value margin is not met, change or stop the use-case hypothesis. Do not convert bounded CPU time, a synthetic search comparison or packet-generation speed into assay savings, customer ROI or willingness to pay.

### DG-4 - Independent future scientific outcome

Freeze one method/representation and comparator, a fixed information schedule and horizon, a predeclared estimand and margin, missing-data rules and assay-replicate uncertainty. Select genuinely unexamined, overlap-screened new-study PLGA data before seeing outcomes. Justify sample size and replication from the scientific question and variability; a blank or unsupported design blocks launch.

The current study remains post-pilot internal validation on the development-exposed Bao corpus. Report every eligible profile and endpoint under the frozen rule. An unfavorable result is retained. Do not search new seeds/grids on the exposed cohort to turn a documentation milestone into an apparent external win. Ocular or route-specific claims require their own applicable evidence.

### DG-5 - Defensibility, provenance and accountable release

Map every selected contribution to its third-party foundations, Amphora-specific integration, evidence and rights disposition. Public source visibility and CC BY data are not evidence of an exclusive asset. Prior-art acknowledgement is not a patent or freedom-to-operate assessment. Ownership and reuse permissions need their actual records and responsible review.

Every activated future track needs an assigned person, approved budget and inclusion decision. Those remain unassigned/unapproved in this assessment. If rights or exclusivity cannot be supported, narrow the wording or payload rather than imply that this review resolved the question. The user's explicit instruction authorizes pushing this revised review branch; it does not turn an investor evidence release or scientific study into an approved completed gate.

Amphora's specific claim is the inspected combination of typed research composition, owner-controlled acceptance, retained scientific context and bounded replacement/recovery examples. Whether this combination creates material incremental value or an exclusive/compounding asset is an investment hypothesis to test. The contribution/provenance matrix records what is implemented, what is sourced and what remains unverified; it does not infer competitor absence.

The commercial hypothesis ledger names a hypothetical buyer/user/workflow and possible measures while keeping interviews, pricing, ROI, adoption and retention unknown. Public Bao data are not described as proprietary assets. Existing source/data terms remain in force; this revision adds no blanket license or new ownership assertion.

## 6. Version 2 verification and trust boundary

The default reviewer route is offline after acquisition, starts no services or models and uses Python 3.12 standard-library dependencies. Optional bootstrap requires the separately supplied NumPy environment. Missing requested NumPy returns exit 3; evidence rejection returns 2; success means all requested required checks completed. Source and capsule reports enumerate what executed, which execution remains historical and what was omitted.

Trust begins with reviewed verifier/policy code and a trusted interpreter/local directory acquired from the identified Git revision. Fixed policy hashes bind the original map, source lock, allowlist and candidate registry. The capsule cannot introduce an extra executable, replace the original checker and rewrite its checksums, or change a declared transform while retaining the reviewed policy. An optional expected-manifest digest obtained outside the capsule adds an independently recorded integrity binding.

If the verifier and all its trust anchors are replaced, its own output is not an authentication mechanism. SHA-256 does not establish author identity, scientific truth or rights. Offline execution is not a safe sandbox. No signing credentials are created and no cryptographic publisher-authenticity claim is made.

Child checkers use isolated Python, bounded stdout/stderr, whole-report JSON validation and a shared timeout budget. The source profile runs the required capsule pass once. Canonical array pointers, phase membership, source ranges, task/evidence support and safe output resolution are checked. The supported local-directory model still does not claim a complete hostile-filesystem/TOCTOU defense.

The current PDF freshness check binds final source inputs, renderer and output bytes. A source/template/brand change invalidates the current render record. Visual acceptance is separately tied to the final PDF hash. This is a concrete current-document check; a universal future investor-prose assembler, signatures and complete production sandboxing are not claimed.

Current code hardening and review publication can complete now without executing DG-2/3/4 studies.

The smallest later investor artifact set is a two-page brief, a concise systems note, the unchanged eight-page PLGA paper, complete scientific card, evidence index and supported reviewer command. A six-page systems version is an editorial target, not a reason to shrink type. Recording, FAQ, extra plots, live calls and new model replay are optional after the core qualifies. No guessed date or uniform task-minute budget is used as acceptance evidence.

All 93 task IDs remain available for implementation traceability. Their states distinguish inspected preparation, fresh mechanical checks and future approval/research. Role placeholders are not appointments. Protected approval tasks cannot be completed by an arbitrary existing file or a preparer receipt. No task-count percentage is presented as investor readiness.
