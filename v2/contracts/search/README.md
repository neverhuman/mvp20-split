# Search and checkpoint wire boundary

Owner: BP-08.01/B1.02. This package owns validation/serialization DTOs, not ranking, state transitions, execution acceptance or scientific truth. Numeric domain behavior belongs to tools/evolution_search. Only public core/tools contracts are imported. [Design](../../docs/Architecture/Campaigns/Search.md).

SearchSpec freezes seed and scope/search identity, representation, finite named variable bounds, named objective units/directions, evaluator ToolBinding, constraint/context Artifacts, operator policies, dependency fingerprints and generation/evaluation/stagnation budgets. A caller cannot replace these pins while resuming the same checkpoint. Numeric genotype is distinct from molecular/sequence representation. Current policies are continuous boxes, constrained feasible-only Pareto selection and portable SHA256 counter draws; no claim of v1 SBX/SplitMix equivalence.

SearchCheckpoint carries the exact specification/digest, predecessor Artifact, generation/phase, RNG seed/counter, bounded attempt pool with parent/draw/rejection/duplicate history, frozen population, pending request identities, observations, selection and progress/stop state. Each checkpoint keeps at most256 current/retained candidates. Earlier dropped attempts remain in the predecessor artifact chain, not silently discarded or folded into survivor IDs. Data/Runtime must retain and verify those artifacts; a shaped ArtifactRef does not prove existence or permission.

EvaluationObservation distinguishes actual finite objective records from unknown/failed/inapplicable outcomes. It binds candidate/request identity, objective units, exact evaluator/constraint pins, evidence artifacts and synthetic/predicted/measured provenance. Those labels are declarations, not owner acceptance or scientific promotion. Unknown outcomes cannot supply substitute objective zeros. SelectionReceipt retains all ranked members and an explicit empty/insufficient feasible-set disposition; infinity is represented by a boundary flag with finite distance.

These strict frozen DTOs enforce shape, closed versions, bounds and finite numbers. The tool's next domain-mapper phase must check scope/pin equality, ordered dimensions, variable ranges, unique identity, ancestry, RNG intervals, exact pending/terminal sets, immutable membership, budget accounting, receipt consistency and stop semantics against an independently supplied original specification. Schema-valid is not resumable or admissible by itself. No SQL, pickle, model call, acceptance flags, arbitrary runtime code or service-private import belongs here.

Module-owned wire tests live under tests/checkpoint. Fixtures are synthetic placeholders with no live tool deployment or Research owner-record claim. Publication verified: four public roots/eight schemas,564 total with556predecessor bytes unchanged. Exact validation identities are exposed by search_spec_schema,search_checkpoint_schema,evaluation_request_schema,evaluation_observation_schema. EvaluationRequest carries frozen spec/candidate/objective/evaluator context; pending/observed rows bind its canonical hash. Domain consistency remains B2. Replacement requires exact field/version behavior plus the owning tool's domain/replay tests.
