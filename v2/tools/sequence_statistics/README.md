# Sequence Statistics Tool

- Status: 0.2.0 accepted in BP-03.03; BP-03.04/B2 accepted immutable replacement 0.3.0 and registry/replica cutover.
- Package/release: `amphora-sequence-statistics` 0.3.0; wire payload version 1.
- Architecture: [tool services](../../docs/Architecture/Capabilities/Tool_Services.md).

Counts up to 65536 case-sensitive ASCII alphanumeric symbols against an explicit nonempty alphabet of at most 62 distinct symbols. Output includes total length and every alphabet symbol in declared order, including zero counts. An empty sequence is valid. An empty/invalid alphabet or malformed payload reports `invalid_sequence_parameters`; duplicate alphabet symbols report `duplicate_alphabet_symbol`; any sequence symbol outside the declared alphabet reports `invalid_sequence_symbol`. There is no implicit alphabet inference or normalization.

The `payloads` module owns boundary DTOs. The `kernel` owns domain behavior and has no runtime/client imports. `adapter` maps tool-local failures to safe execution reason codes. `metadata` owns exact published input/output schema bytes and a release descriptor template. The template is deliberately incomplete without an externally supplied image SHA-256: `describe --image-sha256 <actual-image-digest>` produces the versioned descriptor after an image build. Wheel/source hashes are not image hashes. Earlier 0.1.0 contract fixtures are synthetic metadata only; the implemented releases do not rewrite those payload or release identities.

The package imports only its own code, Pydantic, public contracts and the explicitly public worker SDK. It owns no database or durable execution state. It cannot create graph work, decide scientific acceptance, modify knowledge, choose retry attempts or access another service's private implementation. Applicability is synthetic-tests only. These results establish numerical/string behavior, not biological, chemical or materials validity. The pure-tool egress declaration concerns tool-specific external effects; authenticated runtime/artifact protocol endpoints are configured infrastructure dependencies.

## Executable Boundary

`python -m amphora_sequence_statistics compute` consumes a bounded JSON payload on stdin and writes the versioned result to stdout. `describe --image-sha256 <digest>` prints a descriptor with actual packaged schema digests. `worker --config <path>` attempts one eligible invocation in an explicitly named run through public owner APIs. No eligible work returns that observation; it does not admit or invent work. A supervisor owns repeated polling/replicas. Invalid CLI input produces a bounded safe error without echoing the payload.

Worker configuration contains actor_id, scope, run_id, image_sha256, runtime/artifacts endpoint plus token_env, optional lease_seconds (10..300, default 30) and max_clock_skew_seconds (0..5, default 1). Credential values come only from named environment variables. The SDK currently accepts HTTPS or same-host loopback HTTP. The configured image identity is a deployment assertion, not self-attestation. Local wheel tests prove package/protocol compatibility; deployment must separately verify the actual image/platform. The supplied descriptor template targets Linux x86_64; ARM/target-host validation remains BP-09.

The SDK renews at stage boundaries, verifies the current attempt/fence and limits local authority conservatively using monotonic time and a configured clock-skew allowance. These kernels have bounded small inputs; long-running scientific kernels need a reviewed renewal/cancellation execution profile before reuse. A cancelled/expired attempt may leave provisional bytes, but cannot obtain accepted completion. Interrupted streams are not blindly replayed or assumed finalized; durable owner receipts govern command recovery. An ambiguous completion is never followed by a contradictory failure report.

## Packaging and Replacement

Each package has its own manifest, lockfile, versioned schema files, descriptor template, tests and Dockerfile. Build the wheel independently. The image recipe consumes an offline `wheels/` directory containing this package and only its locked declared dependency closure, and requires a digest-pinned Python 3.12 base via PYTHON_BASE. It runs as UID/GID 65532. Record the resulting image identity and then finalize the descriptor externally; embedding an image's own digest in its source would create a circular build identity. No image build or target-hardware result is claimed by the recipe alone.

Run `uv run --project v2/dev --locked python v2/dev/run_tests.py --module sequence-statistics --coverage`. `tests/kernel/` owns numerical/domain and schema/CLI checks; `tests/fixtures/golden.json` is the independent language-neutral oracle. Foundation isolated installs check that service implementations, scientific libraries and the sibling tool are absent. Schema bytes use UTF-8/LF, and tests reject drift from the owned DTOs. CLI subprocess coverage is separate from in-process coverage. [Preserved acceptance evidence](../../docs/Audits/Evidence/BP-03-Workers/README.md) records actual worker/peer recovery and fresh replacement.

A replacement preserves exact schemas, pure behavior, error vocabulary, input/output port binding, deterministic ordering and replay/fence semantics. Changed behavior/schema/image creates a new immutable release; never overwrite an already registered release. Scratch may be discarded; accepted artifacts, receipts and provenance remain owned by runtime/artifact services.

B2 coverage checkpoint: 19 module tests; 84% combined line/branch over 98 statements/16 branches; kernel 100%, adapter 87%. CLI subprocess golden/invalid cases are separate evidence. Remaining branches are CLI modes and defensive metadata/numeric/fallback guards; B3/V1 separately proves actual configured tool-owner execution and replacement. [Configuration example](config.example.json) deliberately has an invalid image placeholder; supply the verified deployment identity. Runtime grants are claim/renew/complete/read; artifact grants are upload/finalize/read. Worker credentials must not grant admission or administrative work creation.

Terminal schema/configuration failures do not retry; bounded transport/capacity failures may retry only under runtime authority. An incomplete worker execution exits 3 with a safe message; invalid input/configuration exits 2. The worker adapter preserves the tool-specific failure vocabulary above.

## Immutable Release Change

Version 0.3.0 corrects the output port representation from `symbol-sequence` to `symbol-statistics`; the input remains `symbol-sequence`. Payload schema identities, counting behavior, errors and golden outputs are unchanged. This is a new immutable descriptor/image identity, never an overwrite of built 0.2.0. Prior package/image bytes and receipts are preserved in [worker evidence](../../docs/Audits/Evidence/BP-03-Workers/README.md), with source available at commit bb1ee21. The integration harness independently installs both releases and selects by exact lock. Actual cutover passed in BP-03.04/B2; [preserved evidence](../../docs/Audits/Evidence/BP-03-Replicas/README.md) records both exact identities and unchanged old history.
