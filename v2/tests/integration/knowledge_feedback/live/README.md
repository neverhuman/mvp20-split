# Actual feedback baseline

BP-06.06/B1.05 through B3.02. This verification module runs independently installed Data, Research, Knowledge and Runtime services against their retained PostgreSQL schemas and the labeled actual Qdrant fixture. It never imports peer implementations or reads owner tables. Each owner migrates through its isolated interpreter; Research alone seeds synthetic declarations/specimens through its own stores because those records have no general fixture-write HTTP API. This is fixture installation, not a deployed ingestion workflow.

`process.py` owns bounded loopback HTTP/process lifetime and sanitized startup/setup failure. Owner environments contain only their own database credential and explicitly needed peer tokens. `source_graph.py` publishes source bytes, current rights, deterministic conversion, accepted hypothetical assertions and a synthetic logical-entailment receipt through public APIs. `specimens.py` installs reviewed public Research examples and reads lossless specimen/property views. `representation.py` creates a declared deterministic encoding and a real Qdrant generation/query; no semantic embedding-quality claim follows.

`runtime.py` configures an exact receipt wait, compiles in Runtime's interpreter without database credentials, submits the real Knowledge receipt, advances completion, confirms Artifact retention and restarts Runtime before exact command replay. It cancels only its own unfinished campaign on failure. It never resets retained storage, cancels an unrelated run or changes scientific pins. `compile_plan.py` is adapted from Runtime's reviewed acceptance compiler.

`manifest.py` maps observed replies into the existing immutable manifest and verifies canonical replay. The Studio probe invokes compiled production clients against those same live owners. Credentials reach only the separate acceptance driver's stdin and in-memory fetch adapter; they never enter the manifest/evidence or production clients. This proves transport interoperability, not a deployed gateway or browser presentation. The graph and specimen JSON files are copied public synthetic examples with source Artifacts replaced by actual published refs; their hypotheses/measurements are declared fixtures, not scientifically accepted results.

Run the owning test with `AMPHORA_TEST_FEEDBACK_LIVE=1`, `AMPHORA_TEST_POSTGRES=1`, `AMPHORA_TEST_QDRANT=1`, and explicit independently installed interpreters in `AMPHORA_TEST_DATA_PYTHON`, `AMPHORA_TEST_RESEARCH_PYTHON`, `AMPHORA_TEST_KNOWLEDGE_PYTHON`, `AMPHORA_TEST_RUNTIME_PYTHON`. Compile Studio first. `AMPHORA_TEST_FEEDBACK_EVIDENCE` optionally writes credential-free actual records. Run serially with other PostgreSQL/campaign suites. The ordinary module run skips this actual tier unless opted in.

Acceptance asserts exact source content, hypothesis posture, supporting assertion identity, published receipt, readback of declarations/scientific views, actual retrieval binding, Runtime wait closure/completion/retention/replacement replay, manifest fingerprint and Studio source/span hashes. Actual browser, adverse correction races and independent Knowledge/retrieval rebuild remain B3 gates. Harness lines are not production coverage credit; protocol coverage remains separately owned.

## LAB-REF02 correction ordering

`AMPHORA_TEST_FEEDBACK_RACES=1` (with successor progression) adds `races.py`. A bounded Runtime hook runs only after the actual wait opens and before original receipt submission. Two public Knowledge proposals share one base; two Research corrections share one expected head. Client barriers release each pair, requiring one committed winner and one conflict, durable status/readback and exact retry. These are client ordering barriers, not internal transaction scheduling hooks.

The actual correction notice and changed revision are rejected by the original open wait without changing its expectation or closure. Original pinned evidence then completes, retains and survives Runtime replacement; a separate successor selects the winning corrected receipt and different report. Scientific alternatives remain synthetic/qualified and do not automatically replace campaign graph pins. All owner state is accessed through public HTTP; no receipt or successful response is fabricated.
