# Actual feedback baseline

BP-06.06/B1.05. This verification module runs independently installed Data, Research, Knowledge and Runtime services against their retained PostgreSQL schemas and the labeled actual Qdrant fixture. It never imports peer implementations or reads owner tables. Each owner migrates through its isolated interpreter; Research alone seeds synthetic declarations/specimens through its own stores because those records have no general fixture-write HTTP API. This is fixture installation, not a deployed ingestion workflow.

`process.py` owns bounded loopback HTTP/process lifetime and sanitized startup/setup failure. Owner environments contain only their own database credential and explicitly needed peer tokens. `source_graph.py` publishes source bytes, current rights, deterministic conversion, accepted hypothetical assertions and a synthetic logical-entailment receipt through public APIs. `specimens.py` installs reviewed public Research examples and reads lossless specimen/property views. `representation.py` creates a declared deterministic encoding and a real Qdrant generation/query; no semantic embedding-quality claim follows.

`runtime.py` configures an exact receipt wait, compiles in Runtime's interpreter without database credentials, submits the real Knowledge receipt, advances completion, confirms Artifact retention and restarts Runtime before exact command replay. It cancels only its own unfinished campaign on failure. It never resets retained storage, cancels an unrelated run or changes scientific pins. `compile_plan.py` is adapted from Runtime's reviewed acceptance compiler.

`manifest.py` maps observed replies into the existing immutable manifest and verifies canonical replay. The Studio probe invokes compiled production clients against those same live owners. Credentials reach only the separate acceptance driver's stdin and in-memory fetch adapter; they never enter the manifest/evidence or production clients. This proves transport interoperability, not a deployed gateway or browser presentation. The graph and specimen JSON files are copied public synthetic examples with source Artifacts replaced by actual published refs; their hypotheses/measurements are declared fixtures, not scientifically accepted results.

Run the owning test with `AMPHORA_TEST_FEEDBACK_LIVE=1`, `AMPHORA_TEST_POSTGRES=1`, `AMPHORA_TEST_QDRANT=1`, and explicit independently installed interpreters in `AMPHORA_TEST_DATA_PYTHON`, `AMPHORA_TEST_RESEARCH_PYTHON`, `AMPHORA_TEST_KNOWLEDGE_PYTHON`, `AMPHORA_TEST_RUNTIME_PYTHON`. Compile Studio first. `AMPHORA_TEST_FEEDBACK_EVIDENCE` optionally writes credential-free actual records. Run serially with other PostgreSQL/campaign suites. The ordinary module run skips this actual tier unless opted in.

Acceptance asserts exact source content, hypothesis posture, supporting assertion identity, published receipt, readback of declarations/scientific views, actual retrieval binding, Runtime wait closure/completion/retention/replacement replay, manifest fingerprint and Studio source/span hashes. Browser, corrected iterations, two-specimen comparison and independent Knowledge/retrieval rebuild are subsequent B2/B3 gates. Harness lines are not production coverage credit; protocol coverage remains separately owned.


## Future-only successor progression

`AMPHORA_TEST_FEEDBACK_SUCCESSOR=1` extends the baseline through `feedback.py`. Public schemas configure Data for immutable synthetic evidence, scoped assessments and captured observation records. Research's public reads supply each exact measurement; an explicit derived evidence artifact includes the captured report, answer and applicability. The fixture checks observed method/context against the predeclared need. Missing evidence first produces an inspectable gap; matching synthetic evidence produces a purpose-limited receipt, never scientific establishment.

A later owner-installed synthetic observation revision adds a quality flag while preserving the original. Installation uses Research's own interpreter/store; this is not physical instrument or deployed lab-intake acceptance. A persisted Knowledge `correct_assertion` proposal cites the revised report and question/need, preserving qualified hypothesis posture. The second assessment explicitly selects profile v2 and the new logical answer/report. Research commits an adjacent correction record; Runtime explicitly admits a second campaign pinned to that receipt. Both campaigns complete and retain outputs. After Runtime replacement the first closed wait and old measurement/receipt remain exact; the newer plan hash differs. No running campaign is repinned and no quality flag globally vetoes useful exploration.

Studio's compiled production feedback reader/model then traverses the actual unmet need, selected assessment/publication, proposal/change, original/corrected receipts and report derivation. B3 owns overlapping-correction race barriers and actual browser-owner traversal; this sequential progression does not claim those later gates. Public DTO/schema validation and scenario protocols have separate unit coverage; orchestration statements are not production coverage credit.
