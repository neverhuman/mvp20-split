# Research scientific Artifact publication

- Status: Research0.31.0: private journal/workflow, hosted scientific APIs, actual Data publication, fresh replacement and nine process-kill barriers verified. This module publishes Artifacts only.
- Owner: Research. Design: [durable science boundary](../../../../../docs/Build%20Plans/BP-06/BP-06.04%20Durable%20science%20design.md).

This module publishes already committed lab intake, eligibility and synthesis results as immutable Data Artifacts with exact derivation provenance. It does not issue DomainReceipts, claim scientific acceptance, reserve Runtime outputs or change campaign pins. Existing publication/ retains its fixed synthetic sufficiency receipt policy and all prior command/history bytes. This module follows the reviewed finite upload protocol using the public tool-protocol SDK; its independent state and namespace prevent receipt-policy substitution.

artifact.py owns ScientificArtifact. Factories accept a resolved StoredIntake or an exact committed eligibility/synthesis decision. Pending/operationally failed intake is not a scientific publication. Canonical JSON preserves the full stored output, original actor, unknown/weak points and all consumed inputs. Each kind has a self-contained payload schema whose exact digest is in ContentDescriptor; the transformation digest pins the kind, record identity and payload hash. Sorted dependencies preserve all actual consumed references. Payloads are capped at8MiB, schemas at1MiB and headers/events at2MiB. Schema registration is explicit fixture/deployment configuration, never a remote arbitrary schema fetch.

store.py re-reads the immutable owner source and verifies that every prepared payload/declaration field matches before committing a publication header. Kind/scope/id/publisher and payload are pinned; a changed publisher or fabricated payload conflicts. Source verification occurs outside the short publication transaction and remains safe because the source journals are append-only. Source content rights and authenticated API grants remain distinct from this local owner check.

research_0009 owns separate science_publication_headers/events and mutable science_publication_leases. Headers/events have SELECT/INSERT grants only; the service may update only holder/fence/expiry columns on leases. PostgreSQL clock and increasing fences gate writes; stale holders cannot append or release a replacement lease. Every append compares the expected event position and reconstructs the bounded prior history. Failed inserts roll back without a new stage. No SQL transaction spans network I/O. Migration is forward-only and explicit; older Research installations without0009 must not migrate the upgraded owner DB.

attempt.py owns ScientificProgress. Stable commands include a scientific-publication namespace, scope, record kind/id, payload hash, publisher, attempt ordinal and command family. Before/after-effect ambiguity preserves the same begin/finalize command. Uncertain stream effects start a fresh ordinal/upload because stream completion cannot be inferred from a lost reply. Eight stream attempts are the ceiling; exhausted attempts retain a failed operational publication, never a negative scientific result. Only exact retained rejection proof for the original command can terminally reject a remote command. Success verifies upload, final Artifact content/schema/scope, original begin command identity/digest, publisher and complete derivation. Terminal data admits only finalized and derivation fields; a supplied DomainReceipt is rejected.

workflow.py uses a fresh AssessmentDataReader for each attempt and the public ArtifactClient/HttpTransport. Before starting a new upload it checks current access to every consumed input. Rights denial is explicit operational failure; peer outage stays retryable. Data independently fences rights at finalization. Begin/finalize receipts reconcile ambiguous effects; interruption during streaming gets a replacement attempt. Lease renewal completes before each peer operation. A published result replays original history without making new-use authorization claims. Finalized publication is not Runtime retention acceptance; later consumers use the existing reservation/confirmation protocol under their own authority.

Tests are isolated under tests/scientific_publication; run dev/run_tests.py --module research --area scientific_publication with AMPHORA_TEST_POSTGRES=1. The actual Data test requires AMPHORA_TEST_DATA_PYTHON pointing to an independently installed Data interpreter. It verifies typed publication, exact bytes/provenance, weak optional focus, no owner transaction during reads and owner-store reconstruction against actual Data HTTP. Its input is an explicitly trusted synthetic model fixture, not authenticated model-result ingestion. Other tests cover all three output kinds, lost acknowledgements, rejected/substituted proofs, bounded retries, rollback, lease replacement and immutable grants. Scripted lost replies/store reconstruction are a separate tier from the nine actual process-kill barriers described below. Hosted integration is verified through scientific_api.

Replacement must preserve source/result bytes, payload schemas, original command identities, retained rejection/finalization proofs, event ordering, publisher attribution, lease fencing and exact provenance. It must never convert a weak exploratory result or successful upload into scientific or Runtime authority. No graph mutation, scientific evaluator, laboratory submission, global consumer discovery or UI is implemented here.
