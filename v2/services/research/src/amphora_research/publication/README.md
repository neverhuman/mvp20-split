# Research assessment publication

- Status: B1.09 implementation; actual Data publication and acknowledgement-loss recovery verified. Public assessment routes remain B1.10.
- Owner: Research0.9.0; [design](../../../../../docs/Build%20Plans/BP-06/BP-06.03%20Research%20assessment%20design.md#b109-publication-implementation-boundary).
- Authority: fixed research.synthetic_sufficiency purpose, never scientific establishment or Runtime execution acceptance.

AssessmentArtifact restores a completed immutable assessment and its full input set. It publishes canonical EvidenceAssessment bytes with the self-contained research.evidence-assessment.payload schema (Draft2020-12, sorted compact UTF-8 plus newline). Its transformation digest binds the configured profile reference including its full-document digest. The profile/request never installs a Data validator; operators explicitly configure that output schema. The output byte ceiling is8MiB; inputs retain the128 limit. No public Research schema bytes change.

SyntheticReceiptPolicy v1 accepts only answered, supported, sufficient results with no need gaps. Contradicted results reject; unresolved/insufficient results abstain. The receipt binds original assessment actor/request, configured publisher/issuer, subject, finalized derivation and policy. Receipt purpose is fixed regardless of the assessment's requested purpose. Accepted output is an ArtifactConstant with representation research.evidence_assessment.v1 and unit1. Result evidence remains available even for abstained/rejected publication. The policy checks content/declaration/producer binding; PublicationProgress additionally verifies the exact original begin command identity/digest and upload linkage before an owner terminal commits.

PublicationStore owns one publication per scoped assessment identity. begin requires the original assessment actor and pins publisher/issuer, method, schema and output identity. It cannot publish pending assessments or replace a completed decision. Forward research_0004 adds append-only publication_headers/publication_events and separate mutable publication_leases. History grants are SELECT/INSERT only. Event limits are48 positions and2MiB per event; headers2MiB. Leases use database time, fresh holder UUIDs and monotonically increasing fences, bounded1..300 seconds. Each write locks/checks the lease and exact expected journal position. No database transaction spans peer calls. Header creation and its lease row are atomic; final derivation and receipt are retained in one immutable event. Reads replay ordered events and validate transitions/receipt bytes; future policy/schema changes require explicit historical dispatch rather than silently rewriting old receipts.

PublicationProgress owns prepared -> begun -> streaming -> streamed -> finalizing -> published. Begin/finalize IDs are stable hashes of scope, assessment identity, configured publisher, attempt ordinal and command family. An uncertain streaming attempt can only be explicitly replaced, up to8 attempts; the old provisional upload remains Data-owned cleanup work. Finalizing cannot be abandoned or replaced. Matching original-command rejected observations may terminate prepared/finalizing; missing/mismatched proof stays pending. A denied input before publication or exhausted stream attempts produces a failed record with no receipt. Failure does not promise absence of provisional external effects.

PublicationWorkflow uses only public ArtifactClient/WorkerIdentity/HTTP contracts. It checks current Data access to every retained input before begin, then relies on Data's own begin/finalize authorization; this is not a cross-owner authorization lease. Transport uncertainty remains pending. It writes streaming before PUT and never retries ambiguous PUT on that upload. SDK begin/finalize use receipt-first reconciliation. A stale holder may finish a provisional external request but cannot advance the Research journal. Terminal replay returns immutable metadata without reevaluation or fresh source reads; any later payload use remains subject to Data rights. The private caller must supply authenticated original scope/actor; public route authentication is B1.10. No background scanner, Runtime wait delivery or cross-owner SQL is implemented here.

Verification is module-owned under tests/publication. Real PostgreSQL cases cover immutable history, actor/publisher substitution, lease contention/expiry/fences, command/result/proof substitution, bounded streams, atomic terminal rollback and replacement replay. Scripted client cases isolate lost acknowledgements and rejection-proof availability. tests/assessment/test_actual_resolution.py additionally uses production SDK calls to actual independently hosted Data/Knowledge services and drops real begin/PUT/finalize responses after success; uncertain streams move to ordinal2 while begin/finalize keep original identities. This is acknowledgement-loss recovery, not OS process-death or target-host power-loss evidence. Publication-specific process death remains a later acceptance gate. Coverage gaps are defensive corrupt-history handling, missing-assessment path and workflow race/scope/lease-release/progress-limit branches; normal policy and transition statements/branches are fully covered.
