# Research Identity Read Transport

- Status: BP-06.01/B3; authenticated identity resolution and explicit loopback hosting implemented.
- Public contracts: ResolveIdentity and IdentityResolution from amphora-contracts-research0.2.0. No peer implementation imports.

POST /v1/identities/resolve accepts a wire1 scope plus exact candidate/sample revision references. Credentials authenticate opaque bearer tokens into one configured actor/scope/action grant. The resolver checks the request scope and both nested reference scopes before any database lookup. Records are immutable, so separate exact-revision reads cannot combine changing record contents. Unknown records quarantine; transport/database failure is503, never an unknown-identity result. Matching returns authority=identity_only and no artifact payload/reference, fitness, Knowledge publication or scientific acceptance.

The JSON body is at most16KiB and must finish within5 seconds. Content type is explicit. Duplicate keys, nonstandard JSON constants, malformed UTF-8, invalid schema and oversized bodies fail with bounded error codes. Schema parsing is JSON-mode and strict. Denials are401/403; malformed requests422; excessive bytes413; unsupported media415; body timeout408. Error responses do not reflect source text, database diagnostics or credentials. Published request/response schema roots are canonical; the thin route reads Request directly to enforce these limits before DTO construction.

ResearchHost.configured accepts only database_url_env and1..32 principals, each with token_env/actor_id/scope/actions. Secrets come from explicit environment references. Serving requires the research_service database role, an already migrated schema and explicit resolve_identity and/or read_declarations grants. No import-time startup or automatic migration. The host uses a4-connection pool plus2 overflow,2-second pool timeout,5-second connection/statement timeouts,16 concurrent HTTP tasks and127.0.0.1 binding. Operator configuration is not a user-supplied graph node.

`amphora-research check --config config.json` verifies configured owner access; `serve --config config.json --port 8084` starts the local service. `python -m amphora_research` is equivalent. /health reports process identity-only capability, not database readiness or scientific validity. Hosting owns engine disposal. Identity publication remains an owner-private operation; this read endpoint cannot create or rewrite candidates/questions/samples.

Tests in services/research/tests/api use real PostgreSQL for exact, missing and denied references, and scoped fault injection for database unavailability. tests/identity and tests/persistence remain independently runnable. Installed-wheel HTTP evidence starts, terminates and replaces the Research process while preserving exact lookup results; it does not yet prove the Data acquisition client or process-kill during a write. Body-timeout/disconnect races and comprehensive deployment hardening remain explicit acceptance work, not implied by route-unit coverage.

## Scoped question and evidence-need reads

POST /v1/questions/read takes ResearchQuestionRef and returns the exact immutable ResearchQuestion; POST /v1/evidence-needs/read takes EvidenceNeedRef and returns EvidenceNeed. Both reuse contracts0.2.0 and require read_declarations for the reference scope before SQL. They share the strict bounded JSON decoder and safe failures above; unknown revisions return404, database failure503, and successful/history responses use Cache-Control:no-store. Reads never select a mutable latest revision. DeclarationReader owns scoped selection; the ledger remains private. Identity-only grants do not permit declaration reads.

Returned applicability/context ArtifactRefs require a separate Data credential and current Data policy to retrieve bytes. Question/need declarations neither assert that bytes exist nor interpret results, accept evidence, publish Knowledge or grant access. Public reads do not introduce writes. QEV-01 uses actual separately hosted Research and Data, finalized artifact bytes and independent credentials; wrong-owner tokens fail. Test-only Research publication runs within a Research-owned setup process. Independent installed peers are accepted below.
