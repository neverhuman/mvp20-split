# Authenticated interpretation boundary

Design status: Research0.30.0/contracts0.14.0, BP-06.04/B2.04a private workflow implemented; optional hosting/grants/routes and actual HTTP transitions remain b/c. Owner architecture: [experiments](../../../../../docs/Architecture/Research/Experiments.md).

This focused Research module composes the [interpretation store](../observations/interpretation/README.md) with a fresh bounded AssessmentDataReader. It does not own scientific policy, original observation/material/experiment writes, migrations, publication or campaign execution. Other services consume public versioned Research contracts; private Research objects and storage stay inside the owner.

`profiles.py` admits at most32 unique reviewed InterpretationProfile values after complete semantic/hash reconstruction. This registry governs new work only. `workflow.py` strictly validates reference-only requests/scope and pins the complete original actor/profile/request before peer work. A pending retry uses that stored profile even after it is removed from active configuration. Exact owned inputs and full explicit dependencies are prepared with the database connection closed before network access.

Each new-use attempt receives a fresh scope-bound reader with no consumed cache. It reads every required Artifact under current Data authorization, then calls atomic owner completion with the complete consumed set. Reader limits remain30 seconds,128 Artifacts,384 calls,16MiB per source and32MiB total; errors propagate distinctly. Revocation, missing source or peer outage leaves pending operational work and cannot manufacture an unresolved scientific verdict. A completed normalization may legitimately be unresolved under its pinned policy. Source authentication does not validate the science or bypass the earlier report-producer/intake boundary.

`status.py` explicitly maps stored progress to InterpretationStatus: original request/actor, then either pending or interpreted with a typed normalization/use projection. Completed submit replay and reads use committed history without current-profile lookup or Data reads. They do not confer new source rights. Changed inputs/actor/scope cannot retarget a stable job id. There is no current-head selection, live correction adoption, active invalidation, Artifact publication or Runtime receipt authority.

Tests live in `services/research/tests/interpretation_api`; use `dev/run_tests.py --module research --area interpretation_api`. Workflow probes use actual owner PostgreSQL and scripted reader behavior. They prove pin-before-peer ordering, fresh retry authorization, complete dependency consumption, retired-profile resume, offline history and action/scope identity. They do not establish independent HTTP producer/authorization behavior; B2.04c owns that tier. Replacement must preserve stored intent semantics, public status variants, original pins and explicit source-failure handling.
