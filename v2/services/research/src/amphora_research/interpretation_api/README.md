# Authenticated interpretation boundary

Design status: Research0.31.0/contracts0.14.0, BP-06.04/B2.04 authenticated workflow, optional hosting and actual independent HTTP transitions verified. Owner architecture: [experiments](../../../../../docs/Architecture/Research/Experiments.md).

This focused Research module composes the [interpretation store](../observations/interpretation/README.md) with a fresh bounded AssessmentDataReader. It does not own scientific policy, original observation/material/experiment writes, migrations, publication or campaign execution. Other services consume public versioned Research contracts; private Research objects and storage stay inside the owner.

`profiles.py` admits at most32 unique reviewed InterpretationProfile values after complete semantic/hash reconstruction. This registry governs new work only. `workflow.py` strictly validates reference-only requests/scope and pins the complete original actor/profile/request before peer work. A pending retry uses that stored profile even after it is removed from active configuration. Exact owned inputs and full explicit dependencies are prepared with the database connection closed before network access.

Each new-use attempt receives a fresh scope-bound reader with no consumed cache. It reads every required Artifact under current Data authorization, then calls atomic owner completion with the complete consumed set. Reader limits remain30 seconds,128 Artifacts,384 calls,16MiB per source and32MiB total; errors propagate distinctly. Revocation, missing source or peer outage leaves pending operational work and cannot manufacture an unresolved scientific verdict. A completed normalization may legitimately be unresolved under its pinned policy. Source authentication does not validate the science or bypass the earlier report-producer/intake boundary.

`status.py` explicitly maps stored progress to InterpretationStatus: original request/actor, then either pending or interpreted with a typed normalization/use projection. Completed submit replay and reads use committed history without current-profile lookup or Data reads. They do not confer new source rights. Changed inputs/actor/scope cannot retarget a stable job id. There is no current-head selection, live correction adoption, active invalidation, Artifact publication or Runtime receipt authority.

Tests live in `services/research/tests/interpretation_api`; use `dev/run_tests.py --module research --area interpretation_api`. Workflow probes use actual owner PostgreSQL and scripted reader behavior. They prove pin-before-peer ordering, fresh retry authorization, complete dependency consumption, retired-profile resume, offline history and action/scope identity. They do not establish independent HTTP producer/authorization behavior; B2.04c owns that tier. Replacement must preserve stored intent semantics, public status variants, original pins and explicit source-failure handling.

## Optional configured transport

`host.py` parses optional normalization_profiles and observation_use_profiles under the existing science configuration. Existing configurations remain valid without either field; omitted means zero active interpretation profiles. Complete semantic/hash checks still apply. The combined lab/eligibility/synthesis/normalization/use count is at most32, with duplicate interpretation references rejected. Existing loopback/environment-secret constraints,64KiB CLI configuration ceiling, no-startup-migration policy and table readiness checks remain.

`operations.py` applies explicit Principal grants before workflow/store access. POST /v1/observation-normalizations requires normalize_observation; /v1/observation-uses requires assess_observation_use; /v1/observation-interpretations/read requires read_observation_interpretation and original actor. POST /v1/observation-corrections/read and /v1/material-state-corrections/read require read_scientific_record. POST /v1/material-state-impact requires read_scientific_impact; /v1/interpretation-impact requires read_interpretation_impact. Every operation checks exact principal scope. Read grants cannot start a computation or author corrections.

`routes.py` registers these focused endpoints through the existing bounded strict-JSON transport: application/json,256KiB request/5-second body limit, duplicate/nonfinite/extra-field rejection and no-store responses. Missing records/profiles are404; missing credentials401; denied scope/action/original actor403; source/owner outage503; unsupported media415; body limit413; malformed domain requests422; immutable identity conflict409. Source denial cannot become a completed scientific negative. Legacy configuration and scientific routes retain their public request/response schemas. Tests/interpretation_api/test_routes.py use configured host, real PostgreSQL and scripted source readers or a deliberately unavailable loopback source. c owns actual independent peer proof.

## Actual HTTP and replacement evidence

B2.04c runs separate installed Data, initial Research and fresh Research replacement processes. The test owner declares samples/experiments privately and publishes real sample-identity/source Artifacts through Data HTTP. Actual lab intake, exact normalization, weak-but-usable focus, strict action exclusion, correction before pending interpretation completion, explicit later corrected input, exact impacts, current Data access denial, zero-active-profile offline replay and restored-access retry pass from source and installed Research test interpreters. Test helpers live in tests/interpretation_api/actual_fixtures.py and test_actual_workflow.py.

Opt-ins: AMPHORA_TEST_POSTGRES, AMPHORA_TEST_DATA_PYTHON, AMPHORA_TEST_RESEARCH_INTERPRETATION_PYTHON and AMPHORA_TEST_RESEARCH_INTERPRETATION_REPLACEMENT_PYTHON. AMPHORA_INTERPRETATION_HTTP_EVIDENCE optionally captures bounded fixture evidence. This is synthetic interpretation input/replacement proof, not new Runtime campaign authority, physical science, per-source rights-revision proof, quality UI or crash-at-barrier evidence. B3/V1 own the remaining failure and closeout tiers.
