`IdentityLedger.publish(scope, record)` validates a candidate/sample/question/need document under an explicit scope, obtains a transaction-scoped advisory lock for its stable scoped identity, then replays identical canonical bytes or rejects an immutable revision collision. A new revision must immediately follow the persisted head. Candidate references and question/criterion bindings resolve to exact owner records before insertion. Immutable records, reference links and head advancement commit in one PostgreSQL transaction. Reads are explicitly scope/kind/id/revision addressed, never implicit latest.

Canonical bytes use sorted-key compact UTF-8 JSON, finite bounded integer revisions and a256KiB record ceiling. This is a Research record fingerprint, not a new persisted-command profile. Publication has no network/LLM/filesystem effects. The adapter must provide authenticated scope; any artifact consumption requires current Data authorization. This private store records declaration references without consuming payloads and is not a public authorization endpoint. Methods do not automatically retry infrastructure failures. Caller retry with the same immutable record reconciles commit uncertainty.

`research_service` can SELECT/INSERT records and links and update only the head revision column. It cannot UPDATE/DELETE historical records, create tables or read peer schemas. Scoped foreign keys preserve exact local references. SQL statements parameterize values; kind choices are closed. Source bytes and cross-owner SQL are never used. Non-null material-state references now resolve to exact separately owned material-state records; the sample candidate must match. A sample-to-state link commits with the sample identity and head. Missing state stays unknown.
