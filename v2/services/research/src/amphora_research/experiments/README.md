# Research experiment expectations

- Status: Research0.31.0: immutable experiment storage and exact public reads implemented; authenticated lab intake consumes these records through observations/scientific_api. Physical submission and custody workflows remain outside this module.
- Owner: Research. Design: [Experiments](../../../../../docs/Architecture/Research/Experiments.md).

identity.py owns scoped ExperimentReference and immutable one-step ExperimentIdentity revision chains. model.py composes an Experiment from ProtocolContext, exact SampleContext entries and MeasurementExpectations. Each expectation identifies its sample, readout criterion, numeric/categorical/series shape, exact units and replicate/control role. ProtocolContext requires a method revision plus scoped applicability/source Artifacts. Applicability is a reference to reported context, not a universal assay-validity policy.

SampleContext composes the existing SampleDefinition boundary. Supplied material state must match the specimen's exact state and candidate references. A missing state stays unresolved even if the sample names a state reference. Experiment lookup returns an exact expected sample/readout or None; it does not search for similar materials. Collections are bounded and reject duplicate sample references/expectation IDs, cross-scope samples and unbound expectations. Multiple controls/replicates remain distinct expectations.

The pure experiment model has no I/O, persistence, authentication, scheduling, LIMS/CRO submission, statistical aggregation or scientific eligibility authority. Dependencies are public core/research contracts and private Research identity/material/measurement objects. Public DTO mappings preserve these boundaries; storage adapters preserve them; callers outside Research cannot import them. Unknown state and weak quality do not impose a global campaign gate.

Replacement tests live in tests/experiments; select with dev/run_tests.py --module research --area experiments. Preserve exact method/context/sample/state identities, control roles, original units, unknown state and correction immutability. Invalid structures raise stable ExperimentError codes; invalid measurement unit tokens retain MeasurementError. Physical experiments remain unimplemented. Authenticated synthetic report reconciliation and actual-peer proof are owned by observations/scientific_api.

BP-06.04/B1.04, Research0.16.0/contracts0.7.0: wire.py now maps ExperimentDefinition, including existing SampleIdentity and optional full MaterialStateRevision. Decode reconstructs the aggregate and rejects unbound/swapped specimens. Public contracts are exported only from amphora_contracts_research. No new storage, source authentication, HTTP API or campaign effects are added by these mappings.

Research0.17.0 storage boundary: store.py owns ExperimentStore over research.experiment_revisions and experiment_samples. It compares every embedded SampleIdentity and supplied MaterialStateRevision to exact persisted owner records; matching reference labels cannot substitute different content. Missing supplied state remains unknown. Record and sample links commit atomically; no physical lab submission occurs. Shared private revisions.py provides closed-table transaction mechanics only. See [persistence](../persistence/README.md) for exact replay,1MiB canonical limit, actor/scope, append-only grants and migration rules. Tests in this module include actual PostgreSQL with AMPHORA_TEST_POSTGRES=1; run PostgreSQL suites serially. Store replacement must replay original bytes and preserve all historical references.
