## Durable intake boundary

intake.py owns IntakeIntent and IntakeTerminal. Reference-only requests pin the reviewed full-profile digest and exact report Artifact. Bind revalidates configuration/request shape, actor and scope; canonical intent includes the full profile and original actor. Rebuild uses persisted configuration, not current selection. A terminal preserves reconciliation, sorted exact consumed Artifacts and separate pending/resolved/operational-failure status. Explicit failure is not scientific ineligibility. Required report/raw/protocol/applicability references cannot be omitted. Inputs are bounded at128, reports at64 distinct observation identities, intents at2MiB and terminal bytes at8MiB. No averaging, evidence-quality gating, or campaign repinning is added.

intake_store.py owns LabIntakeStore and StoredIntake over research_0007 lab_intents, lab_terminals and lab_observations. begin commits intent before the caller resolves sources; complete accepts the private authenticated resolver result, validates/domain-reconstructs every observation outside the transaction, then locks intake followed by observations in stable identity order. Observation revisions, exact membership links and terminal commit together; a late conflict rolls everything back. Each observation retains the existing1MiB ceiling. No network I/O occurs inside a store method. Callers must supply authenticated resolver results; the private store is not an HTTP authentication boundary.

Exact begin/terminal retries preserve stored bytes and original attribution. Changed actor/request/profile or conflicting terminal fails explicitly. The first committed terminal is immutable; a failed operational attempt cannot overwrite successful results, or vice versa. Source outages before completion leave a retryable pending intent. Historical read requires matching scope/original actor and returns original configuration/outcome; current source disclosure/grants belong to scientific_api and the Data owner. The store does not discover arbitrary consumers, publish Artifacts or create Runtime receipts.
