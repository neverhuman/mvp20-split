# Observation interpretation boundary

Design status: BP-06.04/B2.03 durable interpretation and impact reads implemented; authenticated API remains B2.04. Research0.29.0/contracts0.13.0. Owner architecture: [experiments](../../../../../../docs/Architecture/Research/Experiments.md).

This private Research module reconstructs reviewed conversion/action-use profiles, binds reference-only requests and computes immutable content-addressed projections. It imports public core/research DTOs and private Research observation/experiment objects. Other services use the public contracts; no private cross-service imports or shared database authority exist.

`profiles.py` owns `InterpretationProfile`: exact scope, one closed policy kind, complete reviewed catalog/action requirements, transitive content hashes and strict request identity. Catalog reconstruction reruns exact-decimal, direction, dimension and resource invariants. Action-use reconstruction verifies its own hash and any nested catalog hash. Requests cannot supply replacement values or verdicts. Use requests preserve order and reject repeated observation identities, including different revisions posing as independent replicates.

`wire.py` maps computed values only. Original lexical values, units, censoring, uncertainty, control claims and quality flags remain visible. Raw and effective matching are distinct; `state_bound` means a referenced state record exists, not that its scientific context is known. `focus` identifies next-campaign attention independently of per-action blockers/gaps. There is no campaign-wide quality verdict, numeric confidence invention or scientific acceptance.

`document.py` computes results from original domain objects after verifying exact requested observation/experiment references. The full profile, original actor, scope, stable interpretation id, original/result content and supplied consumed source list determine the digest. Canonical JSON has an8MiB ceiling; at most128 exact scoped Artifacts are retained, duplicates collapse and conflicting identities fail. No truncation or rounding occurs. Empty use batches retain missing-expectation coverage. Unknown normalization remains a completed unresolved computation, distinct from operational inability to authenticate inputs.

The pure builders remain distinct from the store described below. Supplied consumed sources are private preparation inputs, not proof of source rights. B2.04 must authenticate new-use reads and expose separately granted HTTP routes. No Artifact publication, DomainReceipt, Runtime retention, active invalidation or campaign repinning is conferred. Corrections remain future-campaign inputs.

Tests belong in `services/research/tests/observations/interpretation`; `dev/run_tests.py --module research --area observations/interpretation` is the granular entry. Contract examples/schema tests belong in `contracts/research/tests/test_interpretation.py`. Replacement must preserve complete profile hashing, exact reference binding, original evidence, per-action semantics, output bytes and bounded resources. Source and installed-wheel evidence is tracked by the owning plan; UI display remains SQ-01.

## Durable interpretation storage

`intent.py` pins full reviewed profile, original actor and exact reference-only request in at most2MiB of canonical JSON. `preparation.py` loads exact stored immutable observation/experiment revisions and enumerates required report, protocol, applicability, sample identity and material preparation/feature sources. Conflicting source identities, cross-scope dependencies and more than128 Artifacts fail explicitly. Observation binding claims do not become verified material-state dependencies: only actual embedded owned experiment states are indexed. No latest-head lookup or equivalence inference occurs.

`store.py` owns begin/prepare/complete/read. Begin durably accepts configuration before peer work. Prepare closes its database connection before external source reads. Complete computes from private domain inputs, rechecks exact owned content, then commits result and source/observation/material/experiment links in one transaction. Scoped advisory locks serialize retries; stable job identity rejects changed actor/configuration/inputs. Six append-only tables in research_0011 grant the application SELECT/INSERT only. Result identity is also its exact intent association, so no separate mutable completion flag can diverge.

Missing owned input or failed authentication leaves pending operational work, not an unresolved scientific result. A computed unknown conversion may complete as unresolved. Completed begin/read retries require original actor/configuration and can return stored history offline. Source rights are not renewed by history reads. Corrections appended after acceptance do not change pinned inputs, including work not yet completed. Later jobs may explicitly select corrected revisions. No SQL transaction spans Data calls; the store itself has no peer client.

Tests include actual PostgreSQL concurrency, atomic rollback at every result/index insertion, original actor/configuration conflicts, same-reference forged content rejection, source omission, complete material evidence dependencies, absent material context, original pin after correction, exact replay and role-based UPDATE/DELETE denial. These are owner storage proofs; actual HTTP source authentication and process-barrier replacement remain B2.04/B3/V1.

`index.py` exposes explicit known dependencies by exact Artifact bytes, observation revision or verified material-state revision. Pages hold at most128 InterpretationRef values; cursor scope/id/digest is checked against an actual committed result. C-locale kind/id ordering gives deterministic continuation, not a snapshot of concurrent additions. New earlier-sort entries need a fresh scan. This read-only index has no current-head selection, consumer discovery, source-rights renewal or active campaign effects. InterpretationImpactRequest/Page are separate from scientific decision indexes. Tests/observations/interpretation/test_index.py prove exact revisions, full Artifact identity, paging, scope and cursor rejection.

B3.02 actual process proof lives in tests/interpretation_api/test_actual_interruptions.py and the test-only fault_host.py (excluded from wheels). Separate installed Research/Data/replacement owners cover lab intake and interpretation at intent committed, result transaction before commit, and result committed before reply. Six source and six installed cases pass: no partial revisions/results/indexes, original intent hash/actor/policy retained, removed active profiles resume pending work only after fresh Data access, committed history replays offline. Opt-in/evidence paths are documented in the interpretation API README. This establishes process failure, not host power-loss durability.
