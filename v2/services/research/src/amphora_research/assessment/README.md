# Research assessment policy

- Status: BP-06.03/B1.07 producer resolution implemented; exact owner/peer binding and actual Data/Knowledge proof verified. B1.08 immutable assessment storage is verified; B1.09 publication is implemented in the adjacent publication module; B1.10 optional HTTP composition is implemented in the transport module. No public caller can submit trusted observation fields.
- Design: [Research assessment boundary](../../../../../docs/Build%20Plans/BP-06/Completed/BP-06.03%20Research%20assessment%20design.md).
- Authority: synthetic decision policy only; no scientific establishment or Runtime receipt.

`AssessmentPolicy` binds an exact Research question, policy id/version/purpose and1..128 needs. Every question criterion must have a declared need. It validates the existing question/need invariants and fingerprints canonical UTF-8 JSON, including full immutable declarations, categories and issuer sets. This private fingerprint has its own format tag; it is not a persisted command encoding. Requirements have deterministic declared order; category/issuer sets are sorted before hashing.

`CandidateAnswer` maps a criterion to an immutable answer artifact and a Knowledge-derived logical disposition. `EvidenceObservation` represents an authenticated producer observation projected by the authenticated resolver: receipt artifact, need revision, criterion, answer subject, method, context, category, issuer, purpose, authority and disposition. These private dataclasses **do not authenticate their own content**. They must never be exposed as caller-trusted request DTOs. The private resolver implements that adapter; the optional public transport now accepts references only.

`assess` accepts immutable tuples, at most32 answers and256 observations. It rejects duplicate answers/unknown criteria, wrong-scope answers and repeated receipt identities even if the digest changes. Receipts are sorted by scoped identity; no duplicate can multiply evidence. Exact reference comparison covers full ArtifactRefs and method schema digest. Mismatched scope/need/criterion/answer/method/context/category/issuer/purpose/authority and unknown disposition remain named review results. Opinion, simulation, observation and independent replication have no numeric hierarchy; a stronger-sounding label cannot substitute for a configured category. Replication independence is not inferred or checked here.

Every criterion/need pair returns supporting and contradicting receipt references plus an explicit gap. Conflict has precedence and produces unknown; unopposed negatives produce contradicted; remaining gaps produce unknown. Only complete supported answers with every need satisfied produce supported/sufficient. `answered` only reports complete answer-artifact coverage. `scientifically_established` is always false. A configured synthetic fixture is the only admitted authority; receipt transport/publication and scientific claims are outside this module.

The pure policy performs no SQL, network, filesystem, mutable-cache or external effect; the resolver and store below own I/O. Dependencies are the owner's question policy and public Core/Research contracts. Inputs/outputs are private domain objects, not a new public API. Transport must authorize and resolve immutable references before invoking the policy; durable assessment and receipt must commit before future public success. A rebuild must preserve fingerprint bytes, deterministic ordering, exact-reference matching and failure codes or explicitly version them.

`ConfiguredAssessment.from_wire` compiles Research contracts0.3.0 profiles into the private policy. It requires same-scope subject, complete unique criterion targets and unique publisher/category/issuer declarations. Its public reference hashes the complete profile (including adapter trust, expected target digests and subject); this differs intentionally from AssessmentPolicy.sha256, which fingerprints only the private sufficiency algorithm's inputs. The public request always selects the full profile fingerprint. Do not replace one digest with the other.

`bind` validates authenticated scope supplied by the eventual adapter, exact profile/question, unique known answer criteria and scoped artifacts/receipt identities. `BoundAssessment.evaluate` requires exactly the requested resolved answer/receipt references, calls the domain policy, then explicitly maps decisions/gaps/reviews to an EvidenceAssessment. This is not authentication: only the verified peer resolver may supply logical dispositions and EvidenceObservation values. The optional transport exposes reference-only routes, never these private objects. Status assessed means a decision record, not published output or Runtime acceptance.

## B1.07 Data transport checkpoint

Research0.6.1 adds `AssessmentDataReader`, a private public-protocol client with Core/Artifacts DTO dependencies. Construct it per resolution attempt with explicit127.0.0.1 HTTP endpoint, bearer credential and authenticated scope. It reads only Data artifact metadata/content and derivation routes. It verifies exact metadata, content length/SHA-256, scoped derived-command identity and producer actor membership in a caller-supplied **trusted configuration** allowlist. The eventual resolver must obtain that allowlist from ConfiguredAssessment, never from an assessment caller. This read module does not validate the scientific or logical meaning of payloads.

Limits:128 distinct artifact identities,384 HTTP calls,32MiB total received bytes,16MiB per artifact,256KiB per metadata response,30-second attempt deadline and at most5-second inactivity. A timer interrupts trickling response headers at the overall deadline. Reads have no redirects, retries or proxies. Equivocal references fail before further I/O. Only successfully validated content appears in `consumed`, sorted by identity; lineage and payload caching lives only within this attempt. A new assessment/retry must create a fresh reader and observe current Data rights. A historical readable derivation cannot bypass denied payload access. This observation is not an atomic rights lease.

401/403 and404 yield explicit denied/missing-reference codes; other non200 responses, invalid peer JSON and network/deadline failures raise AssessmentPeerUnavailable and must leave a future durable request pending. They are never an evidence contradiction. Strict JSON rejects duplicate keys, nonfinite constants and malformed UTF-8; peer bodies/credentials are excluded from failure messages. The client performs no SQL or peer writes.

`tests/assessment/test_reader.py` uses a real loopback **scripted HTTP server**, including denial, outage, integrity/lineage mismatch, untrusted producer, scoped budgets, multi-chunk payloads and delayed/trickling headers. That reader-only checkpoint did not prove actual Data/Knowledge compatibility. The producer-resolution section below records the subsequent actual-peer proof; the earlier installed0.6.0 evidence remains scoped to its original boundary.

## B1.07 producer resolution

Research0.7.0 adds `AssessmentResolver.resolve(bound)` with the owner's IdentityLedger and a fresh AssessmentDataReader. It compares full exact question/need records with the installed profile before network I/O; each owner SQL read closes before Data reads begin. It reads the configured subject/applicability/need contexts under current Data authorization. All successfully consumed references form the returned ResolvedAssessment.inputs for later derived publication; there is no assessment write, public API or output publication yet.

An answer must use Knowledge's exact public reasoning payload schema and a permitted Data publisher. Verify its derivation includes context/subject and its transformation digest binds the producer's signed-ground-Horn profile plus exact rule-set reference. The resolver consumes public Knowledge DTOs, never that service's implementation or SQL. Request scope, subject, context and purpose must match the installed profile. Findings must correspond exactly to unique requested targets; all target/assertion/proof references stay in the selected graph. The selected criterion matches the configured canonical GroundLiteral digest. Incomplete results and logical conflicts remain unknown; nonconflicting negatives remain contradicted. The pinned answer artifact preserves exact assertion revisions and proof. Research does not reimplement Knowledge inference.

`SyntheticEvidenceRecord` is consumed only after exact schema/content and Data publisher checks. Its issuer must equal the authenticated publication-origin actor. Its subject/context must appear in the derived inputs, and its declared method must match the transformation descriptor. Scope is checked before additional reads. Only then does the resolver construct EvidenceObservation. Correctly attributed but wrong method/context/category/purpose/need remains a named policy review and explicit gap. A raw uploaded JSON object that looks valid cannot impersonate a trusted derived publication.

Verified transport-envelope errors remain retryable AssessmentPeerUnavailable; malformed immutable artifact content, after successful hash verification, is an invalid-evidence-payload error. Peer outage never becomes a negative finding. Caller verdict fields are still forbidden. ConfiguredAssessment/BoundAssessment remain private authenticated-adapter inputs; caller authentication for a public submit route is B1.10, not provided by calling this Python class directly.

CandidateAnswer now retains a private conflict flag. A reproduced case showed that collapsing Knowledge conflict into generic unknown let negative evidence override it. Conflicting answers now force overall unknown, retaining supporting/contradicting references and the pinned Knowledge artifact; no public schema changed for this correction. Independent replication remains a synthetic producer category, not an inferred scientific quality guarantee.

Tests split pure projection (`test_resolution.py`), scripted transport (`test_reader.py`) and actual PostgreSQL/HTTP (`test_actual_resolution.py`). The actual-peer test constructs a graph through Knowledge's public authoring API, reasons and publishes through its production routes, then evaluates missing/opinion/matching synthetic evidence, wrong credentials, source revocation and outage. Research accesses only its own ledger. `dev/verify_research_assessment.py` installs Research without peer implementations and reuses explicit independently installed Data/Knowledge interpreters for this proof. Immutable assessment storage is verified below; publication recovery and live Runtime receipt consumption are now verified in adjacent module/acceptance evidence; child closeout remains separate.

Tests: `tests/assessment/test_policy.py`, selectable using `dev/run_tests.py --module research --area assessment`; pure evidence-category/identity/conflict/gap/fingerprint tests. These tests do not prove producer authentication, live scientific evidence, database recovery or Runtime receipt consumption. Those remain the B1/B2/B3/V1 gates in the owning design.

## Immutable assessment storage

Research0.8.0 adds AssessmentIntent, StoredAssessment and AssessmentStore in store.py. The authenticated adapter calls begin(bound) before resolution, then complete(bound, resolved) after public-peer I/O has ended. read(scope, assessment_id, actor_id) returns the pinned intent and optional resolved decision. It checks the original actor; another scope yields no record. These private methods are not public authorization endpoints. The optional submit route returns stored decisions without reevaluating them. Current source authorization will be checked again before publishing derived output.

The intent pins the full configured profile, exact request and actor in sorted compact UTF-8 JSON. Profile/request array ordering is significant. The decision pins the full result and every consumed ArtifactRef, sorted by artifact ID. Required profile/request references must all be present; inputs must have matching scope and unique IDs, with a128-input ceiling. This trusts the private authenticated resolver to establish producer claims; storing a DTO is not proof of producer authenticity. Reference identity preserves access to immutable source evidence without copying foreign payloads into Research SQL.

Forward research_0003 adds append-only assessment_intents and assessment_decisions. Only SELECT/INSERT grants are given to research_service; a scoped foreign key prevents orphan decisions. Intent bytes are limited to2MiB and decision bytes to8MiB in both Python and SQL. No truncation, mutation, implicit revision lookup, peer SQL or network operation occurs. A stable scoped transaction advisory lock serializes each identity. Identical retries replay; changed actor/request/profile conflicts, as does a differing terminal decision. Retry after ambiguous commit uses the original identity. Failed transactions roll back. A failed resolution leaves the intent pending; no failed network attempt becomes a negative finding. Partial network observations are not frozen, while a committed decision and its complete inputs are frozen together.

Tests in tests/assessment/test_store.py use retained PostgreSQL and service credentials for replay, actor/scope separation, conflicting concurrent writers, rollback after insertion, role denials, bounds and orphan rejection. test_actual_resolution.py also stores actual Data/Knowledge-derived assessments and reads them through a replacement store. The installed verifier proves wheel migration packaging and isolated-owner behavior. No output artifact, DomainReceipt, public assessment API, automatic pending-work scheduler or target-host power-loss durability is provided by this store; B1.09/B1.10 and later gates own those boundaries.
