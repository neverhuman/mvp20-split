# Successor admission boundary

Status: BP-04.04/B2/B3 verified; V1 installed-peer acceptance active. Runtime 0.10.0; graph-runtime contracts 0.4.0. Architecture: [Successor admission](../../../../../docs/Architecture/System/Graph_Successor_Admission.md).

This module resolves explicit carried values from a terminal predecessor and records immutable ancestry for a new reviewed run. It owns source-cut readiness, value fingerprints, transfer identity and bounded source/lineage observations. The coordinator owns admission/frontier creation; lifecycle owns worker reconciliation; Artifact owns bytes/protection. No network I/O, scientific interpretation, topology editing or cross-service SQL occurs here.

`SourceCut` loads a scoped graph run and its persisted outputs. Admission locks the predecessor after the global admission guard, requires its exact plan digest/revision, terminal status, zero reserved budget, no unsettled/leased/uncertain attempts and no prepared completion/binding/wait-retention intent. A carried source is a named run export or a named output of one succeeded graph activation, including a retained checkpoint from a subsequently cancelled run. Notifications do not confer execution authority.

`CarryTransfer` resolves exact value hashes and combines carried and fresh inputs with unique ports. The existing `BoundValues` validator checks the new plan's schema, representation, unit, collection/missing-slot and scope compatibility. Compilation still validates tool/checkpoint pins. This transfers committed data; it does not resume an old worker attempt. New invocations use new run-scoped identities.

Value fingerprints use SHA-256 of sorted compact ASCII JSON with profile `amphora-carried-value-v1` and the fully serialized GraphValue. Transfer fingerprints use profile `amphora-successor-transfer-v1`, predecessor cut, new plan digest, carried mappings sorted by target port and all resolved inputs sorted by port. Preserve these byte profiles across replacement.

Migration `runtime_0014` adds `runtime.graph_successors`, keyed by scoped successor run, referencing predecessor/new runs, retained parent plan and both audit cuts. Service privileges are SELECT/INSERT only. Its mapping and transfer digest commit with the new run, admission audit/outbox and original command receipt. A rollback leaves no successor or ancestry. Rejected command replay remains rejected; accepted replay returns its original receipt before rechecking changed history. Distinct proposals may create sequential siblings, but the installation-wide one-active-run rule remains.

Public contracts are `SuccessorProposal`, `CarrySources` and `SuccessorLineage`. Configured graph HTTP exposes POST `/v1/graph-runs/successors`, GET `/v1/graph-runs/{run}/carry-sources` (optional one `activation_id`) and GET `/v1/graph-runs/{run}/lineage`. Source observation is advisory and repeatable-read; admission rechecks under lock. Missing/foreign runs or sources return 404, malformed activation IDs 422. Admission policy rejection is an ordinary durable command receipt. An ordinary run has no successor-lineage document.

Tests belong to `services/campaign_runtime/tests/successors/`; the source-derived split campaign belongs to `tests/baseline/test_successor_graph.py`. Run them independently with `dev/run_tests.py --module runtime --area successors`. B2 proves actual PostgreSQL transaction behavior and HTTP via TestClient; source orchestration uses real in-process kernels and a scripted Artifact peer. B3 competing-process/crash proof passed; V1 owns new tools with independently installed real peers. Replacement must retain old plans, inputs, accepted outputs, schema bytes, source pins, ancestry and original receipts. Target-host power-loss and scientific validity are outside this module.
