# Runtime Persistence Boundary

- Implemented: forward migrations through `runtime_0009` and owner-private command transactions.
- Design: [Physical records](../../../../../docs/Architecture/System/Persistence_Record_Design.md), [runtime protocol](../../../../../docs/Architecture/System/Runtime_Command_Protocol.md).

`migrate.upgrade(url)` runs packaged SQL/Alembic migrations as `runtime_migrator`. The explicit CLI is `python -m amphora_campaign_runtime.persistence.migrate`, using privately supplied `AMPHORA_RUNTIME_MIGRATION_URL`. No API startup migration occurs. `runtime.alembic_version` is private to this owner. Downgrade refuses destructive rollback; changes require forward migration.

Runtime owns commands, admission guard, runs, activations, fenced attempts, completion intents, immutable results/revisions, worker policy, audit and outbox records. Exact scoped foreign keys prevent cross-project/run/attempt bindings. A partial unique index permits one running campaign installation-wide. Service grants exclude DDL, DELETE, accepted-result changes and immutable identity updates. Outbox scope derives from its uniquely referenced runtime audit event; no artifact table is referenced.

`CommandStore.register` commits canonical bytes and a stable operation ID, rejecting changed bytes under the same identity. `finish` requires the caller's transaction and locks the command after domain locks. Terminal replay returns the stored disposition. Handlers remain responsible for current authority, lease/fence, budgets, validated receipts and atomic events. This storage seam does not implement execution transitions.

`transact` retries the whole database callback at most three times for SQLSTATE 40001/40P01. Callbacks reload all state and contain no network, filesystem or scientific actions. Other failures roll back and propagate. Actual PostgreSQL tests use independent connections for duplicate registration, serialization retry and rollback; relational probes establish storage constraints, not legal execution transitions.

Default API construction remains validation-only; configured lifecycle handlers own atomic domain audit/outbox transitions. Completion/delivery handlers and REC-01..09 prove the implemented acceptance and cross-service process recovery boundaries. Replacement preserves accepted history, migration ownership, scope/fence uniqueness and public contracts, and reruns module tests. Dev owns disposable reset; target-host backup/power-loss proof is BP-09.

BP-02.04/I3 forward migration runtime_0002 persists activation/attempt deadlines, bounds lease expiry and grants the owner deadline-column update. Existing attempts backfill from original expiry; no extended authority. Claim/renew handlers own atomic run-budget/attempt/receipt/audit/outbox transitions under run locks.

runtime_0003 adds a separate scoped policy audit/outbox for worker revocation without a run. Run audit foreign keys remain strict; no dummy run is created. Both journals are private runtime state and are served by the owner delivery module.

runtime_0004 adds immutable tool_snapshot to each run (legacy default empty; no inferred contract) and intent_reservations keyed by scoped intent/output binding. The runtime service may insert/read receipts but cannot update/delete them or replace admitted tool snapshots. Completion preparation and resumable external reservation acquisition own these records; no artifact private schema is referenced.

runtime_0005 adds immutable attempt_reports with scoped exact intent/attempt foreign keys and one report per attempt. Retryable accepted failure reports preserve history without consuming the canonical accepted_completions slot for that activation. The completion owner atomically writes reports, canonical terminal results/checkpoints when applicable, intent/receipt/audit/outbox and conserved budget. Report ID is the public completion reference, even when the report is retryable or uncertain rather than a terminal activation result.

runtime_0006 adds generation/token/lease fencing, bounded backoff/exhaustion metadata and readiness indexes for run/policy journals. Legacy leased entries are reset to pending; quiesce pre-fencing workers first. Transport metadata remains mutable only through scoped conditional owner operations; payloads/events remain immutable.

runtime_0007 adds explicit fixture/graph execution mode, immutable plan/tool metadata, graph-run inputs/limits/deadlines, scoped frontier records and dispatch ordinals. Existing fixture rows default to fixture/ordinal zero. Graph plans and input identity are insert/read only; only named frontier/state fields can change. No peer schema/table access is granted. The [coordinator](../coordinator/README.md) owns domain transitions; worker attempts and their budget remain in the existing lifecycle. Quiesce pre-0.3 Runtime code before enabling graph runs because it cannot respect graph Finish/frontier termination ownership.

runtime_0008 adds append-only aggregate cuts keyed by scoped run/activation. A deferred scoped foreign key binds each cut to the closure revision's ordinal-zero audit event; committing a cut without that event fails. Runtime's service role receives only SELECT/INSERT. Existing rows and public schema bytes are unchanged. The [aggregation](../aggregation/README.md) boundary validates exact replay, run/node authority and observation revision; scheduler policy integration remains in BP-04.03.

runtime_0009 adds the await node tag, immutable wait expectations/issuer receipts/closures and separately scoped external-wait retention intents/reservations. Deferred audit foreign keys bind openings and closures; exact wait revision/hash foreign keys prevent attachment to another expectation. Intents reference registered commands and waits, without worker attempt/fence rows. Only intent status/outcome can change; evidence and reservations are insert/read only. The [waits](../waits/README.md) module owns typed compatibility and preparation. New profile admission remains blocked until B2 transition/outcome/reconciliation integration; this migration alone does not enable external acceptance.

runtime_0010 adds insert/read-only aggregate decisions with an exact scoped cut-hash foreign key. Runtime commits the policy decision, cut, graph output/status, run revision and audit/receipt together. Existing B1 storage-only cuts remain evidence; a later transaction cannot retroactively supply their decision. runtime_0011 adds immutable scope `opened_at`: existing rows remain NULL, newly inserted scopes receive database time. Runtime's column-limited UPDATE grants exclude the clock. Missing historical clocks block deadline collection explicitly; no migration-time timestamp is fabricated. Require these migrations before running Runtime 0.6.0; startup never applies them.
