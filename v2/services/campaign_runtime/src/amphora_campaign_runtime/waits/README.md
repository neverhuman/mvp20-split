# External wait boundary

Owner: Campaign Runtime, package 0.7.0. Active delivery: [BP-04.03/B2](../../../../../docs/Build%20Plans/BP-04/BP-04.03%20Aggregation%20and%20failure%20policy.md). Design: [Graph execution](../../../../../docs/Architecture/System/Graph_Execution_Model.md). Identity, transitions, protection, HTTP and recovery are implemented. Focused owner verification passes; B3 process races and V1 installed issuer/peer acceptance remain distinct gates.

## Responsibilities and authority

`WaitRecord.pin` binds one run/activation/plan occurrence to an exact issuer, purpose, subject artifact, expected external revision, output schema/representation/unit, timeout disposition and deadline. The deadline is the earlier of the node timeout and admitted run deadline. UTC microseconds use exact integer arithmetic, preserving the portable command encoding. Versioned content identity includes all pins. Recreating a record with a later deadline cannot replay the original opening.

`ReceiptEvidence` preserves the issuer's immutable receipt identity and typed accepted/rejected/abstained/superseded outcome. `WaitRecord.validate_receipt` checks all bindings and exact accepted output type. Superseded, foreign-purpose/revision/subject receipts cannot satisfy the wait. This check grants neither scientific authority nor execution acceptance. The configured principal and command boundary own authentication; Research/Knowledge scientific acceptance remains a separate owner. The initial acceptance peer is explicitly synthetic.

Raw DTO fields are revalidated before serialization. This matters because a programmatically constructed invalid integer DTO can serialize a boolean as an integer. `wire.raw_fields` is a private conversion helper, with no policy, state or cross-service imports.

## Durable boundaries

Migration `runtime_0009` adds the await node tag, immutable `graph_waits`, `graph_wait_receipts`, `graph_wait_closures`, separate `wait_retention_intents`, and immutable `wait_intent_reservations`. Opening and closure records bind the scoped ordinal-zero run audit through deferred foreign keys. One activation has one pinned opening and at most one closure. A closure must match the opening's revision and expectation hash. Receipt IDs are unique per scope/issuer; byte changes under the same identity are rejected. Service grants exclude rewriting/deleting pins, receipts, closures and reservation evidence. Only retention status/outcome are updateable by this owner.

`WaitRecords.open(connection, record, opened_revision)` takes the run lock, checks live run/node/plan/deadline and the next run revision, and inserts the pin. The caller must append the matching audit and commit the associated run transition atomically. Exact opening replay returns its original identity, including after subsequent run revisions. `retain_receipt` inserts or verifies immutable issuer bytes; it does not unblock anything.

`WaitRetentionIntent` binds the exact expectation/receipt to one registered command operation and configured runtime owner. Intent IDs use a distinct `wait:` namespace. Its public Artifact reservation uses one internal `result` binding; this is independent of the authored node output-port name. `WaitPreparation.prepare` runs under the same run lock, checks a live unclosed deadline and the exact pending `graph.submit_receipt` payload, then records PREPARED protection before any external call. Replaying PREPARED rechecks authority/deadline; replaying a terminal proof preserves history. No worker attempt/fence is fabricated and no attempt budget is reserved or spent.

## Execution and acceptance

`WaitExecution.step` is a passive Graph Runner transition, not a scientific dispatcher. A ready Await pins its exact committed subject and database deadline, writes the opening and marks its graph node issued in the coordinator's audited transaction. Issued waits consume neither worker capacity nor attempt budget. They can appear within scatter and loop occurrences; distinct activation identities retain distinct pins and loop feedback subjects. Timeout uses database time under the run lock. `on_timeout=abstained` exposes no artifact but can feed an explicitly configured partial collection; required ordinary successors block on missing output.

`WaitDisposition` owns accepted/rejected/abstained, timeout and cancellation meaning. These are distinct from command acceptance and worker outcomes. `WaitClosures.persist` rechecks exact opening identity, run/closure revision and database eligibility. It publishes an accepted output only with the exact committed wait intent and validated saved reservation; the caller commits that intent, closure, graph output/status, run revision, command receipt and audit/outbox atomically. A fault rolls back acceptance while earlier PREPARED protection remains safe. Closures are immutable and cannot be reopened. Cancellation-only recovery may append a closure to an already terminal run without changing its status or exposing output.

`WaitCoordinator.submit` requires configured `submit_receipt` authority and authenticated issuer/command/scope agreement. It registers the canonical command, retains immutable issuer bytes and verifies every pin. Nonaccepted scientific receipts close truthfully without Artifact reservation. An accepted receipt first creates the separate PREPARED intent; the public Artifact reservation call occurs with no SQL transaction/lock open. Saved receipts resume without another reserve call. After I/O, the owner repeats live run/wait/deadline/identity checks before committing. Cancellation or another receipt can win meanwhile: the losing intent is aborted, its original command rejected, and any late reservation is retained for reconciliation. Wrong-purpose/revision/superseded deliveries cannot unblock a wait or abort another command's valid preparation.

The shared owner-local Artifact transport/proof adapter selects wait tables by the fixed `wait:` namespace. Prepared/unknown proofs remain protective. Committed proof requires the saved exact reservation; aborted semantic proof supports release even when the reserve reply was lost. Terminal confirmation/reconciliation uses the existing durable outbox and external delivery worker. No shared peer SQL, fake worker attempt or network exactly-once assumption is introduced.

`WaitIntents.abort` records irreversible wait tombstones and original rejected command receipts in the caller's transaction. Run cancellation and graph root stop close open waits and abort their intents before the same audit commits. `WaitRecovery.tick` handles a graph terminated by another owner path, such as worker uncertainty: at most one terminal run per scoped polling tick is reconciled. It appends closure/proof history, never reopens the run and never releases uncertain worker budget. The normal graph pass handles live wait timeout. HTTP hosting alone does not run maintenance; the configured `coordinate` process owns polling, and `deliver` owns terminal Artifact sends.

## Public compatibility and rebuild gates

Public [graph contracts](../../../../../contracts/graph_runtime/README.md) define the unchanged B1 wire roots. Runtime now admits configured wire-v3 plans alongside v2. `POST /v1/graph-receipts` accepts the canonical `graph.submit_receipt` command when an Artifact peer is configured. `GET /v1/graph-runs/{run}/waits/{activation}` returns exact expectation/closure to a scoped read principal. `GET /v2/graph-runs/{run}` returns GraphRunPageV2 for either plan version. The old page endpoint preserves its schema and returns `graph_observation_v2_required` for v3 runs. Missing/foreign waits are indistinguishable. Host loading supports v3 definitions and requires Artifact protection for Await-only graphs as well as tool graphs. No schema bytes or worker commands changed; migrations through runtime_0011 remain required.

Focused checkpoint: 68 cases passed, with 501/507 wait-module statements and 69/74 branches. Gaps are defensive save/conflict/replay paths and already-reconciled races, assigned to B3 failure/process evidence. Owner tests cover PostgreSQL transitions, strict protection/audit rollback, wrong receipts, timeout/fallback, role checks, HTTP versions, nested scatter/loop feedback, interleaved cancellation/receipt and terminal cleanup after an actual uncertain worker report. Scripted Artifact peers establish the client boundary; in-process interleavings are not competing-process proof. B1 storage fixtures remain explicitly separate. B3 must prove actual competing processes choose one closure; V1 must use the installed owner plus an actual synthetic issuer and available peers, preserving history across replacement.

Owned tests: `tests/waits`; selector `dev/run_tests.py --module runtime --area waits --coverage`. Actual PostgreSQL cases require `AMPHORA_TEST_POSTGRES=1`. Replacement preserves wire versions, both identity profiles, exact issuer/subject/type pins, scoped foreign keys, stable prepared intents and immutable audit-linked history. It may not infer scientific eligibility or missing values from transport success.
