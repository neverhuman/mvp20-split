# Graph navigation

`RuntimeViewCatalog` and immutable RuntimeView definitions now advertise GET `/v1/graph-observations/{run}/views?snapshot_token=...`. This read authenticates the exact observation cut and returns only execution_topology and successor_lineage, each with view/schema version, typed allowed filters, result bound and required capability. Existing successor lineage remains at its original immutable public route. Capability availability does not imply a given run has a predecessor. Runtime cannot advertise Research/Knowledge/Data views. Catalog reads make no mutations or new migrations; scientific projections remain unavailable until their owners exist.

`GraphNavigation` exposes `/v1/graph-observations/{run}/scopes` and `/v1/graph-observations/{run}/scopes/{scope}/topology`. Both require read authority and an existing observation snapshot token. Routes are enabled with the existing graph observation hosting configuration. Scope pages select immediate children of an activation, or root scopes when no parent is supplied. Topology selects one occurrence scope, optionally an undirected discovery neighborhood of radius 0–2; returned links retain their authored direction and branch route.

`ScopeTopology` owns matching retained activations to authored node identities, neighborhood selection and pagination. Activation ordering is only a stable pagination order, never a source of edges. `ScopeRecord` converts retained occurrence addresses to public graph-runtime 0.6 DTOs. Nested bodies and tool parameters are not returned. SQL remains inside Runtime; Studio receives public contracts only.

Reads use the existing read-only repeatable-read transaction, scoped authorization and signed cursor policy. Every page pins run, plan, revision, scope and query. An advanced run requires resnapshot; expired cursors and unavailable scopes fail explicitly. Unknown HTTP filters are rejected. Each page contains at most 100 nodes/scopes; one authored scope contains at most 256 nodes and 1024 edges. Links appear on the page containing their source. A target may be on a later page: consumers must expose omitted context and may draw a link only when both endpoints are present.

There is no migration or new mutable state. Dependencies are Runtime's own observation/cursor policy, private retained PostgreSQL records and public contracts. Replacement must preserve those identities, cursor semantics and permission failures. Focused tests live in `tests/graph_navigation`; run `python v2/dev/run_tests.py --module runtime --area graph_navigation` with the configured PostgreSQL fixture. Tests include nested scatter occurrences, real authored links, revision expiry, query binding and HTTP authorization. Independent installation, browser navigation, performance and replacement acceptance remain unverified for this new boundary.
