# Aggregation policy and evidence

Owner: Campaign Runtime 0.6.0. Active delivery: [BP-04.03/B2](../../../../../docs/Build%20Plans/BP-04/BP-04.03%20Aggregation%20and%20failure%20policy.md); collection slice implemented, full B2/external-wait integration remains in progress.

`AggregateIdentity` binds tenant/project, run and graph activation. `MemberSnapshot` copies an accepted scalar/artifact value or preserves an explicit unavailable reason. `SnapshotCut` freezes declared member order, the observed run revision, the later closure revision and the closure trigger. Its versioned content digest includes all member evidence. A separate identity digest remains stable when a new observation is considered; neither digest grants authority.

The caller must hold the Runtime run lock and obtain observations from committed owner state. These objects cannot establish acceptance by inspecting a worker report. A terminal cut refuses pending members; a deadline cut can preserve them explicitly. Both reject duplicate members, future observations, nested collections and foreign-scope artifacts. Returned records are fresh copies, so later results or consumer mutations cannot rewrite the frozen cut.

`AggregateCuts.persist(connection, cut)` takes the scoped run lock and stores an immutable cut in `runtime.graph_aggregate_cuts` (migration `runtime_0008`). Exact replay returns the original digest even after the run advances; changed evidence under that identity is rejected. A new cut requires a running run, its exact current revision, the immediately following closure revision and an existing join/scatter activation. The deferred foreign key requires the closure's ordinal-zero audit event in the same transaction. Runtime's service role can insert/read these rows but cannot update/delete them. The caller still owns atomic policy, run revision, receipt and output changes; this storage boundary neither manufactures nor independently commits them.

`JoinAccumulator` revalidates the public collection policy and derives an `AggregateDecision` from a cut. All-policy preserves predecessor semantics: explicitly excluded skips do not count as failures; unavailable required members block; unavailable optional members retain their reason slot. Partial-policy uses its declared minimum of accepted successes, retaining every unavailable slot regardless of the all-policy `required` flag. Minimum satisfaction never closes a collection by itself. Blocked decisions expose no collection. The decision digest binds the cut hash, complete policy, ordered eligible members, disposition/reason and exact collection. Consumer mutations cannot change it.

`AggregateCuts.decide` persists cut and decision together. Migration `runtime_0010` gives decisions an exact scoped cut-hash foreign key and insert/read-only permissions. Exact replay returns the original decision; changed policy/output and retroactive decisions on previously committed cuts are rejected. The coordinator owns one transaction containing cut, decision, typed graph output/status, run revision, audit/outbox and command receipt. A failure rolls back all of them. Pure control projections can be derived within this transaction from already committed inputs; unaccepted worker reports are never eligible evidence.

`CollectionWindow` uses the containing scope's immutable `opened_at` database timestamp (runtime_0011), including for scatter. Retries/replacements do not reset it. Historical scopes deliberately retain an unknown clock; deadline policy there blocks explicitly instead of inventing history. All-terminal behavior needs no clock. Deadline eligibility is clipped by the run deadline; the overall run deadline remains a hard stop and wins over collection fallback. Expiry permits the next serialized owner pass to close its exact committed revision; it is not a reconstruction of state at a past wall-clock instant. Results committed before that pass can qualify. Results after the cut cannot change it. Branch choices must resolve before expiry can release a join. Scatter preserves pending/unstarted slots and stops expansion at closure. Root completion settles remaining pure leases/queued work and preserves their terminal history; prepared Artifact intents still require reconciliation.

This module does not schedule workers, authorize retries, retain artifacts, or consume external scientific receipts. The separate [waits boundary](../waits/README.md) owns external evidence pins/preparation; its B2 execution integration remains pending. Cut/decision records are private owner evidence, not new public schemas. Owner-local tests live in `tests/aggregation`; run `dev/run_tests.py --module runtime --area aggregation --coverage`, with `AMPHORA_TEST_POSTGRES=1` for persistence/execution cases. Raw values are revalidated before serialization can normalize a constructed invalid boolean into an integer.

Focused collection checkpoint: 84 cases passed, with 193/193 aggregation statements and 30/30 branches; coordinator adapter 42/43 statements and 9/10 branches. The uncovered adapter branch is legacy tool-disposition fallback without a canonical accepted result. Tests cover pure goldens, real cut/decision/audit atomicity, service-role immutability, reverse-order scatter, abstention cause preservation, minimum failure, elapsed database deadlines, branch controls, settlement and rejected late results. Expiry relaxes only declared member-output dependencies; unrelated pending control prerequisites remain blocking. Scripted Artifact peers in these focused cases prove client behavior only; actual peers/process races remain the child B3/V1 gates.

Replacement must preserve both identity profiles, member order, revision validation, explicit missingness and scope checks. Integration must atomically persist one closure per run/activation with the decision and Runtime receipt before exposing outputs.
