## Responsibilities and boundaries

This module turns a configured exact compiled plan into a durable, scoped graph run and advances its frontier from committed outcomes. It does not introduce another scheduling service, private peer imports, scientific adapters, a shared ORM or a second attempt/budget authority. Existing Runtime lifecycle/completion modules still own worker claims, leases/fences, conserved budget, accepted tool outcomes and artifact-retention handshakes.

| Module | Responsibility |
|---|---|
| `plans.py` | Compile configured definitions against exact public metadata; scope/hash allowlist and immutable tool descriptors |
| `values.py`, `bindings.py` | Typed committed inputs, explicit local source resolution and worker DTO projection |
| `frontier.py` | Pure scope/node identities and deterministic initial ready/waiting intents |
| `storage.py` | Transaction-local immutable plan and scoped frontier persistence |
| `materialization.py` | Idempotent conversion of ready invocation intents to existing worker activation rows |
| `admission.py` | One-running-campaign guard, atomic plan/run/frontier/receipt/audit/outbox admission |
| `reads.py` | Scoped read-only repeatable-read pages of committed graph observations |
| `advance.py`, `advancement.py`, `state.py` | Run-locked bounded passes, committed value/control propagation, atomic decisions and Finish closure |
| `collections.py`, `expansion.py` | Ordered all-member joins, frozen scatter membership, parallel-body bounds and durable loop checkpoints |
| `predicates.py`, `projections.py` | Finite typed evaluation and bounded public Artifact reads outside owner transactions |
| `configuration.py`, `http.py`, `polling.py` | Exact local graph allowlists, scoped HTTP commands/reads and autonomous recovery polling |

`ReviewedPlan.compile` is an owner/configuration entry point, not proof of a human review or a live Registry decision. `PlanCatalog` explicitly authorizes only configured scope/hash entries. `GraphAdmission.admit(principal, command)` requires the existing admit action and exact command identity/scope, then validates named input types/units/schema/representation, expansion limits and the one-running-run slot. Supplied artifact references are trusted immutable pins; admission does not fetch payloads, verify scientific validity or refresh live Registry capacity/lifecycle. Configured HTTP hosting exposes only this allowlist. Current compiler/tool authority remains pure and synthetic-only; live peer/replacement graph acceptance is V1.

## Durable invariants and transactions

Migration `runtime_0007` adds explicit `execution_mode` (existing runs default to fixture), immutable `graph_plans`, run-bound graph input/limit/deadline records, scoped graph bodies and unique node activation identities. Runtime's service role can read/insert these records, update only named state fields, and cannot rewrite/delete plans or admitted input identity. Peer roles gain no access. Startup never migrates. Quiesce old Runtime implementations before graph mode is enabled: pre-0.3 completion code does not understand graph termination ownership.

Admission registers the canonical command, then takes the existing admission guard. Plan, run, scope, all root-body nodes, initially ready invocation rows, notification/audit and accepted receipt commit together. Any failure rolls back that transaction; the registered command remains retryable. Exact command replay returns the original receipt, creates no second run/node/budget reservation and does not refresh authority. Plan storage reapplies the wire types when comparing JSONB so exponent expansion cannot change numeric identity. Scope/run foreign keys and unique scope/node/activation keys prevent duplicates and cross-scope attachment.

Every body node is represented in the frontier. Roots start ready, successors waiting. Ready Invoke nodes are materialized into the existing `PreparedInvocation` protocol with their deterministic activation identity and plan order. Calling the initial planner twice produces the same immutable intents; an inserted invocation must retain the same specification and dispatch ordinal.

`GraphAdvancer.advance` requires maintain authority and a stable `graph.advance` command. It takes the existing run lock, reconciles expired worker budget through the existing settlement policy, reloads the retained plan/frontier and applies at most 256 transitions (default 64). Decisions, new scopes/invocations, run/frontier revisions, receipt and audit/outbox commit atomically. An unchanged pass still receipts its command. Notifications are hints. Per-pass scope caches are discarded; a new coordinator reconstructs from PostgreSQL. Transition count is bounded, but scanning cost grows with the admitted frontier; this is not evidence of high-scale throughput.

Branches persist true/false routes; ordinary successors require every incoming dependency. Unselected routes propagate skipped state. All-member joins wait for terminal predecessors, preserve declared member order, exclude skipped members only by explicit policy and fail required missing members. Optional failures use typed missing slots. Partial/deadline collection policies are currently blocked with `graph_collection_policy_unsupported`, assigned BP-04.03.

Scatter freezes ordered committed values and an `amphora-scatter-membership-v1` digest before creating children. Each occurrence carries that digest and its original index. At most max_parallel child scopes remain active; completed children release slots, and outputs retain membership order regardless of completion order. Empty scatter produces an empty collection. Nested expansion checks the run's max_activations before insertion. Loops create a new indexed child scope for each iteration; committed body outputs determine feedback and the finite until predicate. Only completed checkpoints permit the next iteration. Predicate or declared iteration-limit behavior records why the loop stopped; previous scopes are retained.

Only root Finish completes a graph. Missing required data/dependencies, unsupported policy or a blocked iteration produce a blocked outcome. Root blockage/deadline cancels remaining pure worker work through existing budget settlement and marks unresolved graph state blocked. Prepared-intent protection is never bypassed: maintenance must reconcile it before settlement. Emergency lifecycle cancellation and uncertainty retain their own authority; historical graph projections may show the last coordinator checkpoint.

Materializing queued work costs no attempt budget. The existing claim transaction reserves one unit under the run lock, and terminal attempt settlement spends it exactly once. A graph can have more queued work than available units; it cannot issue more leases than its budget permits. Graph invokes use the earlier of their activation timeout and the admitted graph deadline. Claim order is dispatch ordinal then activation ID; legacy fixtures retain ordinal zero and their existing order.

Graph tool metadata is frozen once by exact binding, allowing later activations without mutating the run snapshot. Completion looks up the matching graph pin and rejects missing metadata; fixture lookup keeps its original invocation-key behavior. Worker success/failure cannot infer whole-graph completion from the currently materialized invocation rows. Graph completion remains running until its coordinator accepts Finish/terminal frontier; uncertainty and emergency cancellation remain fail-closed lifecycle authority. Fixture run terminalization is unchanged.

## Values, observations and identity

Graph command numbers use bounded plain decimal strings, for example `{kind: number, value: "0.25", unit: "g/mol"}`. This preserves the existing float-free `amphora-command-v1` identity and the pinned worker closure. Compiler numeric literals retain their existing wire representation; the value resolver converts them explicitly to plain decimal strings when producing committed graph values. No implicit unit/schema/representation conversion or arbitrary object packing exists. Collections preserve order and explicit missing-member reasons.

`ScopeAddress` hashes the plan and typed loop/scatter occurrences. `ActivationAddress` additionally binds the node. Parent-plan order, occurrence index and local order determine priority; hash ordering is not execution priority. These identities are unique within the run and are not attempts, leases or authorization grants. Human topology changes belong to later campaigns.

`GraphReads.run` requires a read principal and returns at most 100 node observations with a scoped keyset cursor. Counts, run budget and nodes share one repeatable-read snapshot; a missing/foreign run is indistinguishable. Pages are committed observations, not subscriptions or a guarantee that a worker remains authorized. No scientific payload bytes or credentials are exposed.

Graph mode caps queued/leased worker invocations at 256; additional ready graph nodes stay durable until capacity opens. The existing worker RunSnapshot returns only those active invocations in graph mode, preserving all current lease observations as historical rows grow. Fixture snapshots retain their previous behavior. Accepted completion receipts and graph history remain available independently; a completion retry uses its original receipt even after its activation leaves the active snapshot.

Artifact predicates resolve only declared typed paths. Missing values never default to false. Numeric comparisons use Decimal without implicit unit conversions. On a cache miss the scheduling transaction rolls back, then the configured public Artifact client fetches metadata/content outside SQL locks and verifies exact reference, size and SHA. Redirects are refused and proxies disabled. Content is bounded (default 256 KiB, maximum 1 MiB), strict JSON with no duplicate keys or nonfinite constants. Permanent content failures become blocked node reasons; transport/metadata uncertainty leaves the advance command pending. A pass caches at most 64 projections; exhaustion remains explicitly unavailable. Richer recovery policy is BP-04.03.

## Configured hosting and recovery

Optional host `graphs` is a nonempty list of at most 64 entries: each has a `definition` JSON file path, `releases` entries with public `descriptor` file paths and inline exact `lock` DTOs, and `schemas` entries with inline `schema_ref` and byte-file `path`. Paths resolve relative to the host configuration. Startup compiles and checks those resources; it accepts no uploaded/unverified plan. An empty fixture list is allowed only with this graph allowlist. Tool-bearing graphs require a configured Artifact completion peer. Optional `projections` config contains `endpoint`, `token_env`, and `maximum_bytes`; its token needs scoped Artifact read authority. Startup requires runtime_0007 and performs no DDL.

`POST /v1/graph-runs` admits; `POST /v1/graph-runs/advance` advances; `GET /v1/graph-runs/{run}` reads pages. Commands use existing scoped identity/canonical-command semantics. Configured health reports `configured_graphs`; default construction still reports validation-only and legacy validation remains nonexecutable.

Run a separate Runtime process with `coordinate --config <file> --actor <actor> --tenant <tenant> --project <project> --time-budget 20 --poll-interval 1`. It uses an explicitly configured maintain principal, scans only its scoped running graph, reconciles stale intents and issues bounded advancement commands. Duration is bounded to 24 hours; a process supervisor can repeat it. HTTP serving alone does not start this polling worker. Pending projection commands are retried with the same identity within a worker; restarting may issue a new command but cannot duplicate durable activations. Database and unexpected invariant failures exit for supervisor recovery. No human campaign intervention is required.

Completion-specific cases use a scripted reservation peer; this is not actual graph/Artifact peer acceptance.

B3 now passes eight actual coordinator-process scenarios and all 60 owner tests; [test boundary/evidence](../../../tests/scheduling/README.md) records measured lock contention, kill/replay and independently enumerated frontier identities. Ordinary fresh-object tests are not substituted for that process tier. V1 requires independently installed actual graph/worker/Artifact peers and replacement.
