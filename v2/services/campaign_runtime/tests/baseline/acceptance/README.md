`environment.py` composes real Registry, Artifact and Runtime services and five independently installed solver tools. The controller runs in an isolated SDK environment with no Runtime or SQLAlchemy import; owner configuration and compilation execute in Runtime's own install. The registry pins actual image/descriptor/schema locks. Shared DTO schemas are deduplicated by public identity, not local path. Workers receive only public tokens and Artifact inputs. Image golden/isolation evidence is Linux/amd64; worker/service execution evidence here is Windows wheel processes. These tiers do not establish DGX deployment or scientific validity.

`probe.py` executes an initial population and a separately compiled two-generation successor. Two worker processes claim concurrent scoring work; each report is read back through the public receipt/completion APIs and its immutable Artifact bytes are verified. Independent source-derived membership, seeds and parents are the oracle, not a trace generated by the runner. Runtime replacement between campaigns preserves the exact predecessor cut; replacement after completion preserves ancestry, original command receipts, accepted history, Artifact bytes and protection outcomes. Every captured retention reservation must become confirmed through bounded owner delivery passes. Missing notification transport is recorded separately from protection delivery.

The evidence manifest contains scoped run/plan/Artifact identities, source pins, public lineage, immutable receipts, image/wheel digests and boundary-specific assertions. Tokens, private SQL and host environments are never evidence fields. Setup/cleanup owns only its fixture services/processes and active test run. V1 stays incomplete until the probe passes and the owning architecture drift audit closes.
