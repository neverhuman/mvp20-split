# Installed external-wait acceptance

Owner: [wait contract](../../../src/amphora_campaign_runtime/waits/README.md). Plan: [BP-04.03](../../../../../docs/Build%20Plans/BP-04/Completed/BP-04.03%20Aggregation%20and%20failure%20policy.md).

Run `dev/verify_graphs.py --profile waits --images <verified-image-manifest>` with `AMPHORA_TEST_POSTGRES=1`. The default `graphs` profile remains the predecessor scheduling suite. Both profiles build thirteen wheels and create separate Runtime, Registry, Artifact, SDK, tool and fresh Runtime replacement environments. Run serially with other single-campaign suites.

`probe.py` orchestrates actual local HTTP services from the independently installed SDK interpreter. It reuses test-owned process/publication helpers; it imports no owner implementation or SQL client. `compile_plan.py` runs in the installed Runtime environment with no database credentials, compiling exact pinned public definitions/schema bytes. `issuer.py` runs as a separate isolated process with only its own token, endpoints and bounded synthetic input. It uses public wait reads, Artifact upload/finalization and receipt submission; no owner imports or SQL access.

Required oracles: open wait and plan survive replacement; wrong-purpose/superseded evidence cannot unblock; valid issued evidence references an actual published Artifact; accepted closure matches the explicit issuer receipt; graph completion spends no worker budget; Artifact confirmation delivery succeeds; another fresh Runtime preserves original receipt, closure, graph and readable Artifact bytes; scientific abstention closes truthfully without claiming accepted evidence.

Generated manifests preserve package hashes, exact scopes/receipts/waits and process evidence without tokens or database URLs. Reviewed copies belong under `docs/Audits/Evidence/BP-04-Aggregation/`. Synthetic evidence establishes software interoperability, not a Research/Knowledge scientific judgment. This profile does not claim ARM, K3s or power-loss acceptance.

BP-06.03/B3.01 adds domain_bridge.py, loaded by the Research actual-peer fixture as a test-only public HTTP helper. Runtime compilation/migration run only in Runtime's interpreter. AMPHORA_TEST_DOMAIN_RUNTIME=1 enables it; installed verification additionally requires AMPHORA_TEST_RUNTIME_PYTHON. Data gets explicit retention authority and a fixed Runtime outcome endpoint. Both actual owner waits open before correction and preserve original pins through supersession, real retention, confirmation and Runtime replacement. The separate Runtime installer records installation only; verify_research_assessment.py provides the actual integration gate. B3.02 adds domain_partial.py: two current abstained waits and a prior retained report feed an explicitly partial collection. Public snapshot/value reads must return that exact report and two reason-bearing missing slots. The report is context, not renewed scientific acceptance. Live wrong-purpose, wrong-subject and unauthorized submissions leave waits unchanged. B3.03 owns additional delivery faults.

B3.03 fault profile: additionally set AMPHORA_TEST_DOMAIN_FAULTS=1. domain_faults.py forwards real owner HTTP requests and captures the successful response, then returns503 once to suppress its acknowledgement. It does not synthesize a commit. The receipt caller replaces Runtime before exact retry; the delivery worker observes failed confirmation, replaces Runtime, and retries the identical Data command after bounded backoff. Oracles compare original/replayed command hashes and responses, unchanged wait closure and retained Artifact content SHA-256. This proves post-commit acknowledgement ambiguity and process replacement, not arbitrary pre-commit crashes or power loss. The default integration profile keeps normal transport.

On test failure, the harness cancels only its own unfinished campaign through Runtime's public API before stopping its process. It never resets the retained database or cancels unrelated runs. A stranded campaign from an older harness must be identified and closed explicitly before rerunning; the global single-active-run guard is intentional.

This receipt fixture configures Artifact delivery only. Runtime notification sinks are intentionally absent, so their separate outbox entries can fail/retry; delivery totals are not a claim that every outbox target succeeded. The fault probe advances one delivery at a time until its captured actual confirmation request reaches the barrier, preserving unrelated delivery observations in evidence.
