# Installed compiler acceptance

Owner: Campaign Runtime compiler tests; driver: `dev/verify_compiler.py --images <verified-tool-image-manifest>`, with explicit `AMPHORA_TEST_POSTGRES=1`. The driver builds the public package closure, installs Runtime/Registry/two tools separately outside the checkout, and creates fresh second Runtime/Registry environments. It uses the existing labeled fixture with a unique scope and never resets predecessor state.

`probe.py` owns test orchestration. It obtains descriptors through installed tool CLIs and schema bytes from installed public package resources, verifies their preserved image closure hashes, and exercises each installed kernel against its separate golden fixture. An actual Registry process registers/activates the exact releases and serves authenticated public discovery/resolve reads. No replicas are fabricated: resolution correctly reports no eligible capacity while structural/synthetic applicability remains valid. Advertised Linux resource compatibility is not a claim that these Windows processes establish Linux worker deployment or available host capacity.

`client.py` runs in each independent Runtime environment, imports the installed compiler, reads scoped public Registry snapshots, consumes supplied hash-verified schema bytes and compiles five definitions: affine, branch/join, scatter, loop and sequence. It has no SQL credentials or adjacent service/scientific implementations installed. Original retained plan bytes and hashes survive fresh Runtime/Registry replacement, exact original registration-receipt replay and release drain. No run is admitted, artifact published, lease issued or scientific conclusion established.

The harness reuses only test-owned stdlib HTTP/process helpers and the independent documented lock-profile fixture helper. Registry migration/service credentials remain confined to their owner processes. Windows cleanup targets the created host process tree. Evidence contains scoped IDs, package/tool/plan hashes and absolute timestamps, not tokens/database URLs. Failure leaves no successful evidence marker; retained plans, if already written, are not by themselves proof of acceptance. Process acceptance is distinct from compiler pytest coverage.
