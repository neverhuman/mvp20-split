# Knowledge reference validation

Implemented and integrated in BP-06.02/B1; public Knowledge API and actual Data/Research HTTP are verified. Design: [authoring](../../../../../docs/Architecture/Knowledge/Authoring.md).

`ReferenceReviewer` owns fresh observations of public Data and Research identities before structural acceptance. `AuthoringWorkflow.submit` first commits scoped actor-bound intent, then reviews outside any SQL transaction, then asks the Knowledge ledger to atomically accept against the expected head. It never accepts a caller-supplied validation observation as authority. Terminal decisions replay without peer I/O; pending proposals can be retried under the same identity.

`DataReader` calls only public artifact metadata/content, source revision and conversion trace routes. `ResearchReader` calls exact question/need read routes with scoped public references. Both use `PeerTransport`, explicitly configured with loopback endpoints and separate owner credentials. No redirects, automatic retries, peer implementation imports or peer SQL exist. Remote scientific tools are outside this bounded local owner transport profile.

Each review rejects foreign/equivocal identities before I/O, checks exact artifact metadata and content size/SHA-256, verifies byte-span bounds/digests, canonical conversion trace digests and source/output bindings, then verifies exact Research references and need-to-question/criterion membership. Each claim's grounding must associate its own spans and traces; unrelated global provenance cannot satisfy that check. Additional source/trace output and question/need context artifacts are consumed through Data's authorized content route too. Only per-review payload caching exists; no source bytes are stored by this module.

Review budgets are 20 seconds total, 512 HTTP calls, 32 MiB total response bytes, 256 expanded artifacts/sources, 256 KiB per metadata response and 4 MiB per artifact. Individual I/O inactivity is at most 5 seconds. A deadline timer shuts down the connected socket to interrupt trickling headers or bodies. Strict JSON rejects duplicate keys/nonfinite values. Credentials and peer bodies never enter public error codes. The budget is transport admission policy, separate from the graph's persisted structural semantics; changing it does not rewrite historical acceptance.

401/403, missing references, contradictory bindings and bounds failures cause stable rejected decisions. Network failures, non-200 operational responses, malformed peer records and deadlines leave intent pending. A later caller must reconcile/retry the exact request; a completed rejection needs a new attributed proposal if its inputs change. None of these observations is a distributed transaction or continuing rights lease. Later consumption must recheck current Data rights.

Normalized, unresolved and quarantined provenance does not become accepted science. Assertion posture remains reported/hypothesis/unresolved. A link's validation method can differ from a predeclared need's method: that distinction is retained evidence, not a claim that the need is fulfilled. This module does not run ontology extraction, infer truth, fulfill Research questions, perform external actions or mutate campaigns.

Replacement tests live in `tests/validation`: scripted records prove binding rules, a real loopback scripted HTTP server proves transport parsing/bounds/deadlines, and actual PostgreSQL proves durable pending/rejection/replay workflow. These are **not** actual Data/Research owner compatibility proof; the separate tests/acceptance suite now verifies that B1 gate, with independent installation/replacement acceptance now complete in V1. Preserve those tiers and run `dev/run_tests.py --module knowledge --area validation` with explicit PostgreSQL opt-in when appropriate.

BP-06.03 adds review_reasoning(request, applicable_assertions) using the same bounded provenance checks and a fresh per-request read budget/cache. It verifies request context/subject and every applicable assertion grounding/Research link before a new reasoning result is committed. Terminal replay skips fresh reads as historical evidence. PeerUnavailable remains pending; deterministic denied/missing/mismatched inputs produce a failed reasoning decision. No caller-supplied observation is accepted by the HTTP route.
