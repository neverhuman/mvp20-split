# Finite ground reasoning

- Status: BP-06.03/B1 configured profiles, durable results and optional HTTP implemented; artifact publication and domain receipts pending.
- Owner: Knowledge; [reasoning architecture](../../../../../docs/Architecture/Knowledge/Reasoning.md), [activation contract](../../../../../docs/Audits/BP-06.03_Activation.md).

`Program`, `Rule`, `Fact` and `Seed` own validated immutable inputs. Rules are finite grounded implications with one or more explicit premises; no variables, arbitrary expressions, imports, subprocesses, callbacks or negation-as-failure are evaluated. Atom strings are private symbols, not trusted graph references. Supplying a program version or seed origin does not confer scientific authority.

`GraphInputs.from_state` consumes an owner-reconstructed GraphState, never a caller-supplied snapshot DTO. It pins the semantic snapshot and exact scoped context artifact, selects all current nonretracted assertions with identical applicability and reports other-context exclusions explicitly. Endpoint reference digests preserve entity revision identity; aliases do not silently substitute endpoints. Seed origins map to exact assertion revisions; unknown origins and stale/retracted references cannot resolve through this binding. Raw represented hypotheses remain hypotheses: logical entailment from them is not scientific support.

`Evaluator.evaluate` computes deterministic monotonic closure in synchronous rounds. Positive and negative facts coexist; both yield unknown with an explicit conflict flag. Missing facts remain unknown. Cycles without seeds derive nothing; seeded cycles terminate without cyclic proof links. Input order cannot change output. One deterministic shallow proof is retained per derived fact, with all direct input origins retained for seeded facts. This is an explanation witness, not enumeration of every possible proof. Original origins remain original evidence; derivation steps cannot be counted as independent observations.

Inputs cap256 rules,16 premises per rule and8192 seeds. Configured budgets cap64 derivation depth,8192 retained facts and1,000,000 rule/premise checks. Default kernel limits are32/8192/100,000; configured profiles supply all three explicitly. An incomplete round publishes no partial candidates. Productive depth/fact overflow or work exhaustion produces an incomplete closure; assessment remains unknown even when a supporting prefix exists. The pure evaluator performs no database, network or artifact writes.

Owned tests: `tests/reasoning`; selector `dev/run_tests.py --module knowledge --area reasoning`. Pure fixtures cover signed inference, bounds, ordering, exact applicability and projection. PostgreSQL/ASGI tests cover collisions, immutable profile versions, duplicate races, rollback, grants and pending outage recovery. `tests/acceptance/test_public_peers.py` separately proves actual Data/Research provenance reads, Knowledge restart, Research outage/resume and revoked-source denial for new reasoning. Installed replacement, finalized derivation artifacts, Research sufficiency and Runtime receipt integration remain BP-06.03 gates.

## Configured authority and projection

`RuleProfile` strictly validates ReasoningRuleSet records, including constructed scalar types before serialization. Rules/premises are canonically sorted for fingerprinting; duplicate identities/premises and foreign graph/context references fail. Clients select an exact RuleSetRef; they cannot supply definitions or override budgets. Entity revisions and predicate endpoint types must exist in the pinned graph. Evaluation requires reason_graph in the exact scope. Targets are unique and bounded128; snapshot, context, subject scope and profile digest must match.

`Evaluation.to_record` maps domain objects to ReasoningResult with complete/incomplete outcome, findings, original assertion refs and derivation steps. Repeated assertion-reference occurrences cap16384 across findings/steps before serialization; output bytes cap16MiB. Authority is synthetic_logical_entailment. This is not scientific acceptance, a Runtime receipt or a finalized Data artifact.

## Durable state and failures

`RequestDocument` binds canonical request bytes/SHA256 to authenticated actor and scope/graph/request ID. `ReasoningStore` uses applied knowledge_0003: immutable reasoning_profiles, reasoning_intents and reasoning_decisions. Profiles cap2MiB, requests256KiB, terminal status20MiB. Exact snapshot foreign keys and profile hashes are required. A rule-set ID/version cannot acquire new bytes. Service grants allow SELECT/INSERT, never UPDATE/DELETE. Evaluation does not modify the semantic graph head or accepted log.

`ReasoningWorkflow.submit` first commits intent under a short graph lock. It restores the stored profile, replays immutable history through the requested head outside transactions, validates targets and freshly reviews applicable assertion grounding plus request artifacts via public Data/Research readers. The reference reviewer retains its bounded calls/bytes/deadline. Deterministic failures become immutable failed decisions; PeerUnavailable propagates with pending intent. SQL/infrastructure interruption also remains pending. Result and server-issued validation observation commit atomically; observations are not continuing rights leases or distributed transactions.

Concurrent duplicates may both compute/read peers; first terminal result wins and retries return it. Terminal replay skips computation and peer I/O. Pending retry uses its stored definition even after configuration removes it. New requests require a configured profile. Status reads require read_graph and may inspect another actor's scoped request; submission is actor-bound. Later graph changes never silently repin an existing request.

Optional host reasoning configuration contains at most32 profiles. Omission omits the reasoning routes; an empty list permits reconciliation without enabling new profiles. Enabled hosting requires knowledge_0003. POST /v1/graph-reasoning and GET /v1/graphs/{graph_id}/reasoning/{request_id} expose ReasoningStatus. Null decision means pending; evaluated may still be incomplete/unknown. Failed is terminal. HTTP200 is not scientific acceptance; operational peer failure returns503 for exact reconciliation.

Knowledge0.9.0 reasoning validation retains all consumed artifacts for eventual derived publication, with a128-input bound. This does not publish an artifact or receipt yet. Historical terminal results replay unchanged; pre0.9 validation observations must not be reused as complete publication lineage without fresh review.
