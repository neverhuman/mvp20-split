- Status: BP-03.02 B2 boundary/policy implemented; B3 process verification active: private durable registration, revisioned inventory and authenticated ASGI API; independent executable hosting and deeper routing/race acceptance pending.
- Package: `amphora-capability-registry` 0.1.0.
- Architecture: [Catalog](../../docs/Architecture/Capabilities/Catalog.md), [Tool Services](../../docs/Architecture/Capabilities/Tool_Services.md).

This owner will maintain the tool/node index. Its current [descriptor module](src/amphora_capability_registry/descriptors/README.md) binds immutable release identity, canonical metadata bytes, image/schema pins and explicit LockEntry verification. It imports public core/tools/commands contracts and its declared SQL/API dependencies; it does not import runtime/artifact implementations, access peer tables or dispatch work. No import starts a process or network connection.

The new ReleaseDescriptor is a separate wire-v1 root containing the existing ToolDescriptor plus explicit resource/egress/checkpoint/reproducibility metadata and a restricted authority ceiling. Old ToolDescriptor, Invocation and Completion schemas and command fixtures remain unchanged. Release identity differs from deployment/replica identity; health never grants scientific eligibility or execution authority.

The [catalog application](src/amphora_capability_registry/catalog/README.md) now applies immutable identity checks inside its [private owner transaction](src/amphora_capability_registry/persistence/README.md). Accepted registration receipts commit with owner state and audit; registration does not activate or grant execution. Pure policy separates descriptor consistency, scientific suitability, scope/port/resource/permission compatibility and observed capacity. The current child verifies store/routing; later children own SDK/tools and replica integration.

Tests belong to `tests/descriptors/`, `tests/persistence/` and `tests/api/`; run `dev/run_tests.py --module registry --area descriptors --coverage`. Coverage measures all current registry source; independent builds must contain neither peer service nor scientific packages. A replacement preserves canonical release profile, exact byte comparison under existing identity, full LockEntry matching and old execution wire compatibility. Preserve durable release bytes, original command receipts and lifecycle history; do not substitute healthy capacity for release suitability. Synthetic numeric/sequence fixture metadata establishes no chemical or biological validity.
