# Capability Registry

- Status: BP-03.01/.02 descriptor and durable registry boundaries verified; worker SDK/tools and integrated replica dispatch remain .03/.04.
- Package: `amphora-capability-registry` 0.1.0; PostgreSQL schema `registry` with separate migration/service roles.
- Architecture: [Catalog](../../docs/Architecture/Capabilities/Catalog.md), [Tool Services](../../docs/Architecture/Capabilities/Tool_Services.md).

The registry owns the node/tool index: immutable scoped release metadata, exact locks, revisioned lifecycle/deployments and authenticated expiring replica observations. It imports public core/tools/commands contracts and declared SQL/API dependencies. It never imports peer implementations, queries peer tables, creates runtime work or promotes scientific evidence. Imports start no processes or network connections.

The [descriptor module](src/amphora_capability_registry/descriptors/README.md) owns canonical identity, full-lock checks and independent structural/scientific/permission/capacity assessments. [Catalog behavior](src/amphora_capability_registry/catalog/README.md) owns authenticated registration, discovery, lifecycle, inventory and exact resolution. [Private persistence](src/amphora_capability_registry/persistence/README.md) commits owner changes, original receipt and audit together. [Hosting/replacement](HOSTING.md) defines explicit configuration, own-role startup, forward migrations and retained-state cutover.

Registration begins at `registered`; activation is explicit and limited to synthetic/pure tools in this profile. Deployment/replica identity differs from capability/release identity. Health cannot establish scientific eligibility or execution authority. Runtime alone owns claims, fences, grants and acceptance. A candidate is an expiring observation; it reserves no slot. Replayed commands return original receipts, including original expiry. Obtain a new resolution with a new command identity when current capacity is needed.

Bounded catalog reads support exact capability/version filtering and digest-ordered pages, including inactive historical releases. Pages expose current lifecycle observations, not a frozen inventory snapshot or eligible-only ranking. Exact descriptor/lock identities survive drain/revoke and replacement. Catalog-scale semantic matching and LLM prompt budgets remain Agent Planning acceptance; listing metadata makes no scientific-validity claim.

Owner tests live in `tests/descriptors/`, `tests/persistence/`, `tests/routing/` and `tests/api/`. Use `dev/run_tests.py --module registry --area <area>` for granular runs, or omit area and add `--coverage` for the current owner denominator. Actual subprocess acceptance lives in `tests/acceptance/`; its evidence is separate from parent-process source coverage. [Preserved registry evidence](../../docs/Audits/Evidence/BP-03-Registry/README.md) records real race/interruption and independently installed HTTP replacement proofs. [Descriptor audit](../../docs/Audits/BP-03.01_Descriptor_Closeout.md) preserves the narrower initial pure-policy denominator; do not confuse it with service-wide coverage.

Latest full foundation gate: 448 tests, nine independent packages, fresh registry original/replacement hosts, actual runtime/artifact peer compatibility and REC-01..09 passed. The registry wheel includes migration resources and runs without peer service/scientific packages. Target-host backup/power-loss, Kubernetes, real scientific tools and full tool-universe planning remain separately scoped work.

CLI/migration subprocess paths, some defensive configuration/corruption/exhaustion/retry branches are outside measured parent-process coverage.
