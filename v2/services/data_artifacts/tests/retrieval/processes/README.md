# Retrieval process interruption probes

These owner-local tests run the independently installed Data package against the retained PostgreSQL/Qdrant fixtures. Set AMPHORA_TEST_POSTGRES=1, AMPHORA_TEST_QDRANT=1 and AMPHORA_TEST_RETRIEVAL_PROCESS_PYTHON to the isolated Data interpreter. Source setup creates actual source/vector records; the interrupted/replacement operations use actual HTTP routes. No private peer implementation may be installed in the child.

`fault_host.py` is test-only and excluded from production packages/configuration. Its explicit stdin request chooses one allowlisted stage. Wrappers pause after actual owner commits or backend observations; a SQL listener pauses before result insertion for the rollback case. JSON stdout reports only stage/public receipt metadata. A bounded stdin release permits live-barrier tests; forced-death tests kill the whole paused process. `support.py` owns hidden process launch, bounded readiness/event capture, release and cleanup, sharing the existing HTTP client for normal CLI replacement.

`test_death_replay.py` covers generation intent, actual projection write, verified proof, published head, query intent, observed scores, result precommit and result postcommit. An expired building lease gets a distinct fenced attempt/namespace. An expired verified attempt becomes failed and needs an explicit new generation. Committed publication/results replay exactly; uncommitted results do not survive. Fixture-only cursor expiry shortens the test; immutable evidence is never rewritten. Read-only MVCC observations avoid the lock held by the paused transaction.

Evidence under `.test-results/retrieval-process-death/` records stage, scope, child/replacement PID, barrier metadata and recovered public result. Committed audit artifacts preserve the reviewed run. This proves process death and HTTP acknowledgement loss, not power-loss durability on a deployment host. Run PostgreSQL/Qdrant suites sequentially; retain volumes, attempts and namespaces. Use pytest --tb=short to avoid rendering environment arguments on process startup failures.
