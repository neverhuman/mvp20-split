# Retrieval generation boundary

Owner: Data/Artifacts, BP-06.05/B2.01. Pure manifest/generation/attempt identities and transition policy are implemented; private generation admission/history/build claims are implemented. Verified projection records and authoritative PG heads are implemented with an injected backend port. No actual Qdrant adapter or retrieval API exists yet.

This module owns index snapshot identity, ordered corpus manifests, build lifecycle, projection verification and authoritative generation selection. It consumes Data representation profiles, validated source-binding projections and current source rights through their focused boundaries. It does not own source policies, encode scientific inputs, mutate Knowledge, schedule campaigns or treat a backend alias as truth.

A corpus contains 1..256 unique binding IDs in explicit order and one exact shared-role profile. Binding shape/fingerprint checks are distinct from actual retained source/rights authority, supplied by current owner admission. Canonical manifests have a 4MiB limit; their digest is the exact source watermark. A generation pins scope/corpus/id, owner actor, manifest, expected prior head and trusted backend profile. Build token/fence identity yields a distinct backend namespace per attempt; a stale builder cannot write into its successor's namespace. Point IDs are deterministic per complete binding reference and must remain unique.

Generation transitions are prepared -> building -> verified -> published, with failure/abandonment only from nonterminal states. Pure transition permission is not evidence that a projection exists or that publication is authorized. The lifecycle store verifies owner source/profile records and current process rights. Build claims are lease-fenced; actual point comparison and expected-head publication are implemented in B2.01d. Backend integration is a required explicit port, never a hidden fallback; actual Qdrant proof belongs to B2.02.

Tests live in `tests/retrieval/` and must distinguish pure synthetic records, actual PostgreSQL authority, actual Qdrant behavior and process/race proof. Replacement preserves ordered manifest fingerprints, full profile/source/vector identity, attempt namespace isolation and immutable generation history. Actual Qdrant and retrieval APIs are subsequent tasks; no pure-object test grants those completion claims.

B2.01a coverage: all 125 statements and 8 branches in this pure module exercised, including maximum manifest size, duplicate/colliding points, scope/profile separation, generation head and namespace isolation, and every transition pair. This is domain-policy evidence, not database or backend evidence.

`mapping.py` maps pure plans/references/manifests to public representations0.2.0 DTOs and revalidates inbound shapes, including model-construction bypasses. Reverse mapping recomputes all identities; request mapping compares exact ordered owner-resolved bindings and profile. Authenticated actor and trusted backend are separate owner inputs. Mapping is not source lookup, current-rights enforcement or status authority. Status serialization accepts only the domain phase enum and is reserved for future owner lifecycle reads. Existing generation fingerprint formats are unchanged.

## Durable generation state

`GenerationIntents(engine, backend_profile)` admits `BuildIndexGeneration` through `prepare(principal, request)` and reconstructs actor-owned historical status through `read`. Backend profile is owner configuration. Admission requires `representation_manage`; historical reads require `representation_read`. Exact replay preserves history even after rights revocation and never confers fresh content access. New admission resolves exact stored profile/published bindings and process rights. No external I/O occurs in the transaction. Conflicting immutable identities roll back completely.

`GenerationLeases` owns DB-clock 1..300-second claims, renewal and bounded failure/abandonment. Claims return a lease, busy outcome or existing terminal status. Fresh/expired building claims record unique token/fence/private namespace; stale leases cannot renew or terminate successors. Renewal checks the deadline again at the update after source-rights work. `finish` permits only failed/abandoned, never caller-asserted verified/published. Prepared work can be explicitly abandoned. Expired verified attempts become failed and require a new generation; this branch is verified against actual retained verification and subsequent rights revocation.

Migration `artifact_0010` adds immutable generation intent, ordered membership, numbered build-attempt and phase-event tables, plus a mutable cursor. Only phase/sequence/token/fence/expiry may update; all history denies service-role mutation/deletion. The current source-rights scope lock always precedes the corpus lock. Generation ids belong to one actor within a scoped corpus. Short transactions contain no backend calls. Forward migration/replacement preserves all prior records; old packages unable to recognize0010 must not run migrations.

Actual PostgreSQL tests cover admission/replay/conflict, forged/missing/cross-scope bindings, rights revocation versus historical metadata, concurrent claim convergence, expired takeover, stale/foreign/terminal rejection, deadline expiry during rights work, immutable grants and membership FKs. Retrieval coverage now527/527 statements and34/34 branches; the expired verified branch is exercised through actual retained proof. ## Projection verification and publication

`GenerationPublication(reads, backend)` accepts a trusted injected `ProjectionAdapter`, never a backend from a public request. `build_and_verify(principal, lease)` checks configuration identity and live lease, materializes exact retained vector Artifacts outside SQL, builds the attempt-private namespace, then inspects actual points. Owner comparison requires exact dimensions/metric, count, unique deterministic ids, full profile/binding references and canonical binary32 vector content. Observation order is immaterial; input manifest order still pins generation identity. Fingerprints include vector digests, avoiding an oversized full-vector canonical document. No backend acknowledgement is treated as content verification.

After inspection, current process rights and the winning lease are checked in a fresh transaction; immutable proof and verified phase commit together. Lost calls can reconstruct proof from the same live attempt. Two same-attempt verifiers converge on one identical proof. Backend uncertainty leaves building state and no authority; a stale namespace remains unselected. Verification metadata pins generation, namespace, token/fence, manifest, projection fingerprint and point count. The private proof reconstruction verifies canonical bytes and actual retained attempt identity.

`publish(principal, lease)` requires retained matching proof, current rights and exact expected PostgreSQL head, then atomically records publication, phase/event and selected head. Competing publishers cannot overwrite a winner. Exact published replay returns original historical success, even after a newer head or rights revocation; it performs no backend I/O and grants no content access. Unselected conflicting generations remain explicit verified work until failed/abandoned or expired. No automatic repinning or scientific-quality veto is added.

Forward `artifact_0011` adds immutable `index_verifications` and `index_publications`, plus narrowly mutable `index_heads`. Scoped FKs require actual attempts, verified generations and published head targets. Verified build work is not a usable selected generation until publication. Tests use actual Data/PG and a named **test-only** in-memory projection port with corruptions and timing barriers. The independently specified ABBA/AB histogram oracle verifies known retained content. Real Qdrant protocol, index reconstruction and ranking remain B2.02/B2.03; abrupt process death remains B3. Replacements preserve both histories and exact generation/head semantics.
