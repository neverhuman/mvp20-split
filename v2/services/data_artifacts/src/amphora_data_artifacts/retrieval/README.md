# Retrieval generation boundary

Owner: Data/Artifacts, BP-06.05/B2.01. Pure manifest/generation/attempt identities and transition policy are implemented; private generation admission/history/build claims are implemented. No Qdrant adapter, published head or retrieval API exists yet.

This module owns index snapshot identity, ordered corpus manifests, build lifecycle, projection verification and authoritative generation selection. It consumes Data representation profiles, validated source-binding projections and current source rights through their focused boundaries. It does not own source policies, encode scientific inputs, mutate Knowledge, schedule campaigns or treat a backend alias as truth.

A corpus contains 1..256 unique binding IDs in explicit order and one exact shared-role profile. Binding shape/fingerprint checks are distinct from actual retained source/rights authority, supplied by current owner admission. Canonical manifests have a 4MiB limit; their digest is the exact source watermark. A generation pins scope/corpus/id, owner actor, manifest, expected prior head and trusted backend profile. Build token/fence identity yields a distinct backend namespace per attempt; a stale builder cannot write into its successor's namespace. Point IDs are deterministic per complete binding reference and must remain unique.

Generation transitions are prepared -> building -> verified -> published, with failure/abandonment only from nonterminal states. Pure transition permission is not evidence that a projection exists or that publication is authorized. The lifecycle store verifies owner source/profile records and current process rights. Build claims are lease-fenced; actual projection verification and expected-head publication remain B2.01d. Backend integration is a required explicit port, never a hidden fallback; actual Qdrant proof belongs to B2.02.

Tests live in `tests/retrieval/` and must distinguish pure synthetic records, actual PostgreSQL authority, actual Qdrant behavior and process/race proof. Replacement preserves ordered manifest fingerprints, full profile/source/vector identity, attempt namespace isolation and immutable generation history. Verified publication and APIs are subsequent tasks; no pure-object test grants those completion claims.

B2.01a coverage: all 125 statements and 8 branches in this pure module exercised, including maximum manifest size, duplicate/colliding points, scope/profile separation, generation head and namespace isolation, and every transition pair. This is domain-policy evidence, not database or backend evidence.

`mapping.py` maps pure plans/references/manifests to public representations0.2.0 DTOs and revalidates inbound shapes, including model-construction bypasses. Reverse mapping recomputes all identities; request mapping compares exact ordered owner-resolved bindings and profile. Authenticated actor and trusted backend are separate owner inputs. Mapping is not source lookup, current-rights enforcement or status authority. Status serialization accepts only the domain phase enum and is reserved for future owner lifecycle reads. Existing generation fingerprint formats are unchanged.

## Durable generation state

`GenerationIntents(engine, backend_profile)` admits `BuildIndexGeneration` through `prepare(principal, request)` and reconstructs actor-owned historical status through `read`. Backend profile is owner configuration. Admission requires `representation_manage`; historical reads require `representation_read`. Exact replay preserves history even after rights revocation and never confers fresh content access. New admission resolves exact stored profile/published bindings and process rights. No external I/O occurs in the transaction. Conflicting immutable identities roll back completely.

`GenerationLeases` owns DB-clock 1..300-second claims, renewal and bounded failure/abandonment. Claims return a lease, busy outcome or existing terminal status. Fresh/expired building claims record unique token/fence/private namespace; stale leases cannot renew or terminate successors. Renewal checks the deadline again at the update after source-rights work. `finish` permits only failed/abandoned, never caller-asserted verified/published. Prepared work can be explicitly abandoned. Expired verified attempts become failed and require a new generation; this branch is present for B2.01d but not yet verified against an actual retained projection.

Migration `artifact_0010` adds immutable generation intent, ordered membership, numbered build-attempt and phase-event tables, plus a mutable cursor. Only phase/sequence/token/fence/expiry may update; all history denies service-role mutation/deletion. The current source-rights scope lock always precedes the corpus lock. Generation ids belong to one actor within a scoped corpus. Short transactions contain no backend calls. Forward migration/replacement preserves all prior records; old packages unable to recognize0010 must not run migrations.

Actual PostgreSQL tests cover admission/replay/conflict, forged/missing/cross-scope bindings, rights revocation versus historical metadata, concurrent claim convergence, expired takeover, stale/foreign/terminal rejection, deadline expiry during rights work, immutable grants and membership FKs. Retrieval coverage currently346/348 statements and19/20 branches; the expired verified branch belongs to the next projection gate. Full actual Qdrant behavior, abrupt process death and competing head publication remain their named gates. This module does not yet expose transport or host configuration.
