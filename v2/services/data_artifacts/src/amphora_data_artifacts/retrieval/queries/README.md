# Pinned retrieval queries

Data owns query identity, ranking and durable selection here. `QueryPlan` pins the authenticated actor, request id, exact generation, complete query binding and explicit policy. The query is a retained source representation under exactly the generation's shared-role profile; equal dimensions or caller-supplied vectors cannot establish compatibility. Pure objects validate consistency; `RetrievalBroker` separately resolves retained publication and current rights.

`QueryPolicy` supports exact Dot scores, 1..256 top-k and an optional exact binding allow-set. Null means the whole manifest; an empty tuple means no targets. Filter order is canonical and does not affect identity. Unknown references, conflicting digests and foreign scopes fail. There is no implicit latest generation or scientific-quality filter. Current Data source records carry completeness but no Knowledge review status; unsupported review-state predicates must be rejected, never silently interpreted as promotion or inferred from similarity.

`BindingScore` accepts finite numeric observations, normalizes signed zero and rejects booleans, overflow and nonfinite values. Ranking requires exactly one score for every owner-authorized eligible binding, rejects unexpected/duplicate/missing results, then sorts by descending score and ascending binding id/digest. All negative scores remain eligible. Scores are backend metric observations, not probabilities or scientific confidence. Backend response order never breaks ties.

The broker must resolve publication/profile/binding authority, determine current read/process access before backend I/O, validate observed point identities and fence current rights before committing/exposing results. This module cannot grant that authority. No unauthorized omission count, source payload or backend namespace belongs in the public result. Historical records preserve original selections; they do not grant fresh content access. Scientific corrections affect later campaign selection, not pinned current queries.

Tests belong in `tests/retrieval/queries/`. Replacement must preserve descriptor formats and canonical identity, exact profile/scope rejection, full eligible-set validation and deterministic tie behavior. Persistence, HTTP, installed-owner and actual backend tests remain separate evidence tiers.

## Durable execution and recovery

`RetrievalBroker(reads, backend).retrieve(principal, request)` requires representation_read and read actions. The initial generation boundary remains actor-owned: only its original actor may query it. Scope isolation, the exact published generation, exact retained query binding, complete profile, trusted backend descriptor and source rights are checked before admission. Cross-actor generation sharing requires a separately reviewed reader boundary; it is not inferred from knowing a digest.

The owner rights lock precedes the actor/query lock. The immutable intent commits before filesystem/backend reads. `QueryAccess` captures both read and process rights for the query and each target, suppressing only explicit revoked/expired/use-denied targets. Missing policy or lineage failures remain operational errors. Backend calls receive exactly the allowed point IDs. Returned full point/profile/binding/vector content must match actual retained vectors, and the complete eligible score set must pass ranking before commit.

No SQL transaction spans external I/O. Final eligibility and rights epochs must equal the captured state; even an allowed-to-allowed policy revision causes a retryable failure with no result. Intent survives unavailable/uncertain/malformed backend observations. A later invocation may retry the same intent; there is no hidden retry loop. Search is read-only, so duplicate invocations need no external-effect lease. A final short transaction selects one immutable result; simultaneous identical requests converge on it.

`read(principal, retrieval_id)` returns the original result with no backend call, or an explicit missing/pending error. Both reads and completed request replay require current read rights for the query and selected sources. Process-only changes do not rewrite history; read revocation denies serving source/vector metadata while preserving the record. Replays never silently rerank or repin. A new retrieval id requests a new selection. Denied targets yield no source/vector identifiers, scores or omission counts. An empty authorized selection performs no backend call and makes no assertion about backend availability or scientific absence.
