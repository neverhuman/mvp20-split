# Artifact Publication Boundary

Implemented under BP-02.03/A2: `Principal`, `UploadLimits`, `ContentPolicy`, `Capacity` and `UploadAttempt` own access, bounds and immutable upload context. `Uploads` owns begin/start/finish transactions. Storage performs byte I/O outside those transactions. These are private owner objects; external clients use public artifact contracts and HTTP.

BeginUpload authenticates actor/scope before registration, reserves declared bytes and records upload/receipt/audit atomically. Replay returns the same receipt; changed canonical bytes conflict. Only configured exact media/schema pairs are admitted. Legacy uploads retain null actor and are not silently authorized by the new migration.

Lock order is capacity -> upload -> attempt -> terminal command. First stream consumes the begin reservation; retries allocate additional capacity for their separate immutable files. Latest admitted generation alone may become selected; starting a retry clears the previous selection. Settlement decrements active streams once and reduces reserved bytes to the known closed-writer count. Unknown byte state keeps full allocation. Failed and stale attempt bytes remain charged until a later explicit cleanup gate. Empty uploads are bounded by upload/attempt counts as well as stream count.

Limits default to 16 MiB/upload, 256 MiB/scope, two streams, 1024 uploads, eight attempts/upload and a 300-second deadline. All replicas must share the configured profile. DB-clock expiry is rechecked at selection. Process death may leave a charged streaming attempt; A5 owns safe reconciliation. No TTL deletion, automatic retry or finalized artifact is implied by streaming success.

`Finalizer` verifies selected bytes outside SQL locks, then rechecks generation and selection under the capacity/upload locks. Catalog identity, terminal receipt, audit and notification outbox commit atomically. Concurrent finalization commands share the catalog identity; identical command replay returns its original receipt. Missing bytes/infrastructure errors leave the command pending; integrity, schema and selection conflicts persist a terminal rejection. Notifications are durable pending records; delivery is later scope.

ContentPolicy currently supports three explicit synthetic profiles with pinned schema digests: opaque octets, strict UTF-8 text and JSON objects. JSON rejects duplicate keys, nonfinite numbers, invalid Unicode and nesting beyond 64 levels. Configuration cannot claim arbitrary domain-schema validation; adding scientific schemas requires owned validators and acceptance tests.

`tests/publication/` exercises PostgreSQL, HTTP, separate writer processes and killed finalizer processes before/after catalog commit. Interruptions retain provisional status; credentials cannot widen scope; original terminal receipts and quotas survive replay. Injected transaction failure rolls back catalog/receipt/audit/outbox together. Read the service README for granular commands. A replacement preserves these tests, public receipts, generation identity, capacity conservation and owned migrations. A4-A6 still own retention, reconciliation and full service acceptance.
