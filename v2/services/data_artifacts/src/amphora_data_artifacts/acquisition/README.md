`SourceDocument` verifies a scoped SourceRevisionRef against at most4MiB of exact bytes. `extract(SourceSpan)` checks full source identity, half-open byte bounds and digest. It does not translate character offsets or decode/execute instructions. `TraceDocument.verify(trace, source, output)` validates matching scope/schema/source identities, output content, unique target paths, ordered-transform references and copied/converted/inferred/missing field policy. Missing or inferred values cannot receive `normalized` disposition. No disposition grants scientific acceptance.

Verified traces expose deterministic UTF-8 canonical bytes (sorted keys, compact JSON, no NaN; offsets/indices are bounded integers). Their public ConversionTraceRef is SHA-256 over those bytes. The acquisition ledger rejects an existing scoped trace ID with different canonical bytes; the pure provenance objects alone provide no persistence. It changes no existing command encoding.

Pure provenance depends only on public Core/evidence contracts and standard-library hashing/JSON. The private ledger additionally uses SQLAlchemy and the existing Data principal/catalog boundary, within the same service. No peer service imports or SQL are allowed. Callers must obtain bytes through authorized publication/read boundaries and check current rights before using these pure objects. Successful byte verification is not proof of authorization, sample identity, declared conversion algorithm execution or scientific validity.

`tests/acquisition/` owns exact-byte, UTF-8 offset, cross-scope, changed-content and origin-policy cases. The scope is independently runnable via `run_tests.py --module data-artifacts --area acquisition`. Replacement must preserve error codes, canonical bytes and immutable references. Current rights fencing is implemented in [Source Rights](../source_rights/README.md); V1 independent replacement is verified below.

## Private Acquisition Ledger

AcquisitionLedger.register requires the acquire action, matching source/rights scope and a SourceDocument with verified raw bytes. It verifies the entire ArtifactRef against the finalized local catalog. Registration verifies explicit current processing rights; the stored reference remains immutable provenance. A rights grant does not imply scientific acceptance.

Delivery uniqueness is scope/issuer/delivery, independent of source ID. Exact canonical replay returns the original revision even after newer corrections. Changed metadata or bytes under a delivery key conflict; another delivery cannot overwrite a source revision. Corrections name the exact previous reference and must match the persisted source head. Stable, sorted transaction advisory locks serialize delivery/source races; source revision and head commit together. Canonical records are bounded to256KiB.

retain_trace verifies source/output bytes and provenance before storing an immutable trace, requires the exact registered source and finalized output reference, and rejects changed content under the same trace ID. Changed conversions require a new trace ID. history/trace_history require source_history and return exact historical records, never evidence usability. No raw document text is copied into these records.

artifact_0004 adds private source_revisions/source_heads/conversion_traces with scoped catalog/source foreign keys. artifact_service has SELECT/INSERT and only head-column UPDATE, no historical UPDATE/DELETE. Infrastructure errors propagate; retrying identical records reconciles uncertain commits. Public routes, current rights/expiry fencing, durable Research identity observations and four process-kill cases are implemented below; independently installed-owner acceptance is verified below.

Owned PostgreSQL tests use actual upload/finalization, concurrent cross-source delivery contention, correction/replay, trace collision, catalog forgery/missing artifact, head-write rollback, scope and role denial. Pure-source spans retain their existing25 tests. The fixture never resets retained PostgreSQL state.


## Bounded Preparation Profiles

prepare_document accepts verified UTF-8 bytes and emits PreparedDocument JSON with original text intact, including embedded instructions as inert data. Its one conversion field points to the complete raw byte span; empty documents are unresolved. Raw and prepared outputs each have a4MiB limit, including JSON escaping expansion.

prepare_lab accepts at most64KiB of a flat JSON object with exactly the supported field universe: candidate_id/candidate_revision, sample_id/sample_revision, method, context, value and unit. Values are strings (at most2048 characters) or null; revisions and decimal measurements remain lexical strings, never binary floats. Absent fields emit null with missing provenance; explicit null retains its exact source token span. Numeric JSON values, nested structures, unknown or duplicate/escaped-duplicate keys, trailing content, invalid UTF-8 and unpaired surrogates are rejected. This is an explicitly synthetic input profile, not a general instrument/LIMS parser.

The focused flat_json scanner delegates string decoding to the standard JSON decoder and retains byte offsets for each original token. Repeated values and Unicode before a token cannot confuse span attribution. The parser never executes document contents. It preserves censored/malformed measurement text, marks warnings and does no unit conversion or inference. Every lab result remains quarantined with identity_reconciliation_required, even when syntactically complete; public Research matching and scientific interpretation are still separate gates.

PreparedAcquisition owns trace construction after independent output artifact finalization. It requires the exact published preparation schema/media type and matching output bytes. Public prepared_schema pins the exporter's validation bytes; publication must use those trusted deployment profiles. Converter IDs utf8-document and synthetic-lab-json are fixed version1 with empty configuration. A behavior change requires a new converter/profile version; no caller-defined code or transform is loaded.

Tests cover instruction preservation, empty/invalid documents, output expansion, wrong-schema binding, missing versus null units, censoring, unsafe identity/revisions, duplicate keys and escaped Unicode/repeated-value spans. The independent wheel probe runs the pure provenance/preparation suites without Research or Runtime installed. This is not live scientific ingestion acceptance.


## Public Research Client

ResearchClient consumes only amphora-contracts-research DTOs over a configured loopback HTTP endpoint; no Research implementation import or SQL connection. The endpoint must explicitly name127.0.0.1 and a port, without credentials/path/query/fragment. The opaque token is supplied by trusted configuration. Requests and responses carry exact scoped candidate/sample revisions. Responses are limited to16KiB, strict JSON, matching scope/identities, and consistent disposition/reason; redirects are not followed. Default timeout is5 seconds, bounded to30. Denial, unavailable transport and malformed response remain distinct safe errors, never synthesized unknown-sample answers. No automatic retry or authority widening occurs.

lab_identity_query derives explicit candidate/sample references from prepared lexical strings only when IDs and safe positive integer revisions validate. Missing/malformed references return no query; document profiles are rejected. A successful match grants identity_only and does not change the prepared lab's quarantine/scientific status.

Scripted TCP tests cover valid/unknown identity, denial, redirects, loss, bounds, wrong media, malformed/duplicate JSON and response substitution. Separately installed Data and Research wheels communicate through the actual Research HTTP process and PostgreSQL owner. Neither environment has the peer implementation installed. Known, unknown and stopped-peer cases pass; the lab preparation stays quarantined. That earlier probe uses synthetic in-memory raw references; subsequent finalized-source/output integration and durable observation proofs are described below.

## Finalized Owner Stages

AcquisitionWorkflow.prepare(principal, SourceRevision) requires acquire and read, rejects mismatched scope/catalog identity, obtains actual verified bytes through ArtifactReads, registers delivery, then runs the reviewed document/lab converter selected by the declared format. Registration precedes parsing: an invalid document remains an attributable delivery, exact retries repeat the failure, and corrected bytes require a new superseding revision/delivery. No caller content or transformation implementation is accepted.

AcquisitionWorkflow.retain(principal, revision, trace_id, output_ref) repeats authorized preparation, reads the actual finalized output, checks byte-for-byte equality and exact prepared schema/media, and retains the immutable trace through AcquisitionLedger. It never trusts a caller-constructed PreparedAcquisition. Equal bytes in a different artifact do not overwrite an existing trace identity. Publication remains the existing upload/stream/finalize operation, with original command receipts available for reconciliation; these stages do not introduce a second upload store or claim an atomic transaction spanning stages. Source registration can persist when later conversion or output validation fails.

PreparedContentRule(document|lab) is an explicit trusted deployment-installed ContentRule. Its identity is pinned to the published prepared_schema digest and validation uses the corresponding public DTO. Unknown profiles fail configuration; missing/extra fields, wrong versions and type coercion fail validation. Existing generic JsonSchemaRule restrictions remain intact. Host acquisition=true explicitly installs both rules and mounts the staged routes; the default remains disabled.

Current-use rights fencing is implemented in [Source Rights](../source_rights/README.md); final replacement acceptance is verified below. Durable Research identity observations are implemented below. The stages do not turn historical rights references into authorization. All lab traces stay quarantined. Tests use actual upload/finalization, retained PostgreSQL and local bytes: replay, exact spans, denied reads/acquisition, foreign scopes, forged/missing artifacts, parser failure, changed delivery, substituted output, changed trace artifact and corrupt storage. V1 process replacement is verified below.

## Staged HTTP Contract

Host configuration acquisition=true explicitly enables the routes and installs both reviewed output profiles, while still requiring explicit raw profiles and principal actions. Startup checks acquisition tables exist under artifact_service; it performs no migrations. Acquisition reads are capped at the lesser of the configured upload bound and4MiB.

- POST /v1/acquisition/prepare accepts SourceRevision and requires acquire plus read. It returns PreparedSource. UTF-8 encode content_json_utf8 verbatim, verify sha256, and use application/json with schema_ref through existing begin/upload/finalize operations. No output is published by preparation.
- POST /v1/acquisition/retain accepts RetainPreparedSource and requires acquire plus read. It recomputes the reviewed conversion from actual raw bytes, verifies actual finalized output, and returns ConversionTraceRef only after trace commit.
- GET /v1/acquisition/sources/{source_id}/{revision_id} requires source_history; returns the exact scoped immutable SourceRevision or404. This reconciles interrupted preparation before retry without reading raw payloads.
- GET /v1/acquisition/traces/{trace_id} requires source_history; returns immutable ConversionTrace metadata or404. Historical access is separate from permission to read raw bytes or use evidence.

Requests authenticate before parsing; mutation bodies require application/json, are capped at256KiB with a5-second read deadline, and reject duplicate keys, nonfinite numbers, malformed/extra/incorrectly typed fields. Safe HTTP statuses include401/403 authority,413 size,415 media,422 shape,408 body timeout,409 provenance conflict,404 missing artifacts/history and503 existing owner storage failures. Successful responses use Cache-Control:no-store. No body is interpreted as an instruction. Published request schemas are the wire authority; FastAPI response schemas do not substitute for them.

These operations use the existing scoped delivery/revision and trace identities for replay, not a new command encoding. Retry preparation with the exact SourceRevision. Reconcile artifact command receipts before retrying output publication. Retry retention with the same finalized output reference and trace ID: changing output identity conflicts even for equal bytes. Source registration may survive later failure; successful trace retention is immutable. Research lookup is a separate durable observation operation below; lab quarantine persists. Process loss is covered by the explicit four-case suite below; TestClient alone is not process evidence. Independent installed-host acceptance is verified below.

A further process test launches the actual artifact CLI twice against the same PostgreSQL and storage root, prepares a synthetic lab source over loopback HTTP, retains its finalized output and verifies identical receipts/history after replacement. Raw/output uploads use the existing owner API fixture. This proves host restart persistence in the development environment; process loss during writes is covered below, while independent wheel environments are verified below.

## Durable Research Identity Observations

POST /v1/acquisition/identity-observations takes ObserveSourceIdentity and requires acquire plus read. It durably binds scope/observation ID to an exact retained trace before lookup. A different trace under that ID conflicts. For a new/pending lookup, the workflow reads actual authorized raw/output bytes, reruns the reviewed converter and checks the complete trace fingerprint. Documents yield not_applicable; missing/malformed lab identity yields unresolved without calling Research. Otherwise the configured public ResearchClient returns an exact scoped identity-only resolution. No observation promotes a lab trace or establishes scientific eligibility.

The immutable intent commits before external HTTP; no database lock spans a peer call. Unavailable, denied, malformed or substituted responses leave the intent pending and return a safe503. Explicit retry uses the same observation ID. The first result committed under the scoped identity wins: concurrent readers may see different Research knowledge, but all callers return the same stored winner. A lost response is reconciled through GET /v1/acquisition/identity-observations/{id}, requiring source_history. It returns SourceIdentityStatus (result=null while pending), or404 before intent registration. Later knowledge uses a new observation ID; old results and conversion traces stay unchanged. Historical result replay checks principal actions/scope but does not reread raw content or call Research. Historical metadata is not a new-use rights grant.

Host configuration optionally names research: {endpoint, token_env} when acquisition=true. The endpoint must be an explicit loopback URL accepted by ResearchClient; token_env references a trusted environment secret. Missing configuration fails only queryable lab lookup, not document/malformed-identity processing or replay. Startup checks the intent/result tables exist. Each owner continues to migrate separately.

artifact_0005 adds immutable intent/result tables: exact trace/hash foreign keys; insert/select only for artifact_service; result foreign key to its intent; bounded canonical bytes and database timestamps. AcquisitionWorkflow owns composition, IdentityDecision owns local/peer-result policy, and IdentityObservations owns only Data SQL. Source/trace histories and original artifact commands are unchanged.

Verification includes PostgreSQL scope/grants, forged trace hashes, pending retry, first-winner concurrency, transactional rollback, denied UPDATE/DELETE, substituted identities, public status/replay and a real Research CLI HTTP peer. The real peer case records unknown, publishes synthetic Research identities through a Research-owned setup process, observes matched under a new ID, preserves the original, then proves stopped-peer pending/replay.
