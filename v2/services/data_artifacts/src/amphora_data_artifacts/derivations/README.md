# Derived publication boundary

- Status: DER-01/D2 persistence/HTTP implemented; 266 owner regressions pass; D3-D4 pending.
- Owner: Data/Artifacts; [plan](../../../../../docs/Build%20Plans/BP-06/BP-06.03%20Derived%20publication%20prerequisite.md).
- Architecture: [artifact publication](../../../../../docs/Architecture/System/Artifact_Publication_Protocol.md).

`DeclaredTransformation` authenticates upload/read privileges, revalidates immutable command bytes against their identity, rejects repeated input artifact IDs, and binds a final receipt to the exact output descriptor and scope. The public command parser rejects foreign input scopes. Input order is part of command identity: this boundary never silently sorts a retry. A transformation descriptor pins a producer's method/configuration digest; Data does not verify its scientific claim or execute it. No inline executable code or rights override is accepted.

Public artifact contracts0.2.0 add `artifacts.begin_derived_upload`, `BeginDerivedUpload`, `DerivationDeclaration`, `DerivedUploadReceipt`, `DerivedUploadObservation` and `DerivationReceipt`. All predecessor models and command families retain their bytes. A derived begin has a separate observation union so legacy consumers do not receive a new discriminator in their existing schema. Stream/finalize continue to use the predecessor commands and receipts; the derived begin receipt embeds the ordinary upload receipt. Metadata is historical evidence, not a payload-access lease.

Implemented transaction boundary: immutable upload declarations and finalized input edges in new artifact_0007. Begin binds declaration, authenticated command and upload atomically after exact catalog identity and current process permission checks. All finalize paths consult that declaration and commit catalog/lineage/receipt/audit together. Lock order is source-rights scope -> capacity -> upload -> attempt -> terminal command. No peer or filesystem I/O under these locks. Finalization captures rights before verification and fences current rights/expiry plus upload generation before commit. Terminal command replay is historical and does not reauthorize new payload use.

Ancestry traverses conversion and derivation edges together with limits128 direct inputs/parents per visited artifact,4096 visited identities and256 distinct rights bindings. Repeated shared ancestors do not imply cycles; actual cycles, bounds, missing/foreign/conflicting references and denied/expired rights fail closed. Ordinary uploads retain their explicit no-inferred-lineage semantics. A new derived input must already exist, preventing forward edges from normal publication; historical conversion edges still require defensive cycle handling.

Tests belong to `tests/derivations`; contract cases belong to `contracts/artifacts/tests`. D1 pure tests do not establish PostgreSQL atomicity, installed replacement or scientific validity. D2-D4 must supply those scoped software gates before Knowledge publishes via this path. No deletion or mandatory-erasure policy is introduced.

`DerivedPublications` owns POST `/v1/derived-uploads` and exact actor-scoped command history on the existing command-read route. GET `/v1/artifacts/{id}/derivation` is scoped read-only immutable metadata. Derived begin requires upload/read; finalize requires finalize plus the original actor's upload/read grants. Unknown/mismatched input identities persist rejected begin receipts without charging quota. Original terminal command replay remains historical after rights revocation. Payload reads traverse both conversion and derivation ancestry.

`DerivationLedger` inserts the declaration link to immutable command bytes, finalized metadata and exact input edges. All three new tables grant SELECT/INSERT only; finalized metadata and inputs reference existing scoped catalog identities. Applied artifact_0007 is immutable. Ordinary Finalizer always takes the source-rights scope lock first, including ordinary uploads, before capacity/upload locks; a declaration cannot be omitted by choosing the legacy finalize route. Streaming/maintenance/retention take capacity locks without acquiring rights locks, so no reverse edge is introduced. Source registration/trace commits already take rights first and never take publication capacity locks.

Legacy identity-conversion traces whose raw/output artifact IDs are equal contribute no ancestry edge; their artifact still retains all source rights. This preserves the existing identity-converter contract. Derived outputs always have a new artifact ID; self-derived edges are prohibited. Cycles between distinct artifacts remain denied.
