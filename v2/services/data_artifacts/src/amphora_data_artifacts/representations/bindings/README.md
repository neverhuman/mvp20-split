# Source binding publication boundary

Owner: Data/Artifacts, BP-06.05/B1.04a-b. [Design](../../../../../../docs/Build%20Plans/BP-06/Completed/BP-06.05%20Physical%20design.md). Pure boundary checks and durable source preflight/state are implemented; 147 scoped source checks and420 distinct installed regression cases passed. Bounded publication orchestration is verified under B1.04c; source-independent rights and alias/publisher convergence are verified under B1.04d.

`SourceBindingIdentity` binds scope, authenticated publisher actor, exact profile reference and exact source byte span. It revalidates nested wire records and rejects cross-scope references, empty/out-of-bounds spans, inputs above65536 bytes and raw sources above4MiB before I/O. Its versioned digest determines binding identity and stable begin/finalize command ids. Request encoding ids are aliases rather than publication identity: the same actor/source/profile can converge across workflows. Different publishers retain separate command histories. An existing permitted binding can still be referenced by another reader without impersonating its publisher. Computation identity remains independently reusable within scope.

`VectorPublication` groups that identity with the computed representation. It requires exact profile/input identity and the initial context-free source-span profile. It exposes canonical vector Artifact bytes, exact content descriptor, one source-only derivation declaration and real public parsed begin/finalize commands. The transformation digest pins the complete binding recipe. It never aggregates all sources sharing a cached vector into one ancestry chain.

`BindingReceipts` verifies the actor-scoped begin observation identity/request digest, accepted upload/content/declaration, and finalized derivation origin, upload, source edges and Artifact descriptor. Only then does it construct a binding projection whose digest includes the actual Artifact reference. A structurally valid receipt alone is insufficient. The upload receipt has no actor field; actor authentication comes from its enclosing command observation and final derivation origin.

`VectorContentRule` is an explicit opt-in content policy. It checks the published DTO shape plus exact payload length, finite binary32 values, canonical positive zero and payload digest. Full profile meaning, source authorization and provenance remain outside this generic content validator. It is not automatically installed into hosted configuration.

The identity, document, receipt and content-rule files perform no SQL, filesystem, HTTP, encoding or rights-policy operations. The pure canonical record encoder is shared with private cache serialization without importing storage/SQL into these objects. No pending binding, source-read authorization, Artifact publication or rights guarantee is implemented by a pure receipt projection. The modules below supply preflight/state, while B1.04c-d supply orchestration and broader integration; APIs and installed HTTP proof are B1.05-.06.

Tests in `tests/representations/test_binding_models.py` use synthetic public receipts to verify aliases, source/publisher separation, byte/schema descriptors, command identities, scope/span/input bounds, wrong origins/content/lineage and malformed vector payloads. They establish no real owner publication. Replacement must preserve the versioned identity format, canonical bytes, command families/ids and all exact rejection checks. Existing public schema bytes and artifact_0008 remain unchanged in B1.04a.

## Durable source binding state (artifact_0009)

`SourcePreflight` verifies the exact registered source revision and Artifact, bounded byte span/hash, UTF-8 input, complete registered profile and current read/process rights. It fences rights after reading. Unsupported context input is rejected; an unavailable encoder is acceptable only when its exact verified cached result already exists. Scientific source corrections never repin an existing request.

`BindingRequests` commits an immutable publisher-specific job and actor-specific encoding-id alias after a fresh process-rights fence. Same binding aliases converge; reused request ids with different content conflict and roll back the whole transaction. Status reads replay original metadata without reprocessing source bytes. New aliases and pending consumption require current authorization. Admission rights epochs are audit evidence, never a reusable permission grant.

`BindingLeases` supplies DB-clock claims, renewal and release for publication, independently of compute claims. Token/fence checks reject expired or replaced workers. Rights are locked before binding state. No transaction encloses encoding, filesystem work or another publication operation. Immutable jobs, aliases, events and final bindings have SELECT/INSERT-only service grants; only cursor stage/attempt/lease columns are mutable.

`BindingJournal` owns ordered transitions: prepared -> begin_prepared -> upload_begun -> streamed -> finalize_prepared -> artifact_finalized -> published. Commands are retained before effects; accepted/rejected observations are reconstructed from exact owner command history, selected upload state and finalized derivation records. The journal accepts no caller assertion of external success. Final binding visibility and current derivation rights are committed together, with exact cache/Artifact foreign keys. Seven bounded event kinds per attempt retain recovery evidence without source bytes.

Absent/pending Artifact acknowledgements retain the same attempt. Only a proven terminal rejection permits a freshly authorized numbered retry. Attempt1 preserves the original command bytes; later deterministic command suffixes retain the same source binding identity. The immutable rejected event remains in history. Numeric attempt/fence exhaustion is explicit. A process can reconstruct the current prefix without scanning old attempts. Initial cache computation may be unfinished when the job is admitted, so only the final binding references an existing result.

Data0.16.0 is the minimum migration runner for artifact_0009. Existing source/catalog/derivation/cache records are not rewritten; automatic downgrade/reset is prohibited. Rebuilds must preserve these identities, stage ordering, original request aliases, command/receipt prefixes, rights fences and lease semantics. `CommandStore.inspect[_in]` and `Uploads.selected_in` are narrow owner-local read primitives, not additional public endpoints.

These manually driven protocols do not establish hosted/process behavior; separate installed HTTP and process evidence must be consulted. Synthetic vectors have no scientific relevance claim.

## Recoverable orchestration

`BindingWorkflow.encode` checks all grants, validates the request and returns an exact published replay before source I/O. New/pending requests take fresh preflight and persist intent before claiming computation. A compute cache hit is never source permission. Busy compute or publication leases return the immutable request with pending status. Encoding uses the reviewed fixture only; the retained exact cache may outlive encoder availability. Every call has a `RecoveryBudget` of1..64 stage steps (default16), with no synchronous sleep or infinite retry.

The executor drives journal commands and actual DerivedPublications/Uploads/Finalizer operations outside journal transactions. It observes retained outcomes before repeating effects. Accepted lost responses converge; actual rejections are retained and surfaced as operational errors. A later authorized call can advance the numbered attempt. Partial writers close before settlement; uncertainty remains charged. Exact published history never authorizes a new alias after rights revocation.

`publication/recovery.py` owns a narrow upload recovery projection and bounded expired-stream settlement. A live stream returns pending. For an expired stream, an acquired OS guard proves the writer is closed; `LocalBytes.fence_writer` durably prevents delayed writes without deleting bytes, then the existing Uploads.finish primitive releases the stream slot while retaining its entire byte allocation. Failure between marker and settlement is replayable. A held writer lock or filesystem error defers recovery. Cleanup remains the sole existing byte-retirement/refund authority.

The journal may prepare finalization from upload_begun only when actual owner state proves the upload abandoned or its stream attempts exhausted with no selected/live/unsettled stream. The actual final command must still return a retained rejection before numbered retry. This is an explicit failure-disposition path, never a readiness probe based on missing acknowledgement. Public command/receipt bytes, initial identities and schema versions remain unchanged.

`test_binding_workflow.py` exercises the actual stack and faults after durable begin/finalize/publish effects, lost stream settlement, partial writes, grant denials, single-step budgets, busy claims, expired writer locks, exhausted/abandoned uploads and current-rights alias denial. In-process faults do not replace B3 process-death and race evidence. Hosted routes and installed HTTP replay are separately verified under B1.05-.06.
