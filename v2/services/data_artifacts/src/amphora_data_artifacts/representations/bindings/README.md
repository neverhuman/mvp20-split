# Source binding publication boundary

Owner: Data/Artifacts, BP-06.05/B1.04a. [Design](../../../../../../docs/Build%20Plans/BP-06/BP-06.05%20Physical%20design.md). Pure boundary checks are implemented; durable source preflight/state and publication orchestration remain B1.04b-d.

`SourceBindingIdentity` binds scope, authenticated publisher actor, exact profile reference and exact source byte span. It revalidates nested wire records and rejects cross-scope references, empty/out-of-bounds spans, inputs above65536 bytes and raw sources above4MiB before I/O. Its versioned digest determines binding identity and stable begin/finalize command ids. Request encoding ids are aliases rather than publication identity: the same actor/source/profile can converge across workflows. Different publishers retain separate command histories. An existing permitted binding can still be referenced by another reader without impersonating its publisher. Computation identity remains independently reusable within scope.

`VectorPublication` groups that identity with the computed representation. It requires exact profile/input identity and the initial context-free source-span profile. It exposes canonical vector Artifact bytes, exact content descriptor, one source-only derivation declaration and real public parsed begin/finalize commands. The transformation digest pins the complete binding recipe. It never aggregates all sources sharing a cached vector into one ancestry chain.

`BindingReceipts` verifies the actor-scoped begin observation identity/request digest, accepted upload/content/declaration, and finalized derivation origin, upload, source edges and Artifact descriptor. Only then does it construct a binding projection whose digest includes the actual Artifact reference. A structurally valid receipt alone is insufficient. The upload receipt has no actor field; actor authentication comes from its enclosing command observation and final derivation origin.

`VectorContentRule` is an explicit opt-in content policy. It checks the published DTO shape plus exact payload length, finite binary32 values, canonical positive zero and payload digest. Full profile meaning, source authorization and provenance remain outside this generic content validator. It is not automatically installed into hosted configuration.

These files perform no SQL, filesystem, HTTP, encoding or rights-policy operations. The pure canonical record encoder is shared with private cache serialization without importing storage/SQL into these objects. No pending binding, source-read authorization, Artifact publication or rights guarantee is implemented by a pure receipt projection. B1.04b-d supply those gates; APIs and installed HTTP proof are B1.05-.06.

Tests in `tests/representations/test_binding_models.py` use synthetic public receipts to verify aliases, source/publisher separation, byte/schema descriptors, command identities, scope/span/input bounds, wrong origins/content/lineage and malformed vector payloads. They establish no real owner publication. Replacement must preserve the versioned identity format, canonical bytes, command families/ids and all exact rejection checks. Existing public schema bytes and artifact_0008 remain unchanged in B1.04a.
