# Artifact Maintenance Boundary

BP-02.03/A5 owns bounded explicit sweeps. Cleanup only visits the authenticated principal's old provisional/abandoned uploads; it requires the cleanup grant. Reconciler visits that runtime principal's reserved bindings through the existing authenticated public outcome client. Neither reads runtime tables or deletes finalized content.

Cleanup defaults to a 24-hour grace and checks database clock plus every attempt deadline before abandoning an upload under capacity/upload locks. Abandonment fences finalization and new attempts. It then acquires the attempt's OS lock outside SQL; an active writer defers cleanup without refund. The cleaning transition and stream-count settlement commit before storage retirement. A persistent retired marker is fsynced before unlink; delayed writers reject that key forever. After unlink, a second transaction refunds charged bytes and marks cleaned exactly once. Crashes before unlink, after unlink or before refund resume safely. Unstarted uploads refund their begin reservation once at abandonment. Legacy unowned uploads remain inaccessible.

The lock file is never removed, avoiding split-lock races. Markers and database evidence persist; upload_count remains a lifetime admission bound (1024 by default), so cleanup reclaims byte/stream capacity but does not silently allow unbounded metadata growth. A future archival/capacity policy must preserve tombstones. No finalized catalog or reservation content is garbage-collected, including released reservations.

Sweeps accept bounded batch sizes and return cursors; callers wrap an empty cursor to the beginning for future passes. Reconciler reuses a deterministic per-reservation command identity, so repeated outages do not create new pending commands. It uses a scheduling deadline, allowing an in-progress bounded lookup to finish; unknown/outage defers and contradictory proof retains protection. Conflicts need diagnosis, not automatic release. Lifecycle hosting/CLI remains A6.

All replicas must use this writer-lock protocol and the same local storage root. Upgrade requires quiescing older writers that predate it. Windows local-filesystem process-crash tests exercise OS lock release; Linux locks are implemented but require host acceptance. Remote filesystems, hostile administrator mutation and power-loss directory durability are outside this evidence.

Tests live in tests/maintenance (cleanup) and tests/retention (bounded reconciliation). Cases cover live writers, delayed open, no-attempt uploads, finalized preservation, repeated refund, and killed processes at claim/retirement and while writing. Separate authenticated scripted runtime tests remain client evidence; actual runtime terminal races are BP-02.06. Replacement must preserve all fences, charges, terminal evidence and cursors.
