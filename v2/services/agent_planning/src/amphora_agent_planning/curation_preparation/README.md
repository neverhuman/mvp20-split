# Curation preparation assembly

UI-01.08/P2.3b.2. Architecture: ../../../../../docs/Architecture/Agents/Planning.md.
CurationContextAssembler composes configured Planning-owned public readers: exact
Runtime original draft/predecessor, Data processing reads for original roots and
selected Artifacts, bounded Registry discovery, Runtime reviewed universe/schemas,
selected historical Knowledge heads and exact Research questions/evidence needs.
No SQL, model/network host chosen by human text, graph mutation, source publication,
reservation or provider issuance belongs here. Each reader retains its existing
finite time/call/byte limits. No transaction spans any peer operation.

The same immutable request and original human intent bind every lane. Registry
scan max200 releases over2pages; incomplete scans and omitted optional releases
remain explicit. Runtime metadata denial becomes a visible unavailable slice;
malformed internal state propagates. Knowledge and Research gaps/weak records remain
context, not a scientific-success/failure decision. No unselected assessments or
latest revisions are added. Missing required Artifact processing rights short-
circuit unrelated later reads and preparation fails with exact missing identities.

CurationAssembly.prepare fits the complete envelope with required-first policy;
required originals cannot be silently omitted and optional inventory/source drops
retain their identities/hashes. Successful preparation is not current dispatch
permission: later durable linkage and fresh processing checks still gate issue.
Credential/endpoint configuration, policy/declaration publication, journal recovery
and managed workers remain separately owned next work. Tests: tests/curation_preparation.
