# Campaign compiler exchanges

Owner: Planning BP-07.03/B2.02b; Planning0.58 verified with41 loopback tests,12 boundary checks and389 isolated cases. [Design](../../../../../docs/Build%20Plans/BP-07/BP-07.03%20Compiler%20handoff.md). Focused HTTP primitives own framing/resource limits, not orchestration or execution authority.

RuntimeAuthoringClient accepts only canonical AuthoringRequest values for its configured owner/actor. It exposes save/validate, original receipt read and exact accepted readback. Paths derive from validated public identities, never model URLs. Runtime responses pass AuthoringOutcome binding before returning. No activation/admission route exists. RegistryEligibilityClient accepts only public registry.resolve commands and the configured owner/actor. It returns a typed RegistryReceipt; later policy must bind scope/lock/descriptor/status/expiry. Registry does not echo command identity/hash, so the client makes no such claim.

CompilerWindow bounds the whole sequence to20 seconds,16MiB total responses and8 Runtime or64 Registry calls. Individual receipts cap256KiB; draft/validation readbacks cap1MiB. Canonical command parsing caps requests256KiB. Timer-driven socket shutdown bounds slow headers/body; final parsing must finish within the deadline. Origins are explicit authenticated127.0.0.1 HTTP with a port. No redirects, proxies, retry, credential logging or caller-selected routes. Strict JSON rejects duplicate keys, nonfinite values and invalid public records. Error bodies are not retained.

Every write requires a caller guard, invoked before connect and immediately before send. B2.03 owns the durable intent/fence implementation; a callable alone is not a grant or proof of journal origin. Calls perform no SQL and must occur outside owner transactions. Missing reads, denial, identity conflict, invalid requests and unavailable/uncertain exchanges remain distinct. Lost replies never prove that a write failed; reconcile the original command. Existing extraction owner_handoff and read-only transports are unchanged.

Tests belong in tests/campaign_exchanges and use actual loopback HTTP for route/auth/body/receipt, slow responses, size/time/call limits and guard failure. These probes prove the client boundary only. Actual-owner compatibility is B2.02d; durable races/recovery are B2.03/B3. Runtime retains admission, current eligibility, budget and single-active-campaign checks. Synthetic metadata does not establish science.
