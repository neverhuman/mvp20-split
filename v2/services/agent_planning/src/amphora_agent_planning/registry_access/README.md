# Registry metadata discovery

Owner: Planning; BP-07.03/B1.02b.i. This module consumes public Tools0.1 release metadata through metadata_reads. It owns inventory query bounds, page order/filter/continuation validation, immutable observed releases and exact full-lock readback. It owns no Registry state, registration, lifecycle command, eligibility resolution, capacity reservation, compiler review or scientific promotion.

`DiscoveryQuery` binds the immutable campaign_proposal/supervision RequestSnapshot, optional exact capability/release filters, after-digest cursor, page limit1..100 and max_pages1..4. `RegistryReader.discover` consumes at most400 records/four pages under one30s/16MiB window. Scope comes from the original request and authenticated principal, never a caller-supplied URL scope. Every page must preserve filters and strictly increasing unique descriptor digests. A non-null next cursor equals the last digest of a full page.

`ObservedRelease.bind` validates original Python values before JSON serialization, scope and descriptor size<=256KiB, unique port names, the published amphora-tool-release-v1 canonical hash and the entire projected lock (binding/image, descriptor, ordered input/output schemas and checkpoint). It retains canonical bytes and observed lifecycle/revision, including registered, draining and revoked. Examples/applicability remain untrusted descriptive text. Matching a text label is not scientific eligibility, and a lock is not execution authority.

`DiscoveryResult` retains verified pages only, complete/incomplete, safe failure, exact continuation, query and call/byte counts. A later failure preserves prior useful metadata. Reaching max_pages with a continuation is explicitly incomplete without inventing an error. An empty successful inventory is complete; an unavailable page is not. Concurrent insertion before a cursor may appear only on a fresh scan; lifecycle can change between pages. No consistent snapshot claim follows. New handoff must recheck selected locks/lifecycle/eligibility through their owning boundaries.

`RegistryReader.exact(request, lock, window)` separately checks exact scope and every selected lock field, returning current observed lifecycle or raising on unavailable/mismatched data. No fallback to latest or alternate version occurs. It can share the same window with discovery; limits never renew automatically.

Tests live under tests/registry_access and use copied public tool_releases.json vectors plus loopback HTTP tests in tests/metadata_reads. Replacement must preserve literal canonical descriptor vectors, complete lock comparison, inactive explanations, partial results, exact cursor behavior and finite bounds.
