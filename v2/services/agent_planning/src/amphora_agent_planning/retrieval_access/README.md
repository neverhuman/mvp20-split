# Retained retrieval context

Owner: Planning; BP-07.03/B1.02c.ii. Public Representations0.3 supplies DTOs; the closed Data metadata GET target supplies transport. This module owns immutable campaign/query/result selection and consistency of returned source/vector metadata. It has no Data implementation import, Qdrant/SQL access, encoder, ranker, source-rights grant or scientific authority.

`RetrievalSelection.bind(request, query, result_sha256)` binds the original campaign/supervision RequestSnapshot, exact RetrieveRepresentations request and expected result digest. Scopes must match. Explicit allow-sets normalize by binding identity; null/all differs from empty. No new query id, generation, profile or result pin is inferred. Selection does not create a query or authorize processing.

`RetrievalReader.read(selection, window)` performs exactly one GET `/v1/retrieval/queries/{id}` with Data credentials, bounded by30s/32 calls/16MiB aggregate and4MiB response through metadata_reads. It checks actor, complete generation/query reference, policy and the existing documented query/result fingerprints. Every full RepresentationBinding verifies its own projection hash, nested scopes, exact profile and source span geometry. Match identities are unique; order is descending finite score then ascending binding id/digest, with negative scores retained. Top-k and explicit allow-set remain hard bounds. Scores are recorded metric observations, never confidence or proof of relevance.

The immutable observation preserves complete reported source/vector provenance. Data remains authoritative for retained generation membership, current read rights and backend ranking. The result alone cannot prove the private full eligible set. Historical retrieval read permission is not fresh source processing permission: use campaign_data_access and current Data processing-content checks for any consumed source bytes. Vector/source metadata is not retrieved raw content. No external reference is followed here.

Missing/pending/denied/unavailable results return explicit safe failure; invalid bindings cannot yield a usable record. No retries, reranking, POST query creation or replacement identity occurs. New selection creation belongs to durable preparation orchestration, which must retain original intent before effects. Unknown programming errors propagate; the immutable selected pin never changes after failure.

Tests live under tests/retrieval_access and metadata_reads. The literal vector was produced by independently installed Data0.29 pure QueryPlan/QueryRecord from synthetic bindings; it is not a persisted/query/backend/scientific proof. Tests cover fixed fingerprints, altered provenance, foreign scope/actor, filters, profiles, rank order, negative ties, exact HTTP and unavailable outcomes. Actual combined-owner proof remains B1.02d. Replacement must preserve the documented fingerprints, strict policy and exact selected result; any changed identity profile requires explicit versioning.
