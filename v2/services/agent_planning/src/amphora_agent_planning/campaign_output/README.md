# Campaign output boundary

Pure interpretation of planning.campaign-draft/v1 output. CampaignDecisionScope binds an immutable original campaign/supervision request and the exact profile/action/decision digest. CampaignCandidate owns action/payload consistency, supervision cut equality and unique authored node/input adjustment identities. CampaignOutput owns strict JSON decoding, canonical bytes, fingerprints and conversion to the existing TypedProposal. Nested typed scope references must match the original request.

Inputs are a RequestSnapshot and at most65536 raw UTF-8 bytes. Duplicate JSON keys, nonfinite numbers, invalid/deep shapes, unknown fields, mismatched profile/purpose/action/scope/digest/cut and duplicate changes fail with ValueError. Canonical output must also fit65536 bytes. Original request and caller data remain immutable; exact provider capture belongs to the provider journal. proposal() rebinds before emitting the boundary DTO, including when a caller constructs a domain object directly.

There is no I/O, private peer dependency, persistence, provider dispatch or authority to apply a change. Decision digests are opaque identity pins, not decoded target/range permissions. Future graphs are proposals for later campaigns. Runtime has no adjustment write API yet; proposed scalar changes are not executable commands. The parser does not establish evidence selection membership, producer-node meaning, tool eligibility, compiled validity or scientific confidence; those belong to B2 policy and Runtime/domain owners. Unresolved science and compact alternatives remain visible on abstention as well as active proposals.

Owned tests: services/agent_planning/tests/campaign_output. Rebuild acceptance includes each valid action, nested foreign scopes, malformed/deep/nonfinite/duplicate input, original purpose/profile/cut/digest and action boundaries, repeated/conflicting adjustments, exact canonical reconstruction and mutation isolation. Public schema compatibility stays in contract/dev tests. The closed provider catalog delegates this profile here. Capture and persistence reconstruct exact proposals; this pure module alone cannot dispatch. SQL integration tests are separately owned by tests/campaign_output_storage.


CheckpointOutput is the explicit planning.checkpoint-draft parser. It requires supervision purpose and an original Runtime cut, validates concrete-path/field uniqueness, and preserves exact ScalarValue decimal strings. The provider catalog dispatches only the exact schema pin; CampaignOutput retains its closed old profile. Actual SQL capture/settlement replay includes the new profile. These checks grant no Runtime effect; CampaignPrepared legacy future-composition review remains a separate entry point.
