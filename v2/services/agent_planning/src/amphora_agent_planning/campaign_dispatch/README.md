CompilerSelection binds the original Planning actor and provider attempt, preparation/proposal hashes, Runtime owner/actor and exact reviewed declaration/budget/Registry eligibility configuration. It rebinds AuthoringPlan and requires read/write grants for new selection. The stable effect ID excludes configuration and generated content: the selection store rejects changed contents at the same slot rather than creating duplicate effects. Existing authoring command identities remain unchanged.

The witness retains bounded canonical policy bytes, not packet bodies. Restoration requires original read authority and exact actor/scope/canonical encoding but does not require write authority or contact peers. Restoration verifies shape and scoped witnesses; verify_origin compares a reconstructed original proposal and policy. Neither method proves persisted provenance. CompilerHistory loads original owned preparation/attempt/reservation/settlement before registration and historical reconstruction.

CompilerEffect derives exact save/validate commands from the bound AuthoringPlan, or an exact selected release check from EligibilityBatch. The1MiB canonical wrapper retains selection identity/hash, owner, operation kind and original command bytes; public parsers keep their smaller command limits. Validation requires the matching saved-draft receipt/readback. Restore reconstructs from original selection/configuration/proposal and dependency before accepting bytes. Changed configuration/payload retains the operation slot but changes immutable contents. New named checks get distinct identities; lost-reply retries retain the original bytes. Pure derivation and a supplied saved outcome do not prove journal origin or dispatch authority; storage must establish those dependencies.

CompilerObservation binds the exact expected request, effect and selection to public owner receipts/readbacks. Registry observations additionally bind the original configuration/attempt/check/context: command bytes alone cannot prove which Registry policy was expected. Saved, compiled, structurally invalid, pending, rejected, awaiting readback and candidate remain distinct. Historical candidate replay does not renew its expiry. No current permission or database origin is inferred.

CompilerEvent reconstructs at most64 ordered events per effect. Prepared starts the history; dispatch records intent only; uncertain follows dispatch without proving remote absence; blocked retains a bounded operational reason; observed reconstructs the typed outcome. Slot64 is reserved for terminal evidence. Saved/compiled/structural_invalid/rejected/candidate are terminal only for that individual effect. Terminal history cannot advance; it does not mean campaign admission or scientific success. A new freshness check is a separately journaled operation. Immutable event bytes include exact effect identity/hash and position. Future storage must derive the expected request from owned original/dependency state before replay and enforce DB-clock fences; these pure transitions confer no write authority.

CompilerHistory reconstructs the original proposal/review/authoring configuration from immutable owned rows and selection witness; missing history or mismatched charge cannot register. CompilerStore retains first selection bytes/time and uses exact actor/scope/configuration checks. planning0013 adds SELECT/INSERT-only compiler_selections and separate compiler_control, with UPDATE restricted to holder/fence/expiry. Original-attempt uniqueness also has a scoped SQL constraint. Existing migrations and public schemas remain unchanged. Never run Planning<=0.64 migrators on0013.

Leases last1..300 seconds using the database clock, monotonic fences and opaque holder identities. Acquisition is serialized by a scoped advisory lock; competing holders cannot both acquire. Expired/released leases cannot guard, renew or release a successor lease. Read-only replacement verifies original origin and exact stored timestamps without writing. Origin reads occur outside short mutation transactions; no peer I/O occurs under SQL. A lease is only local journal authority: a request already in flight may still commit remotely after expiry, so subsequent operation storage/coordinator must reconcile stable original commands.

CompilerJournal prepares one save and one validation per original selection, requires the saved terminal readback before validation, and atomically registers complete selected-tool rounds (at most16 rounds,1..64 tools each). A new round requires the previous round to be fully terminal. Zero-tool drafts create no rounds. CompilerOperations re-derives stored effects and replays exact events; indexed identities, digests, coverage and control positions must match. Exact append retries preserve first event bytes/time; changed retries conflict. Every mutation checks the active selection fence at the end of its transaction, rolling back new rows if the DB lease expired.

The journal retains at most one verified immutable original context for the exact principal (including grants) and selection. It caches no current processing rights, leases, operation state or owner outcome. Every operation read loads current event/control rows. Derived eligibility batches have a short mutex-protected two-entry cache and are computed outside SQL where possible. Configuration/selection changes replace the cached origin; changed permissions are checked before reuse. New-owner replacement reconstructs history from SQL. Peer calls and current source/eligibility refresh remain coordinator responsibilities.
