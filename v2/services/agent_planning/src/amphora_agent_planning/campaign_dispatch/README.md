# Campaign dispatch

Owner: Planning BP-07.03/B2.03a verified in Planning0.64:53 scoped/198 isolated dispatch cases,277 statements18branches100%;12 boundary checks. Earlier285-case compiler proof remains separate. [Design](../../../../../docs/Build%20Plans/BP-07/BP-07.03%20Compiler%20handoff.md). This module currently owns pure canonical selection, effect payload, typed observation and bounded event values only. No SQL, peer I/O, dispatch, lease, provider call or execution admission exists here.

CompilerSelection binds the original Planning actor and provider attempt, preparation/proposal hashes, Runtime owner/actor and exact reviewed declaration/budget/Registry eligibility configuration. It rebinds AuthoringPlan and requires read/write grants for new selection. The stable effect ID excludes configuration and generated content: the future journal must reject changed contents at the same slot rather than creating duplicate effects. Existing authoring command identities remain unchanged.

The witness retains bounded canonical policy bytes, not packet bodies. Restoration requires original read authority and exact actor/scope/canonical encoding but does not require write authority or contact peers. Restoration verifies shape and scoped witnesses; verify_origin compares a reconstructed original proposal and policy. Neither method proves persisted provenance. The subsequent journal must load original owned preparation/attempt/reservation/settlement before registration or historical reconstruction.

Tests belong under tests/campaign_dispatch. Rebuild acceptance preserves slot identity across configuration/output changes while detecting immutable-content conflict, wrong actor/scope, altered witness/origin and noncanonical bytes. Pending scope: PostgreSQL origin/fences, guarded coordinator and independent recovery. No existing extraction handoff format or public schema is changed.

CompilerEffect derives exact save/validate commands from the bound AuthoringPlan, or an exact selected release check from EligibilityBatch. The1MiB canonical wrapper retains selection identity/hash, owner, operation kind and original command bytes; public parsers keep their smaller command limits. Validation requires the matching saved-draft receipt/readback. Restore reconstructs from original selection/configuration/proposal and dependency before accepting bytes. Changed configuration/payload retains the operation slot but changes immutable contents. New named checks get distinct identities; lost-reply retries retain the original bytes. Pure derivation and a supplied saved outcome do not prove journal origin or dispatch authority; storage must establish those dependencies.

CompilerObservation binds the exact expected request, effect and selection to public owner receipts/readbacks. Registry observations additionally bind the original configuration/attempt/check/context: command bytes alone cannot prove which Registry policy was expected. Saved, compiled, structurally invalid, pending, rejected, awaiting readback and candidate remain distinct. Historical candidate replay does not renew its expiry. No current permission or database origin is inferred.

CompilerEvent reconstructs at most64 ordered events per effect. Prepared starts the history; dispatch records intent only; uncertain follows dispatch without proving remote absence; blocked retains a bounded operational reason; observed reconstructs the typed outcome. Slot64 is reserved for terminal evidence. Saved/compiled/structural_invalid/rejected/candidate are terminal only for that individual effect. Terminal history cannot advance; it does not mean campaign admission or scientific success. A new freshness check is a separately journaled operation. Immutable event bytes include exact effect identity/hash and position. Future storage must derive the expected request from owned original/dependency state before replay and enforce DB-clock fences; these pure transitions confer no write authority.
