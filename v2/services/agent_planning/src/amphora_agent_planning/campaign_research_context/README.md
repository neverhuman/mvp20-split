# Campaign Research projection

Owner: Agent Planning. Architecture: [Planning](../../../../../docs/Architecture/Agents/Planning.md). campaign_context owns question/need/assessment relationships; research_view_access owns typed named pages; owner readers establish public contact. This pure adapter owns bounded context composition and relevant observations. No HTTP, SQL, scientific promotion, pagination or source-processing grant.

CampaignResearchProjection reconstructs ResearchContext from exact selected records and gaps and recomputes findings. A caller-edited finding list cannot erase contradictory, pending or unknown science. Up to32 explicit named-page outcomes must belong to the same original RequestSnapshot. Each successful page is revalidated against its exact query, returned fields and continuation; missing/denied/invalid outcomes retain closed reason codes. Duplicate page identities, mixed requests and contradictory page/failure shapes reject. Catalog discovery is not silently included as evidence; each page includes its published result-schema reference.

Canonical sorted UTF-8 projection bytes retain complete records/gaps/findings and full selected pages/continuations under an8MiB aggregate cap. Overflow raises explicitly, without truncation or hidden omission. Packet policy owns optional exclusion and reporting when a projection cannot fit; this module does not make a prompt-fit claim. Owner labels and page text remain data, not an instruction channel.

Relevant observations use exact Research identities and named view requests including page positions. Record/gap and page/unavailable hashes distinguish absent state. changes compares only original relevant identities; unrelated added views do not invalidate selected records. Cross-scope comparison fails. Original request fingerprints remain provenance rather than a blanket comparison key. This does not repin or invalidate an active campaign; future proposal policy owns comparisons.

Tests under tests/campaign_research_context cover selected findings, missing/pending inputs, exact pages/continuations, unavailable outcomes, request binding, duplicate selection and relevant comparison. Replacement must preserve canonical identities, closed schemas, explicit quality/gap information and bounded behavior. Source freshness, instruction approval, tokenizer fitting and durable preparation remain separate later boundaries.
