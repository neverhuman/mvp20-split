# Reviewed curation policy

UI-01.08/P2.3c.1. Architecture: ../../../../../docs/Architecture/Agents/Planning.md.
CurationPolicy is byte-owned operator configuration, not a browser/model payload.
It pins scope/actor, empty-source request template roots/model/prompt/schema/limits,
policy ID, compiler structural/side-effect ceilings, Registry eligibility context
and original per-call reservation. Parsing enforces the fixed curation cost/model
profile and only abstain/propose_campaign authority. Human intent cannot select
provider endpoints, widen these limits or grant capabilities.

seed binds the original command SHA in provider engagement identity. declare
requires the exact previously read Runtime context for that seed and creates a
reviewed v2 compiler declaration: same campaign ID, next authored revision, explicit
objective/policy/model/selected-source/Knowledge pins and configured ceilings.
Original graph topology is input, not a fixed pathway; the model may propose
composition within those reviewed bounds. No scientific quality is inferred.

ReviewedDeclaration.with_artifact binds exact declaration hash/size/scope/media as
a required constraint and uses its digest as decision_scope. Data availability and
processing rights are checked by later public context reads; a supplied ArtifactRef
alone is not proof of publication. This module performs no I/O, SQL, rights grants,
model call or graph activation. Durable existing-Data-API publication is next.
Replacement tests live under tests/curation_policy; predecessor declarations and
public schemas remain unchanged. No defaults silently expand structural authority.
