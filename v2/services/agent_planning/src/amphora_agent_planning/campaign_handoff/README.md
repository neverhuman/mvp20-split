# Campaign handoff preparation

Owner: Planning BP-07.03/B2.02c.iii; under verification. [Design](../../../../../docs/Build%20Plans/BP-07/BP-07.03%20Compiler%20handoff.md). This module owns read-only origin/accounting checks and prerequisite composition. It has no command dispatcher or new persistent state.

CampaignOriginReader loads preparation, attempt, reservation and settlement through existing Planning journals. Every interface enforces the original actor/scope. StoredCampaignOrigin reconstructs combined policy and compares exact packet/manifest, attempt, capture/observation, demand and conservative charge. Missing, unbudgeted, unsettled or mismatched history cannot prepare a handoff. Reads preserve original timestamps, charges and overage; no reserve, refund or settlement write occurs. Separate short reads are sufficient for these immutable records and never hold SQL across peer I/O. Pure construction verifies consistency only; the reader establishes the available owned-storage provenance.

CompilerPreparer revalidates the authoring plan and complete selected eligibility batch/outcomes, loads owned origin and invokes its configured RefreshCollector. It does not accept an external ready flag. Current-use failures, relevant changes, explicit eligibility rejection and expired observations produce named blocked states with original evidence retained. Eligibility freshness uses the clock after refresh. Unknown/missing scientific points remain diagnostics under the refresh policy. Zero-tool drafts require zero eligibility observations.

The positive state ready_to_journal is not a saved draft, compiler result or execution grant. No save, validate or resolve command is sent here. B2.03 must pin configurations, check identities and outgoing bytes before effects, establish fence authority and re-run current checks for unissued work. A retained preparation cannot be used as a processing or eligibility lease. Source reads do not establish latest Research heads; Runtime alone owns admission/tool budgets/current eligibility and the single-campaign guard. Existing model accounting neither grants another paid call nor funds execution.

Tests belong under tests/campaign_handoff for pure composition and tests/campaign_handoff_storage for actual PostgreSQL origin/authorization/replay. Rebuild acceptance preserves exact immutable accounting and origin, complete outcome coverage, post-refresh expiry, explicit blocked states and absence of writes. Actual Runtime/Registry compatibility remains B2.02d; durable dispatch/recovery remains B2.03/B3.
