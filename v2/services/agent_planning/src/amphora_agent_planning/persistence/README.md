# Planning request and attempt journal

BP-07.01/B1.03, Agent Planning0.3, forward migration planning_0001. PlanningJournal owns only planning.requests/attempts/observations. Explicit migrator role applies DDL; service role has SELECT/INSERT only and cannot rewrite/delete history or read peer owner tables. Serving/importing never migrates. Private Principal is supplied by a trusted owning adapter, not model text or wire-selected grants.

register stores exact validated request bytes, digest and actor under scoped engagement ID. Same-actor exact retry returns original state; changed request/actor conflicts. begin_attempt commits a separate intent before a future orchestrator calls a provider. Ordinals are sequential, within the request's declared bound, and at most one unfinished attempt is allowed per logical request. Duplicate begin returns the original pending/observed record. Unknown request, missing attempt and pending observation remain distinct.

record stores one immutable ProviderObservation and bounded raw capture atomically. It verifies exact request/attempt, capture digest/size/completeness and successful proposal against retained bytes and reviewed output schema. Usage remains separate from text; incomplete streams retain a labeled prefix, not a complete-output hash. First committed observation wins; exact retry replays, differing late observation conflicts. Same-request advisory transaction locks serialize journal writes; no lock spans a provider, filesystem or peer call. Database timestamps record persistence time, not invented provider duration.

read_request/read_attempt require exact scope/read grant and original actor. Reconstruction validates stored canonical request identity and capture bindings. Replacement retains original bytes, hashes, pending intents and observations. Inputs/outputs are private request-scoped diagnostics; no unauthenticated HTTP endpoint, source-access delegation or output publication exists. Actor/grants are infrastructure trust; actual source rights and provider configuration require later context workflow.

This journal does not dispatch, reserve tokens/cost, prove a provider was called, mark Runtime engagement acceptance or reconcile ambiguous calls automatically. B2 adds durable conservative budget/fence/orchestration policy before any public dispatch surface. A terminal unknown observation does not itself authorize a retry or refund. No deletion/retention-expiry authority is added.

Verification: module tests/persistence cover actual PostgreSQL idempotent migration, intent/observation separation, exact conflict, actor/grants, raw/usage replay, pending sequencing, competing writers, corruption rejection, role restrictions and fresh-engine reconstruction. tests/persistence/test_records.py separately tests private principal and preserved-output semantics. B1.04 owns separate-process/independent installation readback; current fresh-engine proof is not that gate.

Independent acceptance is run by `dev/verify_planning.py --output <new-evidence-directory>` with explicit AMPHORA_TEST_POSTGRES=1. The verifier builds the public dependency closure, installs two environments without private peers, copies test sources/fixtures without bytecode caches, supplies only Planning-owned URL secrets through environment, runs the explicit migration CLI and module tests, then checks pending/interrupted/proposed/replay across four fresh owner processes. It preserves evidence and does not reset any schema or fixture volume. This uses one source-built closure in two installs; it is not an independently authored replacement implementation.


## Atomic reservation admission

BP-07.01/B2.01b, planning_0002 adds immutable budget_policies/reservations. BudgetLedger stores exact reviewed policy and conservative demand atomically with the journal attempt intent. It shares the same request-key advisory transaction lock as PlanningJournal; no model/peer call occurs within that transaction. Policy/request changes conflict, existing reservation retries replay, and unbudgeted legacy intents cannot be retroactively authorized. Failed sequence or budget checks roll back any newly inserted policy and intent together.

Readback reconstructs demand from the retained policy and validates stored quantities. All holds currently remain reserved, even after an observed provider response. A reported low usage is not an automatic refund; B2.02 adds settlement. Attempt count, token and accounting limits remain per logical request; Runtime retains aggregate campaign budget authority. Only read/insert service grants are added, no history update/delete. Older service0.4 and earlier migrators cannot understand planning_0002 and must not migrate this retained schema.

Actual PostgreSQL cases in tests/persistence/test_reservations.py verify atomic intent/hold, concurrency/idempotency, exact ceilings, policy/request conflicts, rollback, legacy distinction and SQLSTATE42501 on forbidden history mutations. The installed process probe separately preserves the exact hold and registration time across replacement. This is reservation authority, not public dispatch or a paid/live provider claim.
