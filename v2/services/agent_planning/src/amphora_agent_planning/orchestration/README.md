# Bounded provider orchestration

BP-07.01/B2.03. PlanningRunner composes this service's context, budget, journal, issuance, provider and settlement modules. It owns no Runtime decision, source authorization, scientific tool call, network adapter or campaign state. Public dependencies remain the existing Planning/Core contracts; RunOutcome is a private domain result, not a new wire schema.

execute registers the immutable request, reserves reviewed policy demand and obtains a once-only issuance ticket before invoking the configured ProviderPort. No SQL transaction spans that call. Concurrent/restarted callers cannot reacquire its call grant. They read pending history or recover an expired issuance as unknown. A normal outcome settles before returning; a persistence failure leaves durable facts for replay. BaseException/process death is deliberately not swallowed. Adapter failures are redacted unknown outcomes; raw exception messages are never persisted.

run walks at most the request's original physical-attempt limit. Proposal, deliberate abstention and policy rejection stop; malformed/unavailable/unknown outcomes can consume the next bounded reservation. An unexpired pending attempt returns immediately. Budget exhaustion/overage is an explicit stop reason, never a permission increase. Every attempt preserves the same immutable context/model/prompt/policy and action set. This initial runner does not author repair prompts or silently truncate context. Later task profiles own actual repair payloads.

timeout_seconds is trusted owner configuration (integer1..86400), not model output. Its database-clock deadline governs accepted observations, not remote cancellation. A real adapter must enforce its transport deadline, disable hidden paid retries and observe owner-approved model/egress/spend policy. Deterministic adapters and local issuance do not prove network exactly-once effects. Late output stays separate from recovered history, with conservative charge maxima preventing undercounting; already-issued external calls cannot be undone.

Tests live in tests/orchestration (actual PostgreSQL opt-in), independently selectable through dev/run_tests.py. Replacement must preserve pending/terminal distinctions, once-only local call grant, immutable snapshots, conservative budgets, redacted failures and own-state-only writes. B3 adds independent adversarial/barrier/process-death proof; live provider evaluation is BP-07.05.
