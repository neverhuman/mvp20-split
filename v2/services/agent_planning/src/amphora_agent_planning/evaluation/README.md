# Independent evaluation protocol and scoring

- Owner: Agent Planning; BP-07.05/B1.01. Planning0.90 introduces private evaluation file profile1. Runner is implemented in evaluation_execution; owner inspection and live evidence remain later subunits.
- Design: [evaluation physical design](../../../../../docs/Build%20Plans/BP-07/Completed/BP-07.05%20Physical%20design.md).

`EvaluationProtocol.load` validates bounded original manifest/corpus bytes, exact corpus digest, unique cases/assertions/data, exact category coverage and JSON-pointer/expected-value labels. Frozen public model/limits/Artifact records are reused; these private file DTOs do not change public service schemas. Canonical manifest identity pins mode, adapter revision, model, prompt digest, exact corpus bytes, allowed data, repetitions, resource limits and thresholds. `model_inputs()` exposes only case/input digests, never expected labels. Loading configuration does not authorize processing the pinned data or live egress.

`EvaluationScorer` owns planned repetition enumeration, binding checks, strict structured-fact matching, abstention/error accounting and category/suite decisions. Labels are supplied independently of model outputs. JSON-pointer assertions use strict canonical equality or exact array membership; missing paths fail. Boolean true is not integer1, and reversed relationship endpoints do not match. Duplicate keys/nonfinite JSON/depth/byte overflow cannot pass. This is an explicit structured semantic rubric, not a general entailment model or scientific validation. A caller must supply a validated output/profile and authoritative outcome classification; this module does not trust model text to classify its own authority or abstention.

All planned repetitions remain in the denominator. Missing results fail completion; errors/invalid/unknown/authority violations fail even if the configured semantic threshold is zero. Scientific abstention requires both case permission and category allowance and is separately counted. Allowed abstention earns full rubric credit but remains bounded by its category rate; this is not a grounded-answer claim. Any failed hard-authority case fails the suite regardless of averaged score. Duplicate attempt identities reject instead of replacing a failure; reruns require distinct protocol history in the forthcoming runner. Payloads are rejected except on proposed or rejected observations. Rejected carries sanitized owner status/reason and may satisfy an independently pinned adversarial rubric; it never means execution acceptance. No score is a Runtime decision or Knowledge/Research acceptance.

The module performs no network, SQL, file writes, provider calls, budget issuance or source fetch. Inputs/results are frozen values; no prompts, provider credentials or expected labels are sent anywhere. Protocol DTOs live in records.py; identity/validation behavior in protocol.py; scoring/denominators in scoring.py. Rebuilds must preserve exact identity, independent labels, all-attempt denominators, explicit fixture/live distinction and hard-failure behavior. Durable runner/accounting integration is B1.02; no live readiness claim until B2/B3.

Owned tests: `services/agent_planning/tests/evaluation`. Coverage and exact final checks are recorded in the canonical plan/evidence when verified. Synthetic A-inhibits-B labels demonstrate endpoint direction and evidence identity, not chemistry or biology.
