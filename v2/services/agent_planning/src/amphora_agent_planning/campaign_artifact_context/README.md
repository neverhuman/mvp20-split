# Campaign Artifact context

Owner: Agent Planning. Architecture: [Planning](../../../../../docs/Architecture/Agents/Planning.md). The original RequestSnapshot determines roots, roles, required flags and exclusions; campaign_data_access owns exact bounded processing reads. This module owns preparation ordering and byte-owned observations, not Data state, source conversion, prompt approval, provider permission or scientific interpretation.

ArtifactContextPlan binds four mandatory roots (objective, prompt, policy, model configuration) and up to128 original entries. Up to132 distinct exact identities are supported. Repeated root/entry identities merge roles and escalate to required; contradictory identities fail at the request boundary. Required items precede optional items, retaining original order within each class. Declared omissions are never fetched or silently restored.

CampaignArtifactContextReader divides eligible references into batches of at most128 under one shared ReadBudget (default20 seconds,512 calls,32MiB). Each batch uses a fresh existing CampaignArtifactReader. At most4MiB per Artifact; oversize records become explicit failures without suppressing useful neighbors. Per-record missing/denied/invalid results remain visible; outage/deadline/call/byte exhaustion also stops later batches. No automatic retry, ordinary-content fallback, cross-operation cache or continuing processing lease exists. A fresh preparation performs fresh reads.

ArtifactContextProjection revalidates the original plan, ordered item coverage, exact body type/size/SHA256, failure vocabulary and32MiB aggregate payload cap. missing_required exposes missing mandatory roots/entries without discarding other useful observations. Canonical metadata includes exact content references and availability; metadata fingerprints therefore bind the observed payload identities without serializing every body repeatedly. payload() provides lossless base64 data for arbitrary Artifact formats. This is not text extraction, an instruction channel or current authorization. Immutable prior bytes remain historical observations after rights changes.

Packet policy later decides approved prompt/template use, required/optional inclusion and tokenizer fit. Journal/dispatch later own durable reconstruction and fresh rights/egress checks. Tests under tests/campaign_artifact_context cover the132-identity boundary, mandatory ordering, role merging, omissions, partial/global failure, shared budget across batches, fresh permission loss and exact binary payloads. Replacement must preserve ordering, original selection and explicit unavailable states without widening the reader's established limits.
