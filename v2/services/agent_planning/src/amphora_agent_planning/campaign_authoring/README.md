# Campaign authoring handoff

Owner: Planning campaign compiler client, BP-07.03/B2.02a. Design: [compiler handoff](../../../../../docs/Build%20Plans/BP-07/Completed/BP-07.03%20Compiler%20handoff.md). Planning0.57 values verified:30 focused/348 independently installed cases and12 boundary checks. No dispatch or durable-success claim.

AuthoringPlan reconstructs the combined decision review and reviewed budget, permits only a future draft and binds a configured Runtime owner/actor. Its stable draft and command slot hashes the original provider attempt and owner configuration, excluding generated output. A changed payload therefore retains its command identity for the Runtime owner to reject as a conflict. The later Planning journal must also enforce immutable slot/configuration binding. IDs are namespaced and scoped; they are not credentials.

Save always targets a new draft with expected_revision 0 and uses the public explicit numeric command profile. Validation uses the unchanged v1 command profile and requires exact accepted save readback. Public command parsing owns numeric normalization, byte limits and envelopes. AuthoringRequest retains canonical bytes and revalidates before use. Direct construction is not proof of journal origin or permission to send.

AuthoringOutcome checks the complete receipt identity/request hash and expected committed kind/revision/content. Save readback must match scope, title and the complete original definition. Validation readback must match the accepted validation identity and original draft/content pins. Pending, rejected, awaiting_readback, saved, compiled and structural_invalid remain distinct. A successful validation command can record invalid compilation. Compiler universe/findings/pending checks and scientific_acceptance remain in the immutable public readback; compiled is never an execution grant or a fresh eligibility claim.

These value objects perform no HTTP, SQL, provider call, migration, budget reservation or Runtime admission. Runtime and Registry implementations are not dependencies. Future transports and the B2.03 durable journal must preserve exact requests before effects, reconcile original identities and enforce current prerequisites. No adjustment write API is invented. Rebuild tests belong in tests/campaign_authoring and cover numeric profiles, identity stability, forged values, all receipt states and exact readback rejection.
