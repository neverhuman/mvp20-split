# Campaign tool metadata context

Owner: Agent Planning. Architecture: [Planning](../../../../../docs/Architecture/Agents/Planning.md). Registry and Runtime retain separate state and authority; this module supplies two pure, independently replaceable projections over their bounded public read clients. No discovery HTTP, eligibility call, compiler execution, owner SQL or tool execution occurs here.

RegistryContext revalidates the original discovery query and every observed release, including descriptor/full-lock identity, scope, ordering and filters. Page count, complete/incomplete state, continuation and safe failure codes must agree with declared scan bounds (at most4 pages of100). Up to64 separately selected exact-release observations retain their own lifecycle snapshots; a later revocation does not overwrite an earlier inventory observation. Duplicate exact locks reject. Canonical projection capped at32MiB. Inventory is neither a transactionally consistent catalog snapshot nor eligibility/reservation authority. Packet policy later selects relevant descriptors; B3 owns the300-descriptor relevance/budget gate.

RuntimeContext revalidates the reviewed universe and every selected schema outcome. Up to256 unique selected schema references must each have exactly one available record or safe failure, in selected order. Exact decoded schema bytes and universe identity must match; missing, duplicated, unselected or conflicting outcomes reject. A missing whole universe is explicit unavailable context, not an invented empty catalog. Canonical projection capped at24MiB. Neither the universe nor schema bytes prove a proposed graph compiles or may execute.

Both projections retain the original request fingerprint and owner-specific authority labels. Overflow rejects without truncation; packet policy owns fit and explicit exclusions. Current exact metadata is rechecked by later proposal/hand-off policy, rather than turning unrelated inventory changes into a blanket active-campaign invalidation. Tests under tests/campaign_tool_context cover partial scans, lifecycle separation, schema outcome coverage, tampered bytes, unavailable inputs and original request binding. Actual owner read compatibility remains in the unchanged client acceptance evidence. No persistence or public schema change.
