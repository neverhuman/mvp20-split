# Campaign proposal policy boundary

Owner: Agent Planning. This module is separate from Knowledge extraction proposals. B2.01a/b implement exact prepared-output binding, relevant observation values and evidence-purpose relationships; tool/composition and reviewed decision-declaration policy remain subsequent units.

PreparedCampaignProposal.bind reconstructs CampaignPreparation and the original AttemptBinding/verified_observation, then parses the exact successful campaign capture. It retains original preparation, attempt, raw capture, observation and canonical-output identities. It rejects another request, corrupt input history, unavailable output or a forged typed envelope. Its fingerprint rebinds all these values. This proves compatible retained inputs/output identities, not that a provider actually consumed that packet; issuance integration and fresh processing permission remain separate gates.

ObservedInputs indexes only included candidate observations already matched to packet consumed observations. Keys are lane, kind and canonical identity bytes. Equal duplicates coalesce; conflicting hashes for one key reject. Registry inventory/exact lanes remain independent. select accepts only existing keys, rejects duplicate or omitted/foreign dependencies, and sorts deterministically. RelevantReadSet fingerprints the original preparation and selected observations; changes compares only those identities against another validated same-scope observation index. Changed or missing identities are explicit; unrelated additions or changes do not invalidate the set. Empty selection is allowed for policy to represent no dependency, not a bypass of later required semantic dependencies.

All values are byte-owned/frozen and state-free. No network, provider call, private peer import, SQL write, scientific acceptance, Runtime eligibility or campaign repinning occurs here. Inputs are bounded by the owning preparation/output contracts. Read-set comparison does not establish recency, source rights or owner contact. Subsequent policy must select every dependency that matters; model output cannot provide arbitrary hashes as its read-set.

Owned tests: services/agent_planning/tests/campaign_proposals, covered by the existing agent-planning scope in dev/test_scopes.json. Rebuild acceptance verifies valid prepared outputs, mismatched request/capture/ordinal, forged domain values, exact fingerprints, omitted input exclusion, lane distinctions/conflicts, and selected-only change/missing detection. Preserve public schemas, packet/journal bytes and historical outputs. No migration or new public DTO belongs to this pure value unit.

EvidencePurposeReview reconstructs the complete consumed Research selection/context and checks its original observation hashes before linking output. Intents and unresolved references must use exact selected revisions; assessment requests/hashes and question/need relationships are verified. Missing records remain explicit findings and read dependencies, while scientific supported/contradicted/unknown posture is retained without promotion or a global veto. Producer addresses remain explicitly producer_resolution_required until composition policy resolves them. Anonymous abstention can have no Research context. Changed/omitted findings, identities or observations fail even if packet hashes were recomputed. Tests in test_evidence.py own these relationships.
