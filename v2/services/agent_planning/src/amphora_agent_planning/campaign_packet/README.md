# Campaign packet

Owner: Agent Planning. Architecture: [Planning](../../../../../docs/Architecture/Agents/Planning.md). `prepare(CampaignSlicePlan)` constructs exact fixture-provider input bytes. No network, fresh processing permission, provider dispatch, budget reservation, SQL or owner acceptance occurs here. Use the slice plan's typed factories; direct dataclass construction is not a public ingestion API.

Preparation rebinds original Artifact identities, roles, bytes, status and observations, checks required ordering, and binds the closed model/tokenizer profile. Missing required Artifacts produce `required_artifact_unavailable` with exact missing IDs. Only the original prompt Artifact matching the packaged reviewed instruction profile enters `trusted_instructions`. All request, Artifact, graph, Research, Runtime, Registry and retrieval content remains under `untrusted_context`. A sole-role prompt body is represented there by metadata and its trusted-field location; an additional original data role retains the exact body too. JSON separation is a serialization boundary, not evidence that a live LLM resists injection.

The `planning-campaign-packet.v1` envelope includes the original request, included slices, original omissions, budget omissions and observations of included slices only. Every budget omission records lane, exact identity and payload SHA; dropped inventory records do not enter the consumed read-set. Required scientific gaps remain data, not scientific failure conditions. Scan diagnostics alone do not turn all discovered releases into relevant observations.

Start with every required slice and explicit omissions for every optional candidate. Measure that whole envelope under the original fixture tokenizer, input ceiling and unchanged output reserve. Mandatory overflow yields `required_input_limit` or `required_packet_size`, without truncating constraints. Consider optional slices in stable plan order; regenerate and measure the complete envelope including changed omissions/observations for each candidate. Rejecting one optional candidate does not stop later candidates. The8MiB packet ceiling applies independently of a larger token allowance. At most one initial rendering plus one per optional slice; memory/count inputs remain bounded by the slice plan. No budget refund, prior-attempt accounting or live token estimate is implied.

Successful PreparedCampaignPacket retains exact canonical bytes, measured fit, original plan SHA and included indices. PacketPreparation explicitly distinguishes success from unavailable technical preparation; malformed bindings and unsupported profiles raise validation failures. Byte hashes and fit describe only these exact input bytes, not provider-added framing or egress permission.

Tests in tests/campaign_packet cover deterministic bytes, immutable original limits, trusted/data separation, additional prompt roles, required failures, omission costs, continued optional packing, consumed-only observations and packet byte ceilings. Preserve existing profile bytes for replay when replacing the implementation or introduce a new version. Adversarial reconstruction acceptance, durable journaling and real provider adaptation are subsequent gates.
