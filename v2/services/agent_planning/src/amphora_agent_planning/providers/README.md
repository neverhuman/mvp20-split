# Provider boundary and diagnostic capture

BP-07.01, provider boundary introduced in Agent Planning0.2 and retained in0.7. ProviderPort.supports checks the reviewed model identity; reply takes an exact AttemptBinding and returns a byte stream plus observed usage. FixtureProvider supports only deterministic/adversarial-fixture/revision1. It has no network, credentials, tool execution or peer state. A test barrier simulates a delayed reply; this is not a live transport/deadline implementation.

observe checks the selected output schema and adapter support before dispatch. Capture retains at most64KiB/256 chunks; oversized/wrong-type/flooded streams fail with an incomplete prefix digest. Interrupted replies are unknown, never successful; pre-response unavailability and dispatch uncertainty stay distinct. Raw errors are sanitized. Invalid/partial reported usage becomes unknown while valid partial counts remain observations. Absence is never zero. This step does not reserve budget, persist attempts, infer actual tokenization or refund costs; The persistence and orchestration modules own those implemented behaviors.

The initial reference-proposal/v1 profile supports abstention or proposal categories pointing to an exact explicitly selected context Artifact. Unknown actions, foreign/unselected/substituted Artifacts and payload-bearing abstention fail. This is a reference-only deterministic profile: no inline scientific extraction, Artifact creation, actual owner existence check or domain acceptance is claimed. BP-07.02/.03 add reviewed task payload profiles; proposing a reference does not establish what its content means. Source text/payload is never executed.

Observation groups a bounded captured byte prefix, completion flag, content hash, exact attempt, outcome and observed usage. Public ProviderObservation omits raw capture bytes; storage/access policy for raw outputs is a separate owning workflow. Failed captures may contain untrusted source content and must retain the request's access scope. Adapter replies do not mark Runtime engagements accepted or mutate a campaign.

Owned tests: tests/providers/test_provider.py covers all fixture variants, rejected profile/model before dispatch, scope/action/payload substitution, strict JSON, byte/chunk bounds, sanitization, partial usage and delayed independent calls. Context/contract tests remain separate. Rebuild acceptance preserves these statuses, bytes/digests and attempt linkage; later real transport must separately prove timeout/cancellation and durable accounting. No real model quality or concurrent Runtime engagement authority is asserted.

## Reviewed typed-output profile (Planning0.9)

OutputProfiles is a closed owner-defined catalog keyed by exact public schema identity: reference-proposal/v1 and extraction-draft/v1. It does not discover/import executable handlers from model data. Extraction parsing validates strict schema, permitted action, abstention shape, selected Artifact references and scope. It derives TypedProposal action/rationale/canonical payload JSON/SHA-256, wrapped in observation format2. Citation geometry, exact source-owner existence and identity/semantic policy still belong to the extraction workflow; proposed never means accepted knowledge or Research state.

Raw capture and canonical payload remain at most64KiB. Observation format2 permits256KiB encoded overhead; legacy format1 stays64KiB encoded. wire.observation_document rejects unknown/numeric version tags, malformed/duplicate/nonfinite JSON and version-specific overflow. The common journal, charge and late readers decode both versions without changing prior canonical bytes. Successful read/write reconstructs the reviewed envelope from retained capture; forged schema/action/rationale/payload/hash conflicts. Unsupported profiles reject before provider reply.

Tests/providers/test_task_output.py verifies both format bounds, candidate/rejection/abstention, all candidate reference groups, tampering and a golden exact-byte observation captured from independently installed Planning0.8. Actual PostgreSQL encoded-overhead/late/constraint checks live under tests/persistence/test_task_output.py; installed task_output_probe proves replacement readback. No live extraction-model quality claim.
