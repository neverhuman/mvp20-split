# Campaign decision boundary

DecisionDeclaration owns the canonical planning-campaign-decision.v1 configuration profile. Its SHA must equal the original request's decision_scope. The declaration identifies its separate Artifact by ID only, avoiding a self-referential digest. The original request must include that exact text/plain Artifact as a required constraint and the validated preparation must contain its canonical bytes. Engagement, objective/policy roots, cut, action subset and scope rebind to the original request. No model output can introduce broader authority by supplying new declaration text.

Private DTOs in wire.py serialize bounded reviewed configuration; declaration.py, AdjustmentPermissions and FutureDecisionBoundary own validation behavior. Input/canonical bytes are capped64KiB. The parser rejects duplicate keys, unknown fields, invalid profiles, nonfinite/range errors, duplicate permit identities and missing root context pins. A future boundary fixes campaign identity/revision, exact context-pin set and graph/iteration/timeout/side-effect ceilings. Adjustment permits fix authored target/input, previous-value SHA and typed enumeration or numeric kind/unit/range. Local prior-value hash matching is not an actual Runtime state read.

CampaignDecisionReview composes exact prepared/evidence/tool checks with declaration bounds and a revalidated existing BudgetPolicy reservation demand. It includes required objective/policy/declaration dependencies in the read-set. Its next_step is compile_future_draft, evidence_request, abstained or runtime_adjustment_unavailable. Unknown/weak/contradictory science remains explicit; only declared action prerequisites constrain the proposal. Descriptor applicability matching is metadata consistency, not scientific eligibility.

This module has no I/O, SQL, provider dispatch, budget reservation/spend, peer mutation or execution authority. Fresh processing rights, Registry eligibility/capacity, actual Runtime compilation and durable submission remain B2.02/B2.03. Runtime has no adjustment-write API in this baseline; retain that gap instead of fabricating an acceptance receipt. Decisions are original reviewed inputs, not cryptographic signatures or fresh source grants. Human changes remain between campaigns.

Owned tests live under services/agent_planning/tests/campaign_decisions, included in the agent-planning ownership scope and focused isolated proposals verifier. Rebuild acceptance preserves exact declaration/request/body/budget binding, future/adjustment bounds, conservative uncertainty and unchanged published schemas/command bytes. No new public output schema or migration is introduced.

Known integration blocker (2026-10-05): the v1 self Artifact ID avoids a self-digest cycle but cannot be known before normal Data publication assigns its catalog ID. Existing fixtures use synthetic predetermined IDs. A private v2 profile binding the unique original consumed required-constraint Artifact by declaration digest is proposed in the BP-07.03 declaration publication decision; it is not yet implemented or approved. Preserve v1 canonical bytes and replay.
