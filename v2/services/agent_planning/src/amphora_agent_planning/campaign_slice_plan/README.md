# Campaign slice plan

Owner: Agent Planning. Architecture: [Planning](../../../../../docs/Architecture/Agents/Planning.md). This module composes already observed owner data through closed validating adapters. It performs no I/O, provider call, rights renewal, compiler acceptance or scientific evaluation. Serialized slices are private Planning preparation values, not shared owner models or public DTOs.

Start with `CampaignSlicePlan.from_artifacts`, which revalidates the original Artifact plan, every body and failure. Add at most one selection per family through `with_research`, `with_graph`, `with_registry`, `with_runtime` (or explicit unavailable), and `with_retrieval`. Each adapter invokes the owning projection factory again and requires the identical original RequestSnapshot, not merely the same scope. Duplicate families reject rather than replacing observations. Direct dataclass construction and private methods are internal implementation, not untrusted input boundaries.

Mandatory roots and manifest-required Artifacts retain their original roles and exact bytes. Missing required Artifact IDs are explicit technical blockers for subsequent packet preparation. The prompt body remains observed data here; only the reviewed instruction profile can admit it to the trusted instruction field later. Original omissions remain unchanged and never become candidate reads.

The complete original Research selection (including expected hashes), selected records, criteria, dependency findings and gaps form one required slice; selected graph records with dependency closure form another. Their pending, unknown, contradictory or unavailable scientific contents do not add Artifact blockers. Registry scan diagnostics, separately selected exact release observations, Runtime universe and explicitly selected schemas are required context. Inventory releases, named Research pages and retained retrieval are optional and separately omittable. This bounded policy protects selected constraints before optional expansion; it is not a scientific ranking algorithm. Parameterized relevance ordering is successor policy, not inferred from labels or confidence.

Each inventory release is an individual slice, so a large catalog is never an indivisible optional packet. Registry inventory and later exact observations use distinct observation kinds, preserving differing lifecycle states. Scan diagnostics do not create a blanket all-catalog consumed read-set. Graph observations retain selected alias/retraction absence as well as present records. Optional slices carry their own observations; the packet layer must consume only those it actually includes.

Stable required-before-optional ordering retains original selection/addition priority within each class. Byte-owned payloads, identities and observations cannot be mutated through decoded copies. The closed adapters produce at most 889 slices: 132 Artifacts, one Research context and 32 pages, one graph, 465 Registry items including scan metadata, 257 Runtime items, and one retrieval. A 900-slice guard leaves no supported input silently dropped. A 128MiB aggregate payload/identity/observation bound accommodates projection caps including base64 Artifact expansion; overflow rejects, never truncates. This pre-packing memory bound does not claim the final packet fits a model window.

Module-owned tests cover complete mixed-owner assembly, same-scope different-request rejection, future lifecycle observations, explicit unavailable science, required Artifact failures, immutable bytes, original omissions, duplicate prevention and bounded aggregation. Replace behind the same factories and canonical `planning-campaign-slice-plan.v1` representation or version the profile while preserving replay. Packet rendering/token fitting, reconstruction from stored preparation, durable accounting and fresh processing checks before dispatch remain subsequent work.
