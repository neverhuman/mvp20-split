`DraftSession` owns one scoped next-campaign draft: acknowledged base, local title/definition, selected node, dirty state, latest pinned validation and one original save/validate submission awaiting reconciliation. It performs no network calls, activation, live graph editing or emergency cancellation. The caller loads public records through the authoring transport; presentation consumes copied state. There is no browser persistence or backend credential.

Edits remain possible during a pending save. A valid committed revision advances the base while preserving later local edits. Save/validate acknowledgements must match the original command identity and the exact committed public record before pending state is released. Network loss keeps the same submission. Rejected commands preserve local content. Validation applies only to the acknowledged exact revision/content and is historical when local changes exist; it never grants execution/scientific authority. No automatic rebase or fresh-ID retry is implemented.

Denial clears protected server projections and blocks subsequent transmissions in that session while retaining local work for explicit recovery. A session has immutable actor/scope/draft identity; changing authenticated context requires a new session, never rebinding old local work into another scope. Late results cannot restore a denied session. New-draft creation and adopted persisted revisions pass public shape/scope checks; layout coordinates are not definition state.

`DraftCommands` owns save/validate submission and explicit original-receipt reconciliation for one DraftSession. Accepted receipts trigger exact immutable revision/result reads before settling local state. Pending or missing receipts and failed record reads retain the original command; there is no automatic POST retry or polling. A request generation fence protects against uncancellable late peers. Denial clears protected projections and disables the session; dispose cancels requests/listeners. Observed operation/request-digest bindings and terminal receipt outcomes cannot change during reconciliation. Owned synthetic-peer tests exercise lost acknowledgements, unavailable committed records, denial/late-read races and changed terminal outcomes. They are not live Runtime/browser acceptance.

`ToolChoices` joins a bounded public Registry page (at most100 releases) to Runtime reviewed tool/schema pins. Exact capability/release/image/contract, descriptor, port and checkpoint identities must agree. Duplicate or cross-scope records fail explicitly. Inactive, unreviewed, mismatched or schema-incomplete releases remain inspectable with unavailable reasons. Authoring availability always carries `executionEligibility=not_checked`; it does not replace B2 owner admission policy.

`EditorCatalog` owns one replaceable discovery page and one lazy exact-schema read. It verifies scope and schema bytes before exposure; refresh cancels old schema selections, stale discovery disables executable selection, and either owner denial clears metadata, including late denial after a sibling read failed. All responses have generation fences. No persistent browser cache, remote schema-reference resolution, Registry mutation or catalog-wide schema prefetch. Owned tests cover exact pins, unavailable reasons, lazy fetch/pagination, superseded schema responses, universe changes and parallel-read denial. Bounded schema-field forms and scripted-peer browser evidence now exist; actual-owner B1 acceptance passed.

`DraftComparison` compares bounded same-scope/campaign local and base drafts, matching nodes by scoped identity (including nested bodies), reporting reorder separately, and preserving duplicate identities through positional comparison plus a warning. It reports at most200 rows and exact omitted counts; object key order is irrelevant, other array order and omitted-versus-explicit defaults remain visible structural differences. It never merges, validates scientific compatibility or changes execution.

`SchemaFields` derives at most64 fields from a verified closed object schema. Primitive fields support reviewed scalar constraints and bounded local scalar references; structured/composed/unsupported fields explicitly require bindings. Scalar parsing produces materializer field constants, not uploaded artifacts or complete tool inputs. Whole-object compiler/scientific validation remains authoritative elsewhere. Raw numeric text is checked before conversion, including nonzero underflow and fractional rounding for integer fields. There is no remote schema resolution or default insertion. Caller must use EditorCatalog exact verified schema bytes.

`EmergencyStop` is a separate operational command model with no DraftSession dependency. One fixed actor/scope/run receives current Monitor observations; running revision is pinned into one runtime.cancel command. Stale/historical views disable new submission. Receipt identity, operation/digest, exact run commit and terminal outcome are checked. Pending/lost reads retain the original command and allow receipt GET only; denial/dispose fences late peers. Accepted means a Runtime cancellation receipt, not external effects settled; the observation model is never mutated. A rejected session does not auto-retry or rebase; further operational action requires a fresh deliberate context. Chromium can internally retry identical POST bytes on socket loss, so Runtime idempotency is essential.

DraftRebase owns a bounded latest-head read and review/apply transition. Only an explicitly applied newer same-scope/draft/campaign revision changes the expected base. All local content stays intact; there is no merge, POST, automatic save or activation. Applying clears the old validation, and dirty content must be saved before new validation. Pending commands block rebase; stale/superseded/denied reads cannot change the base or expose protected previews. DraftCommands owns its lifecycle.
