# Studio observation page models

Design authority: [read-model protocol](../../../docs/Architecture/Experience/Studio_Read_Model_Protocol.md). Implemented: BP-05.02 B1-B3; final-source V1 replacement/audit accepted. These objects own disposable browser state, not execution or scientific authority.

## Owners and invariants

- MonitorModel is the sole snapshot, selected-detail/attempt-page and invalidation loader. GraphWindow binds scope/run/plan/cut/query and rejects duplicate membership or false completeness. Refresh preserves selection within a run; context changes clear it. Fetch time is separate from source revision.
- RequestLane combines abort with generation fencing, including peers that ignore cancellation. EventPosition verifies consecutive invalidations and bounded100-entry duplicate memory. Runtime only emits run_changed: invalidate that run's mutable views, never pretend individual changed nodes are known. Hidden views cancel reads and become stale until reactivated.
- NavigationModel owns scope and topology lanes under the Monitor cut. Scope pages replace at100; authored-scope topology accumulates at most256 nodes. TopologyWindow verifies semantic scope/query identity, source-page link ownership and unresolved targets. Navigation.observe restores the occurrence/neighborhood bookmark and viewport at a new cut; denial or context change clears protected context. Groups carry explicit iteration/scatter indices but use stable hash ordering, not chronological order.
- SceneWindow bounds presentation to200 nodes. Only owner-authored edges with captured endpoints are rendered. Navigation stores viewport and scene offset; coordinates never alter executable topology.
- ViewCatalog verifies scoped capability definitions and typed filters. NamedViewsModel owns catalog and immutable lineage lanes; missing predecessor history is unavailable, not invented empty success. Knowledge/material/property/model views remain unavailable until their owners ship.
- EvidenceContext checks completion against selected run/activation/attempt/invocation/fence/canonical status and accepted revision; artifact metadata must equal the retained reference in every identity field. EvidenceModel owns independent completion, output-page and artifact-metadata lanes. References must originate in selected detail/completion/current values. Output pages replace at100; no content fetch or scientific acceptance is inferred.
- InspectionHistory and history_pin retain at most8 ephemeral captures,2MiB each,200 graph nodes plus captured detail/evidence. Pins are immutable copies, explicitly incomplete, and never load historical mutable frontier rows. Scope changes and read denial clear them. No browser persistence or auto-eviction. Captured detail may lie outside the captured scene and is labeled separately.
- PropertySeries is a fixture-tested future-consumer policy. Partition by exact scope/material state/property/method version/unit/applicability/measured-or-predicted/model context; retain all latest timestamp ties and the earlier observations. No unit conversion, state equivalence or scientific promotion. Explanation features remain distinct from causal assertions.

## Named view module replacement contract

Public boundary: `new NamedViewsModel(NamedViewSource)`, stable `snapshot`, `subscribe(listener)`/unsubscribe, async `load(snapshot|null)`, async `lineage()`, and `dispose()`. NamedViewsState remains exported from named_views.ts for existing consumers. Source ports are read-only `catalog(run, snapshotToken, signal)` and `lineage(run, signal)`; no fetch, credentials, owner tables, mutation, arbitrary query or scientific inference exists here.

The rebuilt coordinator owns independent catalog/lineage RequestLanes and subscriptions. NamedViewProjection owns immutable presentation transitions and error policy. ViewCatalog remains the capability/cut/lineage validator. Loading an anchor invalidates both requests and clears old protected state. A null anchor becomes idle. Only an accepted ready catalog permits lineage; its exact public capability must exist before the read and returned scope/run/plan must agree. Loading lineage clears prior lineage/error while retaining the accepted catalog. Ordinary lineage failure leaves the catalog usable; denied/resnapshot failures cancel both lanes and clear catalog/lineage into denied/stale. Abort creates no fabricated result. Disposal cancels requests, clears listeners and blocks later publication.

Begin the request generation before publishing loading state: subscribers may synchronously rebind or dispose. Late/uncancellable responses and subscriber-triggered context changes cannot restore older context. Publish stable frozen state only on a real transition; async operations never change authoritative domain state. Replacement must preserve these methods, region semantics, public transport, existing named_views.test.ts byte-for-byte and real-owner capability/lineage inspection. New replacement tests cover synchronous subscriber rebinding during both loading paths.
