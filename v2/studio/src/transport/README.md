# Observation transport

Owner: [Studio](../../README.md). `ObservationClient` implements the `ObservationSource` port used by page models. It also implements the separate NavigationSource port for scoped topology and occurrence reads. It performs read-only snapshot, selected-node, value-page and invalidation requests; it contains no graph decisions or component state.

The configured prefix is a relative same-origin path, default `/api/runtime`. Request credentials use the browser session; no Runtime bearer key is stored here. A thin server adapter must perform scoped owner routing. Read identifiers/cursors are URL-encoded, redirects are rejected, pages request50 records (events100), response bodies are capped at2MiB and requests default to15 seconds. These are engineering bounds, not measured UI latency targets.

Each request relays caller cancellation to its own controller and clears timer/listener ownership on completion. The body is consumed with a byte limit and fatal UTF-8 decoding before JSON/schema validation. Responses are never accepted solely because TypeScript assigned a static type. Backend raw error text is excluded from `ReadFailure`: denied401/403, missing404, resnapshot409/410, timeout, abort, invalid response and network failure are explicit categories.

The transport owns no retries, caches, polling timers or authority decisions. Page models decide whether a visible invalidated region should refresh. The ten endpoint shapes preserve Runtime's public contracts; possession of a cursor is never treated as authorization.

Owned tests: `tests/transport/` cover actual local HTTP encoding/no owner credential, all DTO roots, status mapping, cancellation/timeout, malformed JSON/UTF-8/type and declared/streamed size limits. The local HTTP server is a labeled synthetic contract peer. Real Runtime/gateway/browser acceptance remains later in this child. Replacement must preserve bounds, sanitized failures, cancellation and public shape validation.

NamedViewSource reads the scoped capability catalog and the existing immutable graph-runs lineage namespace. It shares bounded decoding/cancellation without introducing browser authority or arbitrary owner routes.

EvidenceSource reads `/v1/runs/{run}/completions/{completion}` through the Runtime adapter and `/v1/artifacts/{artifact}` through a separately configured same-origin Artifact adapter (default `/api/artifacts`). Both use the same bounded public-schema decoding/cancellation; no owner credentials enter browser requests. Metadata inspection never fetches `/content`. Adapter prefixes reject cross-origin, protocol-relative and backslash-normalized forms. Production adapter/session deployment remains open.

BP-05.03/B1 authoring is a separate `AuthoringClient`, with Runtime and Registry adapter prefixes. It reads drafts, validations, reviewed universe/exact schema envelopes and public release metadata; it posts explicit save/validate/admit/cancel submissions and reads their original receipts. The shared `bounded_json.ts` owns only byte/UTF-8/JSON bounds, preserving observation behavior. `AuthoringFailure` contains a sanitized category and whether a dispatched command's outcome remains unresolved. A receipt read failure, including404, never proves that the original command was not committed. This layer performs no automatic retries or polling and carries no backend credential.

`Submission` owns an immutable JSON snapshot and original identity, validates public DTO shape, command family, save scope, safe integer/Unicode/depth/size bounds, and requires an expected run revision for emergency cancellation. It verifies receipt actor/scope/family/id; it does not calculate the server's canonical request hash or infer commit from HTTP success. Page models must retain submissions until reconciled and follow exact committed records. Admission transport availability grants no eligibility; Runtime still rejects tool-bearing drafts pending B2. Owner outcome policy, local editing, presentation and browser/gateway acceptance remain separate work.

Owned authoring tests cover mutated caller inputs, wrong identities/families, unsafe numbers, lost acknowledgement/original receipt lookup, missing receipts, timeout versus pre-dispatch abort, status sanitization, streamed size bounds and full schema query/Registry routing. Replacement must preserve unresolved outcomes and immutable original bytes.

Approved numeric correction: Submission selects explicit amphora-command-v2 for save/admit only; validate/cancel remain unmarked v1. Finite numeric values are validated against the existing DTO, signed zero emits positive zero, and unsafe integral binary64 values in number fields use exponent tokens so they cannot be mistaken for unsafe JSON integers. This is wire encoding, not server canonical hashing. Original bodies remain immutable. Runtime NumberValue inputs remain their existing decimal strings. Tests include decimals, 1e20/1e100, subnormals, signed zero, non-finite/range rejection and unchanged legacy actions.

V2 save/admit producers require Runtime0.19.0. Old unmarked callers remain supported by the new owner. A rejected v2 request must not silently fall back to v1 or acquire a fresh identity; reconcile the original command. UI numeric text parsing must also detect overflow/nonzero underflow before converting text to a JavaScript number; the transport cannot recover a spelling already rounded away by a caller.

POST409 classifies command_conflict: the identity may already bind different bytes, so consumers must block adoption of that identity's receipt. GET409 remains stale metadata. A terminal200 rejected receipt is distinct; ordinary network loss still requires original receipt reconciliation. No client computes Runtime canonical request hashes or silently retries under fresh identity.

BP-06.06 scientific/ owns distinct Knowledge/Research same-origin clients with exact query/ref/schema checks and1MiB output bounds. These are metadata inspection reads, not an expansion of Runtime authority. Source bytes are the separate B1.04b boundary.
